# P427 Pull request view for GitHub and Azure Repos

Plan for `docs/v0.2.24/SPEC.md` row P427 (Stream B). Base: `29fc42714` (`chapter/v0.2.24-stream-b`, P423 landed).
Discovery ran through `codegraph_explore` (8 calls: githost contract and registry, github graphql/sync/links, azure
client/map/review/links, `fakehost.Forge`, fakeaz, `bridge/githost.go`, `AdeTaskService.OpenReviewWindow` /
`ReviewWindowTarget`, `ade/review.go` window rows, appwire `Build`/`BindShell`/`Bound`, `internal/shell` OpenWindow and
ephemeral rule, flowharness `WindowManager`, frontend review-window boot in `main.ts`/`App.vue`, `markdownReading.ts`),
then Read/Grep for tests, fixtures, docs.

One sequential Sonnet implementer.

## Ask

- View one PR (GitHub, Azure Repos). No lists, no boards.
- Show: description, comments (read only), checks status, other common details. Keep it simple.
- Later phases build on it:
  - P428 reuses the window for a Jira issue.
  - P429 posts comments with attachments. It extends the read comment model. GitHub attachments stay unsupported
    (Decision 3).
  - P430 opens this view from a clipboard link. It may also open it from host + repo + number.

## Findings (current tree)

- `githost.Provider` roles: Remotes, Auth (repo-scoped since P423), ChangeRequests, URLs. Optional roles:
  ChangeRequestSync, ChangeRequestReviews, BranchLinks, ChangeRequestSearch, CLISetup. No role reads one PR's detail.
  Every call reports failure in a `Status`, never an `error`.
- `Registry.ParseBranchLink` walks only `BranchLinks` providers. `fakehost.Forge` does not implement `BranchLinks`.
  Adding it there would change `BranchLinkLabels()`, and Stream C's `adeflow` asserts that text. So the new role
  carries its own link parser. Forge then implements the new role without `BranchLinks`.
- GitHub client: `c.graphql(ctx, repo, query, []GraphQLVar, out)`. Strings travel as `-f`, ints as `-F`.
  `graphqlTimeout` is 30 s. `toStatus` maps failures. `gone(host)` marks a missing PR. `withRateLimitReset` sets
  ResetAt. Sync reads the rollup via `commits(last:1){nodes{commit{statusCheckRollup{state}}}}`.
- Azure client: every argv goes through `argv(sub, org, extra...)`, which appends `--org --detect false
  --only-show-errors -o json`.
  - `callJSON` sits behind the discovery auth gate.
  - `prShow` uses the `prShowQuery` projection. `policies` uses `policyQuery`.
  - `invoke` is POST only: it always writes a temp `--in-file`.
  - `toolexec.MaxStdoutBytes` is 1 MiB, so every read needs a `--query` projection.
  - `mapPR(r, raw)` composes the URL. `split(r)` returns (org, project).
- The `fakeaz` invoke handler accepts only POST `--area git` (`pullRequestQuery`, `pullRequestThreads`). It records
  posted thread bodies in `a.threads[id]`.
  - Its `projection` struct mirrors `prShowQuery`.
  - Call labels: `pr-show:N`, `policy:N`, `invoke:<resource>:<key>`.
- Window precedents:
  - Space review: `AdeTaskService.OpenReviewWindow` → `ade` creates a `Windows` row (so `SetBounds` persists), then
    bridge calls `OpenWindow(shell.WindowRecord{Key, Order})` + `SetWindowTitle`. An existing window gets
    `FocusWindow(key)`.
  - `main.go`: `WindowOpenerDeps.Ephemeral` returns true for review keys. An ephemeral window never restores, drops its
    row on close (`closeDecision`) and never counts as the last window. `purgeReviewWindows` runs before
    `Windows.List()` at boot.
  - Frontend `main.ts` fetches `reviewTargetKey(windowKey)` first. When a target is set, it skips workspace boot.
    `App.vue` renders `<AdeReviewWindow v-if="reviewWindow.target" />`.
- Flow harness `WindowManager` records `Opened`, `Focused`, `Titles`. `FocusWindow` returns `Known[key]`. The harness
  binds hooks through `BindShell`. It never runs `OnWindowClosing`.
- Coverage gate (`flows/coverage`): every bound method needs a flow call. `exempt.txt` is empty. An exported method on
  a bound service is bound, so `Forget` must live on a non-service type.
- UI entry points: the PR row (`ade/v2/panel/AdeBranchPanel.vue:382-404`) and the task host link
  (`AdeTaskTab.vue` → `AdeLinkRow.vue`) are Stream C files. A menu item needs `packages/shared/protocol/events.ts`,
  which no stream owns. See Ownership.
- markdown-it 15.0.2 is already a root dependency. `views/repo/markdownReading.ts` uses `html: false`, `linkify:
  true`. The `.kira-prose` class lives in `packages/theme/src/base.css`.
- TanStack defaults (`packages/workbench/src/state/queryClient.ts`): `staleTime: Infinity`, no refetch on focus.
  Freshness therefore comes from an explicit Refresh.
- `tests/ui/fixtures.ts` is unowned. Its `reviewTest` sets `readySelector: '[data-testid="ade-review-window"]'`. The
  host view needs its own fixture under `tests/ui/support/` (owned).

## Design

### 1. Neutral contract: `apps/kira-space/internal/githost/detail.go` (new)

```go
// ChangeRequestDetails reads one change request for the PR view.
type ChangeRequestDetails interface {
	// ParseChangeRequestLink reads repo and number from a change request web link (tabs, query and
	// fragment ignored). No host call.
	ParseChangeRequestLink(ctx context.Context, raw string) (Repo, int, bool)
	// ChangeRequestDetail reads number in r. A missing one is Status.Gone.
	ChangeRequestDetail(ctx context.Context, r Repo, number int) (ChangeRequestDetail, Status)
}

type Person struct {
	Login string `json:"login"`          // GitHub login; Azure uniqueName
	Name  string `json:"name,omitempty"` // display name when known
}

type Label struct {
	Name  string `json:"name"`
	Color string `json:"color,omitempty"` // 6 hex digits, no '#'; "" when invalid or none
}

type Reviewer struct {
	Person   Person `json:"person"`
	Team     bool   `json:"team,omitempty"`
	State    string `json:"state"` // ReviewerApproved ...
	Required bool   `json:"required,omitempty"`
}

type Check struct {
	Name     string `json:"name"`
	State    string `json:"state"`         // CheckSuccess ...
	URL      string `json:"url,omitempty"` // https only, else ""
	Detail   string `json:"detail,omitempty"`
	Required bool   `json:"required,omitempty"`
}

type Comment struct {
	ID        string `json:"id"`
	Author    Person `json:"author"`
	Body      string `json:"body"` // Markdown
	CreatedAt int64  `json:"createdAt"`
	UpdatedAt int64  `json:"updatedAt,omitempty"`
	URL       string `json:"url,omitempty"`
}

type Thread struct {
	ID                string    `json:"id"`
	Kind              string    `json:"kind"`                  // ThreadComment | ThreadReview | ThreadCode
	ReviewState       string    `json:"reviewState,omitempty"` // review threads: a Reviewer state
	Path              string    `json:"path,omitempty"`
	Line              int       `json:"line,omitempty"`
	Resolved          bool      `json:"resolved,omitempty"`
	Outdated          bool      `json:"outdated,omitempty"`
	Comments          []Comment `json:"comments"`
	CommentsTruncated bool      `json:"commentsTruncated,omitempty"`
}

type DiffStats struct {
	Commits, Files, Additions, Deletions int // json: commits files additions deletions
}

type ChangeRequestDetail struct {
	ChangeRequest                     // embedded: state, refs, review decision, checks rollup
	Author           Person           `json:"author"`
	Body             string           `json:"body"`
	CreatedAt        int64            `json:"createdAt"`
	ClosedAt         int64            `json:"closedAt,omitempty"` // merge or close time
	Labels           []Label          `json:"labels"`
	Assignees        []Person         `json:"assignees"`
	Reviewers        []Reviewer       `json:"reviewers"`
	Checks           []Check          `json:"checks"`
	ChecksTruncated  bool             `json:"checksTruncated,omitempty"`
	Threads          []Thread         `json:"threads"` // oldest first by first comment
	ThreadsTruncated bool             `json:"threadsTruncated,omitempty"`
	Stats            *DiffStats       `json:"stats,omitempty"` // nil when the host gives none (Azure)
	Mergeable        string           `json:"mergeable,omitempty"` // MergeableYes | MergeableConflict | ""
}
```

- Constants in the same file:
  - `ThreadComment = "comment"`, `ThreadReview = "review"`, `ThreadCode = "code"`.
  - Reviewer states `approved|changesRequested|rejected|commented|pending`.
  - Check states `success|failure|error|pending|skipped|neutral`.
  - `MergeableYes = "mergeable"`, `MergeableConflict = "conflicting"`.
- Caps as consts, shared by both providers: `DetailMaxComments = 100` (conversation), `DetailMaxReviews = 50`,
  `DetailMaxCodeThreads = 50`, `DetailMaxThreadComments = 30`, `DetailMaxChecks = 100`, `DetailMaxLabels = 50`,
  `DetailMaxPeople = 50`.
  - Past a cap, keep the newest and set the matching `*Truncated` flag.
- `ChangeRequestDetail.Normalize()` runs in each provider before return:
  - Nil slices become empty, so JSON shows `[]`.
  - An invalid label colour becomes "".
  - A non-https check or comment URL becomes "".
  - Threads sort by first comment `CreatedAt`, then ID.
  - It applies the caps a provider could not apply server-side.
- Comment fields are read-only now. P429 adds attachments as a new field on `Comment` and a write role. It does not
  change these fields.
- Registry (`registry.go`), added methods:
  - `ParseChangeRequestLink(ctx, raw) (Provider, ChangeRequestDetails, Repo, int, bool)` asks detail providers in
    order.
  - `ChangeRequestViewLabels()` joins `"<Label> <ChangeRequestShort> link"` per detail provider with `" or "`. Its
    first use is the refusal text.

### 2. GitHub: `githost/github/detail.go` (new)

- `ParseChangeRequestLink`: call `p.ParseBranchLink(ctx, raw)`. Accept only when `Number > 0 && !Issue`. Return
  `githost.Repo{Host, Owner, Name}`. It reuses the existing tab rules (`files`, `commits`, `checks`).
- `ChangeRequestDetail`: one GraphQL query `detailQuery`. Vars: `owner`, `name` (`-f`); `number` (`-F`). Envelope
  `repository.pullRequest` plus `rateLimit{remaining resetAt cost}`. A null `pullRequest` returns `gone(host)`. A rate
  limit goes through `withRateLimitReset`. Query fields:
  - Scalars: `number title url state isDraft body createdAt updatedAt mergedAt closedAt reviewDecision mergeable
    additions deletions changedFiles`.
  - People and refs: `author{login ... on User{name}}`, `headRefName headRefOid baseRefName headRepositoryOwner{login}`,
    `id` (NodeID).
  - `commits{totalCount}`.
  - `last: commits(last:1){nodes{commit{statusCheckRollup{state contexts(first:100){totalCount nodes{__typename
    ... on CheckRun{name status conclusion detailsUrl isRequired(pullRequestNumber:$number) title}
    ... on StatusContext{context state targetUrl description isRequired(pullRequestNumber:$number)}}}}}}}`.
  - `labels(first:50){totalCount nodes{name color}}`.
  - `assignees(first:50){nodes{login name}}`.
  - `reviewRequests(first:50){nodes{requestedReviewer{__typename ... on User{login name} ... on Team{slug name}
    ... on Bot{login}}}}`.
  - `latestOpinionatedReviews(first:50){nodes{state author{login ... on User{name}}}}`.
  - `comments(last:100){totalCount nodes{id url body createdAt lastEditedAt author{login ... on User{name}}}}`.
  - `reviews(last:50){totalCount nodes{id url state body createdAt author{login ... on User{name}}}}`.
  - `reviewThreads(last:50){totalCount nodes{id path line originalLine isResolved isOutdated
    comments(first:30){totalCount nodes{id url body createdAt lastEditedAt author{login ... on User{name}}}}}}`.
- Mapping (`mapDetail`, pure, unit-tested):
  - `ChangeRequest` fields: reuse the `gqlPR.toPR()` path from `sync.go`, then `toChangeRequests`-style state and
    draft. Do not duplicate it. Factor a `prFromGQL` helper only if `toPR` cannot take the detail struct (embed
    `gqlPR` in the detail node struct, so `syncPRFields` names line up).
  - CheckRun: `status != COMPLETED` → pending. Conclusion SUCCESS → success. FAILURE, TIMED_OUT, STARTUP_FAILURE and
    ACTION_REQUIRED → failure. CANCELLED, STALE and NEUTRAL → neutral. SKIPPED → skipped. `Detail` = `title`.
  - StatusContext: SUCCESS → success, FAILURE → failure, ERROR → error, PENDING and EXPECTED → pending.
    `Name = context`, `Detail = description`.
  - `ChecksTruncated` = `contexts.totalCount > len(nodes)`.
  - Reviewers: union of `reviewRequests` (state pending; Team → `Team: true`, Login = slug) and
    `latestOpinionatedReviews`. APPROVED → approved. CHANGES_REQUESTED → changesRequested. COMMENTED → commented.
    DISMISSED is dropped. Dedup by login: a review beats a pending request.
  - Threads:
    - Each issue comment → one `ThreadComment` thread.
    - Each review with a non-empty body, or state APPROVED/CHANGES_REQUESTED → one `ThreadReview` thread, with the
      review's body as its single comment and `ReviewState` mapped as above. COMMENTED and PENDING reviews with an
      empty body are dropped: their inline comments appear under code threads.
    - Each review thread → `ThreadCode`. `Line` = `line`, else `originalLine`.
  - `Mergeable`: MERGEABLE → mergeable, CONFLICTING → conflicting, UNKNOWN → "".
  - `Stats` always set.
  - Times: `parseTime` from `sync.go` gives ms.
- Testdata `github/testdata/pr_detail.json`, hand-written from the GraphQL schema. It covers a draft-free open PR,
  every check conclusion, a StatusContext, a team review request, a dismissed review, an empty-body COMMENTED review,
  a resolved outdated thread, label colours (one invalid), `totalCount` above nodes on comments, and the `rateLimit`
  block.
- The implementer may check the query once against a public PR with a signed-in `gh` (`gh api graphql -f
  query=@q.graphql -F number=1 -f owner=cli -f name=cli`). This is optional. Never commit the output.

### 3. Azure: `githost/azure/detail.go` (new)

- `ParseChangeRequestLink`: `p.ParseBranchLink(ctx, raw)`, accepted when `Number > 0 && !Issue`.
- `ChangeRequestDetail`: three reads in an `errgroup` (ctx shared). The first failure is the result, and Gone wins
  over others. `invalidRepo` comes first when `split` fails.
  1. `repos pr show --id N --query PRDetailQuery`. Exported const, so fakeaz can switch on it. It is `prShowQuery`'s
     fields plus `authorName:createdBy.displayName, description:description, mergeStatus:mergeStatus,
     labels:labels[?active!=\`false\`].name, reviewers:reviewers[].{vote:vote,required:isRequired,
     name:displayName,login:uniqueName,team:isContainer}`.
     - Before writing `PRDetailQuery`, read `prShowQuery` in `client.go`. Keep its existing keys verbatim, so
       `rawPR` decoding is shared: embed `rawPR` in `rawPRDetail`.
  2. `repos pr policy list --id N --query policyDetailQuery`: `[].{status:status,type:configuration.type.displayName,
     name:configuration.settings.displayName,statusName:configuration.settings.statusName,
     build:context.buildDefinitionName,blocking:configuration.isBlocking,buildId:context.buildId}`.
  3. Threads GET through invoke (see below), route `project=P repositoryId=R pullRequestId=N`. `--query
     threadsQuery` = `{total:length(value),threads:value[-200:].{id:id,status:status,deleted:isDeleted,
     path:threadContext.filePath,right:threadContext.rightFileStart.line,left:threadContext.leftFileStart.line,
     comments:comments[].{id:id,author:author.displayName,login:author.uniqueName,body:content,type:commentType,
     deleted:isDeleted,published:publishedDate,updated:lastUpdatedDate}}}`.
     - The slice keeps output under the 1 MiB cap.
     - `ThreadsTruncated` is set when `total > 200`, or when the caps in Normalize drop threads.
- `invoke` generalization (`client.go`): `invoke(ctx, org, write, method, resource, route, query string, body, out)`.
  - `body == nil` means no temp file and no `--in-file`.
  - `query != ""` appends `--query <query>`.
  - Both existing callers (`forCommit`, `Comment`/`SubmitReview` thread POSTs) pass `"POST"` and `""`.
  - The implementer verifies in a scratch venv (`pip install azure-cli`, `az extension add --name azure-devops`) that
    `az devops invoke --help` lists the global `--query`. No org is needed.
  - If `--query` is rejected, drop it, decode the full response, and note the 1 MiB risk in Known open items.
- Mapping (`mapDetail`, pure, unit-tested):
  - Base `ChangeRequest` comes from `mapPR(r, raw.rawPR)`. `ChecksState` comes from `checksState(evals)`, as sync
    does.
  - `Author{Login: author, Name: authorName}`. `Body` = description. `CreatedAt` / `ClosedAt` from created / closed.
  - Labels: names only, no colour.
  - Assignees: empty (Azure has none).
  - `Stats` nil.
  - Reviewers, by vote: 10 and 5 → approved. 0 → pending. -5 → changesRequested. -10 → rejected. `Team = team`.
  - Checks: policies whose type is `Build` or `Status`.
    - `Name` = name, else statusName, else build, else type.
    - State: approved → success, rejected → failure, broken → error, queued and running → pending, notApplicable →
      skipped.
    - `Required` = blocking.
    - `URL` = `https://dev.azure.com/<org>/<url.PathEscape(project)>/_build/results?buildId=<id>` when buildId > 0.
  - Threads:
    - Drop deleted threads.
    - Drop comments that are deleted or whose type is `system` or `codeChange`. Accept both the string form and the
      int forms 2 and 3. The REST enum serializes as a string; the int forms are defensive.
    - Drop threads left with no comment.
    - Kind is `ThreadCode` when `path != ""`, else `ThreadComment`. `Line` = right, else left.
    - `Resolved` when status is fixed, wontFix, closed or byDesign.
    - Comment `ID` = `<threadId>/<commentId>`. `URL` "".
  - `Mergeable`: succeeded → mergeable, conflicts → conflicting, else "".
- Testdata (hand-written from REST shapes; `testdata/README` lists each):
  - `pr_detail.json`: projection output with labels, a team reviewer, votes 10/0/-5, and markdown description.
  - `policy_detail.json`: Build rejected with buildId, Status running, reviewer policy (dropped), notApplicable
    Build.
  - `threads_get.json`: projection output covering a general thread with a reply, a code thread fixed, a vote system
    thread, a deleted comment, and `total` 3.

### 4. fakehost and fakeaz

- `fakehost.Forge` (`flowharness/fakehost/fakehost.go`) implements `ChangeRequestDetails`. Add the interface
  assertion.
  - `ParseChangeRequestLink`: regex `^https://forge\.test/([\w.-]+)/([\w.-]+)/-/merge_requests/(\d+)/?(?:[?#].*)?$`.
    Repo `{Host, Owner, Name}`.
  - `SetDetail(number int, d githost.ChangeRequestDetail)` stores an overlay.
  - `ChangeRequestDetail` records `detail:N`.
  - It honours `SetOffline` (same status `match` uses) and `rateLimit()`.
  - An unknown number returns `goneStatus()`.
  - It returns the overlay with `ChangeRequest` replaced by the stored row (`find`) and `Author` from `authors`, then
    `Normalize()`.
- `fakeaz` (`flowharness/fakeaz/fakeaz.go`):
  - `PR` gains `Description`, `AuthorName`, `Labels []string`, `MergeStatus`, `Threads []Thread`.
  - `Thread{ID int; Status, Path string; Right int; Comments []ThreadComment}`, where `ThreadComment{ID int; Author,
    Login, Body, Type, Published string; Deleted bool}`.
  - `Reviewer` gains `Name`, `Login`, `Team`. `Policy` gains `Name`, `Blocking`, `BuildID`.
  - `repos pr show` with `--query == azure.PRDetailQuery` answers the detail projection. Any other query keeps the
    current shape.
  - `policy list` with `--query` equal to the detail one returns the new keys. Export `PolicyDetailQuery` from azure.
    The name is no secret, and the fake can then switch on it.
  - `invoke` with `--http-method GET --resource pullRequestThreads`: there must be no `--in-file`, and `--query` must
    equal `azure.ThreadsQuery` (exported). It answers `{total, threads}` from `PR.Threads` plus posted threads (as
    text threads, newest last). The call label is `invoke:GET:pullRequestThreads:<id>`.
  - A GET for any other resource, or a GET with `--in-file`, is a violation.
  - Unknown PR ids return the not-found stderr the classifier maps to Gone.

### 5. Bridge: `apps/kira-space/internal/bridge/hostview.go` (new)

```go
// HostViewService opens and reads the PR view: one window per change request, never restored.
type HostViewService struct {
	Deps    appcore.Deps
	Windows hostViewWindowRows // deps.Repos.Windows: List, Create, Delete
	Targets *HostViewTargets   // window key → target; not a service, so Forget is not bound
	Now     func() time.Time
	OpenWindow     func(shell.WindowRecord)
	FocusWindow    func(key string) bool
	SetWindowTitle func(key, title string)
	breaker hostViewBreaker
}
```

- Wire types live in the same file. P428 reads `Kind`, and the frontend switches on it.
  - `HostViewOpenArgs{URL string}`.
  - `HostViewOpen{Key string; Opened bool}`.
  - `HostViewWindowArgs{WindowKey string}`.
  - `HostViewTarget{Kind string /* "changeRequest" */; URL, Provider string; Host githost.Info; Repo string /*
    display "owner/name" */; Number int}`.
  - `HostViewChangeRequestArgs{URL string}`.
  - `HostViewChangeRequest{Kind string /* ok|unavailable|gone */; Detail *githost.ChangeRequestDetail; Status
    githost.Status}`.
- `HostWindowKeyPrefix = "hostview-"`. `IsHostViewKey(key) bool`.
- `Open(ctx, args) (HostViewOpen, error)`:
  1. Trim. Reject when `len > 2048`, or when `Deps.GitRegistry` is nil. Then
     `hosts.ParseChangeRequestLink(ctx, url)`.
     - A miss returns `ipcerr.T(CodeBadRequest, "backend.space.gitHost.view.notChangeRequest.body",
       {"changeRequests": hosts.ChangeRequestViewLabels()})`.
     - A GitHub/Azure issue or work item link misses too, because the parser rejects `Issue`.
  2. Canonical URL = `p.ChangeRequestURL(repo, n)`. Tabs and queries are dropped. The identity key is
     `p.ID()+"|"+repo.Host+"|"+repo.Owner+"|"+repo.Name+"|"+n`.
  3. `Targets.KeyFor(identity)` exists and `FocusWindow(key)` is true → return `{key, false}`. Stale (focus false) →
     `Targets.Forget(key)`, then delete its row best effort, then go on.
  4. If any hook is nil → `ipcerr.T(CodeBadRequest, "backend.space.gitHost.view.unavailable.body", nil)`.
  5. Order = max row order + 1, from `Windows.List()` (as `ade/review.go`). Key = prefix + `uuid.NewString()`.
     `Windows.Create(model.WindowRecord{Key, Order})`. `Targets.Put(key, identity, target)`.
     `OpenWindow(shell.WindowRecord{Key, Order})`. `SetWindowTitle(key, i18n.T("backend.space.gitHost.view.window.title",
     {"short": terms.ChangeRequestShort, "number": n, "repo": target.Repo}))` gives "PR #12 · acme/api".
  6. Return `{key, true}`.
- Exported `OpenChangeRequest(ctx, p githost.Provider, r githost.Repo, n int) (HostViewOpen, error)` is the same flow
  from step 2 on. It is not bound: it carries non-wire args, and Wails binds only wire-typed methods. Check how Wails
  v3 treats such a method in `bindings` generation. If it would bind, make it a function `OpenHostView(s, ...)`
  instead. This is P430's "host + repo + number" entry. `Open` calls it.
- `WindowTarget(ctx, args) (*HostViewTarget, error)`: validate the key with `validateAdeItemID`-style rules (non-empty,
  ≤ 128 bytes). Return `Targets.Get(key)` or nil.
- `ChangeRequest(ctx, args) (HostViewChangeRequest, error)`:
  1. Parse as in Open. A bad link is an ipcerr, as in Open.
  2. Breaker key = identity minus the number (one repo). While armed, return `{Kind: "unavailable", Status: <stored
     status>}` with no host call.
  3. `d, st := details.ChangeRequestDetail(ctx, repo, n)`.
     - `st.OK()` → `{ok, &d, st}`.
     - `st.Gone` → `{gone, nil, st}`.
     - `st.RateLimited` → arm until `st.ResetAt`, else `Now()+15*time.Minute` (same fallback as gitsession
       `hostBreakerFallback`; reference it in a comment, do not import it). Then return unavailable.
     - Any other failure → `{unavailable, nil, st}`, not armed.
  4. A cancelled ctx returns unavailable, never armed.
- `HostViewTargets` (same file): mutex map key → {identity, target}, plus reverse identity → key. Methods `Put`,
  `Get`, `KeyFor`, `Forget(key)`.
- The breaker is a mutex map key → until. `armed(key, now)` drops an expired entry.
- No event push: TanStack Query holds the data. The window's Refresh re-runs the call.

### 7. Frontend

All under `apps/kira-space/frontend/src/`, unless a path says otherwise.

- `bridge/index.ts` gets `control.hostViewOpen`, `hostViewWindowTarget` and `hostViewChangeRequest`. Use the
  `unwrap(HostViewService.X(args)).then(r => trust<T>(r))` pattern.
- `hostview/wire.ts`: TS types mirroring section 5 and section 1, plus string-literal unions for kinds and states.
- `hostview/queries.ts`:
  - `hostViewTargetKey(windowKey)`.
  - `changeRequestKey(url)`.
  - `useChangeRequestDetail(url)` = `useQuery`. Call errors are ipcerr. Status failures are data (Kind), not query
    errors.
  - `useOpenHostView()` = `useMutation` over `control.hostViewOpen`. It is unused in this phase unless the gated entry

  - Fenced code: plain `<pre><code>`, escaped, no highlighter.
