Stream A. Branch `chapter/v0.2.24-stream-a`. SPEC row: Kibana support with Discover tab's query
capabilities; autocomplete like Discover (fields, values, operators, syntax).

## 1. Scope

In:

- New connection kind `kibana`, talking to Kibana's HTTP API (never Elasticsearch directly).
- Data views listed as tree nodes. Opening one opens a Discover tab.
- Discover tab: data view picker, KQL/Lucene toggle, time picker (presets, absolute, refresh),
  filter pills, sort, sample size, field sidebar, hit count, date histogram, document results.
- Query editor (Monaco): KQL and Lucene highlighting; KQL autocomplete for fields, operators,
  values and syntax (`and`/`or`/`not`, parentheses, quotes).
- Backend KQL compiler (KQL to ES query DSL), Lucene passthrough via `query_string`.
- Op log, Stop, Re-run and DB MCP `run_query` work on kibana like other engines.
- Chart library decision, shared with P426 (section 4).

Out (stream decisions or later phases):

- ES|QL (streams.md decision).
- Saved queries (P425).
- Agent-filled charts (P426). P424 only adds the library and the histogram.
- Writes of any kind. Kibana kind is read-only.
- Kibana dashboards, visualisations, saved searches import, alerting.
- Field statistics popover ("top 5 values") and field formatters. Values show raw `_source`.

## 3. Kibana API facts the adapter relies on

All requests: header `kbn-xsrf: kira-studio`, `Content-Type: application/json`.
Space: non-default space prefixes every path with `/s/<space>`.
Internal routes also send `elastic-api-version: 1` and `x-elastic-internal-origin: Kibana`.

| Use | Route |
| --- | --- |
| Connect, version | `GET /api/status` → `version.number` |
| Space check | `GET /api/spaces/space/{id}` (404 → CodeNotFound) |
| List data views | `GET /api/data_views` → `data_view[]{id,name,title,timeFieldName}` |
| Data view detail | `GET /api/data_views/data_view/{id}` → `data_view{fields,timeFieldName,title,runtimeFieldMap,sourceFilters}` |
| Field fallback | `GET /internal/data_views/fields?pattern=<title>&meta_fields=_id&meta_fields=_index` (when detail's `fields` is empty) |
| Search | `POST /internal/search/es` body `{"params":{"index":"<title>","body":{...}}}` → `rawResponse` |

Step 1 probes both pinned versions first and records real responses as testdata. If the probe
shows a different shape (e.g. `/internal/search/es` needing another header, or returning a
`isPartial`/`isRunning` async envelope), adapt client code to the recorded shape and write the fact
into ARCHITECTURE (section 9). Expected: `es` strategy answers synchronously, no polling. If the
probe shows `isRunning: true` responses, stop and report; async polling is not planned.

Auth:

- Fields mode: `username` + `password` → Basic.
- `username` blank, `password` set → `Authorization: ApiKey <password>` (encoded API key as Kibana
  shows it).
- Both blank → no auth header (Kibana with security off).

## 4. Chart library decision (shared with P426)

**Apache ECharts 6.1.0 + vue-echarts 8.3.2.**

- `echarts` 6.1.0: Apache-2.0. Deps: `zrender` 6.1.0 (BSD-3-Clause), `tslib` (0BSD).

### 6.4 KQL compiler (`feat: kibana KQL compiler`)

`apps/kira-studio/internal/adapters/kibana/kql/` (package `kql`):

- `lexer.go`, `parser.go` (recursive descent, AST), `compile.go` (AST → `map[string]any` DSL),
  `errors.go`.
- Named requirement for hand-rolling: no maintained KQL library for Go; Kibana's own grammar
  (`@kbn/es-query` PEG) is unpublished and triple-licensed (Elastic License 2.0 / SSPL / AGPL),
  not fully open source, so not copied or ported line by line; a parser generator would add a Go
  module (go.mod not owned). Grammar written from Kibana's public KQL docs.

Grammar (KQL as documented):

```
query      = orExpr? EOF
orExpr     = andExpr ("or" andExpr)*
andExpr    = notExpr ("and" notExpr)*        // keywords case-insensitive
notExpr    = "not" notExpr | primary
primary    = "(" orExpr ")" | fieldExpr | valueExpr
fieldExpr  = field ":" listOrValue
           | field ("<" | "<=" | ">" | ">=") rangeValue
           | field ":" "{" orExpr "}"         // nested
listOrValue= "(" valueOr ")" | value
valueOr    = valueAnd ("or" valueAnd)* ; valueAnd = valueNot ("and" valueNot)* ; valueNot = "not" valueNot | "(" valueOr ")" | value
value      = quoted | unquoted               // unquoted may contain * wildcards and \-escapes
field      = unquoted (may contain *) | quoted
```

Escapes in unquoted: `\\ \( \) \: \< \> \" \* \{ \}` and whitespace; `\and`, `\or`, `\not` keywords.
Quoted strings: `\"` and `\\`.

Compile rules (mirror Kibana semantics):

- `f:v` → `match{f:{query:v, lenient:true}}`. Quoted `f:"a b"` → `match_phrase`.
- Unquoted value with `*` → `query_string{query:<escaped with * kept>, fields:[f], analyze_wildcard:true}`.
  `f:*` → `exists{field:f}`.
- Range → `range{f:{gt|gte|lt|lte: v}}`; date fields add `time_zone` (request `timeZone`).
- Value lists `f:(a or b)` → bool should/must per operator, each element compiled as `f:x`.
- `not` → `bool.must_not`; `and` → `bool.filter`; `or` → `bool.should` + `minimum_should_match: 1`.
- Free text (no field) `v` → `multi_match{query:v, type:best_fields, lenient:true}`; quoted →
  `multi_match{type:phrase}`; with `*` → `query_string{query, analyze_wildcard:true}` over all
  fields.
- Field name with `*` → expand against data view field list (searchable fields only) into a bool
  should over matches; zero matches → `match_none`.
- Nested `f:{ … }` → `nested{path:f, query:<inner compiled with fields prefixed f.>, score_mode:none}`.
- Unknown field (not in data view) still compiles (Kibana does). Value suggestions skip it.
- Empty / whitespace query → `match_all{}`.

Errors: `kql.SyntaxError{Pos int, Expected []string, Found string}`. Adapter wraps to
`adapters.T(CodeQuery, "backend.studio.kibana.kqlSyntax", {pos, expected, found}, err)`. Catalog
text example: "KQL syntax error at position {pos}: expected {expected}, found {found}."

Lucene (`language: "lucene"`): `query_string{query, analyze_wildcard:true, time_zone}`; empty →
`match_all`. Syntax errors come back from ES as 400 → `CodeQuery`.

Tests: `kql/kql_test.go` table: input → expected DSL JSON (golden-in-table, compact JSON compare),
plus error table (position + expected). Cover: precedence (`a and b or c`, `not a and b`),
parentheses, value lists with mixed and/or/not, nested, escapes (`\:`, `\*`, `\and`), quoted vs
unquoted, wildcards in value and field, range on date (time_zone) and number, `f:*`, free text,
empty. This is a parser with interacting rules; unit test is warranted.

### 6.5 Search: Execute, Read, Count, classifier (`feat: kibana search`)

- `buildBody(dv KibanaDataView, req KibanaDiscoverRequest) (map[string]any, error)`:
  - `query.bool.filter` = [compiled query, time range on `dv.TimeFieldName` (`range{tf:{gte:from, lte:to, format:"strict_date_optional_time"}}`; ES date math passes through unchanged; omit format when either side starts with `now`), enabled filters].
  - Filters → clauses: `is` → `match_phrase`; `is_not` → must_not `match_phrase`;
    `is_one_of` → bool should of `match_phrase`, min 1; `is_not_one_of` → must_not of that;
    `exists` → `exists`; `does_not_exist` → must_not exists; `between` → `range` gte/lt (empty side
    omitted). Disabled filters skipped. Filter on field not in data view → `CodeQuery`
    (`backend.studio.kibana.unknownField`).
  - `sort`: request sort, else `[{<timeField>: {order: desc, unmapped_type: boolean}}]` when time
    field set, else `["_doc"]`. Sorting on a non-aggregatable field → `CodeQuery`
    (`backend.studio.kibana.unsortable`) before calling ES.
  - `track_total_hits: true`, `size`, `from` (Read only), `runtime_mappings` from data view
    runtime fields, `fields: [{field:"*", include_unmapped:true}]` only when runtime fields exist
    (merge `fields` values of runtime fields into doc body), `_source.excludes` from
    `sourceFilters`, `timeout: "30s"`.
  - Unknown `dataView` id → refetch once, then `CodeNotFound`.
- `Execute(ctx, op, req ConsoleRequest)`:
  - Exactly one non-empty statement, else `CodeQuery` (`backend.studio.kibana.oneStatement`).
  - Decode with `json.Decoder.DisallowUnknownFields`; bad JSON → `CodeQuery`
    (`backend.studio.kibana.badRequest`, message includes decoder error).
  - `dataView` "" → id from `req.Path`; still "" → `CodeQuery`.
  - `language` "" → `kuery`; other values → `CodeQuery`.
  - `size` 0 → 500; clamp to `ConsoleCapFor(req).Rows` and 10000. Send `size+1`; extra hit →
    `HasMore`/`Truncated`.
  - `op.SetCommand(<statement as given>)` before the request.
  - Build page with `page.NewDocumentPageBuilder(false)`; `Push(_id, body)` where body =
    `{"_id":…, "_index":…, ...<_source>, ...<runtime fields>}`. ES forbids `_id`/`_index` inside
    `_source`, so keys never collide. Stop pushing when `ResultCap.Reached` (bytes).
  - `Finish(page.CappedPosition(rowCount, truncated))`. `op.SetRows`.
  - Result page meta: if the console result shape has a "total"/message slot, set
    `"<n> hits"`; otherwise frontend gets total from histogram (6.10). Check `model.ConsoleResult`.
- `Read(ctx, op, req ReadRequest)` on a data view path: KQL filter = `*req.Filter` (nil → empty),
  time range none (all time), sort = `req.Sort` mapped, else time desc. Offset pagination from
  `req.Cursor` via `internal/page` offset helpers (mirror mongo `read.go`); `from+size ≤ 10000`,
  beyond → `HasMore false`, `Truncated true`. Projection unsupported (caps false).
- `Count(ctx, op, req CountRequest)` → `size: 0`, `track_total_hits: true`, filter as Read →
  `CountResult{Value: total, Exact: relation == "eq"}`.
- `classify.go`: implement `adapters.StatementClassifier` → always read class (find the exact
  constant name via codegraph `StatementClassifier`).

Note `Read` makes the existing data/document tab work if any code path opens a data tab on a kibana
`collection` node; 6.7 routes the tree to Discover instead, but Read/Count keep the Adapter
contract honest and conformance-tested.
