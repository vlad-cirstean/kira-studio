## Ask

- View one Jira issue. No lists, no boards.
- Show: title, description, common details (assignee, status, priority, labels, ...), comments (read only).
- Build on P417's `issuetracker` abstraction. Reuse P427's window, service and frontend; add the issue kind there.
- Later phases build on it:
  - P429 posts issue comments with attachments (Jira supported, Decision 3). It extends this comment model and adds a
    write role.
  - P430 opens this view from a clipboard Jira key or link. `HostViewService.Open` takes a key or a link.

## Findings (current tree)

- `issuetracker.Provider`: `ID`, `Terms`, `Setup`, `ParseRef` (no CLI call), `Status(ctx, refresh)`, `Issue(ctx, ref)`.
  `Issue` has key, title, status, category, dev summary, PR rows, `ChangeRequestsReason`. Failures are typed errors
  (`errors.go`), mapped by `Reason(err)` to `unavailable|unauthenticated|notFound|otherSite|timeout|failed`.
- `issuetracker.Issue` and `ChangeRequest` carry no json tags. Nothing marshals them: `adewire.TaskIssue` copies
  fields. Adding tags is safe.
- `Registry`: `Get`, `All`, `ParseRef(raw) (Provider, Ref, bool)`, `Infos`. One provider: `jira`.
- `jira.client`:
  - `issue(ctx, ref)`: cache per `lower(site)|key` (60 s ok, 15 s error), `singleflight.DoChan`, detached fetch with a
    20 s bound.
  - `fetch`: `disc.status` gate (unauthenticated, unavailable), `ErrOtherSite` check, per-site Development field id
    (`devInfo`), then `view(ctx, path, key, fields)`, `parseIssue`, PR rows via `c.crs`.
  - `view` runs `acli jira workitem view KEY --json --fields F` (10 s) and maps stderr to `ErrNotFound` /
    `ErrUnauthenticated`. `toolexec.ErrOutputTooLarge` passes through unchanged.
  - `firstFields` already excludes `comment` and `description` for size.
- `toolexec.MaxStdoutBytes` is a fixed 1 MiB for every acli call. ADF bodies are verbose, so comments can push past it.
- acli (reference pages):
  - `acli jira workitem view [key] --fields <list> --json`. Default fields `key,issuetype,summary,status,assignee,
    description`. `--fields summary,comment` is a documented example. The JSON shape is not documented. acli is
    Cloud-only, so fields follow REST v3: `description` and comment `body` are ADF objects.
  - `acli jira workitem comment list --key KEY --json --limit N --order <+|->created|updated --paginate`. Default
    limit 50, default order `+created`. JSON shape not documented.
  - acli is not runnable in this sandbox (P417 testdata README). Every fixture is hand-written.
- `fakeacli.Acli`: `SetIssue(key, raw)` serves any `workitem view KEY` regardless of `--fields`. It records `view:<KEY>`.
  `SetInstalled`, `SetLoggedIn`, `Hold`, `Count`. Any other argv is `unsupported` (exit 2).
- Op log: `oplog.NewRecordingToolRunner` wraps the acli runner in `wireTrackers`. `toolKind` keeps two words, so
  `comment list` records as `workitem comment`. Acceptable. `oplog/**` is Stream C's and stays untouched.
- `HostViewService` (P427):
  - `Open(url)` parses through `githost.Registry.ParseChangeRequestLink`; `open(link)` does focus-or-create under
    `openMu`. It writes a `hostview-` window row, `Targets.Put(key, identity, target)`, `OpenWindow`, `SetWindowTitle`.
  - `WindowTarget(windowKey)` returns `*HostViewTarget`. `ChangeRequest(url)` returns `{kind ok|unavailable|gone,
    detail, status}`.
  - `HostViewTarget{Kind, URL, Provider, Host githost.Info, Repo, Number}`. `Kind` is `"changeRequest"`, left for this
    phase.
  - It holds `Deps` only. The tracker registry lives at `git.trackers` in appwire `Build`. It is built at line 218,
    before `w.HostView` at line 267.
- `main.go`: `IsHostViewKey` is ephemeral, `Targets.Forget` runs on close, and `purgeHostViewWindows` runs at boot. All
  of them are key-prefix based, so the issue kind needs no `main.go` change.
- Frontend `src/hostview/`:
  - `HostViewWindow.vue` is the whole PR view and returns early for other kinds.
  - `MarkdownBody.vue` + `markdown.ts`: raw HTML dropped, images as links, http(s) links through `openExternal`.
  - `queries.ts`, `state.ts` (target only), `wire.ts`.
  - `main.ts` and `App.vue` branch on `hostView.target` alone, never on its kind.
- UI support `tests/ui/support/hostView.ts`: `hostViewTest` fixture (ready selector `host-view-window`) and contract

- ADE reason texts `space.ade.artifacts.gap.<reason>.body` and `gapText(g)` live in `src/ade/v2/artifacts/gapText.ts`

## Design

### 1. Contract: `apps/kira-space/internal/issuetracker/detail.go` (new)

```go
// IssueDetails reads one issue for the issue view. Optional: a tracker without it has no view.
type IssueDetails interface {
	// IssueDetail reads ref fresh (no result cache). Failures are the typed errors of errors.go.
	IssueDetail(ctx context.Context, ref Ref) (IssueDetail, error)
}

type Person struct {
	ID   string `json:"id"`   // Jira accountId
	Name string `json:"name"` // display name
}

type Comment struct {
	ID        string `json:"id"`
	Author    Person `json:"author"`
	Body      string `json:"body"` // Markdown (converted by the provider)
	CreatedAt int64  `json:"createdAt"`
	UpdatedAt int64  `json:"updatedAt,omitempty"`
	URL       string `json:"url,omitempty"` // https only
}

type IssueLink struct {
	Key   string `json:"key"`
	Title string `json:"title,omitempty"`
}

type IssueDetail struct {
	Ref                  Ref                  `json:"ref"` // URL filled from the signed-in site
	Title                string               `json:"title"`
	Status               string               `json:"status"`
	StatusCategory       string               `json:"statusCategory"` // new | indeterminate | done | ''
	Type                 string               `json:"type,omitempty"`
	Priority             string               `json:"priority,omitempty"`
	Resolution           string               `json:"resolution,omitempty"`
	Assignee             *Person              `json:"assignee,omitempty"`
	Reporter             *Person              `json:"reporter,omitempty"`
	Labels               []string             `json:"labels"`
	Components           []string             `json:"components"`
	CreatedAt            int64                `json:"createdAt"`
	UpdatedAt            int64                `json:"updatedAt"`
	DueDate              string               `json:"dueDate,omitempty"` // YYYY-MM-DD as Jira stores it
	Parent               *IssueLink           `json:"parent,omitempty"`
	Description          string               `json:"description"` // Markdown
	Comments             []Comment            `json:"comments"`    // oldest first
	CommentsTotal        int                  `json:"commentsTotal"`
	CommentsTruncated    bool                 `json:"commentsTruncated,omitempty"` // older ones not shown
	CommentsOmitted      bool                 `json:"commentsOmitted,omitempty"`   // none could be read
	Summary              ChangeRequestSummary `json:"summary"`
	ChangeRequests       []ChangeRequest      `json:"changeRequests"`
	ChangeRequestsReason string               `json:"changeRequestsReason,omitempty"`
}
```

- Caps (same file): `DetailMaxComments = 100`, `DetailMaxLabels = 50`, `DetailMaxComponents = 50`.
- `(*IssueDetail).Normalize()`, called by the provider before return:
  - Nil slices become empty, so JSON shows `[]`.
  - A non-https comment URL becomes "".
  - Comments sort by `CreatedAt`, then ID. Past the cap, keep the newest and set `CommentsTruncated`.
  - `CommentsTruncated` is also set when `CommentsTotal > len(Comments)`.
  - Labels and components are capped.
- `issuetracker.go`: add json tags to `ChangeRequest` (`title url ref state repo provider`). It now appears on the wire
  inside `IssueDetail`. The comment says so.
- Registry (`registry.go`): `IssueViewLabels() string` joins `"<Label> <lower(Terms.Issue)> key or link"` per
  `IssueDetails` provider with `" or "`, giving "Jira work item key or link". It is nil-safe.
- P429 extension (stated here, not built): `Comment` gains `Attachments`. A write role `IssueComments` sits next to
  `IssueDetails`. Neither existing field changes.

### 2. Jira: `issuetracker/jira/detail.go`, `adf.go` (new)

- `DetailFields` (exported const, so fakeacli can match it):
  `summary,status,issuetype,priority,resolution,assignee,reporter,labels,components,created,updated,duedate,parent,
  description,comment`.
- `(*Provider).IssueDetail(ctx, ref)` = `p.client.detail(ctx, ref)`. Add `var _ issuetracker.IssueDetails =
  (*Provider)(nil)`.
- Refactor `fetch`'s gate into `func (c *client) ready(ctx, ref) (issuetracker.Status, error)`: the status switch and
  the `ErrOtherSite` check. `fetch` calls it. Behaviour does not change, and P417's client tests must stay green.
- `client.detail(ctx, ref)`:
  1. `st, err := c.ready(ctx, ref)`. Return on error.
  2. `c.forget(cacheKey(ref))`, a new method that deletes the 60 s entry. Refresh in the view then means fresh PR rows
     too. The ADE line refetches once after a view load; that is acceptable.
  3. `errgroup.WithContext(ctx)`. A failure of either branch never cancels the other, so return nil from both:
     - A: `iss, issErr := c.issue(gctx, ref)`. Reuses dev-field detection, PR rows and singleflight.
     - B: `out, viewErr := c.detailView(gctx, st.Path, ref.Key)`.
  4. `viewErr` is the result when set. `issErr` alone leaves `Summary` unknown, `ChangeRequests` empty and
     `ChangeRequestsReason = Reason(issErr)`. Otherwise copy `Summary`, `ChangeRequests` and `ChangeRequestsReason`
     from `iss`.
  5. `d := parseDetail(out, st.Site)`. An unreadable payload returns `errors.New("jira: acli returned an unreadable
     work item")`, as `fetch` does.
  6. `Ref`: as `fetch` does, take `Key` from the payload, `URL` = `https://<site>/browse/<KEY>` when the site is known,
     else the pasted URL, and `Site` = st.Site when empty.
  7. `d.Normalize()`.
  - Coalesce: wrap steps 2-7 in `c.sf.Do("detail|"+cacheKey(ref), ...)`. This is synchronous: the caller's ctx bounds
    it, with no detached fetch, because the window is the only reader. The context is bounded by
    `context.WithTimeout(ctx, detailBound)` with `detailBound = 25 * time.Second`.
- `detailView(ctx, path, key)`:
  1. `c.view(ctx, path, key, DetailFields)`.
  2. On `toolexec.ErrOutputTooLarge`, call `view` again with `DetailFields` minus `,comment` (const
     `detailFieldsNoComments`), then `c.commentList(ctx, path, key)`.
     - The list succeeds: comments from it, `CommentsTotal` = max(reported total, len). It holds the newest 50, so set
       `CommentsTruncated` when total is unknown and len == 50.
     - The list fails (any error, including too large): `CommentsOmitted = true`. The rest of the detail stays.
  3. A second `ErrOutputTooLarge` (without comments) is the result: `failed`.
- `commentList`: `acli jira workitem comment list --key KEY --json --limit 50 --order -created` (10 s,
  `viewTimeout`). The same stderr classification as `view`: factor `classify(err, vctx)` out of `view`, and both call
  it. `parseCommentList` accepts a top-level array, or an object with `comments` or `values`. Elements are REST
  comment objects. Reverse into oldest first.
- `parseDetail(out []byte, site string) (issuetracker.IssueDetail, bool)`, pure, in `detail.go`:
  - `key`, `fields.summary`, `fields.status{name,statusCategory.key}`, `issuetype.name`, `priority.name`,
    `resolution.name` (null → ""), `assignee` / `reporter` `{accountId, displayName}` (null → nil), `labels []string`,
    `components[].name`, `created` / `updated` → ms, `duedate` string kept, `parent{key, fields.summary}`.
  - Times: Jira's `2024-01-02T03:04:05.000+0000`. Try layout `2006-01-02T15:04:05.000-0700`, then RFC3339Nano.
    Unparsable → 0.
  - `description`: an ADF object → `adfMarkdown`; a JSON string → `plainMarkdown`; null or absent → "".
  - `comment`: `{comments: [...], total}`. Each comment: `id`, `author`, `body` (ADF or string, the same rule),
    `created`, `updated`. `URL` = `https://<site>/browse/<KEY>?focusedCommentId=<id>` when the site is known.
    `CommentsTotal` = `total`, else len.
- `adfMarkdown(raw json.RawMessage) string`, in `adf.go`. Hand-rolled. Named requirement: the output must be Markdown
  that P427's sanitising renderer (`hostview/markdown.ts`) accepts as-is. Every ADF text run must be escaped so it
  never becomes markup or raw HTML, and mentions, media and cards must map to safe text or http(s) links. The
  implementer searches pkg.go.dev once for a maintained, permissively licensed Go ADF-to-Markdown package. If one
  meets the escaping rule above and its license is MIT/BSD/Apache, use it instead (B owns `go.mod`) and record the
  choice in the Result. Otherwise keep the hand-rolled converter and name this requirement in a one-line comment.
  Rules:
  - Tree walk with a depth cap of 64. Deeper content is dropped.
  - Blocks join with one blank line.
  - `paragraph` → its inline text.
  - `heading` (level 1-6) → `#`×level + space.
  - `text`: escape ``\ ` * _ [ ] < > # + - ! | ~ {`` and leading `1.` / `>`. Then apply marks inner to outer:
    - `code` → backticks, longer than any backtick run inside, with no escaping inside.
    - `strong` → `**`.
    - `em` → `_`.
    - `strike` → `~~`.
    - `link` → `[text](href)` when href is http(s) or mailto, else the text alone.
    - Other marks (`underline`, `textColor`, `subsup`, `backgroundColor`) are ignored.
  - `hardBreak` → backslash + newline.
  - `bulletList` / `orderedList` (attr `order`, default 1) / `listItem`: `- ` or `n. `. Nested content is indented by
    the marker width. A list item's own blocks join with one newline.
  - `taskList` / `taskItem`: `- \[x\] ` when `state` is DONE, else `- \[ \] `. markdown-it core has no task lists,
    so the escaped brackets show literally as `[x]` / `[ ]`.
  - `codeBlock` (`language` attr) → a fenced block with a fence longer than any backtick run inside. The content is
    raw text from child `text` nodes.
  - `blockquote` and `panel` → `> ` prefix on every line. A panel gets no type label.
  - `rule` → `---`.
  - `table`: a GFM table. The first row is the header; markdown-it needs one. Cell content is flattened to inline,
    with `|` escaped and newlines turned into spaces.
  - `mention` → `@` + `attrs.text` without its leading `@`, escaped.
  - `emoji` → `attrs.text`, else `attrs.shortName`.
  - `inlineCard` / `blockCard` / `embedCard` → `[url](url)` when `attrs.url` is http(s), else "".
  - `media`, `mediaSingle`, `mediaGroup`, `mediaInline` → `[attachment: <alt or file name or "file">]` as escaped
    text. Attachment reading is P429's.
  - `date` → `attrs.timestamp` (ms string) as a UTC `YYYY-MM-DD`.
  - `status` → `[<TEXT>]` escaped.
  - `expand` / `nestedExpand` → `**<title>**` line, then the content.
  - `bodiedExtension` → its content. `extension` / `inlineExtension` → "".
  - Unknown node: its `content` recursively, else its `text`, else "".
- `plainMarkdown(s)`: the same text escaping, CRLF → LF, and each single newline → hard break. Jira wiki markup shows
  as literal text (Known open items).
- Testdata (hand-written; append to `testdata/README`):
  - `issue-detail.json`: ADF description with heading, marks, nested lists, code block with backticks, table,
    mention, media, inline card, `<script>` text; assignee null; reporter set; labels; components; parent; 3 comments
    (one string body), `total` 5.
  - `issue-detail-plain.json`: string description, no comment field.
  - `comment-list.json`: an array form of 2 comments, newest first.

### 3. fakeacli (`flowharness/fakeacli/fakeacli.go`)

- `SetIssueDetail(key, raw string)`: served for `workitem view KEY` when `--fields` is `jira.DetailFields` or
  `detailFieldsNoComments`. The call records `detail:<KEY>`. Any other `--fields` keeps the `SetIssue` path and records
  `view:<KEY>`, so P417 counts stay. When the detail form is absent for KEY, it falls back to the `SetIssue` raw, else
  not found.
  - Export `jira.DetailFieldsNoComments` too, so the fake can switch on both.
- `SetTooLarge(key string, v bool)`: a detail view whose fields include `comment` returns `nil,
  toolexec.ErrOutputTooLarge`.
- `SetComments(key, raw string)` serves `jira workitem comment list --key KEY --json --limit 50 --order -created` and
  records `comments:<KEY>`. Any other flag set is `unsupported`. A missing KEY entry returns the not-found ExecError.
- Hold applies to detail and comment calls too.
- `DetailJSON(key, title string) string`: a small builder used by the UI-shaped flow scenario. It is optional when the
  flow reads `issue-detail.json` instead. Prefer reading the testdata file by relative path
  (`../../issuetracker/jira/testdata/issue-detail.json`) and add no builder unless a scenario needs a variant.

### 4. Bridge: extend `bridge/hostview.go`

- `HostViewService` gains `Trackers *issuetracker.Registry`.
- `HostViewKindIssue = "issue"`.
- `HostViewTarget` changes:
  - `Host` becomes `*githost.Info` with `json:"host,omitempty"`. `Repo` and `Number` get `omitempty`.
  - New fields: `Tracker *issuetracker.Terms` (`json:"tracker,omitempty"`) and `Key string` (`json:"key,omitempty"`).
  - The change-request path sets `Host: &info`. Go field access through the pointer leaves P427 test code compiling.
    The implementer fixes any literal that compares `Host` by value.
  - The JSON for a change request is unchanged, so `host-view.json` stays valid.
- `HostViewIssueArgs{Ref string}` (key or URL). `HostViewIssue{Kind string /* ok|unavailable|gone */; Detail
  *issuetracker.IssueDetail; Reason string /* Reason word */}`.
- `Open(ctx, args)`:
  1. Trim. Over 2048 bytes is refused.
  2. Change request link first: `hosts.ParseChangeRequestLink`, as today.
  3. Else `s.Trackers.ParseRef(raw)`. The provider must implement `IssueDetails`; otherwise treat the input as a miss.
     Then `s.openIssue(ctx, p, ref)`.
  4. A miss → `ipcerr.T(CodeBadRequest, "backend.space.issueTracker.view.notViewable.body", {"changeRequests":
     hosts.ChangeRequestViewLabels(), "issues": s.Trackers.IssueViewLabels()})`. With no tracker registered, keep the
     existing `notChangeRequest` refusal. The P427 assertions ("names Forge MR link") still hold because the new text
     contains it.
- `openIssue(ctx, p, ref)`:
  - Site: `ref.Site`, else `p.Status(ctx, false).Site`. That is the cached probe (5 min ok), so a bare key and its
    link dedupe to one window.
  - Identity = `"issue|" + p.ID() + "|" + lower(site) + "|" + ref.Key`.
  - Canonical URL = `https://<site>/browse/<KEY>` when the site is known, else "".
  - Target `{Kind: issue, URL: canonical, Provider: p.ID(), Tracker: &terms, Key: ref.Key}`.
  - Factor the focus-or-create body of `open(l)` into `openTarget(identity string, target HostViewTarget, title
    string) (HostViewOpen, error)`. Both kinds call it, so there is no second copy of the window logic.
  - Title `i18n.T("backend.space.issueTracker.view.window.title", {"key": KEY, "label": terms.Label})` gives
    "PROJ-12 · Jira".
- Exported `OpenHostViewIssue(s *HostViewService, raw string) (HostViewOpen, error)` is P430's typed entry: it
  parses the tracker ref only. It is a function, like `OpenHostViewChangeRequest`, so it is not bound.
- `Issue(ctx, args) (HostViewIssue, error)`:
  1. Trim, then the 2048-byte cap. `Trackers.ParseRef`; a miss or a provider without `IssueDetails` →
     `ipcerr.T(CodeBadRequest, "backend.space.issueTracker.view.notIssue.body", {"issues": IssueViewLabels()})`.
  2. `d, err := details.IssueDetail(ctx, ref)`.
     - No error → `{ok, &d, ""}`.
     - `ErrNotFound` → `{gone, nil, "notFound"}`.
     - A cancelled ctx → `{unavailable, nil, "timeout"}`.
     - Else → `{unavailable, nil, Reason(err)}`.
  3. No breaker: acli has no rate-limit signal, and every call is bounded (10 s view, 25 s detail).
- No event push. TanStack holds the data; Refresh refetches.
