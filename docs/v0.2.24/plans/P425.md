## 1. Scope

In:

- Save the full Discover state of a tab under a name: data view, query text, language, time
  selection, filters, columns, sort, sample size, histogram interval.
- Open (restore exactly and run), Save (update in place), Save as new, Rename, Pin, Delete, Revert
  changes, Open in new tab.
- Tab linked to a saved query: title is the saved name; dirty mark when state differs from the
  saved body; closing a dirty tab asks to discard; `Cmd/Ctrl+S` saves.
- Columns. P424 has no column selection: hits render as documents only. The ask names columns as
  part of saved state, so this phase adds Discover-style selected columns (sidebar add/remove,
  results as a table of time field plus selected fields). No columns selected keeps today's document
  view.

Out:

- Kibana server-side saved queries or saved searches (stream decision 2). No import from Kibana.
- Saved queries in DB MCP tools. `run_query` prompt text unchanged (section 5.1 says why).
- Column reorder by drag, column widths in the saved body. Order is the order columns were added.
- Saved console queries of other kinds stay as they are (no update-in-place added for them).

## 2. Reuse decision

Reuse `saved_queries` (table, `SavedQueriesRepo`, `QueriesService`, `SavedListMenu`) with a third
kind `discover`. Not a parallel table or service.

- `kind` is free `TEXT`, body is JSON, `scanSavedQueryRow` already switches on kind and validates
  the body strictly. A new kind slots in.
- Rename, pin, delete, touch (`QueriesService.Update/Delete/Touch`) are kind-agnostic: reused as is.
- `ConsoleSavedMenu.vue` is not reused directly: it stores `{text}` per `(connection, path)` and
  applies text only. A sibling `DiscoverSavedMenu.vue` on the same `SavedListMenu` shell, same
  mutation/invalidation pattern.
- New pieces only where the existing ones cannot carry it: listing per connection regardless of
  path (Discover tabs sit at different data view paths, saved queries are per connection), body
  update in place (no repo method updates `body` today), unique names (Kibana rejects duplicate
  saved query titles; an "update" that cannot be told apart from a same-named copy is the silent
  fork the row warns about).

### 5.2 Go model (`internal/storage/model/queries.go`)

```go
// KibanaTimeSelection mirrors kibana.ts's kibanaTimeSelectionSchema.
type KibanaTimeSelection struct {
    Mode   string `json:"mode"`             // preset | absolute
    Preset string `json:"preset,omitempty"` // mode preset
    From   string `json:"from,omitempty"`   // mode absolute, ISO
    To     string `json:"to,omitempty"`
}

// DiscoverBody is queries.ts's discoverBodySchema: a saved_queries row of kind 'discover'.
type DiscoverBody struct {
    Query        string              `json:"query"`
    DataViewID   string              `json:"dataViewId"`
    DataViewName *string             `json:"dataViewName"`
    Language     string              `json:"language"`
    Time         KibanaTimeSelection `json:"time"`
    Filters      []KibanaFilter      `json:"filters"`
    Columns      []string            `json:"columns"`
    Sort         []KibanaSort        `json:"sort"`
    SampleSize   int                 `json:"sampleSize"`
    Interval     string              `json:"interval"`
}

func (b DiscoverBody) Validate() error   // wraps ErrInvalidDiscoverBody
func (b DiscoverBody) Normalized() DiscoverBody // nil slices → empty, so JSON never holds null
```

`Validate` mirrors the zod schema exactly, so a row Go accepts always parses in TS:
`DataViewID` non-empty; `Language` ∈ {kuery, lucene}; time preset ∈ the 14 values of
`kibanaTimePresetSchema` with `From`/`To` empty, or absolute with both non-empty and `Preset` empty;
every filter operator ∈ the 7 `KIBANA_FILTER_OPERATORS`, field non-empty; columns non-empty strings,
no duplicates; sort order ∈ {asc, desc}, field non-empty; `SampleSize` ∈ {100, 500, 1000, 5000,
10000}; `Interval` ∈ {auto, m, h, d, w, M, y}. Keep the value sets as package-level Go slices with a
comment naming the TS constants they mirror. Body size: `ValidSavedQueryName`-style cap, encoded body
≤ 256 KiB → else invalid.

`var ErrInvalidDiscoverBody = errors.New("model: invalid discover body")` in `model`.
