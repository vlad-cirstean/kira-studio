## Observed problems and fixes

Screenshots: Space dock at 1280 px with git, ADE, MCP, memory, session, failed and background rows; expanded error
row; expanded steps row; Background on; filter with no match; 820 px window; context menu; empty log. Studio dock with
running, failed (two-line error), http, MCP and connect rows; expanded error; expanded command; 820 px.

1. Command column disappears at narrow width. Space's fixed tracks sum to about 740 px before `1fr` (Studio about 600
   px), so at 820 px the command, the most useful column, is gone and the grid scrolls sideways (Space) or squeezes to
   about 90 px (Studio). Fix: column priorities. `OpLogColumn` gains `priority?: number` (absent: never dropped) and
   `align?: 'end'`. The panel measures its own width (VueUse `useElementSize`) and drops the highest `priority` columns
   until fixed tracks plus gaps leave `COMMAND_MIN_PX = 240` for the command column (`minmax(240px, 1fr)`). Header and
   rows use the same fitted list.
2. Status text is the loudest thing in the list. "Succeeded" on every row, 90-110 px wide; Cancel is a 13 px square
   glued to "Running". Fix: a leading 44 px status column the panel renders itself: codicon `pass` (ok, muted),
   `error` (error tone), `circle-slash` (cancelled), `Spinner` (running); label in `aria-label` and a tooltip; the
   `statusNote` (`×7`, automation state) follows as a small `Badge`. Cancel moves to the row action area (item 8).
3. A failed row is red from time to module to repo. Fix: only the status icon and the error text are error tone; the
   row gets an inset 2 px left accent (`shadow-[inset_2px_0_0_var(--color-error)]`) and `bg-error/10`.
4. Time shows `09:59:20.000` and no date. Milliseconds are noise; a row from yesterday looks like today. Fix:
   `formatOpTime(startedAt, now)` in `lib/opLog.ts`: `HH:MM:SS` (Intl, `hourCycle: 'h23'`) today, `MMM d HH:MM`
   otherwise; `title` holds `formatDateTime` plus `formatClockTime` (ms) for the exact instant. `tabular-nums`.
5. Expanded detail is broken. Fixed 18 px lines: the Space "Failed: …" line is clipped by its own horizontal scrollbar;
   multi-line errors and stderr collapse to one line; only one row can be open; detail lines look like rows. Studio
   mounts one Monaco editor per open row, drops the second line of a two-line error (`DETAIL: …`) and paints scrollbar
   artifacts. Fix: one variable-height detail item per open row, measured by TanStack Virtual (item 9), rendered by a
   new shared `OpLogDetail.vue`: field list, command block, error block, steps table, extra lines, action bar. Text
   keeps its newlines (`whitespace-pre-wrap break-all`), each block capped at 12 lines with its own vertical scroll.
   Several rows can be open at once. Studio's syntax colours come from `monaco.editor.colorize` through the existing
   `paintOverlayHtml` (no editor instance). Studio's scoped `<style>` goes.
6. Parent and child ops are unrelated rows. "Via request_branches" sits at the end of a 150 px source cell and is cut
   ("Kira Space ade board Vi…"). Fix: tree order. Panel prop `parentOf?: (r) => string | null`; a child whose parent
   is in the list renders right under it (oldest child first), indented one step with an `indent` glyph, `aria-level`
   2. A child whose parent is filtered out stays top-level and keeps the "Via <tool>" note in its source cell. Depth
   cap 3; a cycle or missing parent never drops a row. Pure function `orderOpTree` in new `lib/opLogTree.ts`.
7. Empty states lie. With a filter that matches nothing the panel says "No operations yet"; during hydration it says
   the same. Fix: three states. Loading (store `hydrated` false): 4 `Skeleton` rows. Nothing recorded: "No operations
   yet" plus one line of what lands here (app copy via prop `emptyHint`). Filtered out: "No operations match" plus
   a "Clear filters" button that resets text, status and facet.
8. Actions are hidden in the context menu. Copy needs a right-click; the right-clicked row gets no highlight. Fix: row
   action area at the row's right end, over the command cell (`absolute right-1`, `bg-elevated`): Copy command (copy
   icon) on hover or focus-within; Cancel (`debug-stop`, aria-label "Cancel operation") always shown on a running
   cancellable row. The row whose menu is open, and the roving-focus row, get `data-state="selected"` (`bg-select` via
   `tableRowClass`). The detail action bar renders the enabled items of `menuFor` as buttons (same source as the menu).
9. Virtualized detail cannot grow. `useVirtualRows` knows fixed or precomputed heights only; OpLogPanel uses fixed 18
   px. Fix: keep `useVirtualRows` (no edit to `behaviour/virtualRows.ts`), use the `virtualizer` it returns: detail
   items carry `:data-index` and a function ref calling `virtualizer.value.measureElement(el)`; `estimateSize` stays 18
   for rows and an estimate (`detailEstimate(record)`, lines times 16 plus padding) for details through `rowHeights`.
   Keyboard reveal uses `virtualizer.value.scrollToIndex(index, { align: 'auto' })`, not the fixed-height helper.
10. Filters are coarse. Only text and All/Running/Errors; no way to see one module or one connection; "Running: N"
    sits apart from the Running tab; hidden background rows give no count. Fix: Running tab carries the running count
    (`SecondaryTabItem.count`, omitted at 0), the "Running: N" label goes; a facet dropdown (shadcn-vue `DropdownMenu`
    with `DropdownMenuCheckboxItem`): Space "Module", Studio "Connection"; the Background toggle shows the hidden
    background count; filter matches are highlighted in the command cell (`splitMatches` + `HighlightedText`).
11. Raw identifiers read as debug output. Module `ade`, `git`, `memory` in lowercase. Fix: Space merges Module and
    Source into one "Origin" column: module `Badge` (`space.operations.moduleName.<id>`: Git, ADE, Files, VS Code,
    Memory, App; unknown id shows raw) then the source text. Kind stays the raw op kind in `font-data`, muted (it is
    an identifier, and specs and users search it).
12. Studio's Tab column is "—" on almost every row and takes 40 px. Fix: Tab moves into the detail fields (and stays
    in "Reveal originating tab"). Source keeps its column (`op-source-cell`) at lowest priority.
13. Duration and rows are left-aligned and jitter while the clock ticks. Fix: `align: 'end'`, `tabular-nums`.
14. Context menu has no grouping and Studio destructures a fixed array. Fix: `opLogMenuItems(record, cancel, canCancel,
    copy, details?)` returns copy-command, copy-error, copy-details (only when `details` is given), a separator,
    cancel. Space passes its steps text; Studio passes command, error, connection, path, tab; Studio finds items by
    `id`, not by position. `useAutomationOps.ts` spreads the array and keeps working unedited.
15. List keyboard has no way back to the filter and no expand keys. Fix: `useListNavigation` `tree` option (depth from
    item 6; Right opens detail, Left closes it or moves to the parent; Enter and Space toggle, as now); `onExitTop`
    focuses the filter. Arrow keys inside an open detail stop propagation, Escape there returns focus to its row.

Kept: 18 px row height (IDE density, `--kira-h-xs`), newest-first order, the toolbar position, Clear with its
per-app hint, `kira.ops.showBackground`, the dock shell, every existing `data-testid` except `op-tab-cell` (column
removed).

## Design

### Shared types and helpers: `packages/workbench/src/lib/opLog.ts`

- `OpLogColumn { id; label; width; priority?: number; align?: 'end' }`. Width is a px track (`'64px'`), except the
  `command` column, which the panel always renders as `minmax(240px, 1fr)` whatever the wrapper passes.
- `OpLogField { label: string; value: string; mono?: boolean }`: one detail field.
- `OpLogStep { argv: string; status: OpStatus; exitCode: number | null; durationMs: number | null; stderr: string |
  null }`. `SpaceOpStep` satisfies it structurally.
- `OpLogStatusFilter` unchanged (`all | running | error`).
- `fitColumns(columns, widthPx, gapPx): OpLogColumn[]`: drop the highest `priority` first (ties: rightmost first)
  until `sum(fixed) + gaps * (n - 1) + 2 * paddingPx + COMMAND_MIN_PX <= widthPx`; never drops a column without
  `priority`; `widthPx` 0 (not measured yet) returns all.
- `formatOpTime(startedAt: string, now: number): string` (item 4).
- `opLogMenuItems` per item 14.
- `STATUS_ICON: Record<OpStatus, { icon: string; tone: string }>` and `statusLabel(status)` moved here from the panel
  (`STATUS_LABEL` keys unchanged).

### Tree order: new `packages/workbench/src/lib/opLogTree.ts`

```ts
export interface OpTreeRow<R> { record: R; depth: number; viaParent: boolean }
export function orderOpTree<R extends { id: string; startedAt: string }>(
  records: readonly R[], // newest first, already filtered
  parentOf: ((r: R) => string | null) | undefined,
): OpTreeRow<R>[];
```

Rules: no `parentOf` → every row depth 0, input order. A record whose parent id is in `records` goes under it,
children oldest first; a missing parent → top-level with `viaParent: true`; depth capped at 3 (deeper descendants
render at depth 3 under their nearest kept ancestor); a cycle (A parent of B parent of A) breaks at the newest record,
which becomes top-level; output length equals input length, every id once. Top-level order stays newest first.

### Store: `packages/workbench/src/state/createOpLogStore.ts`

- `hydrated` ref: false until `hydrateOps` resolves or rejects; panel `loading` = `!hydrated`.
- Option `facet?: (r: R) => string` and state `facetValues: string[]` (empty means all). `visibleOps` adds
  `facetValues.length === 0 || facetValues.includes(facet(r))`. Export `facetAllows(value: string): boolean` for rows
  the wrapper merges (automation).
- `backgroundCount` computed: records in the background lane (`background?.(r)`), shown on the toggle.
- `resetFilters()`: `filterText = ''`, `statusFilter = 'all'`, `facetValues = []`.
- `opLogMatches` signature unchanged (`useAutomationOps` calls it).
- Existing specs `oplogLanes.spec.ts`, `oplogHydrateRace.spec.ts`, `oplogMarkRaw.spec.ts` must still pass; extend
  `oplogHydrateRace.spec.ts` with `hydrated`: false while the snapshot is pending, true after it resolves and after it
  rejects (race rules interact there already).

### Panel: `packages/workbench/src/components/OpLogPanel.vue`

Props (new or changed): `loading: boolean`, `emptyHint: string`, `parentOf?`, `fieldsFor?: (r) => OpLogField[]`,
`stepsFor?: (r) => readonly OpLogStep[]`, `codeLanguage?: (r, part: 'command' | 'error') => string | null`,
`facet?: { label: string; options: readonly { value: string; label: string }[] }`, `facetValues?: string[]`,
`backgroundCount` is not a prop (the Space toolbar slot shows it). Emits add `update:facetValues` and `resetFilters`.
Removed: the `detail` slot (Studio was its only user). Kept: `records`, `runningCount`, `filterText`, `statusFilter`,
`columns`, `clearHint`, `canCancel`, `menuFor`, `runningNote`, `kindLabel`, `statusNote`, `detailLines`, slots `cell`
and `toolbar`.

Template, top to bottom:

- Toolbar (`h-row`, one line, `gap-2`): `SearchField` (w-40), `SecondaryTabs` segmented with the running count on
  Running, facet `DropdownMenu` when `facet` is set (trigger `Button variant="toolbar"` with label and selected count,
  testid `ops-facet`; items `DropdownMenuCheckboxItem`, testid `ops-facet-<value>`; "All" item clears), `toolbar`
  slot, `ml-auto` Clear with its tooltip.
- Header row: fitted columns, `align: 'end'` columns right-aligned.
- Body: loading skeleton, empty or filtered state (testids `ops-empty`, `ops-no-match`, `ops-clear-filters`), else the
  virtual list. List items: `{ kind: 'op', row: OpTreeRow }` and `{ kind: 'detail', record }` after each open row.
- Op row: `data-testid="op-row"`, `data-op-id`, `data-status`, `data-depth`, `aria-level`, `aria-expanded`,
  `data-state="selected"` when focused or menu-open. Cells: `status` (panel-owned, item 2), `time` (`op-time-cell`,
  item 4), `kind` (`kindLabel` else raw, `font-data text-muted-foreground`), `duration` (running: `op-elapsed`), `command`

- Detail item (`data-testid="op-detail"`, `data-op-id`): `OpLogDetail`.
- Expansion state: `expandedIds` (a `Set` in a `ref`, replaced on change). An id that leaves `records` is dropped
  from the set.

### Detail: new `packages/workbench/src/components/OpLogDetail.vue`

- Layout: `bg-elevated border-b border-border px-2 py-1.5 pl-[52px]` (aligned under the time column), `flex flex-col
  gap-1.5`, `text-kira-sm`.
- Field list (`dl`, two-column grid `grid-cols-[max-content_1fr] gap-x-3`): Started (`formatDateTime` + ms), Duration,
  then `fieldsFor(record)`.
- Command block, error block: `OpLogCodeBlock` with a label line ("Command", "Error") and a copy icon button
  (`TooltipIconButton`). Error tone for the error block. Testids `op-detail-command`, `op-detail-error`.
- Steps (`stepsFor`): one line per step (`op-detail-line`, as today): status icon, argv (`font-data`, truncates with
  tooltip), `exit N`, duration right; a failed step's stderr as an `OpLogCodeBlock` (error tone) under it.
- Extra lines (`detailLines`, automation): one line each (`op-detail-line`), error tone when `tone: 'error'`.
- Action bar: enabled `menuFor` items except separators and labels, `Button variant="toolbar" size="inline"` with the
  item icon and label, `data-testid="op-action-<id>"`.

### Code block: new `packages/workbench/src/components/OpLogCodeBlock.vue`

- Props `text: string`, `language?: string | null`, `tone?: 'error'`. Renders `<pre>` (`font-data whitespace-pre-wrap
