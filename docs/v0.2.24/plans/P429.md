## Ask

- Post comments in the PR view and the issue view.
- Comments can carry attachments. Drag and drop supported.
- Decision 3 (streams.md): attachments on Azure and Jira only; GitHub shows unsupported with clear UI.

## Findings (current tree and real CLIs)

- Write path today: `githost.ChangeRequestReviews.Comment(ctx, r, n, body) Status` (GitHub REST `issues/{n}/comments`
  via `writeArgv` with `-f`; Azure `invoke` POST `pullRequestThreads`; Forge appends to `f.comments`). Used by the
  review window through `gitrpc` with the `MaxHostCommentBytes` (64 KiB) cap. No reply, no attachment.
- `issuetracker` has no write role. `jira.client.view`/`commentList` run acli through `c.runner`, wrapped in
  `oplog.NewRecordingToolRunner` (`wireTrackers`). The recorder logs `renderTool(RedactArgv(args))`: the whole argv
  except `--x=secret`-style flags. A body passed as `--body <text>` would land in the op log.
- `HostViewService` resolves a window key to its target through `Targets.Get(key)`. `main.go` already calls
  `HostView.Targets.Forget` on window close.
- Frontend composer precedent: `AdeReviewSubmitDialog.vue` uses shadcn `Textarea` with Markdown source.
  `AdeNotesEditor.vue` uses tiptap + `@tiptap/markdown`.
- `internal/shell/window.go` sets `EnableFileDrop: false`; `security_test.go` asserts it ("no data-file-drop-target
  consumer exists"). No `useDropZone`, `useFileDialog` or `<input type=file>` exists yet. Bytes over the bridge as
  base64 is the repo precedent (`internal/terminal/service.go`, `internal/docker/exec.go`).
- Wails v3 beta.28 macOS webview implements `runOpenPanelWithParameters` (`webview_window_darwin.m:989`), so
  `<input type=file>` (VueUse `useFileDialog`) opens a native panel. WebKitGTK and WebView2 support it natively.
- `goldmark` v1.7.16 is already a direct `go.mod` require (`internal/memory/importer`). VueUse 15.0.0 has
  `useDropZone`, `useFileDialog`. Theme has `progress`, `textarea`, `tooltip`, `button`, `alert`, `badge`.
- `fakeagent` gh writes each call's argv to `<FakeDir>/gh-<n>.args`. `fakeaz.guard` flags any call without `--org` and
  `--detect false` as a violation.
- `app.W.Ops.Recent(bridge.OpsRecentArgs{Limit: 200})` reads op-log rows in flows (`adeflow/issuetracker_test.go:240`).

### CLI capabilities (verified)

- **GitHub, `gh`**: top-level comment `gh api POST repos/{o}/{r}/issues/{n}/comments -f body=...` (exists). Reply to a
  review (code) thread: GraphQL `addPullRequestReviewThreadReply(input:{pullRequestReviewThreadId, body})`; the P427
  code thread ID is that node ID (`PRRT_...`). Issue comments and reviews on GitHub have no thread reply. No public API
  uploads comment attachments; `gh` cannot attach. Attachments unsupported (Decision 3).
- **Azure, `az`**: top-level thread POST `pullRequestThreads` (exists). Reply: `az devops invoke --area git --resource
  pullRequestThreadComments --route-parameters project= repositoryId= pullRequestId= threadId= --http-method POST
  --in-file <json>` with `{"content":..., "parentCommentId": <first comment id>, "commentType": 1}`.
- **Azure attachments, `az devops invoke` cannot send them.** Extension 1.0.10 `dev/team/invoke.py` does
  `request_body = json.loads(read_file_content(in_file, encoding))` (encodings `ascii|utf-16be|utf-16le|utf-8` only),
  then msrest JSON-serializes `content` again. Binary bytes fail to decode; a JSON string arrives as a quoted JSON
  literal even with `--media-type application/octet-stream`. The REST endpoint needs raw bytes:
  `POST https://dev.azure.com/{org}/{project}/_apis/git/repositories/{repo}/pullRequests/{id}/attachments/{fileName}
  ?api-version=7.1`, body `application/octet-stream`, `201` with `Attachment{id, url, displayName}`.
  - **Fallback (chosen):** Kira asks az for a short-lived token, `az account get-access-token --resource
    499b84ac-1321-427f-aa17-267ca6975798 --query accessToken -o tsv` (Azure DevOps' documented resource id), and POSTs
    the bytes itself over HTTPS. Token in memory only, per post, never cached, never logged. az keeps the credential.
  - **Limit:** works for `az login` (Entra ID / MSA) sign-ins only. A PAT-only sign-in (`az devops login`) has no token
    to hand out: attachments then fail with a named reason; plain comments still work.
- **Jira, `acli`**: `acli jira workitem comment create --key KEY --body-file F` (`-F`); body "plain text or Atlassian
  Document Format (ADF)". `--json` exists, output shape undocumented. Reply: none (Jira comments are flat).
- **Jira attachments: acli cannot upload them.** `acli jira workitem attachment` has `list` and `delete` only;
  `create`/`edit`/`comment create` take no file. Upload needs Jira REST `POST /rest/api/3/issue/{key}/attachments`
  with Kira's own Jira credential. `issuetracker.go` package rule: "A provider keeps its own CLI and credentials;
  Kira holds none." acli exposes no token. **So Decision 3's "Jira supported" is not buildable without breaking that
  rule.** This plan ships Jira attachments as unsupported (same UI as GitHub, own reason) and flags it to the
  orchestrator. The capability flag keeps the switch a provider-only change. A Jira API-token path is a user decision
  and, if wanted, its own follow-up phase (new credential surface, keychain, Settings UI).

## Design

### 1. Neutral write roles (separate from the read roles)

`apps/kira-space/internal/githost/comment.go` (new):

```go
// ChangeRequestComments is optional: a provider the PR view can post to. Separate from
// ChangeRequestDetails (read) and ChangeRequestReviews (review window). Failure is in Status, never an error.
type ChangeRequestComments interface {
	CommentCapabilities(r Repo) CommentCapabilities
	PostChangeRequestComment(ctx context.Context, r Repo, number int, c NewComment) Status
}

type CommentCapabilities struct {
	ReplyKinds        []string `json:"replyKinds"`                  // Thread kinds a reply may target
	Attachments       bool     `json:"attachments"`
	AttachmentsReason string   `json:"attachmentsReason,omitempty"` // why not, when false
}

type NewComment struct {
	Body        string       // Markdown, 1..MaxHostCommentBytes after attachment links are appended
	ReplyTo     string       // a Thread.ID; "" posts a new top-level comment
	Attachments []Attachment // only when CommentCapabilities.Attachments
}

type Attachment struct {
	Name        string // sanitized (bridge), unique per comment
	ContentType string // sniffed
	Data        []byte
}
```

- Consts: `MaxAttachments = 5`, `MaxAttachmentBytes = 10 << 20`, `MaxAttachmentTotalBytes = 25 << 20`.
- `AttachmentMarkdown(name, url string, image bool) string`: `![name](url)` or `[name](url)`. Escape `\ [ ] ( )` in
  name; url must be `https:`, else "" (caller fails the post).
- Registry: no change. The bridge type-asserts the provider found by `ParseChangeRequestLink`.

`apps/kira-space/internal/issuetracker/comment.go` (new):

```go
// IssueComments is optional: a tracker the issue view can post to. Separate from IssueDetails (read).
type IssueComments interface {
	CommentCapabilities() CommentCapabilities
	// PostIssueComment posts Markdown. Failures are the typed errors of errors.go.
	PostIssueComment(ctx context.Context, ref Ref, body string) error
}

type CommentCapabilities struct {
	Attachments       bool   `json:"attachments"`
	AttachmentsReason string `json:"attachmentsReason,omitempty"`
}

const MaxCommentBytes = 32 << 10 // Jira caps a text field at 32,767 characters
```

- Read models (`githost.Comment`, `issuetracker.Comment`) stay unchanged. P427/P428 expected an `Attachments` field
  there; it is not needed: posted Azure attachments are links in the Markdown body, which `hostview/markdown.ts`
  already renders (images as links). Record this in the Result as a deviation.

### 2. GitHub (`githost/github/comment.go`, new)

- `CommentCapabilities`: `ReplyKinds: [ThreadCode]`, `Attachments: false`, `AttachmentsReason:
  i18n.T("backend.space.gitHost.comment.attachmentsUnsupported.body", {"label": "GitHub"})` = "GitHub has no API for
  comment attachments. Add files on GitHub."
- `PostChangeRequestComment`:
  - Attachments non-empty → forbidden Status with that reason (defence in depth; the bridge refuses first).
  - `ReplyTo == ""` → `p.client.CommentOnPull` (existing).
  - Else `p.client.ReplyToReviewThread(ctx, repo, threadID, body)`: GraphQL `mutation($threadId:ID!,$body:String!)
    {addPullRequestReviewThreadReply(input:{pullRequestReviewThreadId:$threadId,body:$body}){comment{id}}}`, vars via
    `-f` (never `-F`, as `writeArgv`). Reject a `threadId` not matching `^PRRT_[A-Za-z0-9_-]{1,200}$` (forbidden
    Status, no spawn).
  - Write timeout: add `func (c *Client) graphqlWrite(...)` beside `graphql` that runs with `writeTimeout` and maps
    `context.DeadlineExceeded` to `writeTimeoutReason`, as `callWithin(write=true)` does. Factor the shared body of
    `graphql` into one helper taking timeout and write; `graphql` keeps its signature.
- `var _ githost.ChangeRequestComments = (*Provider)(nil)`.

### 3. Azure (`githost/azure/comment.go`, `upload.go`, new)

- `CommentCapabilities`: `ReplyKinds: [ThreadComment, ThreadCode]`, `Attachments: true`.
- `PostChangeRequestComment(ctx, r, n, c)`:
  1. `split(r)`, else `invalidRepo`.
  2. Attachments: `token, st := p.client.accessToken(ctx, org)`. Not OK → return it.
     - For each attachment, in order: `url, st := p.uploader.upload(ctx, token, org, project, r.Name, n, a)`. On
       failure, best-effort DELETE every already-uploaded one (same uploader, ignore errors, log `slog.Warn` without
       URL query or token), return st.
     - Body += `"\n\n"` + one `githost.AttachmentMarkdown(...)` line per attachment (image = content type
       `image/png|jpeg|gif|webp`).
     - Final body over `MaxHostCommentBytes` → delete uploads, forbidden Status "comment is too long with attachment
       links".
  3. `ReplyTo == ""` → existing `p.Comment(ctx, r, n, body)`.
  4. Else parse `ReplyTo` as `^\d{1,10}$` (P427 thread ID). Read the parent comment id: the thread's first comment.
     Do not re-read the thread: P427 comment IDs are `<thread>/<comment>`; the frontend sends the thread ID only, so
     use `parentCommentId: 1` (Azure numbers comments per thread from 1; the first comment is 1). State this in a
     one-line comment. Then `invoke(ctx, orgURL(org), true, "POST", "pullRequestThreadComments", route + "threadId=" +
     id, "", {"content": body, "parentCommentId": 1, "commentType": 1}, nil)`.
  5. Comment post fails after uploads → best-effort delete uploads, return st.
- `client.accessToken(ctx, org)`: `call` without the devops gate is wrong (`account` is not a devops command), so
  run directly: `runWithin(ctx, c.runner, st.Path, callTimeout, []string{"account", "get-access-token", "--resource",
  devopsResource, "--query", "accessToken", "-o", "tsv"})` after `c.discovery.Status(ctx, org)` is OK. Trim stdout;
  empty or containing whitespace → unauthenticated. Any error → `classify(org, err, ctx.Err(), false)`; then if the
  kind is unauthenticated, override the reason with `reasonAttachSignIn` = "Attaching files needs an az login
  sign-in. A PAT sign-in (az devops login) can post text only." Never put stdout in a reason.
  - `devopsResource = "499b84ac-1321-427f-aa17-267ca6975798"` with a one-line comment naming it.
- `uploader` (`upload.go`): `type uploader struct{ client *http.Client }` built in `New` from `Options.HTTP
  http.RoundTripper` (nil → `http.DefaultTransport`, which honours `HTTPS_PROXY`). Client: `Timeout: 60s`,
  `CheckRedirect: func(...) error { return http.ErrUseLastResponse }` (the bearer token never follows a redirect).
  - `upload`: URL = `orgURL(org) + "/" + url.PathEscape(project) + "/_apis/git/repositories/" + url.PathEscape(repo) +
    "/pullRequests/" + n + "/attachments/" + url.PathEscape(name) + "?api-version=7.1"`. `orgURL` is
    `https://dev.azure.com/<org>`, fixed host. Headers `Authorization: Bearer`, `Content-Type:
    application/octet-stream`, `Accept: application/json`. Body `bytes.NewReader(a.Data)`.
  - Response: read at most 64 KiB (`io.LimitReader`). 200/201/202 → decode `{url}`; url must parse, be `https`, host
    `dev.azure.com` or suffix `.visualstudio.com`, else forbidden "Azure DevOps returned an unusable attachment
    link". 401 → unauthenticated `signInReason(org)`; 403 → `reasonDenied`; 404 → `gone(org)`; 413 → forbidden "Azure
    DevOps refused the file as too large"; 429 → `reasonThrottled`, `RateLimited` (+ `Retry-After` seconds into
    `ResetAt`); other → forbidden "Azure DevOps answered HTTP <code>". Transport error with `ctx.Err()` → cancelled;
    timeout → `writeTimeoutMsg`-style reason; else "could not reach Azure DevOps". Never include body, URL query or
    token in a reason or log.
  - `remove(ctx, token, org, project, repo, n, name)`: DELETE same URL, status ignored.
  - Uploaded file name: `<8 hex of crypto/rand>-<name>` so two posts never collide on Azure's per-PR name key.
- `Options` gains `HTTP http.RoundTripper` ("attachment upload transport; nil takes http.DefaultTransport").
  `Provider` holds `uploader`.

### 4. Jira (`issuetracker/jira/comment.go`, `mdadf.go`, new)

- `CommentCapabilities`: `Attachments: false`, `AttachmentsReason: i18n.T("backend.space.issueTracker.comment
  .attachmentsUnsupported.body", {"label": ProviderLabel, "cli": "acli"})` = "{label} attachments cannot be added from
  Kira: {cli} has no upload command. Add files in {label}."
- `PostIssueComment(ctx, ref, body)`:
  1. `st, err := c.ready(ctx, ref)`; return err.
  2. `adf, err := markdownADF(body)`; error → `errors.New("jira: comment could not be converted")`.
  3. Temp file: `os.CreateTemp("", "kira-acli-comment-*.json")` (0600 by default on Unix; `f.Chmod(0o600)` anyway),
     write ADF JSON, close, `defer os.Remove(name)`.
  4. `c.runner.Run(wctx, st.Path, []string{"jira", "workitem", "comment", "create", "--key", ref.Key, "--body-file",
     name})`, `wctx` = `context.WithTimeout(ctx, writeTimeout)` with `writeTimeout = 30 * time.Second`.
  5. Error → `classify(err, wctx, "workitem comment create")`. A timeout stays the existing timeout error (`Reason`
     word `timeout`). The may-have-posted wording lives in the UI copy for a post that failed with `timeout`
     (`space.hostView.compose.mayHavePosted.hint`); no new error type.
  6. `c.forget(cacheKey(ref))`.
  - Body never in argv, so the op log row shows `acli jira workitem comment create --key K --body-file <tmp>` only.
- `markdownADF(md string) (json.RawMessage, error)`: goldmark (already a dependency) with `extension.GFM`
  (strikethrough, table, linkify, task list) parses; a walk emits ADF `{"version":1,"type":"doc","content":[...]}`.
  Named requirement for writing the walk: no Go Markdown-to-ADF library meets P428's escape-and-filter bar (P428
  Result surveyed three ADF converters), and goldmark gives the parse tree. Rules:
  - Paragraph → `paragraph`. Heading 1-6 → `heading{level}`. ThematicBreak → `rule`. Blockquote → `blockquote`.
  - FencedCodeBlock/CodeBlock → `codeBlock{language?}` with one `text` child (raw lines).
  - List → `bulletList` / `orderedList{order: start}`; ListItem → `listItem` (inline-only children wrapped in a
    `paragraph`). GFM task list items → `taskList`/`taskItem{localId: uuid, state: DONE|TODO}`.
  - Table → `table` > `tableRow` > `tableHeader` (first row) / `tableCell`, each holding one `paragraph`.
  - Text → `text`; Emphasis level 1 → mark `em`, 2 → `strong`; Strikethrough → `strike`; CodeSpan → `code` mark only
    (ADF forbids `code` with other marks: drop the others). Link/AutoLink → `link{href}` mark when scheme is
    http/https/mailto, else plain text. Image → text `alt` with a link mark to its src when http(s), else alt text.
    HardLineBreak → `hardBreak`; SoftLineBreak → a space. RawHTML/HTMLBlock → their literal text (never markup).
  - Empty doc (whitespace only) → error (the bridge refuses empty bodies first).
  - Text marks nest outer to inner; a node type outside this list → its text children, else nothing.
- `var _ issuetracker.IssueComments = (*Provider)(nil)`.

### 5. Fakes

- `fakehost.Forge` (`flowharness/fakehost/fakehost.go`) implements `ChangeRequestComments`:
  - `CommentCapabilities`: `ReplyKinds: [comment, review, code]`, `Attachments: true` (neutral attachment path).
  - `PostChangeRequestComment` records `post:N`, honours `SetOffline`/`rateLimit()`, unknown N → `goneStatus()`, a
    `ReplyTo` not among the overlay's thread IDs → forbidden "no such thread". Stores `PostedComment{Body, ReplyTo,
    Attachments []PostedAttachment{Name, ContentType, Size int, SHA256 string}}` in `posted[N]`, readable by
    `Posted(n) []PostedComment`. Appends the comment to the detail overlay (new `ThreadComment` thread, or to the
    `ReplyTo` thread) with `Author{Login: account}` and an ID `posted-<k>`, so a refetch shows it.
- `fakeaz` (`flowharness/fakeaz/fakeaz.go`):
  - `account get-access-token --resource <devops> --query accessToken -o tsv`: handled before `guard` (no `--org`).
    Records `token`. `SetTokenUnavailable(true)` returns exit 1 stderr `ERROR: Please run 'az login' to setup account.`
    Else stdout `fake-token\n`.
  - `invoke` POST `pullRequestThreadComments` (route needs `threadId`): records
    `invoke:pullRequestThreadComments:<key>:<threadId>`, stores `{threadId, content, parentCommentId}` in
    `replies[prID]`; unknown PR → `prMissing`. Export `Replies(prID)` and `Threads(prID)` (posted thread contents; read
    whatever existing accessor the P423 flows use, add one only if none).
  - `Transport() http.RoundTripper`: in-process, no network. Accepts only `https://dev.azure.com/<org>/<project>/_apis/
    git/repositories/<repo>/pullRequests/<id>/attachments/<name>?api-version=7.1`, POST or DELETE, with
    `Authorization: Bearer fake-token`; POST also needs `Content-Type: application/octet-stream`. Anything else →
    violation + 400. POST records `upload:<id>:<name>` and stores `{name, size, sha256}` in `uploads[id]`; returns 201
    `{"id":1,"url":"https://dev.azure.com/<org>/<project>/_apis/git/repositories/<repo>/pullRequests/<id>/attachments/
    <name>"}`. DELETE records `delete:<id>:<name>`, drops it, 204. `SetUploadStatus(code int)` forces the next POST's
    HTTP status (413, 401, 429). `Uploads(id)` accessor.
  - `flowharness.WithAzure(o)` unchanged; flows pass `azure.Options{..., HTTP: az.Transport()}`.
- `fakeacli` (`flowharness/fakeacli/fakeacli.go`): `jira workitem comment create --key KEY --body-file PATH` (exactly
  these 8 args) records `comment-create:<KEY>`, reads PATH (must exist), stores the content and PATH in
  `posted[KEY]` (`Posted(key) []PostedComment{Body, Path string}`); logged out → the auth stderr `view` uses; unknown
  KEY (no `SetIssue`/`SetIssueDetail`) → `notFound()`. `Hold` applies. Any other `comment` argv stays unsupported.

### 6. Bridge (`apps/kira-space/internal/bridge/hostviewcompose.go`, new; small edits in `hostview.go`)

Wire additions on existing results (additive JSON, contract fixtures regenerate):

```go
// HostViewCompose says what the window's composer may do. Nil when the provider cannot post.
type HostViewCompose struct {
	MaxBodyBytes            int      `json:"maxBodyBytes"`
	ReplyKinds              []string `json:"replyKinds"` // change requests only
	Attachments             bool     `json:"attachments"`
	AttachmentsReason       string   `json:"attachmentsReason,omitempty"`
	MaxAttachments          int      `json:"maxAttachments"`
	MaxAttachmentBytes      int      `json:"maxAttachmentBytes"`
	MaxAttachmentTotalBytes int      `json:"maxAttachmentTotalBytes"`
	AllowedExtensions       []string `json:"allowedExtensions"`
}
```

- `HostViewChangeRequest` and `HostViewIssue` gain `Compose *HostViewCompose \`json:"compose,omitempty"\``, set on kind
  ok when the provider implements the write role. Issue `MaxBodyBytes = issuetracker.MaxCommentBytes`; change request
  `MaxHostCommentBytes`.

New bound methods on `HostViewService` (all keyed by window key: a window posts only to its own target, the frontend
never supplies a URL):

- `StageAttachment(ctx, HostViewStageArgs{WindowKey, Name, Data string /* base64 std */}) (HostViewStaged, error)`.
  - `Targets.Get(key)` nil → `ipcerr.T(CodeBadRequest, "backend.space.hostView.compose.noWindow.body", nil)`.
  - Target's compose caps must allow attachments, else CodeBadRequest with the provider's `AttachmentsReason`.
  - `len(Data) > base64.StdEncoding.EncodedLen(MaxAttachmentBytes)` → refuse before decoding. Decode (std encoding);
    error → `ipcerr.Contract("data must be base64")`. Empty → refuse "empty file". Over `MaxAttachmentBytes` →
    refuse with size.
  - `name, ok := SanitizeAttachmentName(Name)`; not ok → refuse. Extension (lower) must be in
    `allowedAttachmentExt`: `png jpg jpeg gif webp pdf txt log md json csv yaml yml xml zip gz diff patch`. No `svg`,
    `html`, executables: the host serves them back to reviewers.
  - Content type: `http.DetectContentType(data)`; an image extension whose sniffed type is not that image → refuse
    ("file content does not match .png").
  - `Attachments.Put(key, staged)`: per-window count ≤ `MaxAttachments`, total ≤ `MaxAttachmentTotalBytes`, else
    refuse. Returns `{ID: uuid, Name, Size, ContentType, Image bool}`.
- `DiscardAttachment(ctx, HostViewDiscardArgs{WindowKey, ID}) (bool, error)`: drops it; returns whether it existed.
- `PostComment(ctx, HostViewPostArgs{WindowKey, Body, ReplyTo string; AttachmentIDs []string}) (HostViewPosted,
  error)`.
  - Guards (CodeBadRequest, `backend.space.hostView.compose.*` keys): unknown window; `strings.TrimSpace(Body) == ""`
    and no attachments; body over `MaxBodyBytes`; body not valid UTF-8; `len(ReplyTo) > 256`; more than
    `MaxAttachments` IDs or a duplicate; an ID not staged for this window; attachments on a target whose caps forbid
    them; `ReplyTo` on an issue; `ReplyTo` thread kind check is the provider's (it holds the IDs).
  - Per-window `sync.Mutex` (`Attachments.lock(key)`): a second post while one runs → CodeBadRequest "a comment is
    already being posted".
  - Change request: parse `target.URL` with `s.parse`; provider must implement `githost.ChangeRequestComments`; breaker
    armed → `{Kind: unavailable, Status}` with no host call; call `PostChangeRequestComment`; map like
    `ChangeRequest` (ok, gone, rate limit arms the breaker, else unavailable). Status reason passes through.
  - Issue: `issueProvider(target.Key or URL)`; must implement `issuetracker.IssueComments`; call
    `PostIssueComment(ctx, ref, body)`; nil → ok; `ErrNotFound` → gone `notFound`; else unavailable
    `Reason(err)`.
  - Success → remove the consumed staged IDs. Failure → keep them, so Retry re-sends the same files.
  - Result `HostViewPosted{Kind string; Status *githost.Status \`json:"status,omitempty"\`; Reason string
    \`json:"reason,omitempty"\`}`.
- `SanitizeAttachmentName(raw string) (string, bool)` (exported for its unit test): `filepath.Base` after replacing
  `\` with `/`; NFC is not required; drop control chars and `/ \ : * ? " < > |`; trim spaces and dots at both ends;
  refuse `""`, `.`, `..`, a leading `.` (hidden), no extension; cap 120 bytes keeping the extension (cut on a rune
  boundary). Go never opens a path: names are labels only.
- `HostViewAttachments` (same file, not a service, so its methods are not bound): mutex map key → `{items map[id]
  stagedAttachment{name, contentType, data, at}; total int; posting bool}`. `Put`, `Take(key, ids) ([]githost.Attachment,
  error)` (does not delete), `Drop(key, ids)`, `Forget(key)` (window close), `sweep(now)` dropping items older than 30
  min, run on every `Put`. Memory bound: 25 MiB per window; staged bytes live in memory only, never on disk.
- `HostViewService` gains `Attachments *HostViewAttachments`.
- Coverage gate: `StageAttachment`, `DiscardAttachment`, `PostComment` get flow calls. `exempt.txt` untouched.

## Security and op log

- No path crosses the bridge. Go never opens a user path; bytes arrive base64 from `File` objects the user chose
  (picker, drop, paste). `EnableFileDrop` stays false.
- Names are sanitized labels; extension allowlist plus image sniffing; size caps enforced in Go before decode.
- Posting targets come from `Targets.Get(windowKey)`, never from frontend input.
- Azure: token from az per post, kept in a local variable, sent only to `https://dev.azure.com/...`, no redirects,
  never in logs, reasons, op log (az is unrecorded, P423) or errors. Response bodies capped and never echoed.
- Jira: body only in a 0600 temp file removed by `defer` after the call; argv has the temp path, so the op-log row
  holds no comment text. ADF links limited to http/https/mailto.
- Temp files: only the acli body file (new) and the existing az `--in-file` (`invoke`, already removed by `defer`).
  Attachment bytes stay in memory (per-window cap, 30 min sweep, dropped on window close and on success).
