## 1. Scope

Ask: "Elastic brings visualisations. Extend the v0.2.23 P420 validation proof tool so the agent can present data as a
visualisation, not only plain data views." Decision 4 (streams.md): generic charts the agent fills from its own tool
output, not Kibana saved visualisations.

In:

- One new proof view `chart`, payload `data.type` one of `bar`, `line`, `area`, `scatter`, `pie`. Histogram = `bar`
  with one point per bucket (x `value` or `time`). Time series = `line`/`area` with x `time`. Stacked bar/area and
  horizontal bar as flags.
- Go validation, normalisation and caps; migration widening the `view` CHECK; MCP schema enum and agent-facing text.
- TS schema, ECharts renderer (P424's ECharts 6.1.0 + vue-echarts 8.3.2, SVG renderer, `frontend/src/charts/`), tab icon.
- Per-step chart view state (hidden series, clicked point, zoom range), persisted and restored like grid state.
- Screenshot (copy/save, one/all tabs) captures charts exactly; compare/edit shows old and new charts.
- P425 leftovers first (section 6, steps 1 and 12).

Out, named:

- `metric` tile view: `keyvalue` already shows a labelled single number. Not added.
- Heatmap, gauge, map, dual y axis, per-series chart types, brush selection: no proof need named; bounded set.
- Kibana saved visualisations (decision 4). A data table under each chart: the agent adds a `table` step (prompt says
  so). Keyboard toggling of legend entries: ECharts has none; documented, not built.

## 3. Payload contract

### 3.1 Agent input (`data` when `view` is `chart`)

Cartesian (`bar`, `line`, `area`, `scatter`):

```json
{
  "type": "line",
  "x": { "type": "time", "name": "time" },
  "y": { "name": "errors", "unit": "req" },
  "stacked": false,
  "horizontal": false,
  "series": [ { "name": "before", "points": [["2026-01-15T12:00:00Z", 7], [1768478460000, null]] } ]
}
```

Pie:

```json
{ "type": "pie", "unit": "req", "slices": [ { "name": "/checkout", "value": 12 } ] }
```

Rules (Go, all before any write; each error names field and limit, as P420 D7):

- `type` required, one of the five. Unknown keys rejected (`decodeStrict`). Keys of the other family rejected with a
  named message: `slices`/`unit` on cartesian, `x`/`y`/`series`/`stacked`/`horizontal` on pie.
- `x` required on cartesian; `x.type` one of `category`, `time`, `value`; `x.name` optional, up to 80 runes.
- `y` optional; `y.name` up to 80 runes; `y.unit` up to 16 runes. Pie `unit` up to 16 runes.
- `stacked` only on `bar`, `area`; `horizontal` only on `bar`. `true` elsewhere is an error; `false` allowed.
- `series`: 1-20; `name` 1-120 runes, single line, unique. `points`: at least 1 per series; each point exactly
  `[x, y]`.
- x by axis type: `category` non-empty string up to 256 bytes, unique within its series; `time` RFC 3339 (with or
  without fraction, `Z` or offset), date-only `YYYY-MM-DD` (UTC midnight), or integer epoch milliseconds, within
  years 1970-9999; `value` finite JSON number.
- y: finite JSON number or `null` (gap). Pie `value`: finite number, at least 0; slices 1-50, names 1-120 runes,
  unique; sum must be above 0.
- Caps: distinct categories across all series up to 1000. Total points: `line`/`area` up to 20000; `bar`/`scatter` up
  to 2000 (each is one SVG node; capture cost, section 5.5). 4 MiB step payload cap still applies.

### 3.2 Stored, normalised payload (what `ProofService.Step` returns)

- Every field present: `x.name`, `y.name`, `y.unit`, `unit` default `""`; `stacked`, `horizontal` default `false`;
  `y` default `{name:"", unit:""}`.
- `time` x becomes integer epoch ms. `value` x and every y keep their JSON number text (`json.Number`, precision kept
  as P420 does).
- `line`/`area` points with `time`/`value` x sorted ascending by x (stable). `category` and `bar`/`scatter` points
  keep the given order.
- Category order on screen = first appearance across series in series order (frontend derives it; not stored).

### 3.3 Go (`apps/kira-studio/internal/proof/chart.go`, new)

`ViewChart = "chart"` next to the other view consts in `validate.go`. `checkChart(data json.RawMessage) (any, error)`
decodes with `UseNumber` + `DisallowUnknownFields` (extend `decodeStrict` with a `useNumber bool` or add
`decodeStrictNumbers`; keep table/document/keyvalue behaviour unchanged). Input structs use pointers for presence
checks; output structs (`chartCartesian`, `chartPie`) have no `omitempty`. Points decode as `[]json.RawMessage` so x is
parsed per axis type. Constants: `maxChartSeries 20`, `maxCategories 1000`, `maxPathPoints 20_000`,
`maxMarkPoints 2_000`, `maxSlices 50`, `maxSeriesNameRunes 120`, `maxCategoryBytes 256`, `maxAxisNameRunes 80`,
`maxUnitRunes 16`. `validate()` switch gains `case ViewChart: payload, err = checkChart(in.Data)`; the default message
lists four views.

### 3.4 TS (`packages/shared/domain/proof.ts`)

- `proofViewSchema` gains `'chart'`.
- `proofChartPointSchema = z.tuple([z.union([z.string(), z.number()]), z.number().nullable()])`.
- `proofCartesianChartSchema` (`type: z.enum(['bar','line','area','scatter'])`, `x: {type, name}`, `y: {name, unit}`,
  `stacked`, `horizontal`, `series: [{name, points}]`), `proofPieChartSchema` (`type: z.literal('pie')`, `unit`,
  `slices: [{name, value}]`), `proofChartPayloadSchema = z.union([...])` (or `discriminatedUnion` if zod accepts the
  enum discriminator; check installed zod). Export `ProofChartPayload`.
- `proofChartViewStateSchema = z.object({ hidden: z.array(z.string()), selected: z.object({ series: int, index: int
  }).nullable(), zoom: z.object({ start: z.number(), end: z.number() }).nullable() })`; `proofViewStateSchema` gains
  `chart: proofChartViewStateSchema.optional()` (optional: every stored P420 row lacks it).

## 4. View state

Go `viewstate.go`: `ViewState.Chart *ChartViewState json:"chart,omitempty"`; `ChartViewState{Hidden []string
json:"hidden"; Selected *ChartPoint json:"selected"; Zoom *ChartZoom json:"zoom"}`. `Check`: hidden up to 50 names of up
to 512 bytes; selected `series` 0-49, `index` 0-`maxSelectionIdx`; zoom `0 <= start <= end <= 100`; nil `Hidden` filled
to `[]`. `omitempty` keeps existing `proof.json`/`proof-pending.json` contracts byte-identical. Storage unchanged (JSON
text column). `AcceptEdit` copies raw state, so chart state of unchanged steps carries over with no code change.

Frontend `useStepViewState.ts`: `sameState` also compares `JSON.stringify(a.chart ?? null)`; new
`setChart: (chart: ProofChartViewState) => update({ chart })`. `ResultViewState` keeps its `Omit`; grid updates spread
over `latest` and keep `chart`.

### 5.2 Option rules (`chartOption.ts`)

- Always: `animation: false` (exact screenshots and baselines), `textStyle.fontFamily = theme.fontFamily`,
  `aria: { enabled: true }`, theme colours as `HitsHistogram`, `color: theme.series`.
- Category axis: series data aligned to `categoriesOf` (null where a series has no point). Time/value axis: data =
  points as given (already sorted where it matters). `horizontal` bar swaps axes (category on y).
- `bar`: `stack: 'total'` when stacked. `line`: `connectNulls: false`. `area`: line + `areaStyle` (opacity 0.25,
  0.6 when stacked), `stack: 'total'` when stacked. `scatter`: `symbolSize: 6`.
- Line/area symbols: `showSymbol` true only when total points <= 2000; above that points are not clickable
  (documented). `pie`: `radius: '70%'`, label formatter function `${name}: ${percent}%`, no `{b}` templates.
- Axis labels: time axis `formatDateTime` when the x span is up to 48 h, else `formatWeekdayDate` (`@theme/format`);
  value labels via one module `Intl.NumberFormat` (max 3 fraction digits) plus ` ${unit}` when set; `hideOverlap`.
  Axis names from `x.name`/`y.name`. Keep axis labels inside the box per ECharts 6 (`grid.outerBoundsMode` or
  `containLabel`, whichever 6.1.0 documents as current).
- Legend: shown when series > 1 or pie; `type: 'scroll'`, top; `selected` map = every name true except
  `state.hidden`.
- Selection decoration from `state.selected`: bar item `itemStyle {borderColor: theme.selected, borderWidth: 2}`;
  line/area/scatter item `symbolSize: 10` with the same border; pie item `selected: true` (`selectedMode: 'single'`,
  `selectedOffset: 8`). Built into the data, not via `dispatchAction`, so the first `finished` already shows it.
- Zoom (cartesian only): `dataZoom: [{ type: 'inside', xAxisIndex: 0 (yAxisIndex for horizontal), filterMode:
  'none', start, end }]` from `state.zoom` (default 0-100).
- Tooltip: `trigger: 'axis'` for bar/line/area, `'item'` for scatter/pie; `className: 'kira-proof-chart-tooltip'`;
  `formatter` returns HTML where every agent string (series, category, slice names) passes
  `format.encodeHTML` from `echarts/core`; values formatted as axis labels. This is the one HTML sink; nothing else
  renders agent text as HTML.

### 5.3 Interaction and persistence (`ProofChart.vue`)

- Local `state = shallowRef(seed ?? { hidden: [], selected: null, zoom: null })`. `option` computed from payload,
  theme (`useChartTheme`), `state.value.hidden`, `state.value.selected`, and zoom from a plain non-reactive variable,
  so wheel zoom never rebuilds the option. `VChart` with `:update-options="{ notMerge: true }"`, `autoresize`.
- `@legendselectchanged`: hidden = names mapped to false. `@click` (series component, symbols shown):
  `{series: seriesIndex, index: dataIndex}`, same point again clears. `@datazoom`: read
  `chart.getOption().dataZoom[0]` start/end, round to 2 decimals, `null` when 0-100. Each change updates `state` and
  emits `update:chart` (ProofStepView wires it to `view.setChart`).
- `@finished` first time: emit `ready`. Theme change rebuilds with the latest state.
- Root element: `data-testid="proof-chart"`, `data-chart-type`, `data-hidden` (JSON array), `data-selected`
  (`"<series>:<index>"` or `""`), `data-zoom` (`"<start>-<end>"` or `""`), `aria-label` from new key
  `studio.proof.chart.region.aria` (`"Chart: {description}"`). Height fills the result pane (`min-h-0 flex-1`).
