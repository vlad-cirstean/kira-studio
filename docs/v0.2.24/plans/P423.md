## Ask

- Azure Repos through `az`, as GitHub through `gh`.
- Same capabilities as the GitHub host: change requests, status, checks, branch links, discovery.
- Settings CLI section (P417) gains `az` install and login steps.
- Host abstraction stays provider-neutral.

## Findings (current tree)

- `githost.Provider` = `Remotes` (ParseRemote, Claims) + `Auth` (`Status(ctx, host)`, `Account(ctx, host)`) +
  `ChangeRequests` (ForCommit, ForBranch, Open) + `URLs`. Optional: `ChangeRequestSync`, `ChangeRequestReviews`,
  `BranchLinks`, `ChangeRequestSearch`, `CLISetup`. GitHub implements all. `Repo{Host, Owner, Name}`; Owner "may be a
  nested group path", so Azure fits as `Owner = "<org>/<project>"`.
- **Not neutral today:** `Auth` is keyed by host. Azure signs in per organization: one host (`dev.azure.com`), many
  orgs, a PAT per org. Every `Auth` caller has the repo at hand and lives in a B-owned file:
  `gitsession/crsync.go:312` (`p.Status(ctx, repo.Host)`), `crsync.go:440` (`r.p.Account(r.ctx, r.repo.Host)`),
  `gitsession/crreview.go:115` (`p.Account(ctx, repo.Host)`). Implementers: `github/provider.go`, `fakehost.Forge`.
  No other caller or implementer (grepped).
- `githost.Status` has no account scope; `bridge.ToolStatus.Site` exists but hosts never fill it
  (`bridge/issuetracker.go:57`).
- `providers.New(gh github.Options, extra ...githost.Provider)`. Callers: `flowharness/harness.go:340` (with
  `a.opts.gitHosts`), `gitsession/registry.go:118` (`NewRegistry` default, GitHub only; not B-owned). Production
  `appwire.Build` passes `opts.GitHosts` nil, so production falls to that GitHub-only default. Keep the signature.
- `clisetup` purposes: install, login, loginToken, check. `CliToolsPane.vue` maps each to an i18n label
  (`STEP_LABEL`); unknown purposes print raw. `Tools` lists every `CLISetup` host, then trackers.
- UI is data-driven: `useHostLabels` (`ade/v2/hostLabels.ts`), `RepoSettingsDialog.vue` host select, `factOf`/`chipOf`
  all read `gitHost.providers`. No frontend file holds a GitHub word in logic.
- crsync: backfill pages newest-updated first; delta walks until `UpdatedAt < watermark - 2 min`; `refreshChecks`
  re-reads every open row by `NodeID` (sweep 15 min) and pending ones (2 min). Rows with `NodeID == ""` are never
  refreshed.
- `ade/issuetracker.go` `changeRequestRepo` reads `owner/name` from `/pull/`, `/-/`, `/merge_requests/` URL markers;
  `ade/**` is Stream C. Azure URLs match none, so title-search hits get an empty repo label; index hits fall back to
  `repoKeyTail` (`org/project/repo`). Accept, do not edit (see Known open items).
- `ade/hostlink.go` `planChangeRequest`: same-repo means `HeadOwner == link.Repo.Owner` (case-fold); fork or closed
  PRs fetch `bl.ChangeRequestRef(n)`.
- Op log: `oplog.NewRecordingToolRunner` hard-codes `CategoryTracker`, background lane, and strips a `jira` prefix.
  `gh` is unrecorded (P415 decision). Decision: `az` stays unrecorded too, for parity with `gh`; recording host CLI
  calls needs a host category in `oplog/**` (Stream C). Not in the SPEC row; listed as follow-up.
- Flow fakes: `gh` is the fakeagent binary (`internal/flowtest/fakeagent`, not B-owned); acli is in-process
  (`flowharness/fakeacli`). `az` follows fakeacli: in-process Locator + Runner. It exercises every argv the real
  provider builds and every parser, so it is the `az` boundary; a spawned fake binary would need fakeagent edits.

### `az` facts (verified)

- `az repos pr` commands: `list`, `show`, `create`, `update`, `set-vote`, `checkout`; subgroups `policy`, `reviewer`,
  `work-item`. No thread/comment command: comments go through `az devops invoke`.
- `az repos pr list`: `--org --project --repository --status {abandoned,active,all,completed} --source-branch
  --target-branch --top --skip --creator --reviewer --detect`. `--source-branch` gets `refs/heads/` added by az.
- `az repos pr show --id`, `az repos pr policy list --id [--top --skip]`, `az repos pr set-vote --id --vote
  {approve,approve-with-suggestions,reject,reset,wait-for-author}`; each takes `--org --detect`.
- `az devops invoke --area --resource --route-parameters k=v... --query-parameters k=v... --http-method --in-file
  --api-version (default 5.0) --org --detect`. Area/resource names resolve through the org's resource locations
  (case-insensitive); a JSON response comes back as an object plus a `continuation_token` key.
- `--detect` defaults to true: az reads org/project from the cwd's git remote. Always pass `--detect false` plus
  explicit `--org` (and `--project`/`--repository` where taken).
- `az version -o json` (0.3 s): `{"azure-cli":"2.91.0",...,"extensions":{"azure-devops":"1.0.10"}}`; extensions `{}`
  without it.
- `az devops configure --list` prints `[defaults]`, `organization = https://dev.azure.com/<org>`, optional `project =
  <name>`, blank line, `Use git alias = No`. No `[defaults]` section when unset.
- Logged out, any devops call: exit 1, stderr `ERROR: Before you can run Azure DevOps commands, you need to run the
  login command(az login if using AAD/MSA identity else az devops login if using PAT token) to setup credentials.
  Please see https://aka.ms/azure-devops-cli-auth for more information.` `az account show`: exit 1, `ERROR: Please run
  'az login' to setup account.`
- Every extension command prints `WARNING: This command is from the following extension: azure-devops` to stderr;
  `--only-show-errors` drops it.
- Missing extension: az offers a dynamic install prompt (would block on stdin). Env
  `AZURE_EXTENSION_USE_DYNAMIC_INSTALL=no` turns it into an error.
- Remote grammar (extension `dev/common/uri.py`, MIT): https `dev.azure.com/{org}/{project}/_git/{repo}` (userinfo, if
  any, equals org); legacy `{org}.visualstudio.com/[{collection}/]{project}/_git/{repo}`; scp ssh
  `{user}@ssh.dev.azure.com:v3/{org}/{project}/{repo}` and `{org}@vs-ssh.visualstudio.com:v3/{org}/{project}/{repo}`;
  `ssh://` form only with port 22; legacy `{project}/_ssh/{repo}`. No 3-segment project-less form.
- REST (to confirm in implementation with a real org if one is ever available; fixtures otherwise): PR fields
  `pullRequestId, title, status (active|completed|abandoned), isDraft, sourceRefName, targetRefName,
  lastMergeSourceCommit.commitId, creationDate, closedDate, createdBy.uniqueName, reviewers[].{vote,isRequired},
  forkSource.repository.{name,project.name}`; no update time exists. `url` is the API URL, not the web page. Vote
  values 10, 5, 0, -5, -10. Policy evaluation `status` queued|running|approved|rejected|notApplicable|broken,
  `configuration.type.displayName` (Build, Status, Minimum number of reviewers, ...). Threads: area `git`, resource
  `pullRequestThreads`, route `project repositoryId pullRequestId`, POST body `{"comments":[{"parentCommentId":0,
  "content":"...","commentType":1}],"status":1}`. Query: resource `pullRequestQuery`, route `project repositoryId`,
  POST body `{"queries":[{"type":"commit","items":["<sha>"]},{"type":"lastMergeCommit","items":["<sha>"]}]}`, result
  `results[]` of `{<sha>: [PR]}` maps. API version `7.1`.

## Design

### 1. Neutral contract changes (`apps/kira-space/internal/githost`)

- `Auth` becomes repo-scoped:
  ```go
  type Auth interface {
  	// Status is whether the CLI can act on r: installed, signed in to the account scope r lives in.
  	Status(ctx context.Context, r Repo) Status
  	// Account is the signed-in login for r's account scope; "" when unknown.
  	Account(ctx context.Context, r Repo) string
  }
  ```
  GitHub: `p.client.discovery.Status(ctx, r.Host)` and `p.client.Account(ctx, r.Host)`; behaviour unchanged.
  fakehost: ignore r. Callers: `crsync.go:312` `p.Status(ctx, repo)`, `crsync.go:440` `r.p.Account(r.ctx, r.repo)`,
  `crreview.go:115` `p.Account(ctx, repo)`.
- `Status` gains `Site string \`json:"site,omitempty"\`` with comment "account scope the CLI signed in to, for hosts
  that sign in per organization; '' otherwise". `bridge/issuetracker.go` host probe copies `Site: st.Site`. gitrpc
  `hostStatusFrom` unchanged (no wire change on git-ipc).
- `CLISetup` comment: "probes the CLI against the provider's primary account scope" (GitHub: github.com; Azure: the
  default organization).
- `clisetup`: add `PurposeExtension = "extension"` and `PurposeDefaults = "defaults"`.
- ARCHITECTURE text "No CI status role exists" stays true: checks ride on `ChangeRequest.ChecksState` via sync, as
  for GitHub.

### 2. `apps/kira-space/internal/githost/azure` (new package)

Files and contents. Mirror `github`'s split; no code shared with it (each provider owns its client).

- `doc.go`: package comment: Azure Repos over `az` + `azure-devops` extension; `Repo{Host: "dev.azure.com", Owner:
  "<org>/<project>", Name: "<repo>"}`; no PR update time (see `sync.go`).
- `remote.go`: `ParseRemote(raw) (githost.Repo, bool)` per the grammar above. Path segments `url.PathUnescape`d
  (projects may hold spaces). Legacy hosts normalize to `dev.azure.com`; org from the `{org}.visualstudio.com`
  subdomain or the `v3/` path. Reject: `_UNSAFE` chars (control, space, backslash), empty segments, ssh port other than
  22, userinfo != org on dev.azure.com https. `orgURL(r) = "https://dev.azure.com/" + org`; `split(r) (org, project)`.
- `runner.go`: `Runner interface { Run(ctx, path string, args []string) ([]byte, error) }` (same shape as
  `jira.Runner` and `oplog.ToolRunner`). `NewExecRunner()` = `toolexec.RunIO(ctx, path, args, "", env, nil)` with
  `env = os.Environ()` plus `AZURE_EXTENSION_USE_DYNAMIC_INSTALL=no`, `AZURE_CORE_ONLY_SHOW_ERRORS=true`,
  `AZURE_CORE_NO_COLOR=true`, `AZURE_CORE_SURVEY_MESSAGE=false`, `AZURE_CORE_OUTPUT=json` (az needs HOME and its
  keyring; argv only). `Locator interface { Locate() (string, []string, bool) }`, real one `toolexec.Locate(exec.LookPath,
  os.Stat, "az", {"/opt/homebrew/bin/az", "/usr/local/bin/az"})`. `Clock` as in github. Every argv the client builds
  goes through one helper `argv(sub []string, org string, extra ...string)` appending `--org <url> --detect false
  --only-show-errors -o json`, so no call can omit `--detect false`.
- `errors.go`: `classify(org string, out []byte, runErr, ctxErr error, write bool) githost.Status`, first match wins:
  1. ctx cancelled: `KindNotFound`, reason "cancelled".
  2. `context.DeadlineExceeded`: `KindNotFound`, "az did not respond within <n>s"; a write gets the gh write-timeout
     wording (may have landed).
  3. `toolexec.ErrOutputTooLarge`: `KindForbidden`, output too large.
  4. not an `*toolexec.ExecError`: `KindNotFound`, "az could not be started: …".
  5. ExecError stderr (first line, lower-cased): "before you can run azure devops commands" | "please run 'az login'" |
     "tf400813" | "aadsts" | "401" → `KindUnauthenticated`, reason "Sign in: `az login`, or `az devops login
     --organization <orgURL>` with a PAT".
  6. "'repos' is misspelled" | "'devops' is misspelled" | "extension" + "not installed" → `KindNotFound`, reason
     "run `az extension add --name azure-devops`".
  7. "tf400733" | "429" | "exceeding usage" | "too many requests" → `KindForbidden`, `RateLimited: true`, reason
     "Azure DevOps throttled the request — try again later".
  8. "tf401180" | "tf401019" | "tf200016" | "does not exist" | "could not be found" | "404" → `gone(org)`
     (`KindForbidden`, `Gone: true`, as github's `gone`).
  9. "tf401027" | "403" | "permission" → `KindForbidden`, "your account lacks permission".
  10. else `KindForbidden`, reason = the stderr first line minus `ERROR: `.
  `Host` = `dev.azure.com`, `Site` = orgURL on every status.
- `discovery.go`: `Discovery{locator, runner, clock}` cached per org URL (`okTTL` 5 min, `notOKTTL` 30 s,
  caller-cancel never cached; copy the gh rule, not the code); `Forget(org)`. `Status(ctx, org)`:
  1. Locate; miss → `KindNotFound`, `Probed`.
  2. `az version -o json` (15 s): `Version = "<azure-cli> (azure-devops <ext>)"`; no `azure-devops` key →
     `KindNotFound`, reason step 6 above.
  3. org "" → read defaults (`az devops configure --list`, 10 s, parse `organization = ` line); none →
     `KindUnauthenticated`, reason "Set a default organization: `az devops configure --defaults
     organization=https://dev.azure.com/<org>`". Cached under key "".
  4. `az devops project list --top 1` via `argv` (20 s): ok → `KindOK`, `Site` = org URL; else `classify`.
  5. On ok, `az account show --query user.name -o tsv` (10 s), best effort: `Account` = trimmed stdout, "" on
     failure (PAT sign-in has no az account).
  `DefaultProject(ctx)` reads `project = ` from the same `--list` output (cached with step 3's entry).
- `client.go`: `Client{discovery, runner}`. `call(ctx, r, timeout, write, args) ([]byte, githost.Status)`: auth gate
  `discovery.Status(ctx, orgURL(r))`, then run, then `classify`. Timeouts: reads 30 s, writes 30 s. Projection
  constant `prQuery` (JMESPath `--query`) keeps output small under the 1 MiB `toolexec` cap:
  `[].{id:pullRequestId,title:title,status:status,draft:isDraft,src:sourceRefName,dst:targetRefName,
  head:lastMergeSourceCommit.commitId,created:creationDate,closed:closedDate,author:createdBy.uniqueName,
  forkRepo:forkSource.repository.name,forkProject:forkSource.repository.project.name,
  reviewers:reviewers[].{vote:vote,required:isRequired}}` (and the single-object form for `show`).
- `map.go`: `rawPR` (the projection) → `githost.ChangeRequest`:
  - `Number` = id; `NodeID` = `strconv.Itoa(id)` (non-empty so crsync refreshes it); `Title`; `URL` =
    `ChangeRequestURL(r, id)` (never the API `url`).
  - State: `active` + draft → "draft" (`Draft` true), `active` → "open", `completed` → "merged", `abandoned` →
    "closed". Mirror how github `toChangeRequests` sets `State`/`Draft` together.
  - `HeadRef`/`BaseRef` = `src`/`dst` minus `refs/heads/`; `HeadSha` = head.
  - `HeadOwner`: no fork → `r.Owner` (same-repo rule in `planChangeRequest` and `NewestPerBranch`); fork →
    `"<org>/<forkProject>/<forkRepo>"` (never equals a repo Owner, even for a fork in the same project).
  - `UpdatedAt` = creationDate ms. Azure has no update time; creation order is the listing order, so the delta
    watermark stays sound (section 3).
  - `ReviewDecision` (rules interact, unit-tested): any vote ≤ -5 → `CHANGES_REQUESTED`; else any required reviewer
    with vote 0 → `REVIEW_REQUIRED`; else any vote ≥ 5 → `APPROVED`; else "".
  - `ChecksState` from policy evaluations whose `configuration.type.displayName` is `Build` or `Status`: any
    `rejected` → `FAILURE`; any `broken` → `ERROR`; any `queued`/`running` → `PENDING`; any `approved` → `SUCCESS`;
    none (or all `notApplicable`) → "". Only filled where policies were read (Checks, section 3).
- `pr.go` (`ChangeRequests`):
  - `ForBranch(r, branch)`: `az repos pr list --project P --repository R --source-branch <branch> --status all --top 5`
    + `prQuery`; drop fork rows (GitHub's `head=owner:branch` excludes forks); newest first.
  - `Open(r)`: `--status active --top 100 --skip 0|100|200`, stop on a short page (GitHub's 300 bound).
  - `ForCommit(r, sha)`: `az devops invoke --area git --resource pullRequestQuery --route-parameters project=P
    repositoryId=R --http-method POST --in-file <tmp> --api-version 7.1`; body above. Temp file `os.CreateTemp("",
    "kira-az-*.json")`, mode 0600, removed after the call. Union of both query results, dedup by id, at most 10
    (GitHub's `per_page=10`). Full PR objects here (invoke takes no `--query`): parse with a `rawRESTPR` struct to
    the same `ChangeRequest`.
- `sync.go` (`ChangeRequestSync`):
  - `Page(r, cursor, first)`: cursor = skip offset (decimal, "" = 0); `--status all --top min(first,100) --skip
    cursor`; `HasNext` = full page; `EndCursor` = skip + len. `RateLimit` zero (Azure reports none; crsync treats zero
    as unknown). Concurrent new PRs shift offsets down: repeats upsert harmlessly, nothing is skipped.
  - `Probe(r, etag)`: `--status all --top 1 --query "[0].pullRequestId"`; new etag = that id; changed = etag "" or
    differs. One spawn, no budget concept. Changes to existing open PRs are not probed; `refreshChecks` covers them,
    and it runs after every delta whatever the probe said.
  - `Checks(r, nodeIDs)`: one `Open`-style listing of active PRs (paged); for each wanted id in it, `az repos pr policy
    list --id N` (bounded `errgroup.SetLimit(4)`) to fill `ChecksState`; each wanted id missing from the active
    listing → `az repos pr show --id N` (merged/closed/draft change lands in the row; a gone PR is left out, so crsync
    deletes it). Status failure of any call fails the batch (crsync backs off).
- `review.go` (`ChangeRequestReviews`):
  - `ReviewTarget(r, n)`: `az repos pr show --id N` → title, state, head, author (`createdBy.uniqueName`).
  - `Comment(r, n, body)`: thread POST (`pullRequestThreads`, route `project repositoryId pullRequestId`) with the body
    file; write timeout wording.
  - `SubmitReview(r, n, rv)`: body non-empty → thread POST first; then vote: approve → `set-vote --vote approve`;
    requestChanges → `--vote wait-for-author` (Azure's "changes needed"); comment → no vote. Azure votes carry no
    commit, so `rv.CommitSHA` is not sent (comment says why). Body cap stays `githost.MaxHostCommentBytes` (enforced
    upstream).
- `links.go` (`URLs`, `BranchLinks`), all URLs on `https://dev.azure.com`, path segments `url.PathEscape`d:
  - `RepoURL` `…/{org}/{project}/_git/{repo}`; `ChangeRequestURL` `RepoURL + "/pullrequest/" + n`; `BranchURL`
    `RepoURL + "?version=GB" + url.QueryEscape(branch)`.
  - `IsChangeRequestURL(u)`: https, host `dev.azure.com`, escaped path matches
    `^/[^/]+/[^/]+/_git/[^/]+/pullrequest/[0-9]+$`.
  - `ParseLink(raw)`: `…/_git/{repo}/pullrequest/{n}` → `LinkChangeRequest`, ref `"<repo>!<n>"`;
    `…/{project}/_workitems/edit/{n}` → `LinkIssue`, ref `"#<n>"`. Both hosts (dev.azure.com and
    `{org}.visualstudio.com`), query/fragment ignored, escaped segments accepted.
  - `ParseBranchLink(raw)`: pullrequest link (optional trailing `/`, query such as `?_a=files` ignored) → `Number`;
    repo link with `version=GB<branch>` → `TreePath` = branch (the `path` param is a file, not part of the branch);
    work item link → `Issue: true`; anything else false. `Repo` normalized as in `remote.go`. No host call.
  - `ChangeRequestHead(r, n)`: `pr show` → `ChangeRequestHead{ChangeRequest, Author}`.
  - `ChangeRequestRef(n)`: `refs/pull/<n>/merge` (Azure serves no head ref for a PR; see Known open items).
- `search.go` (`ChangeRequestSearch`): primary scope = default org and default project (`DefaultProject`). None set →
  `KindNotFound` with the defaults reason (`fromHosts` skips NotFound, so a user without Azure sees no gap).
  `az repos pr list --project P --status all --top 200` + `prQuery`; keep titles containing text (case-insensitive),
  newest first, up to limit. Repo for URL composition from the PR's repository: add `repo:repository.name` to the
  projection used here.
- `provider.go`: `ProviderID = "azure"`; `Options{Locator, Runner, Clock}`; `New(o)` fills real seams. `Terms{Label:
  "Azure Repos", ChangeRequest: "Pull request", ChangeRequestNoun: "pull request", ChangeRequestShort: "PR", CLI:
  "Azure CLI (az)"}`. `Claims(ctx, host)` = `host == "dev.azure.com"` (after normalization). `Status(ctx, r)` /
  `Account(ctx, r)` → discovery for `orgURL(r)`. Interface assertions for every role. `Setup()`:
  - DocsURL `https://learn.microsoft.com/azure/devops/cli/`
  - install `brew install azure-cli`
  - extension `az extension add --name azure-devops`
  - login `az login`
  - loginToken `az devops login --organization https://dev.azure.com/<your-org>`
  - defaults `az devops configure --defaults organization=https://dev.azure.com/<your-org> project=<your-project>`
  - check `az devops project list --top 1`
  `CLIStatus(ctx, refresh)`: refresh → `Forget("")` and the default org's entry; then `discovery.Status(ctx, "")`
  (resolves the default org).
- `testdata/`: `version.json`, `version_noext.json`, `configure_list.txt`, `configure_list_empty.txt`,
  `stderr_logged_out.txt`, `stderr_account.txt` (captured, section "az facts"); hand-written `pr_list.json` (active,

### 3. Sync soundness without an update time (documented in `sync.go` and ARCHITECTURE)

- Page order is pullRequestId descending, which is creation order; `UpdatedAt` = creation. deltaStop cuts at the
  first PR older than watermark − 2 min: every PR created since the last run is above it, so new PRs are never missed.
- State, head, review and checks changes of open PRs come from `refreshChecks` (every open row on the 15 min sweep,
  pending ones every 2 min focused); a PR that left `active` is read by `pr show` and its new state stored.
- Gap: an abandoned PR that is reactivated stays "closed" in the index until a re-backfill (account change, schema
  bump, host off/on). Known open item.
