# P378 Finished/stopped agents behind a dropdown

Base: `4eb65a8` (P377 landed). Discovery by Grep/Read: CodeGraph MCP failed to connect (`codegraph` not in `$PATH`).

## Ask

`SPEC.md` row: finished and stopped agents take too much screen space. Move them into a dropdown.

User: "The finished or stopped agents should be accessible from a dropdown as now they waste too much screen space right now."

## Current state

- One list renders finished/stopped agents beside a live one: `ade/v2/sessions/AdeSessionsTab.vue`. Paths below are under `apps/kira-space/frontend/src/`.
- `AdeSessionsTab` has three hosts: task panel Sessions tab (`panel/AdeTaskPanel.vue:191`), branch panel Sessions tab (`panel/AdeBranchPanel.vue:489`), archived panel (`panel/AdeArchivedPanel.vue:45`, `archived`).
- Layout today, top to bottom:
  - `AdeSessionStrip` (running tabs; renders only when `running.length`).
  - Selected running session pane (`AdeTuiPane` / `AdeHeadlessPane`), else `InlineState` `Nothing running` (`ade-sessions-empty`).
  - `AdeStoppedList`: a `border-t` block, `max-h-37.5` (150px), header `Finished or stopped`, one `AdeStoppedRow` per session. This block eats terminal height. That is the complaint.
- `AdeStoppedRow`: dot, age, Take over (`ade-stopped-takeover`, hidden when `archived`), label. A headless row with `runId` has a link button (`ade-stopped-log-toggle`) that expands `AdeRunLog` inline. No row opens a pane: a stopped session has nothing to show except its run log. Take over is the "open" action.
- `ui.sessionId` (`state/adeBoardUi.ts`) selects the strip tab. `current` falls back to `running[0]` when it names a non-running session.
- Ways a stopped session id reaches `ui.sessionId` through `ui.openSession`: an All sessions row click (`needs/AdeAllSessionRow.vue` `@click="open"` fires for stopped rows too), the open-session event (notification click, `emitOpenSession` in specs). Today the user then sees it in the always-visible bottom list. Behind a dropdown it would be hidden.
- All sessions page (`needs/AdeAllSessions.vue`) already hides stopped behind its Running/Stopped segmented filter. Not in scope.
- Mobile app (`frontend/mobile/`) has no stopped list. Not in scope.
- Popover primitive: `@theme/components/ui/popover` (reka-ui). Example host: `panel/AdeRunSandboxBadge.vue`. Count chip: `Badge` `variant="count"`.

## Decisions

- **Popover, not DropdownMenu.** Rows hold a Take over button plus an expanding run log. A menu item is one action and closes on select, so the log toggle cannot live in one. Popover keeps rows unchanged and tabbable. Reuse `AdeStoppedList` as the popover body.
- **Trigger placement.** Session bar = one row: running strip on the left (scrolls), trigger pinned right. Bar renders when `running.length || stopped.length`. With no running sessions the bar holds only the trigger, and `Nothing running` shows below as today.
- **Trigger look.** `Button variant="toolbar" size="kira-lg"`, text = existing `space.ade.sessionList.stopped.label` (`Finished or stopped`), `Badge variant="count"` with the count, `chevron-down` codicon. Hidden when count is 0. No empty popover state needed.
- **Archived panel keeps the list inline.** An archived task never has a running session; hiding every row behind a click under a `Nothing running` placeholder would save nothing and add a click. In `archived` mode the list renders inline in place of the empty state and fills the panel (no 150px cap). The ask targets space next to a live terminal; archived has none.
- **Selected agent is finished.** `ui.openSession` with a stopped session must still show it. Add store field `revealSessionId` (set in `openSession`, alongside `sessionId`). `AdeSessionsTab` watches it (`immediate`): when it names a stopped session in scope, open the popover, mark that row `data-selected`, scroll it into view, focus its first button, then clear the field. When it names a running one, just clear it. A session that stops while selected does not pop anything open: `revealSessionId` only changes on an explicit open, so no surprise popover. The pane falls back to `running[0]` or `Nothing running` as today.
- **Take over closes the popover.** The resumed session becomes a running tab; the pane must be visible. Log toggle keeps it open.
- **No new i18n keys.** Trigger reuses `space.ade.sessionList.stopped.label`. Count is a bare number in the Badge, so trigger name reads `Finished or stopped 2`. Inline header in `AdeStoppedList` drops inside the popover (trigger already names it) and stays for archived.
- **No backend change**, so no flow-test half. CLAUDE.md's split-at-IPC rule covers features crossing the bridge; this is UI layout only.

## Judgment calls

- Popover over DropdownMenu (rows hold two controls plus an inline log).
- Archived panel stays inline (no live pane to save space for).
- Reveal on explicit open only, via a new one-shot store field; a session stopping under the user never pops the dropdown.
- No new i18n keys; existing label plus count badge.
- All sessions page left as is: its Running/Stopped filter already keeps stopped rows out of view.
