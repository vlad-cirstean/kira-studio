# P383 Add a work item from a GitHub link

Base: `38f21b8` (P382 landed). Discovery by Grep/Read: CodeGraph MCP failed to connect (`codegraph` not in `$PATH`).

## Ask

`SPEC.md` row: add a work item by pasting a GitHub link (PR or branch URL). Derive the branch from the link and attach it.

User: "Add a work item using the gh link. It has to get the branch from it."

Scope:

- PR link: `https://<host>/<owner>/<repo>/pull/<n>`, with optional `/files`, `/commits`, `/checks` suffix, query or fragment.
- Branch link: `https://<host>/<owner>/<repo>/tree/<ref...>`.
- Both in the existing Add popover, new task or attach to a task (`attachTo`).
- Out of scope: issue links (see Decisions), phone app, auto clone of an unknown repo, push setup to a fork.

## Current state

GitHub access:

- All GitHub calls go through the user's `gh` CLI (`internal/githost/github`): `Client.get` runs `gh api --hostname <host> ... <path>` behind `Discovery.Status` (version plus `gh auth status`), and `classify` maps the result. Kira holds no token. No go-github.
- Status kinds (`githost/githost.go`): `ok`, `notFound` (no gh), `unauthenticated` (401 or not logged in, reason names `gh auth login`), `forbidden` (403 scope or SSO, rate limit, 5xx). A 404 is `gone()`: not found or not visible, which is what a private repo without access returns.
- `rawPull.toPR()` (`github/pr.go`) already decodes `head.ref`, `head.sha`, `head.repo.owner.login` (empty when the fork is deleted), `base.ref`, derived state (`open|draft|merged|closed`). `PullForReview` (`review.go`) reads `repos/{o}/{r}/pulls/{n}` plus `user.login`.
- Link parsing today: `Provider.ParseLink` (`github/provider.go`) matches `https://github.com/{o}/{r}/(issues|pull)/{n}` and returns only a display `Link{Provider, Kind, Ref}`. It drops owner/repo/number and rejects GHES hosts. Used by `AdeTaskService.validateHostLink` and `TaskBoard.hostLink` for the task `hostUrl` field. No parser yields a branch.
- `Provider.Claims(ctx, host)`: github.com, or a host gh has authenticated against (GHES).
- `github.ParseRemote` parses every remote URL form into `Repo{Host, Owner, Name}`.
- Repo to host matching: `RepoEntry.hostRepoGen` (`gitsession/changerequests.go:363`) resolves only `origin` via `git remote get-url origin` and `githost.Selector.Resolve` under the per-repo setting `GitHostProvider` (`auto|off|<id>`). Unexported. No lookup goes from a host repo to a code repo.

## Decisions

1. **New optional host role, not a widened `URLs`.** `githost.BranchLinks`, like `ChangeRequestSync`. GitHub implements it; a provider without it never resolves a link. `fakehost.Forge` stays as is (not needed for this feature's tests).
2. **Two IPC methods.** `ResolveHostLink` is read only: parse, one host call for a PR, repo match, live-task check. No fetch, no ref write. The UI calls it through TanStack Query as the user pastes. `AddHostLink` re-resolves server side (never trusts a client-sent branch), fetches, attaches. Result is `AddExistingBranchResult`, so the UI handles it like a picked candidate. `AdeTaskService` goes to 67 methods.
3. **Kind uses the existing rule only.** `resolveKind` (tip author email vs `user.email`) after the fetch. A fork PR from another author lands as review, own branch as mine. The preview shows facts (PR author login, fork owner), never a predicted kind, so it cannot contradict the board.
4. **Branch name and fetch:**
   - Same-repo open PR, or a branch link, on the repo's default remote: fetch `+refs/heads/<H>:refs/remotes/<remote>/<H>`, attach `<H>`. `ensureWorktree` creates the tracking branch, so push and pull work as for any remote-only candidate.
   - Fork PR (head owner differs from link owner, or head repo deleted), closed same-repo PR, or any link on a non-default remote: fetch the provider's change-request ref into a local branch. GitHub: `refs/pull/<n>/head:refs/heads/<L>`. Branch link on a non-default remote: `refs/heads/<H>:refs/heads/<H>`. No `+`: a diverged existing ref fails the fetch instead of being overwritten.
   - `<L>` for a fork: `<headOwner>/<headRef>`; head repo gone: `pr-<n>`. Same-repo: `<headRef>`. Rejected: bare `headRef`, since forks commonly use `main` or `patch-1`.
   - A local branch named `<L>` already present: attach it as is, no fetch. Board refresh and pull update it later.
   - Every derived name passes `git check-ref-format --branch` plus the bridge rule (no leading `-`, no `:`, no space) before any refspec is built.
5. **Merged PR refused** (`PR #12 is already merged`). Closed, unmerged PR accepted through the pull ref. Draft accepted.
6. **Branch link path ambiguity.** `tree/feat/x/src` can be branch `feat/x` plus a path. Pick the longest segment prefix that exists as a branch of the matched remote (or local). Resolve uses refs on disk; Add runs a full fetch of that remote first (same as `refreshRepo`), then picks again. None found: the full path, which then fails as `branch … not found on <remote>`. The main branch is refused (`main is the repo's main branch`), as candidates already exclude it.
7. **Repo match.** For each code repo whose `GitHostProvider` is not `off` and is `auto` or the link's provider id: each remote, `origin` first, `get-url` plus `ParseRemote`, equal host, owner and name (case-insensitive, GitHub names are). First code repo in `CodeRepos.List` order wins. So a fork clone with `upstream` set to the base repo matches a PR link on the base repo. No match: `No repo in your workspace has a remote for github.com/acme/api. Add the repo first.` No auto clone.
8. **New task metadata.** A PR link creating a new task sets task title to the PR title and `hostUrl` to the PR URL, but only when `Registry.ParseLink` accepts that URL (github.com today), so `hostUrl` keeps its stored-link contract. A branch link leaves both empty, as attaching a branch does today. Attaching to an existing task changes no task field.
9. **Issue links out of scope.** GitHub exposes an issue's linked branches only through GraphQL `linkedBranches`, which holds 0..n branches across repos. That is a picker, not a derivation. The parser recognises an issue link and answers `An issue link names no branch. Paste its pull request or branch link.`
10. **Errors** are `ErrInvalidInput` details (bad request, shown verbatim, like other ADE refusals). Host failures pass the provider's own `Status.Reason`:
    - no gh: `GitHub CLI (gh) is not installed` (from `Terms().CLI` plus the status reason). A branch link needs no host call, so it works without gh.
    - unauthenticated: reason already names `gh auth login`.
    - 404: `Pull request #12 not found on github.com/acme/api, or your gh account cannot see it` (covers private repos).
    - SSO, scope, rate limit: reason as classified.
    - fetch failure: `RemoteOpError.Message` (`couldn't find remote ref` covers a deleted branch).
    - already on a live task: existing `repos.ErrBranchOnTask` catalog error on Add; Resolve reports `onTaskId` instead.

### Commit 1 `feat(githost): branch links from a pasted URL`

`internal/githost/githost.go`, after `ChangeRequestReviews`:

```go
// BranchLink is a pasted change-request or branch link. Number > 0 names a change request; else
// TreePath is the path after the branch marker, which may hold a file path after the branch.
type BranchLink struct {
	Repo     Repo
	Number   int
	TreePath string
	Issue    bool // an issue link: recognised, names no branch
}

// ChangeRequestHead is one change request's head, read fresh.
type ChangeRequestHead struct {
	ChangeRequest        // number, title, url, state, headRef, headSha, headOwner, baseRef
	Author        string // host login; "" for a deleted account
}

// BranchLinks is optional: a provider that resolves a pasted link to a branch. Every call reports
// failure in Status, never an error.
type BranchLinks interface {
	// ParseBranchLink makes no host call beyond Claims.
	ParseBranchLink(ctx context.Context, raw string) (BranchLink, bool)
	ChangeRequestHead(ctx context.Context, r Repo, number int) (ChangeRequestHead, Status)
	// ChangeRequestRef is the ref the base repo serves a change request's head at.
	ChangeRequestRef(number int) string
}
```

`internal/githost/registry.go`:

- `ParseBranchLink(ctx, raw) (Provider, BranchLinks, BranchLink, bool)`: each provider in order that implements `BranchLinks`.
- `BranchLinkLabels()`: `"<Label> <short> or branch link"` joined by `" or "` (same shape as `LinkLabels`), for the placeholder-free not-a-link error.

`internal/githost/github/links.go` (new):

- `ParseBranchLink`: trim; `url.Parse`; scheme `https`; `Claims(ctx, u.Host)`; path segments (`u.EscapedPath`, split on `/`, each `url.PathUnescape`d) `owner`, `repo` (owner/repo charset `[\w.-]+`, strip `.git`), then:
  - `pull`, `<digits>`, optional one of `files|commits|checks` -> `Number`.
  - `tree`, one or more non-empty segments -> `TreePath` joined with `/`.
  - `issues`, `<digits>` -> `Issue: true`.
  - anything else -> false. Query and fragment ignored.
- `ChangeRequestHead`: new `Client.PullHead(ctx, repo, n)` reading `repos/{o}/{r}/pulls/{n}` once. Extend a local raw type with `user.login`; reuse `rawPull.toPR()` for the rest (embed `rawPull` plus `User`). Host `toStatus`.
- `ChangeRequestRef(n)`: `fmt.Sprintf("refs/pull/%d/head", n)`.
- `provider.go`: `_ githost.BranchLinks = (*Provider)(nil)`.

Unit test `internal/githost/github/links_test.go`, table (parser with several interacting rules, within the CLAUDE.md bar): pull with and without suffix, query, fragment; `/pull/12/foo` refused; tree with nested branch and percent escapes; `tree/` with no ref refused; issue; `http://` refused; unclaimed host refused; GHES host claimed through a fake Discovery (reuse `discovery_test.go` fakes); `.git` repo suffix; three-segment owner path refused.
