# P380 Automation scripts reuse one tab per script; start only from the play icon

Base: `a8cbc29` (P379 closed, P380 amended). Discovery by Grep/Read: CodeGraph MCP failed to connect (`codegraph` not in `$PATH`); `ToolSearch "codegraph"` found nothing.

## Ask

`SPEC.md` row: "Running the same automation script reuses its existing tab. A script starts only from its play icon; clicking elsewhere on the row does not start it." Both apps.

## Current state

- One shared module: `packages/workbench/src/automations/`. Each app wires it in `frontend/src/workbench/automationsModule.ts` (Studio and Space files identical apart from `ade`). Only one script list exists: `AutomationsPanel.vue` + `ScriptRow.vue`, shared by both apps. ADE surfaces (task menu, branch row, branch panel `Run automation`) are explicit menu commands that open the run dialog via `ade/v2/automation/useRunAutomation.ts`.
- Two tab kinds carry a run:
  - `terminal` with `launchKind: 'script'`: a normal script. Opened by `ctx.openTerminalTab` -> `createTerminalTabs.ts` with `reuse: false`, so every run adds a tab. Callers: `runScript.ts` `useRunScript` (no params), `run/RunScriptDialog.vue:94` (`started.terminal`). The tab id is the terminal id; Go `scriptruns.Begin` stores it as `run.terminalId`.
  - `script-run` (`tabs/scriptRunTabKind.ts`, state `{runId, label}`, path = runId): smart and headless runs. `ctx.openRunTab(runId, label)` with `reuse: true` keyed by runId, so each run is a new tab. Callers: `RunScriptDialog.vue:106`, `schedule/ScheduleConfirmDialog.vue:79`, `runs/runsQueries.ts:116` (resume), `runs/RunsSection.vue:46` (history), Space `ade/v2/automation/AdeAutomationChip.vue:38`, `AdeAutomationsBlock.vue:70`, `state/agentNotify.ts:67` (calls `tabs.openTab` directly).
- Neither kind is persisted (`createTabsStore.ts` `persistable` rule), so state schema changes need no migration. Go never reads tab state.
- A terminal tab opens its PTY once, on first mount (`useTerminalMount.ts`, "never reopened for the same tab"). Go registry rejects a live duplicate id (`ErrDuplicateSession`).
- `ScriptRow.vue` root is a `<button>`; `@click` emits `run`. The play glyph in `script-run-slot` is decorative; a spinner replaces it while `liveRun`. `AutomationsPanel.vue` `openItem` (Enter via `useListNavigation.onOpen`) runs the script. Context menu has `Run` (id `run`) and, for scheduled scripts, `Run now`.
- Precedents: Memory panel row click selects (`MemoryPanel.vue:176`, `rowVariants({ selected })`); API tree row click selects, double-click opens (`CollectionRow.vue:133`). `listNavigation.ts`: "Enter: the primary action, same as double-click"; a nested button keeps its own Enter/Space.

## Decisions

- **Tab key = script plus target.** Key `{scriptId, taskId, branchId}` (`''` when none; Studio always `''`). One tab per key, not per script id alone: Space runs one script for several ADE tasks at once, and a script-only key would block task B while task A runs. Stored in tab state (not derived from the runs list): a just-opened terminal has no run row yet, so a fast second click would miss it.
- **Live previous run: focus, no second run.** Live = terminal tab whose session is `starting | running` or missing (opened, not yet mounted); `script-run` tab whose run is `running | waiting`. A start request for a key with a live tab activates that tab (and `showAutomations()`), opens no dialog, starts nothing. Gate runs at every UI start entry: `useRunScript` (play, menu `Run`, `Run again`), `useRunAutomation.start` (ADE), the run dialog's Run (target chosen in the dialog), menu `Run now` (key from `script.schedule`). Not in Go: the scheduler already skips live scripts; the UI gate is about tabs, not a server rule.
- **Finished previous run: replace in place.** The new run's tab takes the old tab's strip position and title; the old tab closes (its exited PTY and xterm drop through the normal close path). New tab id, so terminal id stays unique per run: no PTY reopen under one id, `useTerminalMount`'s open-once rule and `useScriptRunByTerminal` stay valid, Go untouched. Kind may change (script edited normal <-> smart); replace handles any kind.
- **Tab closed: new tab.** No key tab -> append as today.
- **Viewing a run uses the same placement.** History click, ADE chip/block `Open`, agent reveal, resume: tab already showing that run -> activate; key tab not live -> replace it; key tab live with another run (viewing an older run while the latest runs) -> new tab; none -> new tab. Otherwise a history open would leave two tabs per key and the next start could not tell which to reuse. Several key tabs can coexist only via that live case or `Duplicate tab`; lookup takes the first live for the gate and the first finished for replace.
- **Row click selects, nothing else.** Root becomes a `div` (row with a nested button); click focuses the row, which sets `activeKey`; row shows `rowVariants({ selected: activeKey === key })` (Memory precedent).
- **Double-click and Enter: Edit.** Opens `ScriptDialog` on the script, same as menu `Edit` (API tree precedent: click selects, double-click opens; listNavigation: Enter = double-click). Not run: the ask removes run from the row.
- **Play button is the only row control that starts.** `TooltipIconButton` `play` (`script-play`, tooltip `Run`) in `script-run-slot`, `@click.stop`, `@dblclick.stop`, `tabindex="-1"` (row keeps the single roving stop). While the panel key `{scriptId, '', ''}` tab is live the button shows the spinner and its tooltip reads `Show run`; clicking focuses that tab (gate). `RunElapsed` stays beside it for any live run of the script, as today.
- **Context menu `Run` and `Run now` stay.** They are explicit run commands with the play icon, not an accidental row click; both go through the gate. Keyboard start: menu key / Shift+F10 -> `Run`.
- **No new store.** Placement logic is a composable over the module context; tab list lives in each app's tabs store; run state stays TanStack Query (`['scriptRuns','list']`).
- **No split.** Seam change touches both apps' module files and every opener; one sequential implementer.
