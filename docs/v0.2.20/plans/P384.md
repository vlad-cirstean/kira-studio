# P384 Review window fixes

Base: `b6f19d4` (P383 closed). Discovery by Grep/Read: CodeGraph MCP failed to connect (`codegraph` not in `$PATH`).

## Ask

`SPEC.md` row:

- Review window shows latest committed changes. Find why it goes stale and when it refreshes; refresh on right events.
- Show uncommitted changes, clearly separated from committed ones.
- Marking a file reviewed keeps its diff visible on return (as on GitHub), not the plain file.
- Add missing button that hides agent panel.

User: "Make sure the review window has the latest committed changes. I don't know when it refreshes but it's oftentimes stale. Also show the uncommitted changes, but those to be clearly separated and also if I check a file as reviewed when I go back to it I still expect to see the diff, right now it shows the file itself. Like in GH only because you checked some diffs you can still see the diffs later. Also in the review window I asked for a button that hides the agent panel and there's none."

One phase, no split (see Decisions 1).

Committed data flow (git-ui, `packages/git-ui/src`):

- `ReviewView.vue` owns `ReviewSessionState` (`state/review.ts`), `ReviewFilesState` (`state/reviewFiles.ts`), `ReviewCommentsState`.
- Files pane target = `(repoId, branch, base)` from a `watch` in `ReviewView.vue`. `ReviewFilesState.setTarget` runs `review.files` once. Reload only on target change, a mark failure, or `ui.action: refresh` (editor-side range mark).
- `ReviewSessionState` subscribes `repo.changed`/`refsChanged` and runs `#checkForChange`: re-resolves base and, if base or commit count differ, sets `staleReview` (banner, D39 "never applied automatically"). Banner renders only in `ReviewCommitList.vue:124`, i.e. Commits pane.
- Backend watcher (`gitclient/watcher.go`) fires `refsChanged` on `commonDir/refs/**`, `packed-refs`, `HEAD` etc., and on `commonDir/worktrees/**` (a linked worktree's index write lands there). Plain working-tree file edits fire nothing. `gitsession` drops its caches on `refsChanged` before fan-out, so server reads are fresh.

**Root cause of stale committed changes:** window opens on Files pane; a new commit on the branch (same name, same base) never changes the `(repoId, branch, base)` triple, so `review.files` never re-runs. List, `branchTip` and `mergeBase` stay at open-time values; every click opens a diff against the old tip. The only signal (`staleReview`) is a banner in the Commits pane the window never shows, and it ignores same-count rewrites (amend). Nothing refreshes on window focus (desktop `QueryClient` has `refetchOnWindowFocus: false`; git-ui is not on TanStack Query at all). Refresh happens only on window reopen.

Uncommitted:

- No list in the window. Only the header badge count, from the whole board.
- `working.detail` / `editor.openWorkingDiff` exist, but both target the repo's main checkout (`RepoEntry.WorkingDetail`, `CodeWorkspaceService.ReadDiff` over `Session.Root`), never the task worktree.
- `gitsession.WorktreeStatus(ctx, dir)` and `runOneInDir` already run git in a worktree dir; `WorktreeHead(ctx, path)` returns its tip.
- Agent hook events reach every window: `control.onAgentEvent` (`AgentEvent{terminalId, event, cwd, toolName, ...}`), already used by `ade/v2/dialog/turnWatch.ts`.

Reviewed file shows plain file:

- `ReviewFilesState.#openInEditor`: `diffMode` defaults `sinceReview`; `leftRev = entry.review.reviewedAtSha ?? mergeBase`. After a whole-file mark, `reviewedAtSha` = current tip, so left = right = tip. Diff has zero changes, Monaco renders the whole file. Same for a partial mark. That is the "shows the file itself" bug.

Agent panel toggle:

- No toggle exists. `docs/HISTORY.md` has no trace of the earlier request: v0.2.17 P354 fold lists only removed window-only items (review filter, Ask review agent action, session resume/save, target switching), and the chapter's `SPEC.md` is gone with the squash merge (`d281527`). So the request was dropped, not declined.
- Related bug found: `App.vue:88-89` wires `onToggleProjectPanel`/`onToggleOperationsPanel` to `layoutStore` in every window. Menu accelerators (`Cmd+B`, `Cmd+J`, `internal/shell/accel.go`) go to the focused window (`appevent.Signal` -> `EmitFocused`). In a review window they flip the shared persisted layout, which `LayoutService.Set` broadcasts, so the main window's panels toggle from a review window.

## Decisions

1. **No split.** Items 3 and 4 are a few lines each; items 1 and 2 share the same refresh triggers. One sequential implementer.
2. **Committed refresh is deterministic, three triggers:**
   - `refsChanged` for the target repo: `ReviewFilesState` subscribes and reloads `review.files` (coalesced with `AUTO_REFRESH_COALESCE_MS` from `state/refreshTiming.ts`). Reload keeps `selectedPath`, `diffMode` and the list; re-runs `#loadDiff` metadata for the selected file.
   - Locked mode (`lockTarget`, i.e. review window) auto-applies a changed resolution instead of the banner. `ReviewSessionState` gains a constructor option `autoApply: boolean`; `#checkForChange` then calls the same path `acknowledgeStaleReview` uses. Sidebar (unlocked) keeps the D39 banner.
   - Window focus: Space calls new `ReviewApi.refresh()` (files reload plus session check) from `useWindowFocus` (VueUse) when focus returns. Covers a missed watcher event (FSEvents drop, sleep) at the cost of one `review.files` call per focus.
   - No fetch. A foreign review branch only moves after autofetch or a manual fetch; unchanged.
3. **Open diff tabs keep their sha pair** (G13 D8 sha addressing). A refresh changes the list and the next click; an already open tab is not rewritten.
4. **Uncommitted section lives in the git-ui Files pane, data from Space.** Reason: same `FileTree` look as the committed list (git-ui does not export `FileTree`), while server state stays in TanStack Query on the Space side (CLAUDE.md rule). git-ui mount gains `MountHandle.setWorkingChanges(section | null)`; Space pushes the query result in.
5. **Uncommitted data over `AdeTaskService`, not the git IPC contract.** The backend must resolve the task's worktree from `branchId` and must never take a client-sent path as a git `cwd`. Two new methods (67 -> 69):
   - `ReviewWorking(branchId)` -> `{ worktree, head, files: FileChange[] }`: staged, unstaged and untracked changes of the task worktree against its `HEAD`. Untracked -> `added`, as `WorkingDetail` does. No worktree (foreign review branch never prepared, or not created) -> `worktree: ""`, `files: []`.
   - `ReviewWorkingDiff(branchId, path)` -> `codeworkspace.DiffContent`: worktree `HEAD` side vs file on disk, same 8 MiB gate and four-kind classification as `ReadDiff`. `path` passes `ValidateRelPath(worktree, path)`.
   - Git IPC contract unchanged, so no contract version bump.
6. **No reviewed state for uncommitted files.** No checkbox, no comments. review.db keys marks by branch tip sha; working content has no sha, and content-hash marks would need new storage plus a second mark model. Once committed, the file shows in the committed list with the normal since-review rule. Section hint says so.
7. **Uncommitted freshness triggers** (query key prefix `['adetask', 'reviewWorking', branchId]`, list and per-file diff under it):
   - board push (`installAdeReadSignals` `onBoard` also invalidates `['adetask', 'reviewWorking']`; covers commits, stage, checkout),
   - window focus (`useWindowFocus`),
   - agent hook events whose `cwd` is inside the target worktree, `event` in `PostToolUse` or `Stop`: debounced 300 ms (`useDebounceFn`).
   - No polling. External-editor edits are picked up on refocus.
   - Header badge switches from board `branch.dirty` to this query's count, so badge and section always agree.
8. **Reviewed file keeps its diff:** in `sinceReview` mode, `leftRev = reviewedAtSha` only when `review.kind !== 'none' && review.changedSinceReview`; otherwise `mergeBase` with base label. Same as GitHub: a viewed file shows the full branch diff; "changed since review" shows only the delta. Applies to whole and partial marks. Range mode unchanged.
9. **Agent panel toggle:** `TooltipIconButton` in `AdeReviewHeader` right of the title, before `AdeReviewActions`, icon `layout-sidebar-right` / `layout-sidebar-right-off`, `variant="title" size="title"`, `aria-pressed`, same as `WorkbenchTitleBar`.
   - State `usePersistedState('kira.ade.review.agentPanel', true)`, per device, same as the width keys. Per-window state would be lost anyway: review windows are not restored.
   - Hidden removes the right `section` and its `ResizeHandle` (`v-if`); the agent terminal session keeps running, since it is a tracked session, not owned by the pane.
   - Shortcut: in a review window `Cmd+J` (`view.toggleOperationsPanel`, the secondary panel) toggles the agent panel; `Cmd+B` does nothing. `App.vue` routes both channels by `reviewWindow.target`, which also fixes the cross-window layout bug above. No new accelerator.
   - State lives in `useAdeReviewWindowStore` (one concern: this window's review UI), exposed as `agentPanelVisible` plus `toggleAgentPanel()`.
10. **No refresh indicator.** A spinner on every focus or commit would flicker; the existing `loading` state already covers an empty list. Skip.

### Commit 1 `fix(git-ui): review files reload on ref changes`

`packages/git-ui/src/state/reviewFiles.ts`:
