# P382 MCP show-results customizable per connection

Spec row: "Result display settings for MCP 'show results' set per connection." User: "The mcp show
results should be customisable per connection."

CodeGraph MCP failed to connect this session (`codegraph` binary not on `$PATH`). Discovery used
Grep/Read.

## Interpretation

"MCP" = Studio's embedded Database MCP server (`internal/dbmcp`). "Show results" = result review:
global setting `dbMcp.previewResponses` ("Review results before the AI gets them"). With it on,
`run_query` holds each executed result in a response-stage approval; the dialog
(`ApprovalResponse.vue`) shows it as a table or "As sent" text before Send/Withhold.

Today it is global only. `docs/ARCHITECTURE.md` (approval flow) states: "There is no per-connection
preview setting". This phase closes that gap.

Alternative read, not taken: per-connection render limits for what the AI gets (`run_query` default
`maxRows` 200, max 2000; cell truncation). Reasons to decline: those shape the AI payload, not what
the user is shown; `maxRows` defaults are baked into the `run_query` tool schema text
(`llmprompts.LimitVars`), so a per-connection default makes that description wrong for some
connections. If the user meant this, it is its own phase.

Also declined: per-connection default view of the review dialog (table vs As sent). One click in
the dialog, no reported pain, would double the surface.

## Design

One new per-connection field, three values:

| value | meaning |
|---|---|
| `inherit` | follow global `dbMcp.previewResponses` (today's behaviour; default) |
| `review` | always hold results for review on this connection |
| `send` | never hold; results go straight to the AI client |

Name: `mcpReviewResults` (TS/JSON), `McpReviewResults` (Go), column `mcp_review_results`.

Global switch stays. It becomes the default for `inherit` rows. Every existing row reads `inherit`, so
behaviour is unchanged until a user picks an override.

Why tri-state, not a per-connection boolean replacing the global: a boolean needs a data migration
copying the global value into every row, and loses the one-switch "review everything" control. The
tri-state matches the existing per-connection mode words (deny/allow/prompt) and needs no backfill.

### Server gate

- `internal/dbmcp/tools.go` `runQuery`: replace `!s.cfg.PreviewResponses()` with
  `!s.reviewResults(rv.summary)`.
- New method (put in `permissions.go`, beside `modesOf`):

  ```go
  // reviewResults resolves a connection's result review: its own override, else the app setting.
  func (s *Server) reviewResults(c model.ConnectionSummary) bool {
      switch c.McpReviewResults {
      case "review":
          return true
      case "send":
          return false
      default:
          return s.cfg.PreviewResponses()
      }
  }
  ```

  Global setting is read only for `inherit` rows. Fail-closed read in `bridge/dbmcp.go`
  `previewResponses` stays as is.
