# P385 Postman import accepts partial data again

Base: `db08906` (P384 result). Discovery by Grep/Read: CodeGraph MCP failed to connect (`codegraph` not in `$PATH`, ENOENT).

## Ask

`SPEC.md` row: an earlier phase made Postman import reject items with missing values. The export itself lacked that data. Revert to importing partial data too.

User, via orchestrator: items with missing fields import with defaults, no rejection.

## Earlier change

v0.2.18 P361 ("Postman import: collection variables and environment values missing, only keys import"). Squashed into `d1975b0`; per-commit history on `refs/pull/13/head` (`0cd58ea` plan, `1bfccaa` decoder, `1edfb55` warning, `e9cf3f0` legacy promotion). P361 concluded the cause was outside the app: Postman exports only shared values, so unshared ones arrive as `"value": ""`. It added a warning telling the user to fix the export and re-import, and it started skipping more entries.

No code path refuses a whole file, or one entry, because its `value` is missing: `VariableValue` turns null, absent and `""` into `""` and the entry imports (`TestDecodeVariableEntry` rows "null", "absent", "empty string"). What the import does drop today, read from current source:

1. `internal/postman/parse.go` `decodeVariableEntry`: `enabled: false` or `disabled: true` sets `disabled`; `decodeVariables` and `environment.go` `parseEnvironment` skip the entry and count `disabled_variables`. P361 (its G3) added the collection `disabled: true` skip; the environment `enabled: false` skip predates it. Legacy promotion (`repos/variables.go` `promoteIfNeeded` via `postman.DecodeVariables`) skips the same entries since `e9cf3f0`.
2. `decodeVariableEntry`: a `key` that is absent, null, `""` or non-scalar returns `ok = false`; the entry is dropped with no count and no warning.
3. `walkItems`: an item object with neither `item` nor `request` is dropped, counted `malformed_item` ("were neither a folder nor a request and were skipped"). Predates P361 (v1.2 P4 D3).
4. Non-object entries (a variable entry or an `item[]` entry that is a string, number, null or array) are dropped. Item ones count `malformed_item`; variable ones are silent.
5. Warning `empty_values` (P361) reads as a refusal: "Postman exports only shared values; share them in Postman, then export again."

Request members already import partial data: `importKeyValueRows` keeps a row with no key or value, `importRequest` defaults method GET and an empty URL, `defaultRequestName` names a nameless request. No change there.

## Rules after this phase

Every entry or item that is a JSON object imports. A missing field takes a default. Every default is counted in a warning, so the user learns what was filled in. Only entries that are not JSON objects stay skipped: they carry no field to default.

| Case | Today | After |
|------|-------|-------|
| Variable entry, value null/absent/`""` | imported `""`, `empty_values` | unchanged; warning reworded |
| Variable entry, `enabled: false` / `disabled: true` | skipped, `disabled_variables` | imported as-is, active; `disabled_variables` reworded |
| Variable entry, key absent/null/`""`/non-scalar | dropped silently | imported as `unnamed_<n>`; new `unnamed_variables` |
| Variable entry, not an object | dropped silently | unchanged |
| Item object, neither `item` nor `request` | dropped, `malformed_item` | imported as a request with defaults; new `missing_request` |
| Item entry, not an object | dropped, `malformed_item` | unchanged; `malformed_item` reworded |
| Whole-file refusals (size, no `info`/`values`, v2.0/v1 schema, globals, nesting depth) | refused | unchanged: not partial data, wrong or unsupported file |

Defaults:

- `unnamed_<n>`: `n` counts unnamed entries within one array, from 1, in document order. No collision handling with a real key of that name: duplicate names already import and resolve first-wins by `sort_order` (P361 V10).
- A whitespace-only key stays as today (imported verbatim, non-empty).
- A disabled entry keeps its value, type, secret flag and description. The app has no per-variable enabled flag, so it is active. Order stays document order.
- A request-less item: `importRequest(nil, rep)` (GET, empty URL, default body), name from `name` or `defaultRequestName("")` = "Untitled request", origin is the item object through the same strips as a request item. Export already copes: `buildItem` calls `buildRequest(nil, saved)`, which writes `method`, `url` and the rest from the saved request.
