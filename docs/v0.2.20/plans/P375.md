# P375 plan: Studio keeps filter value and results across tab changes

Spec row: `docs/v0.2.20/SPEC.md` P375. One sequential Sonnet implementer. No stream split: most
edits share one pattern and `SearchToolbar.vue` feeds four views.

Discovery note: CodeGraph MCP server failed to connect (`codegraph` binary not on `PATH`).
`ToolSearch "codegraph"` returned no tool. Discovery used Grep/Read only. Base: `1b1efca`.

## Root cause

- Studio tab kinds never set `keepMounted` (only Kira Space uses it). `packages/workbench/src/
  components/MainView.vue:54` renders the active tab with `v-if` + `:key="activeTab.id"`, so every
  tab switch unmounts the old view and cold-mounts the new one.
- Server results survive: each view's runtime store and page store (`views/*/state.ts`,
  `views/*/page.ts`) are keyed by tab id, and every `onMounted` loads only when
  `!runtime[tab.id]`. Committed filters (grid `filter`/`sort`, documents `search`/`sort`, stream
  `offsetFilter`/`timestampFilter`/`partitions`) already persist in `tab.state`.
- Lost: filter inputs held in component-local `ref`s, plus the client-side match/filter results
  their components clear in `onUnmounted`.

### The main case: find bar "filter rows" (grid, documents, key-value, console, stream)

- `views/shared/page/SearchToolbar.vue:60-64` holds `query`, `matchCase`, `wholeWord`, `regex` as
  local refs. Its `onUnmounted` (`:217`) cancels the scan, calls `api.clearSearchState(tabId)` and
  `setSearchFiltering(tabId, false)`.
- `rt.searchOpen` lives in the view runtime store, so on return the bar remounts open but empty,
  the filter-rows toggle off, all rows shown.
- `views/stream/StreamSearchToolbar.vue` repeats this (`query` local `:35`, clears at `:73`).
- Why unmount clears: Cmd+F (`toggleSearchOpen`) closes the bar by unmounting it without calling
  `close()`. Rows must never stay hidden behind a closed bar (P24 D7). The unmount hook cannot tell
  "bar closed" from "tab switched away".

### Other tab-view filters lost the same way

- Browse: `browse/BrowseView.vue:125` `filterOpen` local; `rt.filter` text is in the store. After a
  switch the bar is hidden but `rt.filter` still hides rows. Same P24 D7 violation, worse bug.
- Definition: `definition/DefinitionView.vue:145,157` `searchOpen`, `structureFilterQuery` local.
- HTTP request: `httprequest/HttpRequestView.vue:241-242` `fieldFilterOpen`/`fieldFilterQuery`;
  `httprequest/ResponsePane.vue:185` `headerFilter`; `httprequest/CookiesPane.vue:36` `filter`
  (two instances, `mode` request/response; no tab prop today);
  `httprequest/ResponseHistoryList.vue:63` `filterQuery`.
- gRPC request: `grpcrequest/GrpcRequestView.vue:201-202` field filter;
  `grpcrequest/SchemaBrowser.vue:89` `filterQuery`; `grpcrequest/CallHistoryList.vue:59`
  `filterQuery`.
- Variable set / environments tabs: `api/VariableSetView.vue:195`, `api/EnvironmentsView.vue:106`
  `filterQuery`.
- Uncommitted filter-row drafts: `grid/FilterToolbar.vue:60-61` `whereText`/`orderByText`,
  `documents/DocumentFilterRow.vue:36-37` `searchText`/`sortText`, `stream/StreamFilterRow.vue`
  `useInlineEdit` texts (`:33,:39`) and `selectedPartitions` (`:45`). A mouse tab click blurs and
  applies them. The `tab-next`/`tab-prev` shortcuts (`shortcuts/studioCommands.ts:149`) switch
  without a reliable blur (WebKit fires none on node removal), so typed text is lost.

### Out of scope (find, not filter)

`views/shared/ResponseFindBar.vue` (response body, raw exchange, definition Source pane, cell
editor) and `httprequest/useRequestFind.ts` highlight matches but hide nothing. Not filters; left
as is. Not tab views: `api/VariablesOverviewPanel.vue`, `api/DynamicValuesDialog.vue`.

## Design

Rule: per-tab filter UI state lives in the owning view's existing per-tab Pinia store (one concern
each: that view's runtime), never in a component `ref`. Session-only, never in `tab.state`.
No new cross-view store: a store spanning grid, HTTP and variables would be a grab-bag.

Persistence across restart: not added. `searchOpen`, browse `rt.filter` and every runtime record
are already session-only; only committed filters persist, and they already do.

TanStack Query: not used. Requirement it cannot meet: nothing lost here is a bridge fetch. Server
pages already stay cached per tab and are not refetched on remount. Lost results are client-side
scans over in-memory pages (`scan.ts`, stream `runSearch`, `matchesQuery` filters). HTTP/gRPC
history lists already use TanStack queries (P175) and keep their data.

Declined: setting `keepMounted` on Studio kinds. `KEPT_MAX = 4` evicts past four tabs, so state is
still lost; it also keeps SlickGrid/Monaco instances alive per tab.

Lifetime: tab close clears everything through existing `registerTabRuntimeCleanup` callbacks (new
fields sit inside records those callbacks already delete). Explicit close (X, Esc, Cmd+F, filter
toggle off) clears the query and the filter-rows toggle, as today.

## Changes

### 1. Shared page find (grid, documents, key-value, console)

`views/shared/page/searchFilter.ts` (`usePageSearchFilterStore`, concern widens from "filter-rows
toggle" to "page find state per tab"; update its header comment):

- Add `find: reactive<Record<string, FindInput>>`,
  `FindInput = { query: string; matchCase: boolean; wholeWord: boolean; regex: boolean }`.
- `findInput(tabId): FindInput` (default all empty/false, not stored until written),
  `setFindInput(tabId, patch: Partial<FindInput>)`, `clearFind(tabId)` (deletes `find[tabId]` and
  the toggle).
- `clearSearchFilterState` also deletes `find[tabId]` and `find[`${tabId}::preview`]`.

`views/shared/page/search.ts`: `searchState` entry gains optional `page?: WeakRef<object>`, the
page the completed scan ran over. Update the `PageSearchApi.searchState` type.

`views/shared/page/SearchToolbar.vue`:

- New required prop `isOpen: () => boolean`. A function, not a boolean: at unmount the parent's
  `v-if` has flipped but the child's props are not re-patched, so a boolean prop still reads
  `true`. Calling into the store gives the live value.
- `query`/`matchCase`/`wholeWord`/`regex`: writable `computed`s over
  `findInput(tabId)`/`setFindInput`. `FindBar`'s `watchDebounced` is not immediate, so a restored
  query triggers no scan by itself.
- In `done`: store `page: new WeakRef(pageOf(tabId))` when `pageOf` returns an object.
- `onMounted`: if `query !== ''`, rescan with `startSearch(false)` when there is no entry, the
  entry is `pending`, or `entry.page?.deref() !== api.pageOf?.(tabId)`. Otherwise keep the
  existing matches, index and filtered rows as they are.
- `onUnmounted`: always `handle?.cancel()`. If `props.isOpen()`: keep `searchState` (delete it only
  if `pending`, since a partial list is useless), keep `find` and the toggle. Else: current
  behaviour plus `clearFind(tabId)`.
- `close()`: also `clearFind(tabId)`.

Call sites pass `:is-open`:

- `grid/DataView.vue:330` `() => !!gridViewStore.runtime[tab.id]?.searchOpen`
- `documents/DocumentView.vue:384`, `shared/keyvalue/KeyValueRowsTable.vue:142` (key is
  `viewKey`, may be `${tabId}::preview`), `console/ConsoleView.vue:454` (`v-if` also has
  `!activeResultIsPlan`: switching to a plan result keeps the query; returning rescans because
  `pageOf` is `activePage`).

## Edge cases

- Tab close: cleared via existing cleanups; `::preview` keys cleared alongside.
- Bar closed by X, Esc or Cmd+F: query and toggle cleared; reopening shows an empty bar.
- Page replaced while away (another tab's commit runs `reloadTabsForTarget`, Refresh from the
  palette, stream fetch): rescan on mount with `autoScroll` false; filter-rows applies after the
  scan completes (P42 D38 pending rule unchanged).
- Scan in flight at switch: cancelled, partial entry dropped, rescanned on return.
- Invalid regex restored: `startSearch` reports it inline as today.
- Two tabs on the same table: state is per tab id, never shared.
- Duplicated tab: new id, starts with empty find state (runtime is not copied).
- Memory: kept match arrays are capped by `MAX_SCAN_MATCHES` per open tab and freed on close.
  `WeakRef` avoids pinning a replaced page.
- App restart: none of the new state persists; committed filters restore as today.

## Tests

unit test (no logic past the bar).

New UI spec `apps/kira-studio/tests/ui/tab-filter-state.spec.ts`. Reuse helpers from

1. Grid: two data tabs. Tab A: open find, type `^(2|5|9)$` with regex, toggle filter rows (3
   rows). Switch to B, back to A: input value, regex pressed, filter pressed, 3 grid rows, scope
   text "Showing 3 of 10 loaded rows". Press Esc: bar closes, all rows back; reopen: empty input.
2. Grid close clears: filter applied in A, close A, reopen same table: find bar closed, empty.
3. Grid WHERE draft: type in WHERE without Enter, switch with the `tab-next` shortcut, return with

4. Stream: find query and filter-rows kept across a switch.
5. Browse: open filter, type, switch away and back: bar open, text kept, list filtered.
6. Definition: structure filter kept across a switch.
7. HTTP request: field filter open with query kept across a switch. One case covers the shared
   pattern for gRPC and variable tabs; add gRPC only if its spec setup is cheap.
