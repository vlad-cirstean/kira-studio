Handler today, `terminalRenderer.ts:101-109`:

```ts
// Cmd+Enter is meta-Enter (ESC CR), xterm's own Alt+Enter bytes: a newline in Claude Code and zsh.
term.attachCustomKeyEventHandler((ev) => {
  if (ev.key !== 'Enter' || !ev.metaKey || ev.ctrlKey || ev.altKey || ev.shiftKey) return true;
  if (ev.type === 'keydown' && !ev.isComposing) {
    ev.preventDefault();
    term.input('\x1b\r', true);
  }
  return false;
});
```

Bytes: `ESC CR` (`\x1b\r`, base64 `Gw0=`). xterm 6.0.0 `Keyboard.ts` case 13 sends `ESC CR` only for Alt, else plain `CR`; Shift is ignored, so Shift+Enter today submits.

No conflict for Shift+Enter: `packages/shared/domain/shortcuts.ts` has no Shift+Return chord (only `view.runAll` Cmd+Shift+Return, which the handler must keep passing through). No Go menu accelerator on Shift+Return. Find bars use Shift+Enter, but only in their own inputs, never in xterm.
