# P377 Foreign-branch review tasks: convert to work item, open normal task view

Base: `6b7aac6` (P376 landed). Discovery by Grep/Read: CodeGraph MCP failed to connect (`codegraph` not in `$PATH`).

## Ask

`SPEC.md` row: other people's branches default to review tasks.

1. Task menu gets an action that turns a review task into a normal work item.
2. Clicking a review task opens the branch view. It must open the task view, like any other task.

## Current state

Data:

- `ade_tasks.kind` is `task | review | parked`; `ade_task_branches.kind` is `mine | review | parked` (`storage/model/adetask.go:11-18, 383-397`).
- Kind is set once, at attach: `ade/board_writes.go:366-385` `attachExistingBranch`. `resolveKind` (`ade/gitfacts.go:115`) compares tip author email with `user.email`. A new task from a foreign branch gets `Kind: review, Owner: <author name>`. Board refresh never re-derives a stored kind.
- A review branch gets no worktree at attach; a mine branch gets `prepareAttached` (worktree plus prepare script, `board_writes.go:301-327`).
- `repos.AdeTaskRepo.UpdateTask` (`storage/repos/adetask.go:256-325`) moves kind only task <-> parked, flipping branch kinds mine <-> parked in the same tx. A review task refuses any kind change: `ErrReviewKind` (`adetask.go:21`), mapped as a contract error (`bridge/adetask.go:111`).
- Bridge validation already accepts `kind: 'task' | 'parked'` (`bridge/adetask.go:268`). `adewire.TaskPatch.Kind` (`bridge/adewire/wire.go:654`) needs no shape change.
- `Task.Owner` is read only by the review note in `AdeTaskPanel.vue:186`.

Frontend:

- Menu model: `ade/v2/board/menu.ts` `taskMenuModel`. A review card (`card.review`) gets the reduced set: no step entries, no park, no change base.
- Command runner: `ade/v2/plan/useTaskMenu.ts` `run()`; `park` calls `useUpdateTask` with `taskPatch({ kind })`.
- Review card has no head (`AdeTaskCard.vue:143` `v-if="!card.review"`, P198 design). Its only click target is the branch row. `AdeBranchRow.vue:48` `pick()` calls `ui.selectBranch(...)`, so `AdePanel.vue:67` shows `AdeBranchPanel`. That is the bug in ask 2.
- Row right-click (`AdeBranchRow.vue` `onMenu`) opens the branch fix menu and stops propagation. On a review row that menu holds only the label and Review code. The review task menu is reachable today only by right-clicking the left action cell or via the panel More button.
- `AdeTaskPanel.vue` already renders review tasks: review note, Task/Notes/Sessions tabs. `AdeTaskTab.vue:211` lists branches; a click there opens the branch panel. So the branch view stays reachable from the task view.
- After a kind flip, `usePlanModel.buildCard` derives everything from `task.kind` and `branch.kind`: head, tag, step blocks, park, change base appear without extra code.

## Decisions

- **"Normal work item" in data**: task `kind` review -> task, `owner` -> `''`. Every `review` branch on the task -> `mine`. Created branches get the same worktree plus prepare script a mine branch gets at attach (`prepareAttached`). An existing worktree (from an earlier Start or Take over) is kept; `ensureWorktree` returns `Fresh: false` and no setup reruns. No workflow is assigned: same as attaching an own branch, the user picks one in the panel. Plan day stays as stored; an unpinned review lands in Later like any task with no day.
- **One way only.** review -> parked and task/parked -> review stay refused (`ErrReviewKind`). A converted task cannot recover which branches were foreign; the ask names one direction only. The menu hint states the effect.
- **No new IPC method.** Reuse `UpdateTask` with `patch.kind = 'task'`. Wire shape, Wails bindings and git-ipc `ContractVersion` are unchanged. Only the store rule and the engine side effect change.
- **No confirm dialog.** Nothing is lost: no file, branch or run changes, and the worktree is additive. The hint names the one-way effect.
- **Ask 2 routing**: on a review card, clicking (or Enter/Space on) the branch row selects the task, not the branch: `ui.select(taskId)`, so the task panel opens. Right-click on that row opens the task menu, which already holds Review code and now holds the convert item. Branch panel stays reachable from the task panel's branch list. Rejected: adding the card head to review cards. The row would still open the branch view, the card height and left-cell alignment would change, and the R_li visual baseline would break for no gain.
- A review-kind branch attached to a normal task (task kind `task`) keeps today's row behaviour. Routing keys on the card (`card.review`), not on `row.isReview`.
