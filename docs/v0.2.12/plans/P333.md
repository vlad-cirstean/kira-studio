## 1. Execution semantics (the decision)

Preview runs **after** execution, never before approval. Order per `run_query` call:

1. Existing gate unchanged, including the query approval (stage `query`) when verdict is `prompt`
   or heavy.
2. Execute and render exactly as today, producing the final `(*mcp.CallToolResult, any, error)`.
3. If `dbMcp.previewResponses` is on: hold that result in the handler goroutine and raise a second
   broker request, stage `response`. The AI client stays blocked.
4. Send (Approve) returns **the same result value, unchanged**. Withhold (Deny), timeout, abandon or
   a full queue returns an app-authored `errResult` with no row data.

Why this order:

- Running before approval defeats the gate. A `prompt` verdict means the user wants to decide
  whether the statement runs. A heavy read is gated for its cost, which a preview run would pay.
- One execution only. No double run, so no double side effect and no drift between preview and
  answer.
- Transaction-and-rollback declined: `Router.Execute` has no transaction held across a human wait.
  Holding one open up to 120 s keeps locks on a real database. Redis, Kafka, SQS and S3 have no
  rollback at all.

Write, DDL and unknown classes: the statement has already run when the preview shows. Withhold hides
the result only. The dialog says so in plain words (§5.3). The query-stage approval stays the only
control over whether a write runs.

Byte-faithfulness: the preview text is the `TextContent.Text` of the result the handler will return.
The UI renders a table by parsing those bytes and shows the raw bytes on the As sent tab. Masking
happens once, in `render.go`. Nothing re-renders or re-masks.

What is reviewed: every exit after `Execute` was called (success, `empty`, adapter error, masked
error, masking refusal, internal Go error). Not reviewed: exits before execution (path missing,
deny, all-deny, connect failure, query-stage deny/timeout). Those carry only app-authored text and
no data; reviewing them adds clicks for nothing.

Scope: `run_query` only. It is the only tool returning row data. `explain_query`, `describe_*` and
`list_*` are unchanged (stated in `docs/ARCHITECTURE.md`).

## 4. Part B: holding the result (backend)

### 4.1 Broker

- `ApprovalStage string`: `ApprovalStageQuery = "query"`, `ApprovalStageResponse = "response"`.
  `ApprovalRequest.Stage`; every existing caller sets `query`.
- `ApprovalRequest.Response *ApprovalResponse`, set only for stage `response`:

  ```go
  type ApprovalResponse struct {
      Text    string // exact TextContent text the client will receive
      IsError bool
      Bytes   int
  }
  ```

- Same queue, same FIFO, same timeout, same outcomes. A response review queues behind any query
  approvals already waiting; the dialog title names the stage, so order stays legible.
- `openPrompt`: stage `response` uses new i18n keys `backend.prompt.dbMcpResponse.title` /
  `backend.prompt.dbMcpResponseNamed.title` (title never carries data).
- `(*ApprovalBroker).ResponseFor(requestID string) (ApprovalResponse, bool)`: true only while that
  id is queued with stage `response`.

### 4.2 `tools.go`

- Move everything in `runQuery` after `awaitApproval` (mask set, execute, render, extra-statement
  note) into `executeAndRender(ctx, args, rv, plan) (*mcp.CallToolResult, any, error)`, behaviour
  unchanged.
- `runQuery` then calls `s.reviewResponse(ctx, args, rv, res, out, err)` when
  `s.cfg.PreviewResponses()` is true:
  - Text: the concatenated `TextContent` texts of `res` (exactly one today). For a bare Go error
    (`res == nil`), the text is `err.Error()` with `IsError` true. Before coding, read go-sdk
    v1.8.0's typed-handler error path (`mcp/tool.go` / `server.go`) and confirm the client receives
    `err.Error()` as an `IsError` text result. If it does, the preview matches. If it instead
    returns a JSON-RPC error, still preview `err.Error()` and label it "protocol error" in the UI.
    Record the finding as a one-line comment at the call site.
  - Request: `Stage: response`, `Reason: permission`, `Class: rv.class`, `Statement: args.SQL`,
    `Target: targetOf(rv.summary, args.Path)`, `Response`.
  - Approved: re-run `resolveEnabled` (exposure revoked during review → withhold). Re-run
    `MaskSetFor` and compare with the set used for rendering; if they differ, withhold with
    "masking rules for %q changed while its result was in review; run the query again". Else
    return `res, out, err` untouched. `executeAndRender` returns the `mask.Set` it used; add
    `mask.Set.Equal` (`internal/mask/mask.go`, `Set` has `Rules` and `Masker`) comparing rules and
    key.
  - Denied: `errResult(fmt.Sprintf("query against %q ran, but the user withheld its result", name))`.
  - Timed out: `"query against %q ran, but its result got no review within 2 minutes and was withheld"`.
  - Abandoned: `"the database MCP server stopped before the result of the query against %q was reviewed"`.
  - Queue full: withhold with `queueFullMessage` prefixed by "query ran; ".
  - Never return the held result on any path except Approved.

### 4.3 Bridge

- `DbMcpApprovalRequest` gains `stage` and `response` metadata `{isError, bytes}`. The snapshot never
  carries the text: snapshots fan out to every window on every queue change, and a 2000-row result
  can be MB-sized.
- New bound `DbMcpService.PendingResponse(DbMcpApprovalArgs) (DbMcpPendingResponse, error)` →
  `{requestId, text, isError}`. Empty id → `ipcerr.Required("requestId")`. Unknown id or wrong stage
  → `ipcerr.NotFound` (`internal/ipcerr/errors.go`).
- `NewDbMcpService` passes `PreviewResponses: s.previewResponses`.

  - tabular: result `columns[].name`, `dataType` in the header `title`.

- `isError`: shadcn `Alert` with the exact text, no table (`data-testid="db-mcp-preview-error"`).
- Parse failure of a non-error text: show As sent only, with a one-line notice. Never hide bytes.
- Loading: shadcn `Skeleton`. Fetch error: `Alert`.
