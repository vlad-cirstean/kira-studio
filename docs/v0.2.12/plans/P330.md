# P330: Branch naming, PR automation, release on merge — plan

Planned on `chapter/v0.2.12` at `e2c04fd`. One sequential Sonnet implementer. No parallel streams:
hook, script, workflows and docs share `docs/PACKAGING.md`, `docs/DEV_ENVIRONMENT.md` and the
script names the workflows call, so no zero-overlap split exists.

`P` numbering rule is unchanged by this phase.

## 0. Findings that shape the design

- **GITHUB_TOKEN events start no workflow**, except `workflow_dispatch` and `repository_dispatch`.
  Auto-merge enabled with GITHUB_TOKEN merges as `github-actions`, so that merge's own
  `pull_request: closed` and `push` events start nothing. Confirmed: GitHub's token docs, and
  `peter-evans/enable-pull-request-automerge`'s README ("the merge will not trigger further
  workflow runs"). A `closed`-only release trigger therefore never fires for an auto-merged PR.
  Design (§4.3): four entry points into one idempotent script. `workflow_run` of `PR` (green) waits
  for the merge. `pull_request: closed` covers a human merge. An hourly `schedule` sweep catches
  anything both missed. `workflow_dispatch` is the manual path.
- **Same rule hits `pages.yml`**: its `push: main` trigger stops firing for auto-merged PRs.
  `release-on-merge` dispatches `pages.yml` when it creates a tag (§4.3).
- **A GITHUB_TOKEN-initiated rerun** (flake workflow) may or may not raise a fresh `workflow_run`
  event. Unconfirmed either way. If it does not, flake reruns cap at 1 retry, and a PR that goes
  green on a bot rerun gets released by the hourly sweep. Both degrade safely. §8 verifies at first
  use.
- **A tag created by GITHUB_TOKEN on a commit that changes `.github/workflows/*`** may be refused
  ("without `workflows` permission"). The v0.2.12 merge itself changes workflows. The script then
  fails with the exact manual `git tag … && git push origin <tag>` lines. The manual tag push
  starts `release.yml` through its kept `push: tags` trigger.
- **Dropping `push: main` from `pr.yml` leaves `main` with no saved caches.** PR runs save into
  `refs/pull/N/merge` scope, which no other PR or release restores. Decision D3 (§4.4): a dispatched
  `release.yml` runs on ref `main`, so it saves caches there and seeds every later PR. Tag-push runs
  keep `cache-save: false`.
- **pr.yml concurrency** is `pr-${{ github.ref }}`, cancel-in-progress. A rerun of a stale head
  re-enters that group and would cancel the current head's run. The flake workflow reruns only when
  the failed run's `head_sha` equals the PR's current head.
- Remote state at planning (`git ls-remote`): `v0.2.10`, `v2.0`, `v2.6`, `v2.8`, plus legacy
  `archive/electron-v1.3`, `claude/electron-neutralino-migration-k91kc8`,
  `import/kira-version-vscode-kickoff`. `claude/pensive-hawking-e6ewuw` is **not** on the remote
  any more; only a local branch and a stale `origin/` tracking ref remain here.
- PRs #2, #3, #4, #6 (heads `v2.0`, `v2.6`, `v2.8`, `v0.2.10`) are all closed and merged. None is
  open, so renaming retargets nothing. Default branch is `main`, so no default-branch delete block.
- Rulesets today: "Protected branches" on `refs/heads/main` (deletion, non_fast_forward,
  pull_request with squash only, 0 reviews; **no required status checks**). "Protected tags"
  exists but is **disabled**. `allow_auto_merge` is **false**.
- References to old branch names: none in `scripts/`, `.github/`, `.githooks/`, `package.json`.
  `docs/HISTORY.md:5459` ("Work in v2.2 happens on branch v2.0") is history and stays (HISTORY
  edits forbidden). `git show <sha>:docs/v2.0/…` lines are commit-pinned paths, not branch refs.
- `scripts/release-ci-gate.sh` is referenced only by `release.yml` (`ci-gate` job) and
  `docs/PACKAGING.md` §7. No test, no `package.json` script.
- `gh pr create` and other GraphQL calls get 403 from cloud sessions; REST works
  (`gh api repos/{owner}/{repo}/pulls`). `gh api …/actions/…` is blocked by the session proxy.

## 3. Pre-push branch-name gate

Rule: a branch push must target `main` or `chapter/v<major>.<minor>.<patch>` (no leading zeros, no
pre-release suffix). Tag pushes, branch deletes and non-branch refs pass. **`claude/*` gets no
exemption** (user decision). Trade-off: a cloud session whose harness names a `claude/*` working
branch cannot push it. It must push to the chapter branch (`git push origin
HEAD:chapter/vX.Y.Z`), or its work stays local. The strict rule keeps one branch per chapter. The
server-side ruleset (§6) backs this up, since `--no-verify` skips the hook.

### `scripts/check-push-refs.sh` (new)

```sh
#!/bin/sh
# check-push-refs.sh — pre-push branch-name gate (P330). Reads git's pre-push stdin: one
# "<local ref> <local sha> <remote ref> <remote sha>" line per ref. A branch push must target main or
# chapter/v<major>.<minor>.<patch>; tag pushes, deletes and other refs pass. Exit 1 names each refusal.
set -eu

CHAPTER_RE='^chapter/v(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$'
bad=0
while read -r _lref lsha rref _rsha; do
  [ -n "${rref:-}" ] || continue
  # An all-zero local sha is a delete (40 zeros for SHA-1, 64 for SHA-256).
  case "$lsha" in *[!0]*) ;; *) continue ;; esac
  case "$rref" in
    refs/heads/*)
      name="${rref#refs/heads/}"
      if [ "$name" = main ] || printf '%s\n' "$name" | grep -Eq "$CHAPTER_RE"; then
        continue
      fi
      echo "pre-push: refusing branch '$name'. Push only main or chapter/v<major>.<minor>.<patch>, e.g. chapter/v0.2.12." >&2
      bad=1
      ;;
  esac
done
exit "$bad"
```

## 4. Workflows

The Linux sandbox cannot push `.github/workflows/*` (`docs/DEV_ENVIRONMENT.md`). Edited workflows
go to `docs/pending-changes/<path with / as __>.patch`. New workflows go complete to
`docs/pending-workflows/`. To make a patch: edit the real file in the working tree, then run
`{ echo "P330: <one-line why>"; git diff -- .github/workflows/X.yml; } > docs/pending-changes/.github__workflows__X.yml.patch`,
then `git checkout -- .github/workflows/X.yml`. `git apply` skips the leading note line. Check with
`git apply --check docs/pending-changes/*.patch`.

All `actions/checkout` uses keep the repo's pin `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7`.
Every untrusted value (head ref, PR number, sha) reaches shell only through `env:`, never `${{ }}`
inside `run:`. Every workflow sets top-level `permissions: {}` (or the existing `contents: read`)
and grants per job.

### 4.2 `docs/pending-workflows/pr-auto-merge.yml` (new)

```yaml
name: PR auto-merge

# P330: a chapter PR squash-merges once every check the main ruleset requires has passed
# (docs/PACKAGING.md §7). Merging as github-actions starts no further workflow; release-on-merge.yml
# handles that.
on:
  pull_request:
    types: [opened, reopened, ready_for_review]
    branches: [main]

permissions: {}

jobs:
  auto-merge:
    if: >-
      github.event.pull_request.head.repo.full_name == github.repository &&
      startsWith(github.event.pull_request.head.ref, 'chapter/v') &&
      !github.event.pull_request.draft
    runs-on: ubuntu-latest
    timeout-minutes: 5
    permissions:
      contents: write
      pull-requests: write
    env:
      GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
      GH_REPO: ${{ github.repository }}
      PR: ${{ github.event.pull_request.number }}
      HEAD_REF: ${{ github.event.pull_request.head.ref }}
    steps:
      - name: Refuse a malformed or already-released version
        run: |
          set -eu
          printf '%s\n' "$HEAD_REF" | grep -Eq '^chapter/v(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$' \
            || { echo "head '$HEAD_REF' is not chapter/vX.Y.Z" >&2; exit 1; }
          TAG="${HEAD_REF#chapter/}"
          if gh api "repos/$GH_REPO/git/ref/tags/$TAG" >/dev/null 2>&1; then
            echo "tag $TAG already exists: rename the branch to the next version" >&2
            exit 1
          fi
      - name: Enable squash auto-merge
        run: gh pr merge "$PR" --auto --squash
```

`pull_request`, not `pull_request_target`: fork PRs get a read-only token and the `if` skips them
anyway. Same-repo pushers are collaborators.

### 4.3 `release-on-merge`: `scripts/release-on-merge.sh` (commit 3) and `docs/pending-workflows/release-on-merge.yml`

Script, POSIX sh. Every `gh` call inside a function ends in `|| return 1`, because `set -e` is off
inside a function called from an `||` list.

```sh
#!/bin/sh
# release-on-merge.sh — tags a merged chapter PR's merge commit and dispatches release.yml (P330).
#   pr <number> [--head-sha <sha>] [--wait <seconds>] [--dry-run]
#   sweep [--dry-run]    every PR into main merged in the last 48h
# Idempotent: a tag already at the merge commit is kept, and a release run that exists is not
# dispatched again. Needs gh, GH_TOKEN, GH_REPO (contents: write, actions: write).
# Exit: 0 done or nothing to do, 1 failure, 2 usage.
set -eu

CHAPTER_RE='^chapter/v(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$'
POLL_SECONDS=15
DRY_RUN=0

usage() {
  echo "usage: $0 pr <number> [--head-sha <sha>] [--wait <seconds>] [--dry-run] | sweep [--dry-run]" >&2
  exit 2
}

# tag_commit <tag>: prints the commit the tag points at; prints nothing when the tag does not exist.
tag_commit() {
  _err="$(mktemp)"
  if _ref="$(gh api "repos/$GH_REPO/git/ref/tags/$1" --jq '.object.type + " " + .object.sha' 2>"$_err")"; then
    rm -f "$_err"
    _type="${_ref%% *}"
    _sha="${_ref#* }"
    if [ "$_type" = tag ]; then
      _sha="$(gh api "repos/$GH_REPO/git/tags/$_sha" --jq .object.sha)" || return 1
    fi
    echo "$_sha"
    return 0
  fi
  if grep -q 'HTTP 404' "$_err"; then rm -f "$_err"; return 0; fi
  cat "$_err" >&2
  rm -f "$_err"
  return 1
}

# handle_pr <number> <head sha or empty> <wait seconds>
handle_pr() {
  _pr="$1"; _want_head="$2"; _wait="$3"
  case "$_pr" in ''|*[!0-9]*) echo "bad PR number '$_pr'" >&2; return 1 ;; esac
  _start="$(date +%s)"
  while :; do
    _row="$(gh api "repos/$GH_REPO/pulls/$_pr" --jq '[.state, (.merged | tostring), (.merge_commit_sha // "-"), .base.ref, .head.ref, .head.sha, (.head.repo.full_name // "-")] | join(" ")')" || return 1
    read -r _state _merged _merge_sha _base _head _head_sha _head_repo <<EOF
$_row
EOF
    if [ "$_base" != main ] || [ "$_head_repo" != "$GH_REPO" ] || ! printf '%s\n' "$_head" | grep -Eq "$CHAPTER_RE"; then
      echo "PR #$_pr ($_head into $_base) is not a chapter PR; nothing to release"
      return 0
    fi
    if [ -n "$_want_head" ] && [ "$_head_sha" != "$_want_head" ]; then
      echo "PR #$_pr head moved past $_want_head; a later run handles it"
      return 0
    fi
    [ "$_merged" = true ] && break
    if [ "$_state" = closed ]; then echo "PR #$_pr closed unmerged; nothing to release"; return 0; fi
    if [ $(($(date +%s) - _start)) -ge "$_wait" ]; then
      echo "PR #$_pr not merged after ${_wait}s; the hourly sweep handles a later merge"
      return 0
    fi
    sleep "$POLL_SECONDS"
  done

  _tag="${_head#chapter/}"
  _existing="$(tag_commit "$_tag")" || return 1
  if [ -z "$_existing" ]; then
    if [ "$DRY_RUN" = 1 ]; then
      echo "would tag $_tag at $_merge_sha, dispatch pages.yml and release.yml"
      return 0
    fi
    if gh api -X POST "repos/$GH_REPO/git/refs" -f "ref=refs/tags/$_tag" -f "sha=$_merge_sha" >/dev/null; then
      echo "tagged $_tag at $_merge_sha"
      # The merge was made by github-actions, so pages.yml's push trigger did not fire.
      gh workflow run pages.yml --ref main || return 1
    else
      _existing="$(tag_commit "$_tag")" || return 1
      if [ "$_existing" != "$_merge_sha" ]; then
        echo "could not create tag $_tag at $_merge_sha. From a machine with push access:" >&2
        echo "  git fetch origin && git tag $_tag $_merge_sha && git push origin $_tag" >&2
        echo "That tag push starts release.yml." >&2
        return 1
      fi
    fi
  elif [ "$_existing" != "$_merge_sha" ]; then
    echo "tag $_tag already exists at $_existing, not at PR #$_pr's merge commit $_merge_sha; the version was already released" >&2
    return 1
  fi

  if gh api "repos/$GH_REPO/releases/tags/$_tag" --jq .draft 2>/dev/null | grep -qx false; then
    echo "release $_tag is already published"
    return 0
  fi
  _runs="$(gh run list --workflow release.yml --limit 100 --json displayTitle --jq ".[] | select(.displayTitle == \"Release $_tag\") | .displayTitle")" || return 1
  if [ -n "$_runs" ]; then
    echo "release.yml already ran for $_tag; rerun its failed jobs from the Actions tab if it failed"
    return 0
  fi
  if [ "$DRY_RUN" = 1 ]; then echo "would dispatch release.yml for $_tag"; return 0; fi
  gh workflow run release.yml --ref main -f "tag=$_tag" || return 1
  echo "dispatched release.yml for $_tag"
}

sweep() {
  _since=$(($(date +%s) - 172800))
  _prs="$(gh api "repos/$GH_REPO/pulls?state=closed&base=main&sort=updated&direction=desc&per_page=50" \
    --jq ".[] | select(.merged_at != null and (.merged_at | fromdateiso8601) >= $_since) | .number")" || return 1
  _fail=0
  for _n in $_prs; do
    handle_pr "$_n" "" 0 || _fail=1
  done
  return "$_fail"
}

: "${GH_REPO:?GH_REPO not set}"
command -v gh >/dev/null 2>&1 || { echo "release-on-merge: gh not found" >&2; exit 1; }
MODE="${1:-}"
[ $# -gt 0 ] && shift
PR=""
HEAD_SHA=""
WAIT=0
case "$MODE" in
  pr) [ $# -gt 0 ] || usage; PR="$1"; shift ;;
  sweep) ;;
  *) usage ;;
esac
while [ $# -gt 0 ]; do
  case "$1" in
    --head-sha) [ $# -ge 2 ] || usage; HEAD_SHA="$2"; shift 2 ;;
    --wait) [ $# -ge 2 ] || usage; WAIT="$2"; shift 2 ;;
    --dry-run) DRY_RUN=1; shift ;;
    *) usage ;;
  esac
done
case "$WAIT" in ''|*[!0-9]*) usage ;; esac
if [ "$MODE" = pr ]; then handle_pr "$PR" "$HEAD_SHA" "$WAIT"; else sweep; fi
```

Notes for the implementer:

- `$_tag` is interpolated into a jq string only after `CHAPTER_RE` validated `_head`, so it holds
  only `v`, digits and dots.
- The release run lookup matches `run-name: Release <tag>` (§4.4). Keep the two strings identical.
- "Fail if tag exists" (SPEC): a tag at a *different* commit fails. A tag already at this merge
  commit is this script's own earlier work (two entry points fired), so that case continues to the
  dispatch check instead of failing.

Workflow:

```yaml
name: Release on merge

# P330: tags a merged chapter PR's squash commit (vX.Y.Z from chapter/vX.Y.Z) and dispatches
# release.yml (docs/PACKAGING.md §7). Auto-merge merges as github-actions, and GitHub starts no
# workflow from that merge's events, so pull_request: closed alone would miss it. Four entry points
# share one idempotent script: workflow_run (PR CI green, then wait for the merge), closed (a human
# merge), an hourly sweep (whatever both missed), and a manual dispatch.
on:
  workflow_run:
    workflows: [PR]
    types: [completed]
  pull_request:
    types: [closed]
    branches: [main]
  schedule:
    - cron: '17 * * * *'
  workflow_dispatch:
    inputs:
      pr:
        description: Merged PR number; empty sweeps PRs merged in the last 48h
        required: false
        type: string

permissions: {}

# One at a time: two entry points can fire for one merge.
concurrency:
  group: release-on-merge
  cancel-in-progress: false

jobs:
  release:
    if: >-
      (github.event_name == 'workflow_run' && github.event.workflow_run.conclusion == 'success' &&
       github.event.workflow_run.event == 'pull_request') ||
      (github.event_name == 'pull_request' && github.event.pull_request.merged &&
       github.event.pull_request.head.repo.full_name == github.repository) ||
      github.event_name == 'schedule' || github.event_name == 'workflow_dispatch'
    runs-on: ubuntu-latest
    timeout-minutes: 20
    permissions:
      actions: write
      contents: write
      pull-requests: read
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7
        with:
          ref: main
          sparse-checkout: scripts
          persist-credentials: false
      - name: Tag and dispatch the release
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          GH_REPO: ${{ github.repository }}
          EVENT: ${{ github.event_name }}
          PR_NUMBER: ${{ github.event.pull_request.number || github.event.workflow_run.pull_requests[0].number || inputs.pr }}
          HEAD_SHA: ${{ github.event.workflow_run.head_sha }}
        run: |
          set -eu
          case "$EVENT" in
            workflow_run)
              [ -n "$PR_NUMBER" ] || { echo "run has no PR; nothing to release"; exit 0; }
              sh scripts/release-on-merge.sh pr "$PR_NUMBER" --head-sha "$HEAD_SHA" --wait 600 ;;
            pull_request)
              sh scripts/release-on-merge.sh pr "$PR_NUMBER" ;;
            *)
              if [ -n "$PR_NUMBER" ]; then
                sh scripts/release-on-merge.sh pr "$PR_NUMBER"
              else
                sh scripts/release-on-merge.sh sweep
              fi ;;
          esac
```

`ref: main` is literal: a `schedule` payload carries no `repository` object. `workflow_run` and
`schedule` workflows run only from the default branch's copy.

Bootstrap (v0.2.12's own merge): when `pr.yml` completes, `release-on-merge.yml` is not on `main`
yet, so `workflow_run` has nothing to start. A bot merge raises no `closed` run. The hourly sweep
runs from `main` once the merge lands, and releases v0.2.12 within the hour. Tag creation may hit
the workflow-permission refusal (§0); the job log then prints the manual commands.

### 4.5 `docs/pending-workflows/pr-rerun-flaky.yml` (new)

```yaml
name: PR flake rerun

# P330: reruns a failed PR CI run's failed jobs, up to 3 attempts in all. A cancelled run (a newer
# push superseded it) is never retried.
on:
  workflow_run:
    workflows: [PR]
    types: [completed]

permissions: {}

jobs:
  rerun:
    if: >-
      github.event.workflow_run.conclusion == 'failure' &&
      github.event.workflow_run.run_attempt < 3 &&
      github.event.workflow_run.event == 'pull_request'
    runs-on: ubuntu-latest
    timeout-minutes: 5
    permissions:
      actions: write
      pull-requests: read
    env:
      GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
      GH_REPO: ${{ github.repository }}
      RUN_ID: ${{ github.event.workflow_run.id }}
      HEAD_SHA: ${{ github.event.workflow_run.head_sha }}
      PR: ${{ github.event.workflow_run.pull_requests[0].number }}
    steps:
      - name: Rerun failed jobs when the run is for the PR's current head
        run: |
          set -eu
          [ -n "$PR" ] || { echo "run has no PR; not retrying"; exit 0; }
          # A rerun re-enters pr.yml's cancel-in-progress group: rerunning a stale head would cancel
          # the current head's run.
          CURRENT="$(gh api "repos/$GH_REPO/pulls/$PR" --jq 'if .state == "open" then .head.sha else "" end')"
          [ "$CURRENT" = "$HEAD_SHA" ] || { echo "run is not for PR #$PR's open head; not retrying"; exit 0; }
          gh run rerun "$RUN_ID" --failed
```
