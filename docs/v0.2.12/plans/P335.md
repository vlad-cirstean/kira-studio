# P335: SQL grid: context-menu "Copy as" with multiple rows selected

Planner: Opus. Implementer: one Sonnet subagent, sequential. Base: `149129bfe`.

No split. Both grids route through one new shared module. The console fix depends on its API. The
data grid change touches the same API. One implementer, commit groups in §8.

UI only. No bound call is involved, so no backend flow half (SPEC row, CLAUDE.md test rule).

## 0. Which grid, what exists (CodeGraph findings)

"Copy as CSV" / "Copy as JSON" (`studio.copy.asCsv.label`, `common.action.copyAsJson.label`) appear
in two places only: the query console's tabular result grid and single-cell menus. The data grid's
multi-row menu says "Copy rows ▸ TSV/CSV/JSON/Insert statements" instead. So the reported grid is
`apps/kira-studio/frontend/src/views/console/ConsoleSlickGrid.vue` (SQL query results).

Console grid today:

- `currentSelection` (page-row space) is set by `onSelectedRangesChanged` from
  `selectionFromRanges` (`views/shared/slick/selection.ts`). Kinds: `cell`, `range`, `row`, `column`.
- Keyboard: `onKeydown` → `onCopy()` branches on all four kinds. `row` →
  `rowsToTsv(sel.rows.map(rowSnapshotFor))`.
- Right-click: `onGridContextMenu`.
  - Gutter (`hit.cell === 0`): `tabularRowMenu` for `sel.rows` if `sel.kind === 'row'` and it holds
    the row, else `[pageRow]`. The selection is not moved.
  - Body: a `range` covering the hit → `tabularRangeMenu`. A `column` covering it →
    `tabularColumnMenu`. **Anything else, `row` included → `tabularCellMenu` for the clicked cell.**
- Menu builders in `views/console/menu.ts` (`tabularCellMenu`, `tabularRangeMenu`,
  `tabularRowMenu`, `tabularColumnMenu`). Each formats its own text again (`columnsToTsv`,
  `rangeSnapshots` + `rowsToCsv/rowsToJson`, `rowsToTsv/Csv/Json`). Only `ConsoleSlickGrid.vue`
  imports them.
- `onCopy` cell kind writes raw `dc.text`; the data grid's cell copy writes `tsvField(dc.text)`.

Data grid today (`views/grid/SlickGridHost.vue`, `views/grid/menu.ts`):

- `onCopy()` has the same four branches, through `displayCell` / masked `rowSnapshot`, with a bare
  `void copyText(...)` (a rejection is unhandled and silent).
- `onCellContextMenu`: outside the selection → `setActiveCell` (selection becomes the cell) →
  `cellMenu`. Inside a non-cell selection → `rowMenu` over `rowsForSelection(...)`.
- `onGutterContextMenu`: `rowMenu` over `sel.rows` or `[row]` after `setActiveCell(row, 0)`.
- `rowMenu`'s `copy-rows-tsv` prints `shortcut: 'grid.copy'` (⌘C). True for a `row` selection.
  False for `range` and `column`: there ⌘C copies only the selected cells, the item copies whole
  rows.

Shared plumbing: `MenuItems.vue` `onItemClick` calls `item.run()` synchronously inside reka's
`MenuItem` `click` handler (`node_modules/reka-ui/dist/Menu/MenuItem.js`). `copyText` is
`navigator.clipboard.writeText`. `copyAndAnnounce` / `copyOrReportError`
(`packages/workbench/src/behaviour/clipboard.ts`) call it before their first `await`.

Other grids: `proto/grid/CheetahProto.vue` (dev prototype, not shipped) already routes `row` kinds
to its `rowMenu`. Documents, key-value and stream views (`documents/menu.ts`,
`shared/keyvalue/menu.ts`, `stream/menu.ts`, `ConsoleResultGrid.vue` document/kv branches) select one
row at a time and share no tabular menu code. None changes.

## 1. Reproduction and root cause

Repro (scratch WebKit spec, `project ui`, real `navigator.clipboard.writeText` wrapped by a
pass-through recorder that logs each resolved or rejected write; console result `a,b` = `1,2 / 3,4 /
5,6`):

| Step | Clipboard write |
|---|---|
| Gutter click row 0, Shift+click row 1, ⌘C | `ok "1\t2\n3\t4"` |
| Same selection, right-click body cell (0,0) | menu = `copy`, `copy-with-header`, `copy-as-json` (cell menu) |
| → Copy as JSON | `ok "\"1\""` (one cell, not the rows) |
| Shift-click range (0,0)-(2,1), right-click inside → Copy as CSV | `ok "1,2\r\n3,4\r\n5,6"` |
| Gutter rows 0-2, right-click gutter → Copy rows ▸ CSV | `ok "1,2\r\n3,4\r\n5,6"` |

Same recorder on the data grid (`bigRowsFixture`, columns `id, hash`):

| Step | Clipboard write |
|---|---|
| Gutter rows 0-1, ⌘C | `ok "1\tc4ca…\n2\tc81e…"` |
| Same, right-click body cell → Copy rows ▸ CSV | `ok "1,c4ca…\r\n2,c81e…"` (correct) |
| Range `id` (0)-(2), ⌘C | `ok "1\n2\n3"` |
| Same, right-click inside → Copy rows ▸ TSV (prints ⌘C) | `ok "1\tc4ca…\n2\tc81e…\n3\teccb…"` (whole rows) |

Data grid rows work. Its drift is the ⌘C hint on a range or column selection.

Root cause: `onGridContextMenu`'s body branch has no `row` case. A row selection made in the gutter,
then right-clicked on a cell, falls through to `tabularCellMenu`. Every copy item there writes the
clicked cell only. On a NULL cell "Copy" writes `''`, which reads as "nothing on the clipboard". The
selected rows never reach the clipboard from the menu. The highlight still shows the rows, so the
menu acts on something other than what is shown.

Ruled out, with evidence:

- Selection loss on menu open: the range case kept its selection; right-click is not a drag
  (`slick.interactions.ts` ignores `button !== 0`).
- User gesture / async clipboard: every menu write above resolved in real WebKit. Text is built
  synchronously inside the click handler before `writeText`.
- Empty range: the range branch copies the right rows.

Underlying cause: keyboard and menu are two code paths per grid. `onCopy` decides "what does this
selection copy" from the selection kind. The menu decides it again from the hit and a subset of
kinds. Each menu builder re-formats text. The two drifted (missing `row` case; console cell copy
skips `tsvField`; data grid `copy-rows-tsv` prints ⌘C where ⌘C differs).

Step 0 for the implementer (before any fix): write the spec from §5, run it on the unchanged tree,
and confirm it fails on exactly the rows marked "fails before". If any other row fails, stop and
report it: the root cause above is then incomplete.

## 2. Shared module: `views/shared/slick/selectionCopy.ts` (new)

Lives in `views/shared/` because `views/console/**` may not import `views/grid/**` (biome).

```ts
export type CopyFormat = 'tsv' | 'csv' | 'json' | 'insert';

export interface InsertTarget {
  qualifiedName: string;
  dialect: SqlDialect | undefined;
}

export interface CopySource {
  /** Displayed cell (masking-aware in the data grid). */
  cellAt(row: number, col: number): { text: string; isNull: boolean };
  /** Whole row in display column order (masked in the data grid). */
  rowSnapshot(row: number): RowSnapshot;
  /** Display names for display columns, before disambiguation. */
  columnName(col: number): string;
  /** Visible page rows in [r0, r1] under the active filter. */
  rowsInSpan(r0: number, r1: number): number[];
  /** Every visible page row (column-scoped ops). */
  allRows(): number[];
  insertTarget?: InsertTarget;
}

/** Text for already-built row snapshots. The one formatter switch. */
export function rowsText(rows: RowSnapshot[], format: CopyFormat, target?: InsertTarget): string;

/** What `selection` copies as `format`. The one "selection to clipboard text" function. */
export function selectionText(sel: Selection, format: CopyFormat, src: CopySource): string;
```

Rules (current output, kept byte for byte, except the console cell `tsvField` fix):

- `cell`: `tsv` → `isNull ? '' : tsvField(text)`. `json` → `JSON.stringify(isNull ? null : text)`.
  `csv` → same as a 1x1 `range`. `insert` → same as a one-row `row`.
- `range`: rows = `rowsInSpan(anchorRow, row)`, cols = `anchorCol..col`. `tsv` → `columnsToTsv`.
  `csv` / `json` → snapshots of those cols keyed by `disambiguateNames(cols.map(columnName))`, then
  `rowsText`. Moves `rangeSnapshots` out of `console/menu.ts`.
- `column`: same as `range` with rows = `allRows()`, cols = `sel.cols`.
- `row`: `rowsText(sorted unique sel.rows.map(rowSnapshot), format, src.insertTarget)`.
- `range` / `column` with `insert`: same as `row` over the covered rows (whole rows).
- `insert` needs `insertTarget`; `rowsText` throws without it. Only the data grid offers `insert`
  and always passes one.

`rowsText` and `selectionText` stay synchronous and never await: WebKit only grants
`writeText` inside the user gesture. Add a one-line comment saying so.

No unit test: a switch over four kinds and four existing formatters. The UI spec covers every
kind x format pair on the real clipboard.

## 4. Console grid (`ConsoleSlickGrid.vue`, `views/console/menu.ts`)

### 4.1 One target selection

`menuTarget(hit): Selection` in `ConsoleSlickGrid.vue`, the rule the data grid already follows:

- Gutter hit: `currentSelection` if it is `row` kind and holds the row; else `{ kind: 'row', rows:
  [pageRow] }` and select that row first (`grid.setActiveCell(pos, 0, false, false, false)`, as
  `SlickGridHost.vue`'s `onGutterContextMenu`).
- Body hit: `currentSelection` if `selectionCovers(currentSelection, pageRow, displayCol)` (covers
  `row`, `range`, `column`); else `{ kind: 'cell', … }` and select that cell first
  (`setActiveCell(pos, displayCol + 1, …)`).

Then build the menu by `target.kind`:

| Kind | Builder | Items (ids unchanged) |
|---|---|---|
| `cell` | `tabularCellMenu` | `copy`, `copy-with-header`, `copy-as-json` |
| `range` | `tabularRangeMenu` | `copy`, `copy-as-csv`, `copy-as-json` |
| `row` | `tabularRowMenu` | `copy-rows` ▸ `copy-rows-tsv`, `copy-rows-csv`, `copy-rows-json` |
| `column` | `tabularColumnMenu` | `copy-column`, `copy-column-name` |

The header right-click (`onGridHeaderContextMenu`) keeps its no-selection-change rule and builds
`tabularColumnMenu` for `{ kind: 'column', cols: [displayCol] }`.

### 4.2 Builders take text, not data

- Every builder context replaces `rows` / `cols` / `cellAt` / `snapshots` / `text` / `isNull` with
  `copy: (format: CopyFormat) => string`. The grid passes `(f) => selectionText(target, f, src)`.
  `copy-with-header` keeps `columnName` plus `copy('tsv')` output for its body line. Column menu keeps
  `columnName`.
- `copy-column` uses `copy('tsv')`, so a multi-column selection copies every selected column, same
  as ⌘C (today it copies only the clicked one).
- Row snapshots stay lazy and memoized for the row menu: `src.rowSnapshot` is cheap per row, but
  `copy` must not run at menu build. Memoize per menu instance in the grid (`let cached`), same shape
  as today.
- `onCopy()` becomes `selectionText(currentSelection, 'tsv', copySource())` through the same
  `copyOrReportError(text, onCopyError)`.
- Delete `rangeSnapshots` and now-unused imports. `bun run lint:dead` (knip) must stay clean.

## 7. Open questions, recommended defaults

- Q1. Console right-click outside the selection: select the clicked cell/row first (like the data
  grid), or leave the highlight? **Default: select first.** Otherwise the highlight and the menu
  disagree, which is this bug's own shape.
- Q2. Keyboard copy now announces through the live region and reports a rejection, where the data
  grid was silent. **Default: yes**, same runner as the menu; the announce is screen-reader only.
- Q3. Data grid range/column right-click: keep `rowMenu` (whole rows, prior user-reported fix) or add
  console-style "Copy / Copy as CSV / Copy as JSON" over the selected cells? **Default: keep
  `rowMenu`**, fix only the misleading ⌘C hint. A cell-level "Copy as" there is a feature, not this
  bug; raise it as a follow-up row if wanted.
- Q4. Console `copy-column` on a multi-column selection copies every selected column. **Default:
  yes**, it then equals ⌘C.
- Q5. Run the new spec in Chromium as well as WebKit. **Default: yes**; Chromium is the only
  Playwright engine that reads the real clipboard. If `ui-clipboard` proves flaky in parallel (one
  OS clipboard per browser context is isolated in headless Chromium; verify), set its `workers: 1`.
