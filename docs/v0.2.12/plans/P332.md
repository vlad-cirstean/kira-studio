# P332: Kira Space as default app for code and data files

Planner: Opus. Implementer: one Sonnet subagent, sequential. Base: `537310cab` (P331 result).

No split. Both halves share one extension vocabulary, one `Info.plist` change and one window path.
The settings half alone is one service plus one pane; it cannot ship before the open half.
Commit groups in §9 keep history legible.

## 0.1 Wails v3.0.0-beta.28 behaviour (read from module source)

- macOS: `AppDelegate application:openFile:` calls `HandleOpenFile`, which queues
  `events.Common.ApplicationOpenedWithFile`; `ApplicationEventContext.Filename()` returns the path.
  Wails implements only `openFile:` (singular). AppKit then calls it once per file for a multi-file
  open.
- Cold start: LaunchServices delivers the open as an Apple Event after launch; the file is not in
  argv. Listeners registered before `app.Run()` receive it.
- Running app: LaunchServices routes the open to the running instance (one process per bundle). No
  second process, so the single-instance lock is not involved.
- Linux/Windows: Wails reads `os.Args[1]` only at startup and only for extensions listed in
  `Options.FileAssociations`. Kira Space has no Linux/Windows package, and its lock makes a second
  process exit. Out of scope (§8).
- Generator template emits one `CFBundleDocumentTypes` entry per extension, with
  `CFBundleTypeExtensions` only. No `LSItemContentTypes`, `LSHandlerRank` or
  `UTImportedTypeDeclarations`, so it cannot carry this design (§2).

## 1. Extension vocabulary

One Go table, `apps/kira-space/internal/filetypes/filetypes.go`: `Entry{Ext, Group, UTI, Imported,
ConformsTo, Description}`. It is the single source for the plist generator, the open-path filter and
the settings service. The frontend gets it from the bound `Status` call; no TS copy.

Code group (`code`):
`ts tsx mts cts js jsx mjs cjs vue svelte py go rs java kt kts swift c h cpp cc cxx hpp m mm rb php
pl lua sh bash zsh sql graphql gql proto css scss less md markdown`.

Data group (`data`):
`json jsonc jsonl ndjson yaml yml toml xml csv tsv ini cfg conf log`.

UTIs: use the system identifier where macOS 14 has one. Examples: `public.json`, `public.yaml`,
`public.xml`, `public.comma-separated-values-text`, `public.tab-separated-values-text`,
`public.python-script`, `public.shell-script`, `public.bash-script`, `public.zsh-script`,
`public.swift-source`, `public.c-source`, `public.c-header`, `public.c-plus-plus-source`,
`public.c-plus-plus-header`, `public.objective-c-source`, `public.objective-c-plus-plus-source`,
`public.ruby-script`, `public.php-script`, `public.perl-script`, `com.netscape.javascript-source`,
`com.sun.java-source`, `public.css`, `com.apple.log`, `net.daringfireball.markdown`.
Every other extension gets an imported declaration (`Imported: true`) under a reverse-DNS id the
community already uses where one exists (for example `com.microsoft.typescript`,
`org.golang.go-source`), else `com.kirathecat.kira-space.<ext>`. Each conforms to
`public.source-code` (code) or `public.plain-text`/`public.data` (data).
Imported, never exported: an app that exports the type wins, which is correct.

Excluded, with reason in a code comment:
- `html`, `htm`: the system browser default. The read-only source view is a worse default.
- `txt`, `rtf`: plain prose, not code or data.
- `.env`, `Dockerfile`, `Makefile`: no extension to associate.
- `sqlite`, `db`: binary; Kira Studio's domain; the viewer would show "binary".
- `ipynb`, `parquet`, `xlsx`: no viewer here.

Extensions not already in `codeworkspace.languageFor` (`kt kts swift c h cpp cc cxx hpp m mm rb php
pl lua jsonl ndjson csv tsv conf log`) render as plain text unless the frontend
`views/repo/language.ts` already maps them. Check that file; add a Monaco built-in language id where
one exists (Monaco ships `kotlin`, `swift`, `cpp`, `objective-c`, `ruby`, `php`, `perl`, `lua`).
Mirror any addition in `languageFor` so the wire field stays truthful.

## 3. Receiving an external open

### 3.1 Backend: `apps/kira-space/internal/openedfiles`

- `Coalescer`: `Add(path)` buffers; one batch flushes 300 ms after the last `Add`. AppKit sends a
  multi-file open as back-to-back `openFile:` calls, so one Finder action becomes one window. The
  flush timer comes from an injected `after func(time.Duration, func()) Stop` seam so tests are
  deterministic. `Close()` stops the timer and drops the buffer (teardown).
- `Resolve(path, repos []model.CodeRepo) (Target, error)`:
  `filepath.Abs`, `EvalSymlinks`, `os.Stat`. A regular file is required, and its lower-case
  extension must be in `filetypes`. Find the imported repo by longest `Root` prefix, after running
  `EvalSymlinks` on each root. Hidden repos count: hidden only filters the Git panel list. With a
  match, `RelPath` comes from `codeworkspace.ValidateRelPath`. The file opens in that repo's
  workspace and keeps blame and git context. With no match, `Target{Path}` is a standalone file. A
  git repo that is not imported is never auto-imported (no side effects).
  `Target` wire: `{path, repoId, relPath}` (repo fields empty for standalone).
- `Service`:
  - `Open(paths []string)`: resolve each path. A failure is logged and skipped, with the reason.
    Zero targets means no window. Otherwise mint a key, store `pending[key] = targets`, then call
    the `OpenNewWindowKeyed(key)` seam. Key and pending are registered before the page can boot.
  - `Pending(windowKey) []Target`: take-once. A second call returns empty.
  - `Forget(windowKey)`: wired into `WindowOpenerDeps.OnWindowClosing`. A window closed before its
    page pulled leaks nothing.
  - `Read(path) (codeworkspace.FileContent, error)`: requires an absolute, `filepath.Clean`-stable
    path whose extension is in `filetypes`. Then it runs `codeworkspace.ReadFile(path,
    filepath.Base(path))`.
    Security note (put it in the doc comment): Wails-bound services are reachable only from this
    app's own webviews. The mobile server serves its own route table, and the `-tags server` build is
    test-only. The renderer already holds broader powers (terminals, git writes). The extension
    filter keeps the surface to what this feature opens.
    Do not add a persisted allow-list. It would add a table, and it guards nothing the renderer
    cannot already do.
- Bound wrapper `bridge.OpenedFilesService` with `Pending(args{windowKey})` and `Read(args{path})`,
  plus `ipcerr` mapping. Register it in `Bound()` and update the bound-service count line in
  `docs/ARCHITECTURE.md`.

### 3.2 Shell

- `internal/shell/openwindow.go`: split `OpenNewWindow` into `OpenNewWindowKeyed(d, key)` and
  `OpenNewWindow(d)`, where the second calls `OpenNewWindowKeyed(d, uuid.NewString())`. Behaviour is
  unchanged for both apps' existing callers.
- `appwire.ShellHooks` gets `OpenNewWindowKeyed func(key string)`. `BindShell` hands it to
  `openedfiles.Service`. Flowharness `WindowManager` records keyed opens (`OpenedKeyed []string`).
- `apps/kira-space/main.go`: before `app.Run()`, register
  `app.Event.OnApplicationEvent(events.Common.ApplicationOpenedWithFile, ...)`. It calls
  `wired.OpenedFiles.Add(e.Context().Filename())`. Add `OpenedFiles.Forget` to `winDeps.OnWindowClosing`.
- Cold start restores saved windows as today, then opens the file's new window. This is stated
  behaviour, not a bug. The saved window set is the user's session; the file window is additive.
- Already running, including no windows open (the app stays alive with zero windows): a new window
  opens. Reopen (`AttachReopen`) is not involved, because an open document is `odoc`, not `rapp`.
- Same file opened twice gives two windows. The user asked for a new window per external open.

## 4. Settings: make Kira Space the default

### 4.1 macOS mechanics

- Resolve the live type: `[UTType typeWithFilenameExtension:ext]`. If `isDynamic`, the type is not
  registered (the app was never registered with LaunchServices), and that row is `unavailable`.
- Read the current default: `[NSWorkspace URLForApplicationToOpenContentType:]` (macOS 12+). Read
  name and bundle id from `NSBundle bundleWithURL:`.
- Set: `[NSWorkspace setDefaultApplicationAtURL:toOpenContentType:completionHandler:]` (macOS 12+;
  `LSMinimumSystemVersion` is 14), with the app URL `[NSBundle mainBundle].bundleURL`. The
  deprecated `LSSetDefaultRoleHandlerForContentType` is not used.
- Prompts: Apple documents a confirmation only for the web-browser URL schemes. For content types,
  no prompt is expected. That is unverified here (no macOS); see §7 item 4. If one appears, the
  completion handler still reports the user's choice, and the service returns it as-is.
- Undo: macOS has no "unset". Before the first switch of an extension, save the previous handler's
  app path. Turning it off sets that app back. If the app is gone (path missing, or the bundle won't
  load), the extension stays on Kira Space and is reported in `unrestored`. The pane says so and
  names Finder's Get Info > "Open with" > "Change All" as the user's way out.
- Kira Space is not App-Sandboxed (ad-hoc signed), so LaunchServices writes need no entitlement.

### 4.2 Code

- `apps/kira-space/internal/filehandlers`:
  - `Registry` interface (the OS seam): `Resolve(ext) (uti string, dynamic bool)`,
    `Default(uti) (App, error)`, `SetDefault(uti, appPath string) error`, `Self() App`.
    `App{Path, BundleID, Name}`.
  - `registry_darwin.go` (`darwin && cgo && !server`): Objective-C via cgo, as in the existing
    darwin cgo files. `SetDefault` blocks on the completion handler with a 10 s timeout.
    `registry_other.go`: `Unsupported` (every call reports not supported).
  - `Service`: `Status() StatusResult{Supported bool, Groups []Group{ID, Extensions
    []ExtStatus{Ext, UTI, State: self|other|none|unavailable, Handler *App}}}`.
    `Set(args{Exts []string, On bool}) SetResult{Unrestored []string}`. With `On`, it saves the
    previous handler (only when no row exists and the current handler is not self), then sets self.
    With off, it restores the saved app, deletes the row on success, and reports `unrestored` on a
    failure. Unknown extensions are refused. Every call re-reads live state; nothing is cached.
- Storage: migration `0045_p332_file_handler_previous.sql` creates
  `file_handler_previous(ext TEXT PRIMARY KEY, app_path TEXT NOT NULL, bundle_id TEXT NOT NULL,
  saved_at TEXT NOT NULL)`. Growth is bounded by the `filetypes` vocabulary (~55 rows max). Add a
  repo `FileHandlerPrevious` (Get/Put/Delete) in `internal/storage/repos`. Update the migration
  high-water line in `docs/ARCHITECTURE.md`.
- Bound `bridge.FileHandlersService{Status, Set}`. `appwire.Options.FileHandlers filehandlers.Registry`
  is an OS seam owned by `main.go`, and nil means `registry_other`. Flowharness gets the option
  `WithFileHandlers(fake)`.
- No settings leaf. LaunchServices is the source of truth. The user can change defaults in Finder,
  so the pane shows the live state, never a stored boolean. It never re-applies on launch, because
  silently undoing a Finder choice would be hostile.

### 4.3 Pane

- New section `'File types'` in `sections`, placed after `'Git'`. Label `space.settings.nav.fileTypes.label`.
- `frontend/src/workbench/settings/FileTypesPane.vue`:
  - `useQuery(['fileHandlers'])` fetches `control.fileHandlersStatus()`. It refetches whenever the
    pane becomes active, because Finder can change defaults while the dialog is closed.
  - `useMutation` runs `fileHandlersSet` and invalidates `['fileHandlers']` on settle.
  - One block per group: a shadcn-vue `Switch` (on = every available extension is self, mixed =
    `aria-checked="mixed"` and the label says "Some"). A `Collapsible` holds a per-extension
    `Checkbox` list with the current handler name ("Kira Space", "Visual Studio Code", "None",
    "Not registered").
  - Not supported (`registry_other` or server build): one `Alert` saying this works only in the
    installed macOS app, with every control hidden.
  - All rows unavailable (dev build run outside `/Applications`, never registered): an `Alert`
    explaining that the app must run once from `/Applications`.
  - `unrestored` non-empty: an `Alert` that names the extensions and the Finder "Change All" path.
  - Tailwind utilities only. Every interactive element gets a `data-testid`.
- i18n under `space.settings.fileTypes.*`.

## 7. User-side items (real Mac; not verifiable from Linux)

1. Build and install the DMG. Run Kira Space once from `/Applications` so LaunchServices registers
   it. `lsregister -dump | grep -A3 kira-space` lists both document types.
2. Finder > a `.go` file > Open With lists Kira Space. Opening it brings up a new window with the
   file. Repeat with the app quit (cold start) and with zero windows open.
3. Select three files of mixed types in Finder > Open With > Kira Space. The result is one new
   window with three tabs.
4. Settings > File types > Code on. Check that no system prompt appears; if one does, note it in
   `docs/ARCHITECTURE.md`. `mdls -name kMDItemContentType x.go` and Finder Get Info show Kira Space as
   the default. Double-clicking opens Kira Space.
5. Turn Code off. The `.go` default returns to the previous app.
6. For each `Imported` UTI, run `mdls -name kMDItemContentType` on a sample file. If it reports
   another app's exported identifier, that row still works through the live `Resolve`. If a row
   shows "Not registered" after step 1, report the extension; the fix is to the table's UTI.

## 8. Out of scope (state in `docs/ARCHITECTURE.md`)

- Linux and Windows. No package exists. The single-instance lock would drop a second process's argv,
  and forwarding it needs Wails `SingleInstance` plus `.desktop`/`mimeapps.list` and registry
  writes, none of which this repo ships.
- Folders dropped on the Dock icon (no `public.folder` doc type).
- Editing, saving and live reload of an opened file. The viewer is read-only by design (`RepoFileView`
  §11).
- A CSV or table view for data files. They open as highlighted text.
- Auto-importing an un-imported git repo that contains the opened file.
