## Decisions

### 1. Drop same-day delimiters

- Delete the `Separator` element and its import in `AdeDayBand.vue`. Keep the `v-for` over cards.
- Keep spacing rhythm without a line: cards after the first get `mt-2` (fallthrough class on `AdeTaskCard`'s root, `:class="i > 0 ? 'mt-2' : undefined"`). Drop-area `gap-2` plus `mt-2` = 16px between cards, close to the old 17px (8 + 1 + 8). Other rows in the drop area (history, overdue, overflow, spans) keep `gap-2`.
- Why not raise the container gap: `dropEl` children must stay direct children for SortableJS (`draggable: '[data-ade-task]'`), so no wrapper; a container-wide `gap-3` would also spread history and span rows, which nobody asked for.
- Band-to-band `border-t` lines (`AdeDayBand.vue:103`) stay: those separate days, not tasks in one day.

### 2. Board background = terminal ground

- Reuse `--kira-bg-chrome` via `bg-chrome`. No new token, no new colour.
- `AdePlanView.vue:321`: `cn(paneFrame, 'relative flex-1 overflow-auto bg-chrome')`. `cn` is tailwind-merge, so `bg-chrome` replaces `paneFrame`'s `bg-bg`; frame border and radius stay. Do not edit `paneFrame` itself (every pane uses it).
- `AdePlanView.vue:330` sticky header: `bg-bg` to `bg-chrome`, so scrolled content does not show a lighter strip.
- `AdeDayBand.vue:80` ruler dot hollow fill: `bg-bg` to `bg-chrome` in both branches, so a hollow dot still reads as hollow.
- Weekend and day-off bands (`rowBgClass`): the `bg-chrome` tint is now the board colour and would vanish. Drop the tint (`rowBgClass` and its binding removed). Greyed days stay marked by what already carries it: `text-disabled` label and sub, `border-r-border` ruler, muted dot, compact empty height (`min-h-4`), and day-off strike-through. Not a lighter tint: weekend bands accept drops, and a band lighter than the board would put cards back on a near-identical ground.
- Scope: Plan pane only. Panel (`AdePanel`), Backlog, Archived and other panes keep `bg-bg`. `AdeHistoryBar` (`bg-elevated`) and repo chips (`bg-elevated` when shown) stay; both now contrast more, not less.
- Light mode: none exists. Every class above resolves through `--kira-*`, so a future light `:root` flips the board with no `ade` edit. ARCHITECTURE "No light theme" item stays open, unchanged.

### 3. Tasks distinguishable, palette kept

- Palette (`palette.ts`, 20 slots) unchanged. Server slot assignment (`insertTask`: first unused slot, else least used) unchanged, so neighbours already get different colours; the board just has to show them.
- Card fill stays `bg-elevated` (#202020). On `bg-chrome` (#181818) that is a visible step instead of a 1-step tie. Edge stays 1px `border-badge`: est. 2.9:1 against #181818 (was 2.7:1 against #1f1f1f).
- Add a task-colour left edge: `AdeTaskCard.vue` `Card` gets `border-l-3` plus `:style="{ borderLeftColor: card.color }"`. Same inline-style mechanism the head dot already uses (`AdeTaskCard.vue:148`), so no new literal and `check-ade-colours.sh` stays green. Every slot is a mid-to-light hue on #181818, est. well above 3:1 (WCAG 1.4.11 non-text); no measurement needed, it would not change the decision.
- Border, not an absolute rail span: a border shifts card content right by its width, so nothing in the head (dot, step segments) is overlapped. The selected state's `border-focus` colours top/right/bottom; inline `borderLeftColor` keeps the left edge in task colour, and `ring-1 ring-focus` still frames the whole card. Do not touch `boxClass`'s selected/ripple entries or head focus styles: P402 owns the click border flash.
- Parked card: fill `bg-bg` to `bg-chrome` (`boxClass`), so a parked card stays hollow against the board, same as its hollow dot. Its left edge keeps task colour (identity), title stays `text-muted-foreground`.
- Review cards get the same edge (same `Card`).
