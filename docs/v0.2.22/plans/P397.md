# P397 Task repos and branches: add, edit and delete independently

Spec row: "A task can add repos and branches. Add edit and delete for both. Today, a repo added without a branch cannot get a branch added later; fix that."

Base: `967bdb7` (P396 landed). Discovery via `codegraph_explore` (AddTaskRepo, AddBranch, attachExistingBranch, ensureWorktree, claimBranchName, RequestBranch, ArchiveTask/branchRisk, SetBranchBase, AdeTaskTab.vue, AdeAddPopover.vue, queries.ts).

## Current model

- One table holds both concepts. `ade_task_branches` row = one repo on a task; `name = ''` means "branch not created" (migration 0008). Unique index `ade_task_branches_live_name (code_repo_id, name) WHERE name <> '' AND archived_at IS NULL`.
- Store `AdeTaskRepo.AddBranch` (`internal/storage/repos/adetask.go:403`) refuses a second live row for the same repo on a task: `ErrRepoOnTask`.
- Add repo: `TaskBoard.AddTaskRepo` (`internal/ade/board_writes.go:214`) inserts a not-created `mine` row. UI: `NativeSelect` `ade-add-repo` in `frontend/src/ade/v2/panel/AdeTaskTab.vue`.
- Add branch: `TaskBoard.AddExistingBranch` / `attachExistingBranch` (`board_writes.go:318,361`) always calls `AddBranch` with a new row. UI: `+ Add branch` opens `AdeAddPopover.vue` (attach mode) listing `CandidateBranches` across all repos.
- Naming a not-created row happens only at launch: `ensureWorktree(…, wanted)` (`internal/ade/setup.go:136`) via `claimBranchName`, from `StartRun.branchNames`, `launchGate` or the agent's `RequestBranch` (`internal/ade/agenttools.go:285`).
- Edit today: only `SetBranchBase` (base of a not-created row, `internal/ade/base.go:148`). Delete today: none. Rows leave only through `ArchiveTask` (whole task).

## Root cause of the bug

Repo added without a branch = live row with `name = ''`. Attaching an existing branch for that repo goes through `AddBranch`, which sees the live row and returns `ErrRepoOnTask` ("repo already on task"). Nothing fills the existing row with an existing branch. A new branch name can only be given at Start. So the row can never get a branch from the task panel.

## Design

Keep one row per repo per task (the run engine, board facts and the Space tools all assume it). Repo and branch ops act on that row.

Operations (all for `mine`/`parked` rows of a live, non-review task):

| Op | Row state | Effect |
|---|---|---|
| Add repo | — | existing `AddTaskRepo`, unchanged |
| Edit repo | not created | swap the repo; base resets to the new repo's main. Base edit stays `SetBranchBase` |
| Delete repo | any | detach the row, no replacement |
| Add branch | not created | fill the row: attach an existing git branch, or create a new named branch now |
| Edit branch | created | replace the row's branch with another existing branch or a new name |
| Delete branch | created | detach the branch; a not-created row for the same repo takes its place (repo stays) |

Rules:

- Git refs are never renamed or deleted by these ops. "Delete branch" removes the task link and the ADE linked worktree only. Rename of a created branch is out of scope (pushed refs and PRs would diverge).
- Detach primitive (one store transaction): a row never created and with no runs is hard-deleted; any other row gets `archived_at = now` so its runs, reviews, marks and setup rows stay as history (P399 relies on history staying). A replacement row, when given, takes the old row's `position`.
- Dependents: live rows with `base_branch_id = old.id` get `base_branch_id = ''` and `base = old.name` when created (ref still in git), else `old.base`; `base_pending_from` cleared. Rows with `queued_after = old.id` get `queued_after = ''`.
- Guards before any detach (under `taskMu`): `checkNotArchiving`, task kind not review, row kind not review, no running TUI session on the row (`runningTUI`), no pending launch (`tracker().hasPending`), `checkNoBackgroundRun` (run or rebase in the worktree). Refusals go through `invalid(...)` so the bridge maps them to BadRequest with readable text.
- Worktree: when the row has a linked worktree (`linkedBranches` logic), `branchRisk` first; refuse when `Blocked`; else `removeWorktree` (discards dirty files). The UI asks first through a risk read, same pattern as Archive (`ArchiveRisk` then `ArchiveTask`).
- Edit branch validates the target before detaching (existing branch found in inventory and not on a live task, or new name passes the name check and is free), so a refusal changes nothing. A git failure after detach leaves a valid not-created row plus the error, same contract as `RequestBranch`.
- `AddExistingBranch` with a `taskId` whose task has a live not-created row for that repo fills that row through the same path (replacement row, worktree prepared via `prepareAttached`). The existing `+ Add branch` popover then works for the bug case with no UI change. A created row for that repo still returns `ErrRepoOnTask`.

## Backend changes

### Store — `apps/kira-space/internal/storage/repos/adetask.go`

1. `DetachBranch(id string, replacement *model.AdeTaskBranch, now int64) error`, one tx:
   - load the row joined to a live task; `ErrBranchMissing` if absent or archived.
   - count runs with `branch_id = id` (`ade_runs`); delete when `name = ''` and no runs, else set `archived_at`.
   - re-point dependents per the rule above.
   - when `replacement != nil`: set `replacement.Position = old.Position`, `insertTaskBranch` (unique-name violation maps to `ErrBranchOnTask`).
2. No migration needed: soft delete reuses `archived_at`; the unique index already excludes archived rows.
3. Note: `BranchesArchived` returns rows of archived tasks only. Rows detached from a live task are not listed anywhere live. That is the intended "deleted" view; P399 owns archived-data display.

### Engine — new file `apps/kira-space/internal/ade/taskbranches.go`

- `editableRow(tc *taskCtx, branchID string) (model.AdeTaskBranch, error)`: the guards above.
- `detachRow(ctx, tc, sb, replacement *model.AdeTaskBranch) error`: worktree risk check, `removeWorktree`, `Tasks.DetachBranch`.
- `TaskBranchRisk(ctx, branchID) (adewire.BranchRisk, error)`: `branchRisk` of the row's linked worktree; a row with no worktree returns an empty risk (`Dirty: []`, `Unmerged: 0`).
- `SetTaskBranch(ctx, args adewire.SetTaskBranchArgs) (adewire.Branch, error)`: add (not-created row) or edit (created row).
  - `Existing: true`: resolve via `BranchInventory`/`resolveQueuedRef`, refuse when on a live task, kind via `resolveKind` (parked task gives parked). Replacement row has `Name` set; then `prepareAttached` unless review.
  - `Existing: false`: name check, then replacement row `Name: ''` keeping base; then `ensureWorktree(ctx, taskTitle, rec, newRow, args.Name)` and `startSetup` when fresh (copy the `RequestBranch` tail, minus the agent origin mark).
  - Return the wired branch (`repoFacts` like `attachExistingBranch` does).
- `RemoveTaskBranch(ctx, branchID)`: row must be created; replacement = not-created `mine` row, same repo, `Base`/`BaseBranchID` from old.
- `RemoveTaskRepo(ctx, branchID)`: detach, no replacement.
- `UpdateTaskRepo(ctx, args adewire.UpdateTaskRepoArgs) (adewire.Branch, error)`: row must be not created; `requireRepos`; refuse `ErrRepoOnTask` if another live row of the task uses the new repo; replacement row in the new repo with empty base.
- Every write calls `notifyBoard()`.
- Refactor `attachExistingBranch` (`board_writes.go:361`): in the `TaskID != ""` branch, look for a live not-created row of `args.CodeRepoID` on the task; when found, use `DetachBranch(old, &newRow)` instead of `AddBranch`.
- Extract the name rules from `validateAgentBranch` (`agenttools.go:245`) into `checkNewBranchName(ctx, rec, name) (msg string, err error)` (or equivalent) shared by `SetTaskBranch` (wrapped as `invalid`) and the agent tool (wrapped as `agentmcp.ToolError`). Keep the agent's message text byte-identical so the Space tool contract and real `claude` tests are unaffected.

### Wire — `apps/kira-space/internal/bridge/adewire/wire.go` and `frontend/src/ade/v2/wire.ts`

- `SetTaskBranchArgs { BranchID string; Name string; Existing bool }`
- `UpdateTaskRepoArgs { BranchID string; CodeRepoID string }`
- Reuse `BranchArgs` for `RemoveTaskBranch`, `RemoveTaskRepo`, `TaskBranchRisk`; reuse `BranchRisk` as the risk result.

### Bridge — `apps/kira-space/internal/bridge/adetask.go`

`SetTaskBranch`, `UpdateTaskRepo`, `RemoveTaskBranch`, `RemoveTaskRepo`, `TaskBranchRisk`: validate ids with `validateAdeItemID`, `Name` with `validateAdeBranchName`, then `adeTaskError(s.Engine.X(...))`. No new sentinel errors expected. If one is added, give it a catalog key in `adeTaskCatalog` and the copy catalog.

Wiring touchpoints (mirror `SetBranchBase`): `frontend/src/bridge/index.ts`, `tests/ui/support/ipcChannels.ts`, `tests/ui/support/mockRuntime.ts` (channel plus `adeTaskBoardChanged` emit after each write), `tests/ui/support/adeV2.ts` default responses.

Add one line to `docs/ARCHITECTURE.md` beside the AddTaskRepo note (line ~2031): one row per repo; add/edit/delete ops; detach = hard delete when never created and run-less, else archive; git refs never touched.

- Component-local `ref`s hold open state. No new Pinia store: nothing here is shared across components. If the row selection (`ui.selectBranch`) points at a removed row, clear it in `useAdeBoardUiStore` (existing store) when the board no longer lists the id.

## Tests (split at the IPC boundary)

Backend flow test — `apps/kira-space/internal/flows/adeflow/taskbranches_test.go`, using the existing `helpers_test.go` fixture (real temp git repos, as `branching_test.go`/`newtask_test.go`). One scenario:

1. Create task; `AddTaskRepo` repo A (not created).
2. Bug case: `AddExistingBranch{taskId, A, existing}` fills the row: board lists one row for A with that name, no `ErrRepoOnTask`.
3. `RemoveTaskBranch`: A row back to not created; git branch still exists; worktree gone.
4. `SetTaskBranch{existing:false, name}`: branch and worktree created; row named.
5. `SetTaskBranch{existing:true, other}` on the created row (edit): row points at `other`; old worktree removed.
6. `AddTaskRepo` repo B, `UpdateTaskRepo` B to C; `RemoveTaskRepo` C: task lists only A.
7. Refusals: edit while a TUI session runs on A (BadRequest); `UpdateTaskRepo` on a created row; any op on a review task.
8. Run history kept: a row with a run is archived, not deleted (`BranchesArchived` after task archive includes it).

Store unit coverage of `DetachBranch` dependents re-pointing (base_branch_id, queued_after, hard vs soft delete) earns a test per CLAUDE.md (interacting rules): `apps/kira-space/internal/storage/repos/adetask_detach_test.go`, table-driven, small.
