## Design

### Placement

`packages/workbench/src/components/pickers/`. Every caller already imports `@workbench` (git-ui uses `MenuItems`, workbench memory and automations live there, kira-space too). Components are presentational: options come in as props, choice goes out as a model/emit. Each caller keeps its own data source (TanStack Query in kira-space and memory, git-ui's `RefsState`), mapped through a small typed adapter. No Pinia store: open, search and cap state are per-instance and never shared.

Files:

- `pickers/options.ts`: types plus one pure fold.
  - `PickerOption { value: string; label: string; detail?: string; group?: string; keywords?: readonly string[]; disabled?: boolean; reason?: string; labelClass?: string; labelStyle?: StyleValue; mono?: boolean }`
  - `PickerGroup { id: string; label: string }`
  - `foldOptions(options, groups, query, cap)`: filter with `matchesQuery` over `label`, `detail`, `keywords`; keep caller order; bucket by `groups` order (ungrouped first); cap the flat result with the same counting `useCappedList` uses; return `{ sections, hiddenCount, exact }` where `exact` = an option label equals the trimmed query.
- `pickers/PickerCombobox.vue` (internal, not imported outside `pickers/`): shadcn `Command` with `ignore-filter` (see Theme), `CommandInput` bound to `v-model:search`, `CommandList`, one `CommandGroup` per section with `SectionHeading`-style heading, `CommandItem` per option. Disabled option shows `reason` as a visible second line (`text-kira-sm text-muted-foreground`) and as `aria-description`. Optional "custom" item at the top when `custom` prop is set, query non-empty and not `exact`: label from `custom.label(query)`, validated by `custom.validate(query)` (string error = item disabled with that error shown as `FieldError` under the input). `ShowMoreButton` (step = cap, default `REF`-style 50) when `hiddenCount > 0`, reset on query change and on open (`watch`). States: `loading` → "Loading…" row; `error` → `FieldError`; empty → `emptyText`. Slot `#top` above the list (ADE link paste). Emits `select(option)` and `custom(text)`. Test ids from one `testid` prop: `${testid}-search`, `${testid}-option-${value}`, `${testid}-custom`, `${testid}-more`, `${testid}-empty`.
- `pickers/ProjectPicker.vue`: `defineModel<string | null>()` (project value), props `projects: PickerOption[]`, `placeholder`, `custom?` ("Use {value}" for free keys), `loading`, `error`, `disabled`, `inline` (list only, no popover), `size` (`kira` | `kira-lg`), `trigger` (`field` | `toolbar`), `testid`. Popover mode: shadcn `Popover` + `PickerTrigger` (`#leading` repo color dot from the chosen option's `labelClass`/`labelStyle`) with `data-testid=testid`, `PopoverContent` `data-testid=${testid}-content`, close on select, `v-model:open` exposed for callers that open from a menu. Inline mode renders `PickerCombobox` only. Group none by default.
- `pickers/BranchPicker.vue`: same shape; props `branches: PickerOption[]`, `groups: PickerGroup[]`, `create?: { validate(name): string | null }` (custom item labeled "Create branch {name}"), `custom?` for any ref or sha ("Use {value}"), `current?` marks one value with a check, `triggerDetail?` (meta text right of the label, BaseSelector's reason), leading `git-branch` icon. Emits `create(name)` besides the model.
- Both pickers: `<script setup lang="ts">`, Tailwind utilities only, no scoped style. Popover from `@theme/components/ui/popover`, focus to the search input on open (`CommandInput` `auto-focus`), Escape and outside click from reka. Long lists capped, never virtualized (ARCHITECTURE "A picker section showing a large set caps with useCappedList plus ShowMoreButton").

### Theme

`packages/theme/src/components/ui/command/Command.vue`: add `ignoreFilter?: boolean` (default false). When true, `filterItems` does not run and every `CommandItem` renders (`isRender` true), and `CommandEmpty` stays hidden. The pickers filter and cap themselves, because the built-in filter runs on rendered text only and cannot see capped-out rows. Mirrors reka `ComboboxRoot`'s own `ignoreFilter`. Existing `Command` users unchanged.

### Adapters (data → options)

- kira-space projects — new `apps/kira-space/frontend/src/repo/state/projectOptions.ts`: `useProjectOptions(exclude?: MaybeRefOrGetter<readonly string[]>)` over `useRepos()` (existing TanStack query). `value = codeRepoId`, `label = nickname || name`, `detail = nickname ? name : path`, color from `useRepoLinksStore().repoColorOf` + `repoText` (same as `AdeCandidateRow`). Returns `{ options, isPending, error }`.
- ADE candidates — new `apps/kira-space/frontend/src/ade/v2/branchOptions.ts`:
  - `candidateOptions(list, repoLabel, now)`: `value = ${codeRepoId}\u0000${name}` (unique across repos), `label = name`, `detail = "<repo> · <ago> · <author|You>"`, keywords repo label + author, `mono: true`.
  - `baseOptions(data: RepoBranches)`: groups `previous`, `main`, `planner`, `branches`; planner `label = name || notCreated text`, `detail = taskTitle`; `!local` → detail "remote"; `reason` from the exclusion code (below). Value encodes `BaseChoice` (`b:<branchId>` or `r:<ref>`, main = `r:`); `baseChoiceOf(value)` decodes.
  - `newBranchError(name)`: `validateRefName` from `@kira/git-core` (already a kira-space dependency), rendered through `renderText`, same as `WorktreeDialog`.
- git-ui refs — new `packages/git-ui/src/lib/refOptions.ts`: `branchOptions(refs: RefsState, { remote: boolean; exclude?: string })` → local group then remote group, `compareNatural` order (same sort `buildRefListSections` used), `mono: true`. `baseCandidateOptions(resolution)` → `suggested` group with reason detail. Groups labels: `common.module.branches.label`, `git.picker.remoteBranches.label`, `git.review.base.suggested.label`.
- memory — `useMemoryProjects()` keys → `{ value: key, label: key, mono: true }`, with `custom` "Use {value}".
- automations — `needs.branches` → `{ value: id, label, disabled, reason: why }`.
