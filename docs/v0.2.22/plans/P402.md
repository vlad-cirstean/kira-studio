# P402 Agents panel: drop tab delimiter, center action buttons, remove click border flash

Spec row: "Remove the grey delimiter between the main tabs (Backlog, Plan) and the rest. Center-align the "type a thought" and "add task" buttons. Remove the white border that flashes on click of a task; it must not appear at all."

User's words: "The agents panel has a grey delimiter between the main tabs (backlog, plan) and the rest. Drop it. Then align to middle the type a thought and add task buttons. Also when clicking on a task there's a white border that appears and then disappears immediately, get rid of it entirely."

Base: `53ceb26` (P401 done). Discovery via `codegraph_explore` (AdeShell, TabsList, TabsTrigger, tabChipVariants, AdeCaptureBox, AdeAddPopover, AdeTaskCard `boxClass`/head, AdeDayBand `useDraggable`), then grep for `h-tabbar`, `SORTABLE_CHOSEN_CLASS`, focus-ring CSS (`tailwind-core.css:189-207`), U76 in `scripts/check-ui-primitives.sh`, and spec selectors. Each cause below was reproduced with a throwaway Playwright spec on the `ui` project (WebKit, mock harness, `openPlan`), 1440x960 viewport; the spec was deleted, not committed.

## Causes, with evidence

### 1. Grey delimiter

`AdeShell.vue:96`: `<nav class="flex h-tabbar shrink-0 items-center gap-0.5 border-b border-border bg-chrome px-1">`. Its `border-b border-border` is a 1px `rgb(43,43,43)` line at y=67. Directly under it, the active pane's `paneFrame` top edge (`packages/theme/src/lib/frames.ts`, `border border-border`) sits at y=68. Pixel probe at x=700: rows 67 and 68 both `(43,43,43)`, so the bar reads as a 2px grey band between the tabs and everything below.

No other line exists in the bar: the probe found no left/right borders on any `nav` child, and `TabsList`/`TabsTrigger` (`packages/theme/src/components/ui/tabs/`) carry none. The delimiter is the nav's `border-b`.

`h-tabbar` users: `AdeShell.vue`, `AdeReviewWindow.vue:98`, `WorkbenchShell.vue:94`. Only `AdeShell` is in scope; the other two keep their border.

### 2. Capture box and Add alignment

Same nav: left `TabsList` (Backlog, Needs you, Plan, Archived), `<span class="flex-1" />`, a `mx-2 flex items-center gap-2` group (`AdeCaptureBox` input, `AdeAddPopover` "Add task"), right `TabsList` (Workflows). The spacer pushes the group right, against Workflows. Probe: nav 6..1434 (centre 720); group 943..1334 (centre 1138.5), 418px right of centre.

Vertically the group is already centred: input and button both 37.5..63.5, centre 50.5, nav content centre 50.5 (34..67). So "align to middle" means horizontal centre of the bar.

`AdeCaptureBox.vue:49` renders its "Added to backlog" note (or an error) in flow beside the input for `TIMING.copiedFeedback` (1500ms). Once the group is centred, that note would widen the group and shift input and button left for 1.5s.

### 3. White border on task click

Not focus. It is SortableJS's chosen class.

- `AdeDayBand.vue:49-58`: `useDraggable(dropEl, { …, chosenClass })` with `chosenClass = SORTABLE_CHOSEN_CLASS` = `'ring-2'` (`packages/workbench/src/behaviour/sortableReorder.ts:9`).
- Sortable adds `chosenClass` to the draggable (`[data-ade-task]` wrapper, `AdeTaskCard.vue:100`) on pointer down (`sortable.esm.js:1302`), before any drag tolerance, and removes it on pointer up (`:1952`).
- `ring-2` sets no ring colour. Tailwind 4 falls back to `currentcolor`; the wrapper's colour is `--kira-fg`.
- Probe, mouse down on `ade-card-head`: wrapper class `flex items-start gap-2 ring-2`, box-shadow `rgb(204,204,204) 0 0 0 2px`. Mouse up: class `flex items-start gap-2`, box-shadow `none`. That 2px light-grey ring around the whole card plus action cells is the flash.
- Same ring on down for `ade-card-title` and `ade-branch-row`: any press inside a card.
- Focus is not involved: on every pointer press `:focus-visible` is false and `outline-style` is `none` (global ring is `:focus-visible` only, `tailwind-core.css:205`). Tab onto the head gives `:focus-visible` true, `outline-style: solid`.
- The selected state (`border-focus ring-1 ring-focus`, blue, `boxClass`) persists after the click; it is selection, not the flash. Card `transition` is `all 0s`, so no animated border either.

`SORTABLE_CHOSEN_CLASS` has no other user (`sortableReorder.ts:92` passes only `ghostClass`).

## Decisions

### 1. Drop the delimiter

`AdeShell.vue:96`: remove `border-b border-border` from the nav. Nothing else. Tailwind preflight is `box-sizing: border-box`, so the nav stays `h-tabbar` tall and panes start at the same y; the tab chips move down 0.5px (centre of a 1px-taller content box). The pane frame's own rounded top edge remains: it is the pane's outline, same as on every other pane in the app, and the gap between bar and pane now reads as the shared `bg-chrome` ground, not a line.

### 2. Centre the capture box and Add

- Nav becomes a 3-column grid: `grid h-tabbar shrink-0 grid-cols-[1fr_auto_1fr] items-center gap-0.5 bg-chrome px-1`. Add `data-testid="ade-shell-bar"` for the spec.
- Left `TabsList`: `class="justify-self-start"`. Right `TabsList`: `class="justify-self-end"`. The middle group keeps `mx-2 flex items-center gap-2`. Delete the `<span class="flex-1" />` spacer.
- Why grid, not flex with two `flex-1` sides: equal `1fr` side columns put the middle column on the bar's true centre whatever the tab widths (left tabs 337px vs Workflows 86px). `1fr` is `minmax(auto, 1fr)`, so on a narrow window a side column grows to its content and the group slides, never overlaps.
- Tabs keyboard behaviour unchanged: both `TabsList`s stay children of the same `Tabs` root; reka's roving focus is per list, as today.
- `AdeCaptureBox.vue`: take the note out of flow so the centred pair never moves. Root `relative flex items-center gap-2`; note `absolute inset-y-0 right-full mr-2 flex items-center whitespace-nowrap bg-chrome text-kira-sm text-muted-foreground`. It shows left of the input, in the empty left column. Not truncated: an error must stay readable; a long one may briefly cover tab chips (opaque `bg-chrome`), acceptable for 1.5s. Keep `data-testid="ade-capture-note"`; `ade-v2-add.spec.ts:24` (`toHaveText`) still holds.

### 3. Remove the click flash: pointer press only, keyboard ring kept

- `AdeDayBand.vue`: delete `chosenClass` from the `useDraggable` options, the `const chosenClass` line and `SORTABLE_CHOSEN_CLASS` from the import. Sortable then uses its default `sortable-chosen`, which no CSS styles (grep: no rule in `apps/` or `packages/`).
- `sortableReorder.ts`: delete `SORTABLE_CHOSEN_CLASS` and its doc comment (dead export; `lint:dead` would flag it).
- `scripts/check-ui-primitives.sh` U76 message: `ghostClass/chosenClass outside sortableReorder.ts (use SORTABLE_GHOST_CLASS; no chosen class)`. Pattern unchanged: it still blocks a hand-set `chosenClass:` anywhere else.
- Scope decision: the flash is a pointer-press artefact, not focus, so the fix touches no focus styling. The keyboard ring (`:focus-visible` outline on `ade-card-head`, title button, branch rows) stays: it is the only focus cue for keyboard users, and a click never shows it (probe: `:focus-visible` false on every pointer press). Removing all focus rings would cost keyboard accessibility for a problem focus does not cause.
- Drag feedback without the ring: the source stays at `opacity-50` (ghost class), the fallback clone follows the pointer, the target band shows `outline-focus` (`AdeDayBand.vue:131`). Enough cue; the ring on the drag clone was the same white border the user wants gone.
- Selected state (`border-focus ring-1 ring-focus`) unchanged: it is persistent, blue, and is the selection marker.

### 4. Docs

`docs/ARCHITECTURE.md:1287` becomes: "The drag ghost class is SORTABLE_GHOST_CLASS (U76). No list sets a chosen class: Sortable's unstyled default keeps a press from flashing a ring." No new open item.
