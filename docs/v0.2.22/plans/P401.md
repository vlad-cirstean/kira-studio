# P401 Task board: 7-day window, Later section, no date control

Spec row: "Show only the next 7 days on the task board, unless work is scheduled later than that. Remove the date control that adds a new week. Work scheduled beyond the window sits in a Later section."

User's words: "Show only 7 days from now on the task board unless I have work scheduled later than that. Remove the date thing, and instead of adding a new week they will just sit in a later section."

Base: `90e8b25` (P400 done). Discovery via `codegraph_explore` (AdeDayControls, AdePlanView, timeline.ts `buildTimeline`/`collectDayKeys`/`buildBand`/`buildHours`/`spansOn`, calendar.ts, dropPlan.ts `dropVerdict`, adeBoardUi, settingsDomain `adeSettingsSchema`, Go `model/settings.go`, AdeHistoryBar, menu.ts `dayMenuFor`, usePlanModel), then grep for `horizonDays`/`extraDays`/`ade-more-week`/`ade-add-day`/`dayControls` and spec selectors.

## What "the date thing" is

`AdeDayControls.vue`. It is the row rendered just above the Later band (`AdePlanView.vue:370-375`, `v-if="band.isLater"`). It holds an `Add week` button (`data-testid="ade-more-week"`) and an `Or choose a date` date input (`ade-add-day`). Evidence:

- Its own comment, line 7: "`Add week` grows the horizon, `Or choose a date` appends one future day."
- i18n `space.ade.plan.dayControls.moreWeek.label` = "Add week", `addDay.label` = "Or choose a date".
- Handlers: `onMoreWeek` adds 7 to `settings.ade.horizonDays` (cap 365). `onPickDate` calls `extendHorizon`, which appends the ISO date to `settings.ade.extraDays`.

The user pairs "the date thing" with "adding a new week". Both live in this one control, so the whole row goes.

Not "the date thing": `AdeHistoryBar.vue`'s `Go to` date input (`ade-go-to-date`). It shows only while scrolled into the history region and navigates, never adds days. It stays. Its future-date path loses `extendHorizon` (below).

## Current state

- Day range = `collectDayKeys` (`timeline.ts:382`): history keys when `showHistory`; `0..horizonDays-1` (default 14), trimmed to `lastShownDay` while the first-10 cap hides items; every day of every shown entry's span; every `extraDays` and `offDays` date from today on; then `LATER` (9999) last, when nothing is hidden or a shown entry is unplanned.
- So today the board shows 14 days, plus any day a task touches, plus picked dates.
- Persisted range state: `settings.ade.horizonDays` and `settings.ade.extraDays`. TS: `settingsDomain.ts` schema (lines 82, 96-101, 108) and both default objects (165-174, 226-228). Go: `model/settings.go` `AdeSettings` (61, 63), `DefaultAdeSettings` (148, 150), `AdePatch` (208, 210), `ValidAdeHorizonDays` (312), `Validate` (339-346); `repos/settings.go` `readAde` (96, 98) and `upsertAde` (141-149). No settings pane shows either leaf. `adeBoardUi` holds no range state (`showAllItems`, `showHistory`, `hiddenRepoIds` stay).
- Scheduled-date model: `Plan.day: Record<taskId, ISO>`, absent = Later (`wire.ts:404`). `buildMineEntries` turns it into `TimelineEntry.day` (offset from today, `LATER` when absent), `end`, `days`. Backend stores plain dates. No backend model change is needed.
- `today` = `localIso(now)`, `now` ticks on `TIMING.clockTickSlow` (`usePlanModel.ts:225-249`). Every offset is relative to it.
- Later band: `dayLabel(LATER)` = "Later", `data-ade-day="9999"`. It holds unplanned tasks, parked tasks (`kind === 'parked'`, no plan day) and unplaced review items. Hours = `hours.on.get(LATER)`; never overflows; `dayMenuFor` returns `null` for it. Drop on the band = clear the plan day.

## Decisions

### 1. Window = today plus 6 days

- `export const WINDOW_DAYS = 7;` in `timeline.ts`, next to `ITEM_LIMIT`, one-line comment ("P401: day bands shown from today; later work sits in Later").
- Future day bands are keys `0..WINDOW_DAYS-1` only. No setting, no extension control. `horizonDays` is not replaced by a new setting; nobody asked for one.
- Past bands keep today's rules: history keys when `showHistory`, and a shown entry's own past days (overdue work keeps its band and its rollover strip).

### 2. Work after the window sits in Later, it does not grow the window

The user says "they will just sit in a later section", "instead of adding a new week". Read: scheduled work past day 6 adds no day band. It joins the Later section and keeps its date. "Unless I have work scheduled later" is when Later has these items, not a cue to extend the window.

- One Later band, not two. It already means "not on a visible day". A second band would need a second label and drop rule for the same idea.
- Band membership: new local helper `bandKey(e) = e.day === LATER || e.day >= WINDOW_DAYS ? LATER : e.day`. `buildBand`'s `taskIds` filter uses it instead of `e.day === dk`.
- `TimelineEntry.day` stays the true offset. Merge order, `mergeOrder`, `after`, drop math and card meta keep the real date.
- Order inside Later is `shownTaskIds` order, which is `seq` order (merge day, start day, position). Scheduled items (end < 9999) therefore come first, by date; unplanned and parked ones follow. No extra sort.
- Later band hours = `on(LATER)` plus every `on(k)` for `k >= WINDOW_DAYS`. Compute this in `buildBand` for `isLater`. Per-day overflow beyond the window is not shown; it shows once that day enters the window. `overflowOf(LATER)` stays `[]`.
- A multi-day task that starts inside the window and ends after it: its continuation rows show on in-window days only (no band exists for the rest). Its card meta already says `3d → <end day>`, so the end stays visible. No change to `spansOn`.
- A task that starts after the window gets no continuation rows (no bands for its days).
- Auto-placed review items take their placer's `day`, so they follow the placer into Later. Consistent; no special case.

### 3. Later cards show their date

A Later card scheduled past the window must say when. `cardMeta` (`usePlanModel.ts:157`) gains a prefix when `entry.day !== LATER && entry.day >= WINDOW_DAYS`: `<dayLabel> <month> · `, for example `Tue 29 Sep · `. Build it from `dayLabel(c.cal, entry.day)` plus `monthLabel(dateParts(c.cal, entry.day).month)`, the same parts `bandLabels` uses. No `Date` constructor (calendar.ts's clock-read rule). The existing `Nd → <end>` part follows it unchanged.

Unplanned and parked cards keep today's meta (no date).

### 4. `collectDayKeys` rewrite

```ts
for (let k = 0; k < WINDOW_DAYS; k++) {
  if (input.showAllItems || !hiddenCount || k <= lastShownDay) keys.add(k);
}
for (const e of seq) {
  if (!shown.has(e.taskId)) continue;
  for (const d of e.days) if (d < WINDOW_DAYS) keys.add(d);
}
for (const iso of settings.offDays) {
  const k = isoToOffset(today, iso);
  if (k >= 0 && k < WINDOW_DAYS) keys.add(k);
}
```

`LATER` is pushed when nothing is hidden, or when a shown entry has `bandKey(e) === LATER`. `d < WINDOW_DAYS` also excludes `LATER` (9999), so drop the old `d !== LATER` test. `extraDays` is gone.

### 6. Edge cases

- Today rollover: no persisted range, so nothing goes stale. At midnight `today` changes, offsets shift by one and a task on old day 7 moves from Later into the new day 6 band on the next model build. The old `extraDays` pruning (`d >= today`) disappears with the leaf.
- Overdue: a past, unmerged task keeps its own past band and rollover button (`buildBand` `overdue`, unchanged). Rollover moves it to `firstWork(cal, 0)`, inside the window.
- Overflow move and the day-off confirm move tasks to `nextWork(cal, dk)`. From day 6 that can be day 7 or later; the task then sits in Later with its date. Expected; no clamp.
- Drag: a card dropped on a Later card scheduled past the window takes that card's `entry.day` (`dropVerdict` card branch: no band matches, so it is allowed), so it keeps a real date. A drop on the Later band itself clears the date (unchanged meaning: unschedule). No `dropPlan.ts` change.
- Day-off and weekend bands: unchanged inside the window. An `offDays` date after the window adds no band.
- Unscheduled and parked: unchanged, in Later after the scheduled-later items.
- First-10 cap: unchanged counting. Later shows when nothing is hidden or a shown item sits in it, which now includes shown scheduled-later items.
- Repo filter: unchanged.
