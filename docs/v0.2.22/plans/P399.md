# P399 Archived work stays viewable with all data

Spec row: "Archived work must be visible in the UI. Opening an archived task shows its session, notes, links, PRs and all other data, unchanged from before archiving. Archiving must not drop or hide any of it."

User's words: "I should be able to see the archived work. To access the session see the notes links prs etc. I expect all that data to remain there."

Base: `b199d36` (P398 done). Discovery via `codegraph_explore` (ArchiveTask engine and store, teardownReview, closeTaskTerminals, removeWorktree, PurgeArchived/logpurge, ListArchived/BranchesArchived, toWireHistory, ChangeRequests/resolveRepoHost, ResolveBranchChangeRequest, gitreview Purge/SetPinned/sweepDB/Comments, AdePanel, AdeArchivedPanel, AdeSessionsTab, AdePlanView history region, timeline historyItems, AdeShell, adeBoardUi, readQueries, AdeReader).

## What archive does today

`TaskBoard.ArchiveTask` (`apps/kira-space/internal/ade/archive.go:132`):

1. Refuses when a linked worktree cannot be removed.
2. `stopTaskWork`: cancels runs and setup scripts.
3. `closeTaskTerminals`: closes running TUI terminals. Session rows stay (`ade_sessions`).
4. `removeWorktree` per linked branch. Git branch refs stay (asserted in `TestArchiveRisk`).
5. `teardownReview` (`review.go:264`): unpins **and purges** each branch's `review_session` (marks and review comments, `gitreview/reaper.go:54`), closes review windows, deletes review window records.
6. Store `ArchiveTask` (`repos/adetask.go:1287`): sets `archived_at` on task and its live branch rows, deletes the plan row.

Data kept in DB: task row (title, jira, host URL, notes, est, status, workflow snapshot, since), branch rows, runs, reviews, setup rows, sessions, logs.

Data lost:

- **Review sessions and review comments**: purged in step 5, immediately.
- **Run and setup logs**: `purgeArchivedLogs` (`logpurge.go`, P177) deletes logs of tasks archived 90+ days ago, hourly. Headless session output is these logs.
- **PRs**: never stored. `ChangeRequests` (`board.go:606`) resolves only `BranchesLive`, so an archived task's PRs are not resolved at all.

Data hidden (kept but not shown):

- Board sends archived tasks only as `HistoryEntry {taskId, title, codeRepoIds, mergedAt, archivedAt}` (`toWireHistory`, `board.go:571`).
- `AdeArchivedPanel.vue` shows title, repos and the Sessions tab only. No notes, Jira, host link, branches, PRs, status, workflow, estimate.
- Archived tasks are reachable only inside the Plan's history region (`ui.showHistory`, limited by `settings.ade.historyDays` plus Go to date). No list of archived work.
- Sessions of an archived task render with degraded labels: `useSessionViews` looks up task and branch on the live board only.
- Branch rows detached by P397 (`DetachBranch`, archived on a live task) are not listed anywhere.

## Decisions

### Archived view is read-only, with Restore

- Archived task view shows everything, but edits nothing (notes, links, status, branches are read-only). Archive means frozen; editing a frozen record would blur that, and every write path assumes a live task (`checkNotArchiving`, `AddBranch` refuses archived tasks).
- Add **Restore** (unarchive). It is cheap and consistent:
  - Store: one transaction flips `archived_at` back to NULL on the task and on the branch rows archived with it, and inserts a plan row in Later.
  - Worktrees need no restore step. `ensureWorktree` (`setup.go:136`) already recreates a worktree for a named row on next launch (existing local branch, or off the remote tracking ref).
  - Review sessions survive archive after this phase (below), so a restored task gets its review state back as it was.
  - Only real conflict: a branch name now live on another task (unique index `ade_task_branches_live_name`). Restore refuses then, naming the branch and the task holding it; nothing changes.
- To edit an archived task, restore it first. The archived panel says so in its header hint.

### Nothing dropped on archive

- `teardownReview`: keep closing review windows and deleting window records (UI state, not task data). Stop `SetPinned(false)` and `Purge`. ADE already pins review sessions it opens (`review.go:145`, `reviewstep.go:184`), so they stay pinned and survive the idle sweep and the merged-PR eager purge. Rename the function to `closeReviewWindows` since it no longer tears down review data.
- Delete the archived log purge: `logpurge.go`, `AdeLogsRepo.PurgeArchived`, its test `TestAdeLogsRepo_PurgeArchived`, the `runLogPurge` goroutine start and `archivedLogRetention`. Per-log size cap (`truncated`) still bounds each log. Replace the P177 retention line in `docs/ARCHITECTURE.md` (line ~2074) with the new rule.
- PR snapshot at archive: store each branch's change request on its row before the store archive call, so the archived view shows it even when the host is unreachable later or the branch ref is gone.

### Where archived work is browsed

- New top tab **Archived** in `AdeShell.vue`, after Plan (`data-testid="ade-tab-archived"`, view `'archived'`). Page = searchable list on the left, archived panel on the right.
- Plan's history region stays. Clicking a history item still opens the same (now full) archived panel beside the Plan.

## Backend changes

### Migration — `apps/kira-space/internal/storage/migrations/0052_p399_ade_branch_change_request.sql`

Add to `ade_task_branches`, all nullable: `cr_number INTEGER`, `cr_title TEXT`, `cr_state TEXT`, `cr_url TEXT`. NULL = none recorded. Follow the existing migration test pattern only if the migration does more than add columns (it does not; no test).

### Model and store — `internal/storage/model/adetask.go`, `internal/storage/repos/adetask.go`

1. `AdeTaskBranch.ChangeRequest *AdeChangeRequest` (`Number`, `Title`, `State`, `URL`). Extend `adeTaskBranchColumns`, `queryBranches` select, `scanAdeTaskBranch`. Insert paths leave it NULL.
2. `SetBranchChangeRequests(crs map[string]model.AdeChangeRequest) error`: one tx, `UPDATE … WHERE id = ?` per entry.
3. `BranchesOfTask(taskID string) ([]model.AdeTaskBranch, error)`: every row of one task, archived or not, position order.
4. `RestoreTask(taskID string, now int64) error`, one tx:
   - load task; `ErrTaskNotFound` if absent; new `ErrTaskNotArchived` if `archived_at IS NULL`.
   - rows to restore: `task_id = ? AND archived_at = <task.archived_at>`. Rows with an earlier `archived_at` were detached by P397 and stay detached.
   - for each named row, check no live row has the same `(code_repo_id, name)`; on a hit return `ErrBranchOnTask` wrapped with branch name and holding task title (engine maps to `invalid`).
   - set `archived_at = NULL` on task and those rows; insert plan row `(task_id, NULL day, MAX(position)+1)` like `insertTask`.
5. Delete `AdeLogsRepo.PurgeArchived` (`repos/adelogs.go:163`) and its test.

### Engine — `internal/ade/archive.go`, new `internal/ade/archived.go`

1. `ArchiveTask`: after `stopTaskWork` and before `Tasks.ArchiveTask`, call `snapshotChangeRequests(ctx, tc)`:
   - group named rows by repo, `openRepo`, reuse `resolveRepoHost` (`board.go:649`), `Tasks.SetBranchChangeRequests(found)`.
   - best effort: bound by `context.WithTimeout(ctx, 5*time.Second)`; any failure logs `slog.Warn` and archive continues. `ResolveBranchChangeRequest` already answers from its persisted index and caches first.
2. `teardownReview` → `closeReviewWindows`: keep the `ReviewWindows` block only (`review.go:289-296`).
3. Remove `runLogPurge` start (find it in `NewTaskBoard`/start code) and `logpurge.go`.
4. `ArchivedTask(ctx, taskID) (adewire.ArchivedTask, error)` in `archived.go`:
   - `GetTask`; `invalid("task is not archived")` when live (wrap `repos.ErrTaskNotArchived`).
   - `BranchesOfTask`, `RunsOfTask`, `Tasks.Reviews()` for the task wire.
   - Task: `toWireTask(t, branchIDs, runs, reviews)` plus `decorateTask(&wt, t, b.liveWorkflows())` so `workflow`, `jira`, `hostLink`, `notes`, `est`, `statusId` match what the live panel showed.
   - Branches: `ArchivedBranch` per row (below). `Removed = row.ArchivedAt != task.ArchivedAt`.
   - PRs: per repo, live `resolveRepoHost` with `context.WithTimeout(ctx, 5*time.Second)`. Live answer wins; else the stored snapshot; `PRSource` says which (`live` | `archived` | `''`). Repo open failure: repo `Kind: "unavailable"`, stored snapshot used. Never an error.
   - Branch web URL: `entry.BranchURL` when the host resolves, else `''`.
   - Review comments per named branch: raw stored rows via the review store (`Registry.Review.Comments(ctx, gitRepoID, branch)`; resolve `gitRepoID` as `teardownReview` did via `entry.Summary.RepoID` and `reviewSpellings`, falling back to `sb.Name`). No anchoring: the branch tip may be gone. Map to `ArchivedComment`. Nil review registry gives `[]`.
   - Status defs: include `toWireStatuses` result so the UI can name the status without the board.
5. `RestoreTask(ctx, taskID) (adewire.Task, error)` in `archived.go`: `taskMu` lock, `Tasks.RestoreTask`, map `ErrBranchOnTask`/`ErrTaskNotArchived` to `invalid(...)` with the readable text, `notifyBoard()`, `notifySessions()`, return the wired task (load like `Board` does for one task, or `loadTaskCtx` + `toWireTask`).

### Wire — `internal/bridge/adewire/wire.go`, `frontend/src/ade/v2/wire.ts`

```go
type ArchivedTask struct {
	Task       Task             `json:"task"`
	ArchivedAt int64            `json:"archivedAt"`
	Statuses   []TaskStatusDef  `json:"statuses"`
	Branches   []ArchivedBranch `json:"branches"`
	Repos      []RepoHost       `json:"repos"`
}
type ArchivedBranch struct {
	ID, CodeRepoID, Name, Kind, Base, Origin string
	AddedAt     int64
	MergedAt    *int64
	ArchivedAt  int64
	Removed     bool
	ChangeRequest *ChangeRequest
	PRSource    string // "live" | "archived" | ""
	BranchURL   string
	Comments    []ArchivedComment
}
type ArchivedComment struct {
	Path string; Start, End int; Body, Kind, State, Reply string; CreatedAt int64
}
```

3. `ArchivedTask`: notes, jira, hostLink, est, status equal pre-archive values; branch row named, PR number and title present, `prSource == "live"`; comment present; `Removed == false`.
