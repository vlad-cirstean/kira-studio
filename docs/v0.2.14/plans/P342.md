# P342 plan: git graph keeps state across tab switches

Base: `fcc58b1`. One sequential Sonnet implementer; no stream split (MainView, RepoGraphView and
git-ui changes form one chain).

## Root cause

`packages/workbench/src/components/MainView.vue` renders only the active tab:
`<component :is="host.views[activeTab.kind]" v-if="activeTab" :key="activeTab.id">`. Opening a
diff (or file, terminal, any tab) activates another tab, so `RepoGraphView.vue` unmounts
(`onUnmounted` -> `handle.unmount()` -> git-ui `app.unmount()`). Returning remounts: new git-ui app,
new `GraphViewState`/`GraphOrderState`/`CommitStore`, fresh `app.init` + `graph.stream` walk,
layout worker re-run, grid rebuilt. `TabViewStateStore` restores only `PersistedViewState`
(scrollRow, selectedSha, loadedRows, widths, search toggles); everything else (expanded groups in
`GraphOrderState.#expandedKeys`, search query text, detail pane content, menus, lane layout) is
rebuilt or lost, and the user sees the whole graph re-walk.

Not the cause: no Pinia store reset (graph state lives in git-ui's per-mount classes, not Pinia),
no TanStack Query (git-ui talks to its own `Transport`; no query wraps the graph, so no
`refetchOnWindowFocus`/invalidate path), no backend involvement (`gitTransportFor` already keeps one
shared client per workspace across mounts).

History: P72/P79 fixed this with `KeepAlive` in MainView plus `MountHandle.setVisible`/
`GRAPH_VISIBLE_KEY` (`packages/git-ui/src/graphVisibility.ts`). The KeepAlive was later dropped
when MainView moved into `packages/workbench`; `docs/ARCHITECTURE.md` (C10 section, "In Kira Space a
tab switch fully unmounts..." and "graphVisibility.ts ... is unreachable") records the regression.
The git-ui half (deferred rebuild while hidden, catch-up on show, document keydown gating) is still
in place and is reused.

## Decision

Keep a graph tab's view mounted, hidden with `v-show`, from its first activation until the tab
closes. Opt-in per kind through the tab-kind registry; only Kira Space's `repo-graph` opts in.

Why `v-show` over `KeepAlive`: KeepAlive caches by vnode key and prunes only by component name
(`include`/`exclude`) or `max` LRU. A closed graph tab (workspace close) would stay cached, with its
git-ui app alive on a disposed transport lease, until LRU eviction. A `v-for` over open, visited
kept tabs unmounts exactly when the tab record disappears. No library offers per-key KeepAlive
eviction.

Why no Pinia store: the "visited" set is MainView-local view lifecycle, read by nothing else. One
component, one `ref`. Pinia is for shared client state.

Refresh in place: while hidden, `repo.changed`-driven refreshes still run (same `GraphViewState`,
same `CommitStore`); `CommitGrid.vue` defers its grid rebuild (`pendingRebuildOnVisible`) and
replays it once on show. No remount, no re-walk.

### `packages/workbench/src/components/MainView.vue`

- `visited = ref<string[]>([])` of kept tab ids. `watch(activeTab, ...)` (immediate): when the
  active tab's kind has `host.kinds[kind]?.keepMounted`, push its id if absent.
- `keptTabs = computed(() => host.tabs.tabs.filter((t) => visited.value.includes(t.id)))`.
- Prune: `watch(() => host.tabs.tabs.map((t) => t.id), ...)` drops ids no longer present, so a
  closed then reopened workspace remounts cold and the array never grows unbounded.
- Template:

```vue
<component
  :is="host.views[tab.kind]"
  v-for="tab in keptTabs"
  v-show="tab.id === activeTab?.id"
  :key="tab.id"
  :tab="tab"
  :active="tab.id === activeTab?.id"
/>
<component
  :is="host.views[activeTab.kind]"
  v-if="activeTab && !host.kinds[activeTab.kind]?.keepMounted"
  :key="activeTab.id"
  :tab="activeTab"
/>
<slot v-if="!activeTab" name="empty" />
```

### `apps/kira-space/frontend/src/views/repo/RepoGraphView.vue`

- `defineProps<{ tab: RepoGraphTabRecord; active?: boolean }>()`.
- After `handle = mount(...)`: `handle.setVisible?.(props.active !== false)` (covers a hide
  that lands while `loadGitUi()` is in flight).
- Hide must reach git-ui before `display: none` applies (CommitGrid's resize guard keys off it):
  `watch(() => props.active, (v) => { if (v === false) handle?.setVisible?.(false); }, { flush: 'sync' })`.
- Show must reach git-ui after the DOM is visible, so the catch-up rebuild measures real size:
  `watch(() => props.active, (v) => { if (v !== false) handle?.setVisible?.(true); }, { flush: 'post' })`.
- `onUnmounted` unchanged (now runs only on tab close / workspace close / window close).
- Rewrite header comments (lines 2-9, 66-70): view stays mounted while the tab is open; unmount
  means tab closed.
