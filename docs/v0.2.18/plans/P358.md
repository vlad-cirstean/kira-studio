## 2. Design

### 2.1 Mark a folder reviewed

**Contract (additive, 51 -> 52).** New request `review.markMany`:

```ts
'review.markMany': {
  params: { repoId: string; branch: string; paths: readonly string[]; reviewed: boolean };
  result: { readonly results: readonly { readonly path: string; readonly review: ReviewFileStatus }[] };
};
```

Whole-file only, no `ranges`. Edit `packages/git-ipc/src/contract.ts`, the method table in
`validate.ts` (line ~277), `CONTRACT_VERSION` in `validate.ts:198` and `ContractVersion` in
`internal/gitrpc/contract.go:189` with a `P358: 51 -> 52, additive.` history line. Grep for other
hard-coded `51` contract-version expectations (fixtures, specs) and bump them.

**Go.**

- `internal/gitrpc/wire.go`: `ReviewMarkManyParams{RepoID, Branch, Paths []string, Reviewed}`,
  `ReviewMarkManyResult{Results []ReviewMarkManyEntry}`, entry `{Path, Review}`.
- `internal/gitrpc/handlers.go`: register `"review.markMany"`. `incremental.go`:
  `handleReviewMarkMany` through `handleRepoCall`. Validation: `requireNonEmpty` repoId,
  `validRefArg` branch, `len(paths) >= 1`, every path non-empty (`ipcerr.Contract` naming the
  field). Dedupe paths, keep first-seen order.
- `internal/gitsession/incremental.go`: split `MarkFile`'s body after the tip resolution into
  `markFileAt(ctx, tip, branch, path, reviewed, ranges)`. `MarkFile` = lock, `branchTip`,
  `markFileAt` (behaviour unchanged). New `MarkFiles(ctx, branch, paths, reviewed)`: resolve tip
  once, then per path: `ctx.Err()` check, take that path's lock, `markFileAt(..., nil)`, unlock.
  First error returns it; earlier writes stay (each file's record is independent, no cross-file
  invariant). Comment that one line on the handler.

**Transport repaint.** `repo/git/transport.ts`: `ReviewRepaintEvent` `mark` variant carries
`paths: readonly string[]` instead of `path`. `review.mark` fires `paths: [path]`;
`review.markMany` fires its params' `paths` once. Update listeners: `reviewDecorations.ts:647`
(`event.paths.includes(deps.path)`), `AdeReviewWindow.vue:35` (repoId only, unchanged logic).

**git-ui state.** `ReviewFilesState.markMany(paths, reviewed)`: same queue (`#markChain`,
`#markState`, `pending`, `markError`), resets `#lastQueuedKey`. Applies every result to `files` in
one assignment. Reloads selected file's diff metadata when the selected path is in `paths`. On
error sets `markError` and calls `reload()` (partial writes may have landed). `onMarked` becomes
`(paths: readonly string[]) => void`; `mark()` calls it with `[path]`. Propagate the signature
through `ReviewView.vue` prop, `main.ts` mount option `onReviewMarked`, `AdeReviewFiles.vue` emit.

**Tri-state (FileTree.vue).** Tree mode with `reviewStates` only. Flat mode has no directory
rows, nothing to add.

- Scope of "every file under it": the files the directory row contains in the current tree, i.e.
  after the filter. A filtered-out file is not visible, so marking it would surprise. Collapsed
  chains (`src/main/java`) cover their whole subtree.
- One `computed` `dirReview: Map<dirPath, { state: boolean | 'indeterminate'; paths: string[] }>`,
  built by one post-order walk over `tree` (not per row): state `true` when every descendant file
  is `full`; `false` when every one is `none`; else `'indeterminate'` (a `partial` file counts as
  "some").
- Replace the empty slot with the same `Checkbox` as file rows (`data-testid="review-folder-check"`,
  `aria-label`/`data-kira-tip` "Mark folder reviewed" / "Mark folder unreviewed", `@click.stop` so
  the row does not toggle collapse). Checkbox's own `'indeterminate'` gives `aria-checked="mixed"`.
- Click rule: state `true` emits `toggleReviewedFolder(paths whose kind !== 'none', false)`;
  otherwise `toggleReviewedFolder(paths whose kind !== 'full', true)`. Sends only files that
  change. A `partial` file becomes `full` on mark, `none` on unmark.
- Delete the P75 §4.3 comment. `ReviewFilesPane.vue` forwards the emit to
  `reviewFiles.markMany`.

### 2.2 Next / previous change

**Within a file.** New `views/repo/diffNavigation.ts`, `attachDiffNavigation(mod, diffEditor,
opts)` returning `{ next(), previous(), canNext, canPrevious (Ref<boolean>), dispose() }`, same
attach/dispose shape as `attachReviewDecorations`.

- Own change list from `getLineChanges()`, refreshed on `onDidUpdateDiff`. Anchor line per change:
  `Math.max(1, c.modifiedStartLineNumber)` (pure deletion reports `modifiedEndLineNumber === 0`;
  its start is the line above).
- Own `index` (-1 before first move). Independent of cursor, so `revealCommentLines`'
  API-sourced selection moves do not reset it. A user cursor move
  (`onDidChangeCursorPosition` with `source` `mouse` or `keyboard`) resyncs `index` to the last
  change whose anchor is at or above the cursor line.
- Reveal: `modifiedEditor.setPosition({ lineNumber: anchor, column: 1 })` then
  `revealLineInCenter(anchor)`. The position change also unhides via P357's listener (a change is
  never collapsed anyway). Do not call `goToDiff` (wraps, see section 1).
- Not using `goToDiff` is a real requirement, not preference: crossing files needs "no further
  change", which Monaco's API cannot report.

**Crossing files (yes, recommended and adopted).** `next()` past the last change opens the next
file in the review list, landing on its first change; `previous()` before the first change opens
the previous file, landing on its last change. At the first/last file the button disables.

- git-ui: extend `onReviewApi` payload with
  `adjacentFile(path: string, dir: 'next' | 'previous'): string | null`, implemented in
  `ReviewView.vue` from `reviewFiles.files` plus its `listMode`/`filter`. Order = the order the
  tree shows: add `orderedFilePaths(files, filter, listMode)` to `fileTreeModel.ts`
  (`flattenTreeRows(buildFileTree(filterFiles(...)), () => true)` file rows for tree mode,
  `buildFlatList` for flat). A path absent from the list returns null.
- Kira Space: new Pinia store `state/reviewNavigation.ts` (one concern: cross-file review
  navigation). State: `navigators: Map<gitRepoId, { adjacentFile, selectFile }>` (`markRaw`), and
  `arrival: { gitRepoId; path; at: 'first' | 'last' } | null`. Actions `register(gitRepoId, nav)`
  returning an unregister, `navigatorFor(gitRepoId)`, `requestArrival`, `takeArrival(gitRepoId,
  path)`.
- `AdeReviewFiles.vue` registers on `onReviewApi` (key `target.gitRepoId`), unregisters in
  `onUnmounted`. `RepoReviewView.vue` does the same (main-window Review segment gets crossing for
  the cost of a few lines; key its prop's git repo id via `gitRepoIdFor`).
- `RepoDiffView.vue`, review tabs only (`tab.state.review !== null`): when in-file nav is
  exhausted, `adjacentFile(tab.path, dir)`; if non-null, `requestArrival(...)` then
  `selectFile(next)` (opens the preview tab as a click does). On mount, `takeArrival` for its own
  path; apply `first`/`last` after the first `onDidUpdateDiff` (attach navigation after
  `attachReviewDecorations` so its listener runs after `revealCommentLines`).
- `canNext`/`canPrevious` = in-file move possible, or adjacent file exists. Navigator is not
  reactive across the git-ui app boundary, so recompute both on mount, after each move, and on
  `onDidUpdateDiff`. Non-review diff tabs: in-file only, buttons disable at the ends.
- A file with zero line changes (pure rename/mode change) has an empty change list: next/previous
  cross immediately. Binary/too-large/missing review files: show the toolbar for every non-loading
  state on review tabs, with in-file nav off and crossing still live; otherwise the user is stuck
  on that file. Go-to-file and the layout toggle stay `found`-only.

**Toolbar.** Two `Button variant="toolbar" size="kira"` before go-to-file: icon-only codicons
`arrow-up` / `arrow-down` (verify both names exist in the codicon font), `aria-label` +
`data-kira-tip` "Previous change" / "Next change", `data-testid` `repo-diff-prev-change` /
`repo-diff-next-change`, `:disabled` from the refs. Tailwind only, no `<style>` block.

### 2.3 Inline / side-by-side toggle

- New `views/repo/diffLayout.ts`: `useDiffLayout()` =
  `usePersistedState('kira.repo.diffLayout', 'sideBySide', { schema: z.enum(['sideBySide',
  'inline']) })`. Per-device UI preference, the same mechanism the review window's pane widths
  use; not a settings-store entry (no Settings UI asked for). Shared ref plus `storage` sync means
  the main window and the review window agree.
- `useDiffEditor.ts`: create with `renderSideBySide: layout.value === 'sideBySide'`; `watch` the
  ref and `updateOptions({ renderSideBySide })` on change. `useDiffEditor` runs inside an async
  `mount()`, outside the component's effect scope, so keep the `WatchStopHandle` and stop it in
  `dispose()`. All repo diff editors (single and multi-diff) follow the one choice.
- Toolbar control in `RepoDiffView.vue`: `SecondaryTabs variant="segmented"` (shadcn `ToggleGroup`)
  with two icon items, Side by side / Inline, `data-testid` `repo-diff-layout-side-by-side` /
  `repo-diff-layout-inline` via item `testid`, pushed right (`ml-auto`). Same pattern as
  `ReviewFilesPane.vue`'s mode toggle.
- Keep `useInlineViewWhenSpaceIsLimited: false`: the user's choice must win over width.

### 2.4 Scope

- In: files named above, i18n keys in `en.json`, `docs/ARCHITECTURE.md` (add one line near 1884:
  folder mark via `review.markMany`, own-index change navigation crossing files via
  `reviewNavigation` store, `kira.repo.diffLayout`).
- Out: keyboard shortcuts / palette commands for next/previous (not asked); controls on
  `RepoMultiDiffView.vue`'s section headers (it follows the layout choice, adds no controls);
  VS Code extension (native diff); auto-expanding a collapsed tree folder when navigation selects
  a file inside it (existing `selectedFile` watch behaviour stands).
- Library rule: Monaco, shadcn-vue (`Checkbox`, `ToggleGroup` via `SecondaryTabs`, `Button`),
  VueUse (`useLocalStorage` via `usePersistedState`), Pinia (navigation store), Tailwind. TanStack
  Query: no new fetch; viewed-sync-plan invalidation stays as is. git-ui keeps its class-based
  state (no Pinia in that package; extending it is not this phase's design call).
