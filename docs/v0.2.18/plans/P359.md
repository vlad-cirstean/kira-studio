## 2. Decisions

What "app window is focused" means: any Kira Space window (normal or review) is the macOS key
window. Matches user wording "the app window", not "the session's window". A finished note for a
session in window A is skipped while window B is focused too. User is in the app; finished state
shows in tab activity icons.

Focused but on a different tab/session/module: skip. User asked for app-window focus, not tab focus.
This widens today's tab-level rule for `KindFinished` only.

Kinds in scope: `KindFinished` only (row names "agent-finished"). Unchanged: `KindNeedsInput`
(still tab-level suppression: a permission prompt on an unseen tab blocks the agent, so the note
still earns its place), `KindRunEnded`, `KindAutomation`, `KindTest`. Orchestrator: if user wants
needs-input or run-ended covered too, that is a user call, not inferred here.

Where decision lives: backend, at decision time, from native focus. Reasons:

- Native `isKeyWindow` is authoritative. DOM `useWindowFocus` reads false when focus sits inside an
  iframe and lags 150 ms through the debounce. A `Stop` right after a blur/focus would race the report.
- Review windows report nothing to `ReportFocus`; native registry covers them with no renderer change.
- Same pattern as prompt router. No new IPC, no contract change.
- VueUse stays where it is (per-tab reporting for needs-input/run/automation). No frontend change, so
  no frontend library question arises.

Rejected: frontend-only (renderer reports "any window focused", backend ORs live reports) for the
race and review-window gap above. Rejected: making review windows call `installAgentNotifyFocus`
(more IPC, still debounced).

## 3. Changes

1. `internal/shell/registry.go`: add `AnyFocused() bool`. Snapshot non-nil `win` handles under `r.mu`,
   release, then return true on first `win.IsFocused()`. Never call `IsFocused` under `r.mu` (main
   thread may be inside `Add`/`removeAndCount` waiting for the lock). Shared package; Kira Studio
   untouched otherwise. Doc comment: must not run on main thread.
2. `apps/kira-space/internal/agentnotify/agentnotify.go`:
   - Remove dead `Deps.Focus`. Add `AppFocused func() bool` with comment "any app window is the key
     window; nil reads false".
   - In `notifyTerminal`, after the prefs check and before taking `n.mu`: if `kind == KindFinished`
     and `n.d.AppFocused != nil && n.d.AppFocused()`, return. Outside the lock: `AppFocused` blocks on
     the main thread.
   - Skipped note does not consume cooldown (check precedes `admitLocked`). Matches today's
     `watchedLocked` order.
   - Update package comment only if wording goes stale (it says "focus"; still true).
3. `apps/kira-space/internal/appwire/appwire.go`:
   - `ShellHooks` gains `AppFocused func() bool` ("nil defaults to the window registry").
   - `Wired` gains unexported `appFocused func() bool`, set in Build to `w.Windows.AnyFocused`.
   - `agentnotify.New` Deps: `AppFocused: func() bool { return w.appFocused() }` (closure, since
     `BindShell` runs after Build).
   - `BindShell`: `if h.AppFocused != nil { w.appFocused = h.AppFocused }`. Set before any hook event
     can fire in flows (BindShell runs inside harness build, before tests drive hooks); production
     never overrides. If a data race shows under `-race` (hooks goroutine started in Build), store
     it in an `atomic.Pointer[func() bool]` instead.
4. `apps/kira-space/internal/flowharness/shellfakes.go`: `WindowManager` gains `appFocused bool` plus
   `SetAppFocused(bool)` and `AppFocused() bool` (mutex-guarded). `harness.go` `BindShell` call passes
   `AppFocused: a.WindowMgr.AppFocused`. Default false, so every existing notify test keeps posting.
5. `docs/ARCHITECTURE.md` "Agent notifications (P238)": replace line 2241 with two lines:
   finished notes skip while any app window (review included) is key (`WindowRegistry.AnyFocused`,
   native); other kinds keep the per-window tab rule from `ReportFocus`.

## 4. Tests

Logic is one guard, not complex: no unit test. IPC-split rule: no frontend half, since renderer
behaviour and IPC are unchanged; a UI spec would assert nothing new. Existing
`tests/ui/settings-agent-notify.spec.ts` "a window reports its focus at boot" stays valid.

Flow test change is required anyway: `notifyflow/notify_test.go` `TestFocusedTabSuppresses` uses
`stop` (finished) and asserts its middle case posts while another tab is active. Under the new rule
that case is driven by native focus, not `ReportFocus`. Rewrite into:

- `TestFocusedAppSkipsFinished`: `app.WindowMgr.SetAppFocused(true)`, no `ReportFocus` at all,
  `stop` then `sink.none`. `SetAppFocused(false)`, `stop` again (cooldown shortened), one finished
  note. Proves the native path and that a blurred app still notifies.
- `TestFocusedTabSuppresses` keeps the tab rule on needs-input: report focus on `tab-1`, needs-input
  hook, none; report `tab-2`, one; report blurred `tab-1`, two. Also call `SetAppFocused(true)` at the
  start of the `tab-2` step so it proves app focus does not suppress needs-input (scope boundary).

Run: `go test -race ./apps/kira-space/internal/flows/notifyflow/... ./internal/shell/...`, then the
full `go test ./apps/kira-space/internal/flows/...`. Typecheck/lint via pre-commit.

Real-window check: `AnyFocused` reads `isKeyWindow` only on macOS Wails; Linux sandbox cannot run it.

## 5. Edge cases

- Screen locked or display asleep with Kira Space frontmost: window may stay key, so finished notes
  skip while user is away. Accepted, per user wording; note it in the Result. No cheap reliable
  signal (`useDocumentVisibility` does not flip on lock).
- Wails dialog/sheet key instead of window: `isKeyWindow` false on the window, note posts. Harmless.
- Space-switch animation can read false briefly (`prompts/router.go` `raiseQuiet`): note posts.
  Harmless; no debounce added.
- No window open (app hidden, Dock only): registry empty, `AnyFocused` false, note posts.
- Window closing mid-check: `IsFocused` returns false on destroyed impl; no panic.
- ADE manual-step sessions (`TestAdeManualSessionNote`) are `KindFinished` too; covered by the same
  guard.
