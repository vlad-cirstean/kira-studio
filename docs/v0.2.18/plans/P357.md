## 2. Design

### 2.1 Enable collapsing for review diffs

In `useDiffEditor.ts` replace `{ enabled: !review }` with one explicit option object, same for
both variants:

```ts
hideUnchangedRegions: { enabled: true, contextLineCount: 3, minimumLineCount: 3, revealLineCount: 20 },
```

Values are Monaco's defaults, set explicitly so a Monaco bump cannot silently change "a few lines
of context". Plain diff behavior stays the same (defaults equal). Delete the gotcha-2 comment. Fix
`DiffEditorParams.review` doc comment (now only toggles `glyphMargin`). Monaco's own collapsed
placeholder ("N hidden lines", click/drag to reveal) is the collapse UI. No custom widget: the
library already meets the requirement (library rule).

### 2.2 Keep comments visible (gotcha 2's real requirement)

Requirement stands: a comment anchored on an unchanged line must not vanish into a collapsed
region. Lever: Monaco 0.56's `HideUnchangedRegionsFeature` listens to `onDidChangeCursorPosition`
on both panes and calls `ensureModifiedLineIsVisible` / `ensureOriginalLineIsVisible` for every
selection start/end line. That is a public-API path (`setSelections`) to unhide specific lines.

Step 0, before coding: `bun install`, then confirm in
`node_modules/monaco-editor/esm/vs/editor/browser/widget/diffEditor/features/hideUnchangedRegionsFeature.js`
that this listener exists and which `CursorChangeReason` values it skips. Confirm `setSelections`
from API fires it (reason `NotSet`/`Explicit`, not `ContentFlush`). If the listener is absent or
filters out API changes, stop and report: that is a design decision for the orchestrator, not a
silent fallback to whole files.

In `reviewDecorations.ts` add `revealCommentLines()`:

- Collect distinct `comment.range.start` lines (modified-side coordinates, already what paint()
  uses), clamp to model line count.
- None: return. Else `modifiedEditor.setSelections(lines.map(l => new mod.Selection(l, 1, l, 1)))`
  then collapse back to one selection on the first comment line
  (`setSelection`) so the user is not left with a multi-cursor. Do not restore a pre-existing
  line-1 cursor: that would unhide the top region.
- Call it after `loadComments()` applies a fresh list, and on `diffEditor.onDidUpdateDiff` (regions
  are rebuilt per diff compute; comments may arrive first). Register the listener's disposable in
  the handle's `dispose()`.
- Opening a thread zone already targets a visible line (add-glyph only shows on rendered lines;
  comment glyph lines now revealed). No change there.

Hunk glyphs sit on `hunkChangeBlock(hunk).start`, always inside a changed region: visible.
Reviewed-line tint inside a collapsed region needs nothing: hidden lines need no tint.

### 2.3 Scope

- In: `useDiffEditor.ts`, `reviewDecorations.ts`, `docs/ARCHITECTURE.md:1884` (rewrite the line:
  review diff now collapses; comment lines unhidden through selection, name the Monaco listener).

- Out: VS Code extension `reviewMarking.ts` (native VS Code diff, own setting). Studio

Frontend-libraries rule: no new UI surface, no component, no store, no fetch. Nothing to adopt;
Monaco's built-in feature is the library answer.
