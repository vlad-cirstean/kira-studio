## 1. What exists

"Planning board" is the ADE v2 Plan: `apps/kira-space/frontend/src/ade/v2/plan/AdePlanView.vue`. Its "columns" are day bands (`AdeDayBand.vue`): one per day offset from today (past days with history on, today, horizon days, extra days) plus a `Later` band (`LATER = 9999`, `board/calendar.ts`). No other board or column UI exists in Space.

A "review" card is a task with `kind: 'review'` (`Task['kind']` in `ade/v2/wire.ts`). Backend makes one in `TaskBoard.AddExistingBranch` (`internal/ade/board_writes.go` ~line 372) when the branch author's email differs from repo `user.email` (`resolveKind`, `internal/ade/gitfacts.go:115`). Its branch has kind `review`. The card renders blue-edged, has no header, and a reduced menu.

How a task card moves today:

- Drag: each band's drop area is a SortableJS list (`useDraggable`, `draggable: '[data-ade-task]'`, `sort: false`). `usePlanDrag.ts` resolves the pointer target (card, else band). `dropVerdict` (`board/dropPlan.ts`) turns it into one `SetPlanArgs` write via `useSetPlan` (`ade/v2/queries.ts`, optimistic `withPlan`).
- Menu: task menu `Plan` submenu (Today, Next work day, Later), `planEntry` in `board/menu.ts`, run by `useTaskMenu.ts` case `'plan'` with `movePlanArgs`.
- Band buttons: overdue rollover and overflow move (`shiftPlanArgs`).
- Wire: `AdeTaskService.SetPlan(SetPlanArgs{order, days})`, `days` value `null` = Later. Backend `TaskBoard.SetPlan` (`board_writes.go:405`) accepts any live task id; repo `AdeTaskRepo.SetPlan` updates `ade_task_plan`. Every task, review included, gets an `ade_task_plan` row on create (`insertTask`, `internal/storage/repos/adetask.go:198`), review with day NULL. Board wire `Plan.day` omits null days (`internal/ade/board.go:482`); `Plan.order` lists every live task.

No status transition is involved: a plan day is scheduling only. Task status is derived (ARCHITECTURE D10), never set by a move.

## 2. Why a review cannot move

Backend allows it already; all blocks are frontend:

1. `AdeTaskCard.vue`: `:data-ade-task="card.review ? undefined : ''"` takes review cards out of the Sortable `draggable` set; `cursor-default` on review.
2. `board/timeline.ts`: `buildMineEntries` skips `kind === 'review'`; `placeReviews` derives a review's day (the day of the first task that builds on or conflicts with its branch, else `LATER`) and never reads `plan.day`. A plan day written for a review would be ignored.
3. `board/menu.ts` `taskMenuModel`: `planEntry` sits inside `if (!review)`.
4. `board/dropPlan.ts` `dropVerdict`: refuses a review card as target.

## 3. Chosen semantics

A review gets an optional pinned day, stored as its existing `ade_task_plan.day`:

- `plan.day[reviewId]` present: review is pinned. It sits on that day like a task: one-day entry, no hours, position from `plan.order` within the day.
- Absent: auto placement as today (above first dependent task, else `Later`).
- Move to a day band (drag, or menu Today / Next work day): writes that day.
- Move to `Later` (drag onto Later band, or menu Later): writes `null`, which un-pins. Review returns to auto placement: `Later` when nothing builds on or conflicts with it, else its dependent's day.

Why: no wire, migration or fixture change; `SetPlan` and storage already carry it. Auto placement stays the default, so every existing review renders unchanged (all stored review days are NULL today). An explicit "Later, even with a dependent" needs a tri-state day (new column or sentinel, wire field, fixtures, migration); not worth it, because a review a planned task builds on must merge before that task anyway.

Assumptions for user to check:

- A1. "Columns" means Plan day bands, including `Later`. No kanban by status exists; a status-column move is not possible (status is derived).
- A2. Moving a review to `Later` un-pins it; if a planned task builds on or conflicts with it, it shows on that task's day, not in `Later`.
- A3. A pinned review counts in the overdue rollover of a past day (moves to today with the others). It adds no hours, stays out of overflow, and stays out of the day-off "move tasks starting this day" confirm (same as parked tasks today).
- A4. A pinned review on a later day than its dependent task is allowed; the Plan shows it where the user put it.

## 4. Changes

All paths under `apps/kira-space/` unless noted. No Go code change. No wire change, so no `adewire` fixture update; the `gitrpc` `ContractVersion` covers the git helper only and does not move.

### 4.1 `frontend/src/ade/v2/board/timeline.ts`

- `TimelineEntry`: add `auto: boolean` with doc `/** A review item placed by the merge-order rule: it has no plan day. */`. Update the `day` doc: `A review item with no plan day takes its placer's day.`
- `reviewEntry(taskId, day, end)`: set `auto: true`.
- `buildMineEntries`: drop the `if (t.kind === 'review') continue;`. Instead skip only a review with no plan day (`t.kind === 'review' && board.plan.day[t.id] === undefined`). For a review with a day: `est: null`, `span: 1`, `days: spanDays(cal, day, 1)` (or `[day]`; match the task path's shape), `done: false`, `auto: false`, `pos` from `plan.order` as for tasks. Tasks get `auto: false`. Keep the one sort.
- `placeReviews(mine, reviews, graph)`: pass only unpinned reviews (filter in `buildTimeline`: `kind === 'review' && plan.day[id] === undefined`). In the loop, a pinned review entry is pushed as-is and never acts as a placer: `if (me.kind === 'review') { seq.push(me); continue; }` before the inner loop.
- `buildBand` overdue filter: replace `e.kind !== 'review'` with `!e.auto`. Leave `buildHours` and `overflowOf` review exclusions as they are (reviews carry no hours).
- `mergeOrder` (counts `kind === 'task'`) unchanged.
- Grep `TimelineEntry` object literals (`tests/unit/**`, `frontend/src/**`) and add `auto` where a full entry is built; `Pick<…>` users need nothing.

### 4.2 `frontend/src/ade/v2/board/dropPlan.ts`

- `dropVerdict`, card target: keep refusing itself and a card on a past or day-off band. A review target with `entry.auto` true has no real order slot: treat it as a drop on its band (`movePlanArgs(plan, today, draggedId, null, entry.day)`, still subject to the band past/day-off refusal). A pinned review target (`auto` false) behaves like a task card (move before it). Widen the `entries` `Pick` to include `'auto'`.
- Update the function doc comment (no longer "never on a review item").

### 4.3 `frontend/src/ade/v2/board/menu.ts`

- `taskMenuModel`: push `planEntry(i)` for review cards too. Keep `park` and `changeBaseEntry` inside `if (!review)`. Order for review: after the automation submenu, same slot as for tasks.
- `planEntry`: current day is `i.card.entry.auto ? LATER : i.card.entry.day`, so an auto-placed review shows `Later` checked and disabled, and Today stays enabled to pin it.
- `useTaskMenu.ts` case `'plan'` needs no change.

### 4.4 `frontend/src/ade/v2/plan/AdeTaskCard.vue`

- Wrapper: `data-ade-task=""` always (drop the `card.review` condition).
- `boxClass`: `cursor-grab` for review too; keep `border-l-tone-blue-solid` on review.

No change to `AdeDayBand.vue`, `usePlanDrag.ts`, `AdePlanView.vue`, `queries.ts`: they already work off the task id and `SetPlanArgs`.

### 4.5 `docs/ARCHITECTURE.md`
