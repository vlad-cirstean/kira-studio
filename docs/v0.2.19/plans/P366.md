## 3. Branch tooltips: why ugly, what "the plan's colour coding" is

Every branch tooltip is `AdeTip` on the shared `TooltipContent` (`packages/theme/src/components/ui/tooltip/TooltipContent.vue`): inverted ground `bg-fg text-bg` (#cccccc, #1f1f1f text). Branch tips render `VarText` parts with `kind:'branch'`, which render P355's `BranchChip` (`Badge` variant `default` = `bg-field text-muted-foreground`, or `info`/`warn`). Result: dark chips on a light ground, one tooltip per child element (repo badge, base marker, owner pill, agent icon, name, progress, each chip), each with a sentence fragment. The ade tones (`tones.css`) are dark-only (`docs/ARCHITECTURE.md` Known open items), so they cannot be used on the inverted ground at all.

The plan's colour coding (Plan view, `board/actions.ts`, `tones.ts`, `palette.ts`):

- Status tone `STATUS_TONE`: To do grey, In progress amber, In review blue, Blocked red, Done green.
- Branch tag tone (`tag()`): merged purple; review, preparing, rebasing blue; conflict, failed red; pending amber; not created, parked grey.
- Base marker (`board/baseMarker.ts`): grey own-task parent, blue another task's branch (`outside`), warn while base change pending.
- Task work colour `taskColor(slot)`: card left rail and dot.
- Repo tint `repoTint(repoLinks.repoColorOf(id))`: repo chip.
- Purple border: every branch merged.

Tooltip uses exactly these: tag chip in its tag tone (`AdeChip` = `TONE_TAG_CLASS`), owner chip blue, base BranchChip in its marker variant plus parent task's work-colour dot, header dot in the row's work colour, repo chip in repo tint, merged/deployed chip labels amber when stale.

## 4. Decisions

- Primitive: shadcn-vue Tooltip (reka `Tooltip`), not HoverCard. Content is non-interactive; tooltip gives `pointer-events-none`, shared provider delay (`TOOLTIP_DELAY_MS` 400, skip 300), one-open-at-a-time, `role=tooltip` + `aria-describedby`. HoverCard is for interactive content, opens on any focus (`HoverCardTrigger` `onFocus`, read in `node_modules/reka-ui/dist/HoverCard/HoverCardTrigger.js`) and would add a second ui/* set needing its own consumer.
- Ground: new `TooltipContent` variant `surface` = popover surface (`bg-elevated text-fg ring-1 ring-fg/10 rounded-kira`), the ground the ade tones were built for. No shadow (ARCHITECTURE: tooltip has no shadow), no arrow, same z and motion.
- Plain inverted tips that still carry branch parts (review button, base-rebase actions, Needs) keep the inverted ground; the branch chip inside goes neutral inverted, like `Kbd` already does: `**:data-[chip=branch]:bg-bg/15 **:data-[chip=branch]:text-bg`.
- One rich tooltip per branch row, on one trigger group, replacing the per-element `AdeTip`s.
