## 4. Direct changes

### 4.1 `scripts/lib.sh`: `retry`

Append:

```sh
# retry <attempts> <seconds> <command>... — runs <command> up to <attempts> times, sleeping 10 s,
# 20 s, ... between. <seconds> > 0 bounds each attempt with timeout(1) where it exists (CI's Linux
# runners); 0, or no timeout(1) (stock macOS), runs unbounded and leaves the bound to the CI step.
retry() {
  _retry_max="$1"
  _retry_secs="$2"
  shift 2
  _retry_n=1
  while :; do
    if [ "$_retry_secs" -gt 0 ] && command -v timeout >/dev/null 2>&1; then
      timeout --kill-after=10 "$_retry_secs" "$@" && return 0 || _retry_rc=$?
    else
      "$@" && return 0 || _retry_rc=$?
    fi
    [ "$_retry_n" -lt "$_retry_max" ] || return "$_retry_rc"
    echo "retry: attempt $_retry_n/$_retry_max of '$*' failed (exit $_retry_rc); retrying in $((_retry_n * 10))s" >&2
    sleep $((_retry_n * 10))
    _retry_n=$((_retry_n + 1))
  done
}
```

`_retry_` prefix: `pull-test-images.sh` loops on `_i`; avoid any collision. Exit 124 means the attempt timed out.

In `pull_images`, change both `docker pull -q ...` calls to `retry 3 300 docker pull -q ...`, redirections unchanged (retry's messages land in the per-image `.err` file).

### 4.2 `scripts/retry.sh` (new) and `scripts/ci-apt-install.sh` (new)

`scripts/retry.sh`, for workflow steps:

```sh
#!/bin/sh
# retry.sh <attempts> <seconds> <command>... — lib.sh's retry, callable from a workflow step (P365).
set -eu
SCRIPT_DIR="$(CDPATH= cd -- "$(dirname -- "$0")" && pwd)"
# shellcheck source=./lib.sh
. "$SCRIPT_DIR/lib.sh"
[ $# -ge 3 ] || { echo "usage: $0 <attempts> <seconds> <command>..." >&2; exit 2; }
retry "$@"
```

`scripts/ci-apt-install.sh <package>...`, Linux CI only:

1. Exit 2 with usage if no args. Source `lib.sh`.
2. Write `/etc/apt/apt.conf.d/80-ci-retries` via `sudo tee`, content `Acquire::Retries "3";`, `Acquire::http::Timeout "30";`, `Acquire::https::Timeout "30";`. Same values the spec row names as `-o` flags; a conf file instead so Playwright's own `apt-get` calls (no flags possible) get them too. Idempotent.
3. Up to 2 rounds. Each round: `retry 3 45 sudo apt-get update`, then `sudo timeout --kill-after=10 150 apt-get install -y "$@"`. Success exits 0.
4. Between rounds: if `/etc/apt/apt-mirrors.txt` exists with more than 1 non-empty line, print it, then `sudo sed -i 1d` it, logging the dropped line. Comment why: a slow mirror trickles data, so no apt timeout fires; the runner's list orders mirrors (Azure first, observed in PR #13 logs), and a retry against it stays slow. The edit persists, so the later Playwright apt step uses the next mirror too. Then `sleep 10`.
5. After round 2 fails, exit 1.

Budget: worst case about 2 x (3 x 45 + 150) s plus sleeps, under 10 min. Healthy: about 22 s.

## 5. `pr-rerun-flaky.yml` patch

Supersession check. `pr.yml` concurrency is `pr-${{ github.ref }}` with cancel-in-progress, so ref `refs/pull/<n>/merge`. A new push changes the head SHA; the existing head-SHA guard rejects that run. Gap: close and reopen at the same SHA starts a new run that cancels the old one, both with the same `head_sha`; the head-SHA guard passes it. Rerunning it would cancel the newer run. Close the gap two ways: a newest-run guard (applies to `failure` too), and the supersession annotation check.

Target file content (header comment and job):

```yaml
name: PR flake rerun

# P330: reruns a failed PR CI run's failed jobs, up to 3 attempts in all. P365: also a cancelled run
# whose jobs hit their timeout (a hung network fetch). Never a superseded or hand-cancelled run.
on:
  workflow_run:
    workflows: [PR]
    types: [completed]

permissions: {}

jobs:
  rerun:
    if: >-
      (github.event.workflow_run.conclusion == 'failure' ||
       github.event.workflow_run.conclusion == 'cancelled') &&
      github.event.workflow_run.run_attempt < 3 &&
      github.event.workflow_run.event == 'pull_request'
    runs-on: ubuntu-latest
    timeout-minutes: 5
    permissions:
      actions: write
      checks: read
      pull-requests: read
    env:
      GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
      GH_REPO: ${{ github.repository }}
      RUN_ID: ${{ github.event.workflow_run.id }}
      ATTEMPT: ${{ github.event.workflow_run.run_attempt }}
      CONCLUSION: ${{ github.event.workflow_run.conclusion }}
      WORKFLOW_ID: ${{ github.event.workflow_run.workflow_id }}
      HEAD_SHA: ${{ github.event.workflow_run.head_sha }}
      PR: ${{ github.event.workflow_run.pull_requests[0].number }}
    steps:
      - name: Rerun failed or timed-out jobs when the run is the PR's current head and newest run
        run: |
          set -eu
          [ -n "$PR" ] || { echo "run has no PR; not retrying"; exit 0; }
          # A rerun re-enters pr.yml's cancel-in-progress group: rerunning a stale run would cancel
          # the current one.
          CURRENT="$(gh api "repos/$GH_REPO/pulls/$PR" --jq 'if .state == "open" then .head.sha else "" end')"
          [ "$CURRENT" = "$HEAD_SHA" ] || { echo "run is not for PR #$PR's open head; not retrying"; exit 0; }
          # Same head, newer run (close and reopen).
          NEWEST="$(gh api "repos/$GH_REPO/actions/workflows/$WORKFLOW_ID/runs?head_sha=$HEAD_SHA&event=pull_request&per_page=100" --jq '[.workflow_runs[].id] | max')"
          [ "$NEWEST" = "$RUN_ID" ] || { echo "run $NEWEST is newer for $HEAD_SHA; not retrying"; exit 0; }
          if [ "$CONCLUSION" = cancelled ]; then
            TIMED_OUT=0
            for JOB in $(gh api --paginate "repos/$GH_REPO/actions/runs/$RUN_ID/attempts/$ATTEMPT/jobs" --jq '.jobs[] | select(.conclusion == "cancelled") | .id'); do
              # A job's id is its check run id. Messages verified on PR #11 and PR #13 runs.
              MSGS="$(gh api --paginate "repos/$GH_REPO/check-runs/$JOB/annotations" --jq '.[].message')"
              case "$MSGS" in *"Canceling since a higher priority waiting request"*) echo "job $JOB superseded; not retrying"; exit 0 ;; esac
              case "$MSGS" in *"has exceeded the maximum execution time"*) TIMED_OUT=1 ;; esac
            done
            [ "$TIMED_OUT" = 1 ] || { echo "cancelled, not by a job timeout; not retrying"; exit 0; }
          fi
          # --failed reruns cancelled jobs too.
          gh run rerun "$RUN_ID" --failed
```

3-attempt cap unchanged (`run_attempt < 3`). Hand cancel: annotation is not the timeout message, so no rerun. Known limit: a run where one job timed out and the user cancelled the rest still reruns; rare, not worth matching an unverified hand-cancel string.

## 8. Producing the patches

For each workflow file, in order:

1. Edit `.github/workflows/<name>.yml` in the working tree.
2. Validate: `yq . .github/workflows/<name>.yml >/dev/null` (installed yq is the jq-style one).
3. Write the patch: `{ echo "P365: <one-line why>"; git diff -- .github/workflows/<name>.yml; } > docs/pending-changes/.github__workflows__<name>.yml.patch`. The note line precedes `diff --git`; `git apply` skips it.
4. Restore the real file: `git checkout -- .github/workflows/<name>.yml`.
5. `git apply --check docs/pending-changes/.github__workflows__<name>.yml.patch` must pass against HEAD.
6. `git status` must show no `.github/workflows/` change before committing.

`actionlint` and `shellcheck` are not installed, and fetching actionlint via `go run` was refused in this sandbox. Instead: `sh -n` on every touched and new script, `yq . .github/actions/setup/action.yml >/dev/null`, and `chmod +x` parity with sibling scripts (check `git ls-files -s scripts/setup.sh` mode).
