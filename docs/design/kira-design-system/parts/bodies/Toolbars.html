Toolbars

Every toolbar in Kira Studio is the same object: 28 px tall, holding only 22 px controls, 6 px between siblings, 8 px at the ends and between groups, hairline groups separated by a 14 px rule. What changes between views is the verbs — never the metrics. Below is every toolbar the app has, drawn from the same parts.

01 · Data toolbar — three states

Refresh and Stop are one group and both are always present; Stop greys out rather than disappearing, so the button never moves under the cursor. The pager reads an absolute row range, because "page 3 of 47" answers a question nobody asked.

02 · Filter toolbar — four states

One row, two inputs, one verb. WHERE and ORDER BY are prefixes inside the field rather than placeholder text that vanishes the moment you type. A sort set by clicking a column header says so, so the field is never mysteriously full. The row is permanent — there is no close button, only Clear; a filter bar that can be dismissed makes the grid change height and hides the reason it is showing 41 rows.

WHEREstatus = 'paid' ORDER BYplaced_at DESC empty
WHEREstatus = 'paid' AND total > 50 ORDER BYplaced_at DESC from header applied
WHEREstatus = 'paid' AND ORDER BYplaced_at DESC invalid
Unexpected end of expression after AND — the filter was not sent to the server, so the grid still shows the last good result.

03 · Search toolbar — in-result find

Docks at the bottom of the result it searches, so it is obvious what is being searched. The three modifiers are labelled instead of cryptic: Aa, ab and .* only ever meant anything to whoever wrote them. Search runs over the loaded rows only — it never issues a query. The bar says which rows those are, so a hit count is never mistaken for a count over the whole table; to search further, widen the filter above and fetch more.
