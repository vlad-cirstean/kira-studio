Colour and radius already exist in src/renderer/theme/tokens.css and are reproduced here unchanged. Type, space and control height are new — the app has no scale for any of the three today, which is why forty components each invented their own. Connection colour is re-derived. Every other artboard on this canvas is built from the twelve primitives and sixteen laws below and nothing else: they all load this one stylesheet, so a change here is a change everywhere.

02 Connection colour re-derived — twelve hues at one lightness and one chroma

A connection colour is a label, not a highlight. The old set was mixed saturated brand colours, so red and blue shouted while grey disappeared — twelve different loudnesses for twelve equal things. The new set is generated: every hue is oklch(0.72 0.09 h), eleven hues evenly spaced around the wheel plus a near-neutral grey at C 0.012. Same perceived lightness, same perceived saturation, so no connection can out-shout another and all twelve read as one family against bg.

No colour is the default. A new connection has none, and most stay that way; colour is what you reach for when two of the twelve look alike enough to be dangerous. The rail slot is always 2px whether or not it is painted, so a coloured and an uncoloured connection align to the same pixel and nothing shifts when one is assigned.

Where it is allowed to appear. The group rail in the tree, the rail on a tab, the rail capping the primary toolbar — so the colour is present in the view you are actually working in, not only in the chrome you selected from — the dot before the connection name in a view header, and the dot on an operations row. Not the top of the editor panel: the tab strip holds tabs from several connections at once, and a rail above it would colour the panel for whichever one is in front. Nowhere else: not a panel background, not text, not a border. There is one palette and no intensity setting; twelve hues already share a lightness and a chroma, so there is nothing left to turn up or down.

03 Type new — replaces 6 unrelated sizes (9 / 10 / 11 / 12 / 13 / 14px)

Two roles. Chrome — tree, tabs, toolbars, status bar, dialogs — is set in the UI face. Data — grid cells, values, identifiers, editors, durations — is set in mono. The app currently sets everything in SF Mono, including buttons and labels; that is the single largest reason it does not read as a designed product.

07 Engine marks eight — drawn here, not vendored

These are our own redrawings of each engine's mark, not the official brand assets: one 16px viewBox, one currentColor path each, no fills or gradients, so an engine mark obeys law 02 and takes the connection colour like any other icon. Holes — Slonik's eye, the sea lion's eye, the leaf's midrib — are cut with fill-rule="evenodd" rather than painted in the background colour, so they stay right on a hovered or selected row. Shipping the real trademarked marks instead is a licensing decision, not a design one; if that decision is made, these are drop-in replacements at the same size and weight.

09 Composition laws sixteen — what makes two unrelated screens look like one app
  1. 01A toolbar is 28px tall, holds only h-sm controls, separates siblings by s-3, groups by s-4, and pads its ends by s-4. Every toolbar in the app — data, DDL, console, stream — is the same object.
  2. 02Every icon occupies a 16px box with a 13px glyph inside it. Icons are never sized to their control; only the box's container changes.
  3. 03One border colour per role. border outlines surfaces, border-strong outlines things you type into or press. Nothing else draws a border.
  4. 04Hover is hover, selection is select, pressed is bg-input. No component invents its own hover tint or lightens a background by hand.
  5. 05Focus is always the same ring — 1px focus, inset on filled controls, outset on buttons. It is never a colour change alone.
  6. 06Panels float on bg-chrome. A panel is bg + 1px border + r, separated from its neighbours by s-2. No shadows anywhere in the workbench; shadows belong to dialogs and menus only.
  7. 07Connection colour is a 2px rail and a 5px dot, nothing else — the tree group, the tab, the cap on the primary toolbar, the dot in a view header and on an operations row. It caps the toolbar rather than the panel because the tab strip above carries several connections at once. Never a background, never text, never a border. Most connections have no colour, and the rail slot stays reserved so nothing moves when one is set.
  8. 08Mono is for data. If a string came out of a database — a value, an identifier, a query, a duration — it is mono. If the app wrote it, it is UI.
  9. 09Every editor opens with the same three rows in the same order: a view-head naming the target, then the primary toolbar, then — where the view can be narrowed — the filter toolbar. Grid, documents, key/value, stream, console and DDL differ only in what sits inside those rows, never in the rows themselves.
  10. 10The left edge of a toolbar is fixed. Refresh, then Stop, then the separator. Stop is always present — disabled when nothing is running, red-lit while it is — so the way to cancel is in the same place in every view rather than appearing only once work starts.
  11. 11Rows of data are one object. thead/th/tbody/tr/td with h-row rows and mono cells serve the grid, key/value fields, stream messages and console results alike. A "different kind of data" is not a reason for a different table.
  12. 12Work in progress is a ring and an elapsed time, in the toolbar that started it. A bar across the top of the view only said "something is happening"; the ring sits beside Refresh, Run or Poll, so it says which thing — and the number next to it is the only place a duration is reported. Idle keeps the same slot, as a still ring holding the last duration, so nothing reflows when work starts. The view never blanks.
  13. 13Three strips, one shape. strip err for what failed, strip warn for what is about to be destructive, strip note for what the view is quietly doing. Each is 26px, sits directly under the toolbars, carries an icon, one sentence, and — when there is one — the action that resolves it. Errors never open a dialog.
  14. 14No custom title bar. macOS draws it. The status bar is the app's only full-width chrome: on the left, one readout answering where the caret is — the selected cell, field, document or line — then cache and latency, then the panel toggles and settings as icon-only buttons behind a hairline. Row counts, pending edits, durations and read-only live in the toolbars, and are never repeated here; the editor status line was deleted for saying all of it twice.
  15. 15Empty is a state, not a blank. Every empty region says what is missing and offers the one action that fills it — no tabs, no connections, no results and no matching rows all use the same centred object.
  16. 16Filter narrows the query; search walks what you already have. The filter row is part of the view and cannot be closed — closing it hid the reason a table looked short. Search never issues a query: it walks the rows that are already fetched, and says so next to the field.
