## 2. Decisions

### 2.1 Bar thickness

- `MARK_SHAPE.rail`: `w-0.5` (2px) -> `w-1` (4px). One token, so every rail in both apps moves
  together, incl. the Repositories dialog list (same mark, same design rule).
- 4px fits: depth-0 rows start content at 6px (`rowIndent`), leaving a 2px gap. 3px is off the
  density scale (`ARCHITECTURE.md` "Density scale is 0.5, 1, 1.5, 2, 3, 4").
- Unchanged: `bar` (tab chips, StudioStart list), `band` (view toolbars), `dot`, `swatch`. They are
  not panel marks.
- Comments saying "2px rail" for the tree: `TreeRow.vue:64` -> "4px rail";
  `views/definition/DefinitionView.vue:211` lists tree, tab and toolbar together: drop the width
  from that sentence rather than state two.

### 2.2 Scope of reorder

| List | Reorder within | Across | Collections/groups themselves |
|---|---|---|---|
| Connections | the one flat list | n/a (no folders) | n/a |
| Scripts | own set: ungrouped, or one collection | **no**. Moving between collections stays the existing "Move to collection" menu. Reason: one id list per Sortable instance, and a cross-set drop needs collection change plus position in one write. Out of scope entirely, not half-built. | yes: collections reorder among themselves |
| Repos | top-level repos | n/a | worktree rows are not reorderable (git order) |

- While a panel search is active, drag and keyboard moves are disabled (filtered view; the
  position of hidden rows is ambiguous). Drag is also disabled with fewer than 2 items in a set.
- Order is app-wide (DB rows), same in every window, synced by the existing broadcasts.
- Everything else reading these lists (connection pickers, DB MCP `list_connections`, script
  launchers, ADE repo tabs) follows the user order for free; no change there.

### 2.3 Drag UX

- Whole-row drag, no grip (panel rows stay compact; TabStrip precedent). 4px pointer tolerance
  before a drag starts, so click, double-click and the twisty keep working.
- Dragged row: `SORTABLE_GHOST_CLASS` (`opacity-50`, U76). Sortable lists show the live slot
  (Sortable moves the ghost). The Studio tree shows a 2px drop line on the target connection row
  edge (section 5).
- Esc cancels a running drag, item returns.
- Cursor stays `cursor-default` (rows are not handles per the P267 cursor rule).

### 2.4 Keyboard alternative (required, not optional)

- Alt+ArrowUp / Alt+ArrowDown (`list.moveUp` / `list.moveDown`, mac Option) move the focused item
  one place within its set. Focus stays on the moved item.
- Scripts, collections, repos: `useSortableReorder` `keyboard: true` (existing convention, every
  caller passes it).
- Connections: context menu items "Move up" / "Move down" on connection rows, printing the chords,
  disabled at the ends or while searching. The chords dispatch through the menu builder like every
  other tree chord. Menu items also give mouse users a non-drag path.

### 2.5 Libraries

- Use: vue-draggable-plus 0.6.1 (MIT) through `useSortableReorder` for scripts, collections,
  repos; VueUse 15.0.0 (MIT) `useMouse`, `useElementByPoint`, `useRafFn`, `useEventListener` for the
  Studio tree. **No new dependency.** `git diff package.json` must stay empty.
- Declined for the Studio tree:
  - SortableJS/vue-draggable-plus: requires every item mounted in DOM flow. The tree mounts only
    the visible window, rows are `absolute` + `translateY` (`VIRTUAL_ROW_CLASS`), and child rows
    interleave connection rows. DOM moves neither show nor map to list indices.
  - `@atlaskit/pragmatic-drag-and-drop` (Apache-2.0, license fine): built on native HTML5 DnD,
    which Playwright cannot drive (P137 decision above).
  - What remains hand-written is index math (`edge` from pointer Y vs row midpoint) plus an
    auto-scroll step, on top of VueUse pointer primitives, following `usePlanDrag`.

## 4. Shared Sortable pieces (workbench)

- `sortableReorder.ts`: new option `keyboardHandle?: string`. When set, a keyboard move fires only if
  `e.target.closest(keyboardHandle)` is inside the item. Needed where an item contains other
  focusable rows: a collection entry holds script rows, a repo entry holds worktree rows. Without
  it, Alt+Up on the first script of a collection (inner list has no `to`, does not
  `preventDefault`) would bubble to the outer list and move the whole collection. Existing callers
  unchanged.
- New `packages/workbench/src/components/SortableList.vue` (`<script setup lang="ts">`): props
  `ids: readonly string[]`, `draggable: string`, `handle?`, `keyboardHandle?`, `disabled?: boolean`;
  emit `move: [fromId: string, toId: string]`; template `<div ref="el"><slot /></div>` (attrs fall
  through for classes). Calls `useSortableReorder(el, () => props.ids, (f, t) => emit('move', f,
  t), { draggable, handle, keyboardHandle, disabled: () => props.disabled, keyboard: true })`.
  Reason: one Sortable per collection needs a component per group (composables cannot run in a
  `v-for`). vue-draggable-plus `start(el)` destroys and recreates on a new element, so a `v-if`
  remount of a collapsed group rebinds cleanly.

### 5.3 Connections (Studio project tree)

New composable `apps/kira-studio/frontend/src/project/connectionReorder.ts`:

```ts
export function useConnectionReorder(opts: {
  container: Ref<HTMLElement | null>;
  ids: () => readonly string[];          // connectionsStore.records order
  disabled: () => boolean;               // search active or < 2 connections
  rowHeight: () => number;
  onReorder: (ids: string[]) => void;
}): { draggingId: Readonly<Ref<string | null>>; drop: Readonly<Ref<{ id: string; edge: 'top' | 'bottom' } | null>> }
```

- Start: `useEventListener(container, 'pointerdown')`, primary button only, target
  `closest('[role="treeitem"][data-kind="connection"]')` (sticky band rows count: same connection).
  Read `data-connection-id` (new attribute on `TreeRow`, connection rows only). Record start point.
  Do not `preventDefault` (focus and click must still happen).
- `useEventListener(document, 'pointermove' | 'pointerup' | 'pointercancel')`; document, not
  pointer capture, because autoscroll can unmount the source row. Drag starts after 4px; export the
  tolerance from `sortableReorder.ts` (`DRAG_TOLERANCE_PX = 4`, also used for its
  `fallbackTolerance`) so both paths share one value.
- Hit test while dragging only: `useMouse({ type: 'client' })` + `useElementByPoint` with a
  `useRafFn` scheduler, paused when idle (`usePlanDrag` pattern). Target = connection row under the
  pointer whose id differs from the dragged one; `edge` = pointer Y above or below the row's
  vertical midpoint. Over a child row, background or the dragged row: `drop = null`.
- Auto-scroll: `useRafFn` while dragging; pointer within one row height of the container's top or
  bottom edge scrolls `scrollTop` by `rowHeight / 4` per frame.
- End: `pointerup` with a target -> new order = remove dragged id, insert before (`top`) or after
  (`bottom`) the target; call `onReorder` only if the order changed. `pointercancel`, Esc
  (`useEventListener(document, 'keydown')`), or no target -> cancel. Reset state, pause loops.
