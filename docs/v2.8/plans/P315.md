# P315 plan: short-text distill mode (rewrite)

One sequential implementer, then a pilot loop (implementer runs, Opus judge scores). No stream
split (see "Streams").

## Ask

SPEC row: distill of small pasted/in-memory text (a code comment, not a file read from disk) gets
its own single-call rewrite path instead of extract, verify, merge. Keep every non-obvious fact,
drop trivia, keep the input's form. Plan decides prompt, gates and API shape. Includes a pilot on
fresh comments, Opus-judged, results reported to the user.

User rules (via orchestrator): one comment per call, no batching. No deterministic or regex
stripping of content; the model does the cleanup. Mechanical gates only ACCEPT or REJECT a rewrite
(reject falls back to the original), never edit content.

## Design

### 1. Trigger and API shape

Decision: explicit mode, no size trigger. `mode` is `facts` (default, unchanged pipeline) or
`rewrite`. Size is only a cap on `rewrite`: `RewriteMaxRunes = 2000`.

Why not auto by size: size cannot tell a memory note from a form-bearing snippet. The three
short-text facts callers above (UI notes with run trivia, docshistory sections, flow test) want fact
lines for the store; a size trigger would silently switch them to a rewrite with no lines. Rewrite
is a different product (same-form text, not memory lines), so the caller names it.

Why 2000: covers 99% of repo comments (p99 under 1500); the 43 longer ones keep facts mode or stay
untouched in P318. A "small text" path stays one call with bounded cost.

Go, `internal/memory/importer`:

- `distill.go`: consts `ModeFacts = "facts"`, `ModeRewrite = "rewrite"`, `RewriteMaxRunes = 2000`,
  `RewriteMaxContextRunes = 6000`, `RewriteWidth = 100`; stages `StageRewrite = "rewrite"`,
  `StageCheck = "check"`.
- `DistillRequest` gains `Mode string` ("" means facts), `Context string` (rewrite only, read-only
  code around the text), `Check bool` (rewrite only, see section 3).
- `DistillResult` gains `Mode string` and `Rewrite *RewriteResult` (nil in facts mode).
- `Distill` (`:148`): validate mode first. `rewrite` with `Path` set, or `Context`/`Check` without
  `rewrite`, or unknown mode: `invalid(...)` (`memory.ErrInvalid`). Rewrite text over
  `RewriteMaxRunes`: `invalidReason(ReasonTooLong, {count, max: 2000})` (reuses the `tooLong`
  catalog body "The input is {count} characters. The limit is {max}."). Context over its cap:
  `invalid`. Then dispatch to `d.rewrite(ctx, req)` before `chunkFile`. Facts path unchanged.
- New `rewrite.go`: `RewriteResult`, `DroppedSpan`, `RewriteCheck`, `ClaudeAgent.Rewrite`,
  `ClaudeAgent.CheckRewrite`, `(Distiller).rewrite`. Methods on `ClaudeAgent` only; the `Agent`
  interface (`agent.go:7-14`, import runner) does not widen.
- New `rewrite_gate.go`: pure accept/reject gate functions (section 3).

```go
// RewriteResult is the rewrite path's outcome. Changed is Text != input. Gate names the check that
// rejected a draft; "" with Changed false means the input was already clean (accepted, no-op).
type RewriteResult struct {
	Text    string        `json:"text"`
	Changed bool          `json:"changed"`
	Gate    string        `json:"gate"`    // "" unless a gate rejected the draft
	Reason  string        `json:"reason"`  // the model's one-sentence reason
	Draft   string        `json:"draft"`   // the rejected rewrite, when a gate rejected one
	Dropped []DroppedSpan `json:"dropped"` // what the rewrite left out, with why; empty when unchanged
	Check   *RewriteCheck `json:"check"`   // nil unless Check ran
}
type DroppedSpan struct{ Text, Why string } // json "text", "why"; Why: tag, history, restatesCode, trivia
type RewriteCheck struct {
	OK    bool     `json:"ok"`
	Lost  []string `json:"lost"`
	Wrong []string `json:"wrong"`
}
```

Three outcomes, all valid results:

- rewritten: `Changed true`, `Gate ""`.
- unchanged: model returned the input verbatim (already clean). `Changed false`, `Gate ""`. An
  accepted no-op, never a failure: re-passing a distilled comment must change nothing.
- kept: a gate rejected the draft, input returned. `Changed false`, `Gate` set, `Draft` set.

Gate codes (consts `GateGrew`, ...): `grew`, `form`, `indent`, `width`, `directive`, `tokens`,
`check`, `output` (unusable output twice). No minimum-shrink rule of any kind.

`DistillResult` in rewrite mode: `Chunks 0`, `InRunes` of input, `OutRunes` of `Rewrite.Text`,
`CostUSD` sums every call (draft, retry, check), `Lines`/`Unresolved` nil.

### 2. Prompt and output contract

Input sent on stdin (JSON): `{"text": "<verbatim input, markers and indentation included>",
"context": "<optional code around it>"}`.

Decision: the caller sends the whole text with comment markers and indentation; no split of
marker, indent and body. Splitting and re-adding them would be code editing the output, which the
user's rule bans. The model keeps the form; gates reject any rewrite that breaks it.

Output: structured output via the existing `--json-schema` (`claude.go:134`), so free-text JSON
breakage (sonnet1 #26) cannot happen. No `action` field: the model always returns the full text,
the input verbatim when it is already clean, so `Changed` is plain `draft != input` with no model
flag to trust. `ErrClaudeOutput`, or an empty or whitespace-only `text`, is unusable output: retry the call once; second time keep the original, `Gate "output"`, no error.
Other errors (auth, rate limit, timeout, cancel, budget) return as errors, no retry, like facts mode.

New registry entries (`registry.go`, after `MemoryMergeRules`):

- `MemoryRewriteSystem`, ID `memory.rewrite.system`, `KindSystem`, `spaceApp`, `NextCall`,
  `RequiredFragments: memory.dataHygiene`, vars `RewriteVars{MaxWidth int json:"maxWidth"
  prompt:"required"}` example `{MaxWidth: 100}`. Default:

```text
You clean one short text, usually a code comment: drop its trivia, keep every fact and its form. Output only the schema.

{{template "memory.dataHygiene"}}

Input: "text" (verbatim, with its comment markers and indentation) and optional "context" (code around it; read it, never rewrite or quote it).

Keep, exactly:
- Every non-obvious why, constraint, workaround, limit, consequence and cross-reference to another file, function or setting.
- Cause links (because, so, since, otherwise, unless). Splitting a sentence keeps its link.
- Negations (not, never, no, only, except), numbers, units, identifiers, paths, error strings, quoted literals and backticked spans, verbatim, backticks included.
- Qualifiers of scope and place ("here", "itself", "in templates", "per call").
- What the declaration below holds, when the text defines it.

Drop:
- Phase, plan and review tags (P107, M2, D7, F3, C5 §3.1, v1.8, iter2, "Part 2", "round 2"). Keep the fact a tag labels; when a tag is the only name of a referenced thing, drop its clause only if the rest stays true.
- History narration ("was X, now Y", "previously", "no longer", "until now", "used to"): keep the current fact.
- A sentence that restates what the context code shows.
- Filler, hedges ("just", "really", "basically", "actually", "simply"), pleasantries, and articles where meaning stays clear.

Form:
- Same form as the input: same comment markers (//, /** */, /* */, <!-- -->, #). JSDoc stays JSDoc; a Go doc comment starts with the symbol name; Markdown stays Markdown.
- Each line starts with the leading whitespace of the input line it replaces; JSDoc lines keep their " * " prefix.
- Lines at most {{.MaxWidth}} columns, indentation and markers included; a tab counts 4. Wrap and reflow; sentences may share a line.
- Terse: fragments fine, active voice, present tense, short word over long phrase. No invented abbreviations, no arrow connectors.
- Never add a fact, example or claim the text does not state. Never reword an identifier, literal or error string.
- A directive (//go:build, //go:generate, //go:embed, //nolint, eslint-disable, biome-ignore, @ts-expect-error, @ts-ignore, /// <reference, a licence header) stays byte for byte.
- Never longer than the input.

Already clean: a text with nothing from the Drop list, within the width, is returned verbatim, byte for byte. Never pad it, reword it or shorten it to look different. A text you cleaned before comes back unchanged.

"text": the full result, markers and indentation included; the input verbatim when already clean.
"dropped": each word, tag or clause of the input missing from "text", with "why": "tag", "history", "restatesCode" or "trivia". Empty when "text" is the input.
"reason": one short sentence.
```

Schema:

### 3. Gates (accept or reject only)

A usable draft equal to the input (byte for byte) is the unchanged outcome: accepted, no gate
runs, no check call. Otherwise run in this order. First failure sets `Gate`, keeps the original as
`Text`, puts the draft in `Draft`, `Changed false`. No gate ever edits text. A regexp only
classifies and counts. No gate ever rejects a draft for failing to shrink.

1. `grew`: runes of draft > runes of input. Equal length passes. Why keep a length guard at all:
   the prompt's job is to drop trivia, never to add; growth is the bloat failure distill showed
   (#19 345 to 568 chars, #11 171 to about 260, #20 restated rule) and it costs the reader. Known
   cost: a reflow-only fix of an over-width input that adds line breaks and markers can grow and is
   kept as the original; the `width` gate already tolerates the input's own width, so nothing
   regresses.
2. `form`: marker of the input's first non-blank line, after its indentation, longest match of
   `///`, `//`, `/**`, `/*`, `<!--`, `#`. `//` or `#` family, every non-blank input line starts with
   it: every non-blank draft line must too. `/**`, `/*`, `<!--`: draft's first non-blank line starts
   with the same opener and its last non-blank line ends with `*/` or `-->` like the input. No
   marker: no form check. Evidence: distill's `/** */` demotion.
3. `indent`: leading whitespace of the draft's first non-blank line equals the input's; the set of
   leading-whitespace strings over non-blank draft lines is a subset of the input's set. Evidence:
   sonnet1 #30, #36, #38.
4. `width`: column count per line, tab = 4, others 1 per rune. Each draft line <= 100, or, when the
   input's widest line is over 100, the draft's widest line <= the input's widest. Never widens.
   Evidence: sonnet1 23/44 over 100.
5. `directive`: each input line containing a directive token (the list in the prompt, same strings)
   appears verbatim in the draft.
6. `tokens` (backstop): protected tokens of the input must each occur in the draft, unless the
   token is a substring of some `dropped[].text`. Protected: backtick spans `` `[^`\n]+` ``, double-quoted
   spans `"[^"\n]{1,80}"`, numbers `\b\d+(?:[.,:]\d+)*\b`, dotted or path identifiers
   `\b[A-Za-z_]\w*(?:[./]\w+)+\b`, camelCase `\b[a-z][a-z0-9]*[A-Z]\w*\b`, multi-hump PascalCase
   `\b[A-Z][a-z0-9]+[A-Z]\w*\b`, snake_case `\b[A-Za-z0-9]+_\w+\b`. The `dropped` excuse covers
   tags and narration numbers, the false positives sonnet1 found (#19, #31, #34). Kept as a
   backstop: it caught 0 meaning errors in sonnet1, but it rejects a lost backtick span or literal
   (distill's 41 lost spans).
7. `check`, only with `Check`: second call, `MemoryRewriteCheckSystem`, input `{"original",
   "rewrite", "context"}`. `ok false`, or unusable output (no retry), sets `Gate "check"`; `Check`
   holds the verdict either way.

Declined: a negation-count gate. No negation loss in any experiment, and "do not X" to "never X"
rephrasing would false-reject. The check and the judge cover it.

Check default: off. Reasons: sonnet1 single call measured meaning-level bad 4% (2/45) without a
verifier; r2's verifier false-alarmed 2 of 6 rejections and false-passed about 3% on meaning; it
doubles cost (about 0.0096 to about 0.018 USD per comment); the UI case has a human reading the
output. The pilot runs every unit with `check: true` and records draft plus verdict, so both arms
are measured on one sample (section 5). P318 (unattended bulk) chooses `check: true` on its own if
the pilot says so; flipping this default is the user's call after the pilot.

## Resolved ambiguities

- Trigger: explicit `mode`, no size trigger; 2000 runes is a cap on rewrite only (section 1).
- "In-memory text": `text` only; `rewrite` with a path is refused. A file's comment arrives as text.
- Clean input is a no-op (user decision): `Changed` is `draft != input`; no shrink gate, no
  `action` flag; `grew` (never longer) is the only length guard, equal length passes.
- No delete action: the model only rewrites or returns the input. An all-trivia comment's removal is P318's
  policy with its own gate.
- No retry on gate rejection, only on unusable output. Width misses are a prompt matter for the
  pilot loop.
- `context` is MCP and Go only; the view sends none. The pilot sends it, as P318 will.
- Draft and check verdict ride the Go and MCP result for audit and the pilot; the UI schema omits them.
- Comment markers and indentation stay inside the text the model sees; gates enforce form.
- Pilot model: setting default `sonnet` through temp homes, same as docshistory.
- `P318.md` conflicts with this design (batching, cost basis); left for P318's replan.
