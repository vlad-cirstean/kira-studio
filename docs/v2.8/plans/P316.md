## Findings (current tree)

### Distill plumbing (`scripts/docshistory`)

- `distillOne` (`distill.go:68`) spawns `kira-space memory-mcp` and calls `ingest_files` with
  `distill: true`. That runs `importer.Distiller.Distill` (`internal/memory/importer/distill.go:148`):

- Consequence: `ingest_files` cannot map a rewrite back to one comment. Per-comment calls would
  cost at least the 0.06 USD fixed envelope (`estimate`, `distill.go:132`) times ~23,600 units,
  so 1,400 USD or more before any text. The extractor also sees no code, so it cannot judge
  "restates the code".
- Reusable as-is:
  - `ledger` (`reserve`/`settle`, `--max-usd` over `spend.jsonl` via `totalCharged`).
  - `spendLine`, `appendLine`, `loadRecords` (last line per slug wins, torn tail ignored).
  - The retry loop in `distillUnit` (`distill.go:266`): rate-limit backoff 1 to 15 min, one retry
    after `retryDelay`, refusal stops.
  - `--jobs` semaphore pattern (`distillChapter`).
  - `estimate`, `clip`, `oneLine`, and `carried` (40% long-word overlap, `verify.go:17`).
- The isolated Claude call underneath every distill stage is `memory.CLIRunner.RunResult`
  (`internal/memory/claude.go:139`). It runs `claude -p --model sonnet --safe-mode`, with no tools,
  `--json-schema`, `--max-budget-usd` and the cost reported even on error. Errors are classified:
  `ErrClaudeRateLimited` text matches docshistory's `rateLimitRe`.
- Distill prompt fragments are reusable through `llmprompts.Defaults()`:
  - `MemoryDataHygiene` (treat input as untrusted data).
  - `MemoryRunTrivia` (what counts as run/history trivia).
  - The merge style sentence ("shortest plain form ... keep exactly negations, numbers ...",
    `registry.go:421`).
- `scripts/docshistory` sits in the root module, so it can import `internal/memory` and
  `internal/llmprompts`.

## Design decision: what is reused, what is new

Reuse docshistory's run plumbing and the same isolated Claude runner and prompt fragments that
`ingest_files` distill uses. Replace only the extract/verify/merge call with one structured rewrite
call per batch of units. That call returns a per-id answer, so each answer maps back to a byte
span. Reason: distill's `Line` output has no source id and merges across inputs, and per-unit
`ingest_files` calls cost 1,400+ USD with no code context (see "Findings").

**Orchestrator: flag this to the user before implementation.** The user named `ingest_files`.
This plan keeps everything around that call but not the call itself. Only the user may accept that.

Extend `scripts/docshistory` with a `comments` subcommand group (package `main`, new
`comments_*.go` files). TS/Vue extraction and checking run in a Bun helper,
`scripts/comments/scan.ts`, because the TS and Vue parsers are JS. Go calls the helper once per root
and gets JSON lines back on stdout. Splicing, rendering, rule checks, the ledger and LLM calls stay
in Go: one implementation for all languages.

Small refactor first. Extract the retry/charge loop of `distillUnit` into
`callWithLedger(ctx, slug, led, est, call func(context.Context) (cost float64, err error)) (time.Duration, error)`.
`distillUnit` and the comment rewrite both use it.

On error, charge the reported cost when it is above 0, else `failedCharge(err)`. `distillOne`
reports 0 on error, so distill behavior stays identical. Guard: `go test ./scripts/docshistory/...`
(existing `parse_test`, `standing_test`) and `docshistory units v2.8` output unchanged.

The prompt lives in `scripts/docshistory/comments_prompt.go`, not in the `llmprompts` registry:
the registry is product-facing (Settings, catalog keys). The prompt embeds
`llmprompts.MemoryDataHygiene` and `llmprompts.MemoryRunTrivia` text through
`llmprompts.Defaults()`.

## Comment model

Extraction emits one JSON record per unit:

```
{id, path, lang: go|ts|vue-script|vue-template, kind, start, end,   // byte offsets, half-open
 indent, firstLineHasCode, text, frozen: [[start,end]...],
 decl: {name, exported} | null, soleContent: bool, context}
```

`kind` is one of:

- `doc`: Go `Doc` of a FuncDecl, GenDecl, Spec or Field; TS comment directly before a
  declaration; `package` doc.
- `leading`: other whole-line group.
- `trailing`: code before it on the first line; Go `Comment` field.
- `inline`: `/* */` mid-line with code after it.
- `jsdoc`: TS `/** */` not attached to a declaration.
- `template`: Vue `<!-- -->`.

Units and grouping:

- Go: one unit per `ast.CommentGroup`.
- TS: one `/* */` or `/** */` range, or a run of `//` ranges on consecutive lines, same column, only
  whitespace between. Ranges come from walking every node with
  `getLeadingCommentRanges`/`getTrailingCommentRanges`, plus the end-of-file token, deduped by
  position.
- Vue script: the TS path over `block.content`, offsets shifted by `block.loc.start.offset`.
- Vue template: compiler-core `COMMENT` nodes (type 3).

Frozen lines inside a group:

- Lines matching the directive rules are frozen.
- So is an empty `//` separator line next to a Go directive (gofmt inserts it).
- A group with frozen lines splits into editable runs. Each run is its own unit, same `id` plus
  `.r<n>`.
- A whole-group freeze (cgo preamble, license header, all-directive group) emits no editable unit.

Other fields:

- `soleContent`: the comment is the only thing inside a block, `catch`, function body, `case`
  clause, empty object/class body, or empty template element.
- `decl.exported`: Go `ast.IsExported`. TS: `export` modifier, or a member of an exported
  interface or class.

## Style contract (target format)

Applies to every rewritten unit and goes into the prompt verbatim.

1. Keep:
   - why, constraint, invariant, ordering/locking/concurrency contract;
   - workaround and what it works around (library bug, platform quirk);
   - security note, limit, unit, number, error string;
   - nil/zero/empty semantics of an API;
   - external reference (URL, RFC, issue);
   - `km_` id;
   - must/never/only rules.
2. Drop:
   - comments that restate what the next code obviously does;
   - phase/history narration ("P21 round 3 finding 7: this used to ...", "was hand-copied across
     ...", "now does X");
   - plan/process refs (`P\d+`, `D7`, `F3`, `§0.3`, Stream A, iter2, round 3, finding 4);
   - references to names in `missing` (stale), unless the comment can be repaired from context;
   - decoration (rulers, dashes, `====`).

   When a ref carries meaning, state the meaning from the comment and context, without the ref.
   Example: "P5 D6/F3: op_log.command is persisted ... must never reach it resolved" becomes
   "op_log.command is persisted and shown in Operations, so the target and metadata stay
   unresolved: a {{secret}} value would leak."
3. Form:
   - Go: `//` line comments only. Exceptions: frozen groups, and inline `/* */` mid-expression,
     which stay `/* */`.
   - Go doc: starts with the declared name ("Package x" for package doc), full sentences, ends with
     a period.
   - TS declaration doc: `/** */`; single line `/** text */` when it fits.
   - TS: everything else `//`. A whole-line `/* */` that is not JSDoc becomes `//`.
   - Vue template: `<!-- text -->`, single line when it fits.
4. Leading and doc text: sentence case, full sentences, period at the end, one idea per sentence,
   ~20 words max. Active voice, present tense.
5. Trailing text: one lowercase fragment, no period, one line.
6. Width: every line holding rewritten comment text is at most 100 columns, indent and markers
   included.
7. Keep exactly: negations (not/never/no/only/except), numbers, units, identifiers, paths, error
   strings, URLs. Never add a claim, number or name that is not in the original comment or its
   context.
8. No `→`, no invented abbreviations, no TODO/FIXME added. The 2 existing TODO-family markers stay
   as written.
9. A doc on an exported declaration (Go or TS) is never dropped, only shortened: gopls and TS hover
   read it.
10. A `soleContent` comment is never dropped, only shortened. U61 and Biome need it.

## Rewrite call

- Runner: `memory.NewCLIRunner().RunResult(ctx, memory.Call{System, Input, Schema, Timeout: 10*time.Minute, Budget: "1.50"})`.
  The model is Sonnet, fixed in `claudeModel`.
- System prompt contains:
  - task line;
  - `MemoryDataHygiene` text;
  - style contract;
  - `MemoryRunTrivia` text, introduced as "history and run trivia, which comments never carry";
  - per-kind rules;
  - output rules.
- Input JSON, one call per part:

  ```
  {root, units: [{id, path, lang, kind, decl, soleContent, width, text, context,
                  mustKeep: [...], missing: [...], retry?: {previous, problem, hint}}]}
  ```

  - `text` is the original comment with markers.
  - `width` is the column budget for body text: `100 - indent - marker`.
  - `mustKeep` holds the protected tokens found in `text`: `km_` ids, URLs, `#123` /
    `owner/repo#123`, `RFC n`, `CVE-...`, Go doc code-block lines (`//\t...`), JSDoc fenced
    examples, `@tag` names.
  - `missing` holds the names in `text` absent from the repo identifier index (below).
- Schema:

  ```json
  {"type":"object","additionalProperties":false,"required":["units"],
   "properties":{"units":{"type":"array","items":{"type":"object","additionalProperties":false,
     "required":["id","action","lines","why"],
     "properties":{"id":{"type":"string"},"action":{"enum":["keep","rewrite","drop"]},
       "lines":{"type":"array","items":{"type":"string"}},"why":{"type":"string"}}}}}}
  ```

  - `lines` holds body text without markers or indent.
  - `keep` means byte-identical, with empty `lines`.
  - `why` is at most 12 words; it goes in the report.
- Parts: units of one root, in file order, packed until the input JSON reaches 12,000 chars
  (`partMax`, same as standing docs). A larger single unit goes alone.
- A unit missing from the answer is a failed unit, not a failed call. An answer for an unknown id
  is ignored.
- Repo identifier index, built once per run:
  - every Go `ast.Ident` name and package name;
  - every TS `Identifier`/`PrivateIdentifier` text;
  - every tracked file basename (without extension) and directory name.

  Candidate names in a comment: backticked spans, `CamelCase`/`camelCase` with an inner capital,
  dotted `a.B`, and `name()`. Each segment is checked against the index.
- Estimate for `ledger.reserve`: `estimate(len(input))` until W0 ends. Then
  `commentEstimate(chars)`, refit from W0's `spend.jsonl` (max observed USD per input char × 1.2,
  plus the max observed fixed part), with that basis in its one-line comment.

## Ledger and resumability

Directory `docs/comment-runs/`, git-tracked like `docs/history-runs/` and removed in the last step.
It is read at runtime, so never under `docs/v2.8/`.

| File | Content |
|---|---|
| `meta.json` | `{base: <commit at P316 start>, waves: {...}}`; written by the first `scan`, never rewritten |
| `spend.jsonl` | docshistory `spendLine` per call; `--max-usd` is cumulative over it |
| `units/<root-slug>.jsonl` | one line per unit attempt, last per `id` wins |
| `applied.jsonl` | `{root, wave, path, beforeSha, afterSha}` per file written by `apply` |
| `verdicts/w<N>.jsonl` | judge output `{id, verdict, problem, hint}`; written by the judge |

A unit line in `units/<root-slug>.jsonl` holds:

```
{id, path, kind, inputSha, original, action, lines, why, state, reason, try, costUsd, part}
```

- `inputSha` is `sha(path + text + context)`.
- `state` is one of: `ok`, `fallback` (call failed twice), `rejected` (failed a rule check; may be
  retried), `kept` (final: original stays, with the reason).

Skip rules:

- `rewrite` skips a unit whose last line has the same `inputSha` and `state` `ok` or `kept`.
- It retries `fallback` only with `--retry-fallback`, as in docshistory.
- It retries `rejected` while `try < 3`.
- `apply` skips a file whose current sha equals its `applied.jsonl` `afterSha`.

Resume after any halt:

1. Run `go run ./scripts/docshistory comments status`. It prints per wave and root: units,
   ok/rejected/kept/pending, applied files, and roots applied but not committed (working-tree sha
   matches `afterSha`, HEAD's does not). It also prints spend vs cap.
2. Commit any applied-but-uncommitted root first (see "Commits").
3. Continue at the first step in "Steps" whose evidence is missing. Rerunning a command is always
   safe: settled units and applied files are skipped.

## Apply (positions)

Edits are `(start, end, replacement)` over the original bytes of one file. They are sorted by
`start` descending and applied in one pass. Overlap is an error. An edit range that intersects a
frozen range is an error. Files with `\r\n` are refused (repo is LF).

- Whole-line unit, `rewrite`: span from the first comment byte to the last comment byte.
  Replacement: rendered lines joined with `"\n" + indent`. `indent` is the original first line's
  leading whitespace, copied byte for byte (tabs in Go).
- Whole-line unit, `drop`: span from the start of the first line to after the last line's `\n`.
  Formatters collapse double blank lines: `go/format` keeps at most one, Biome likewise.
- Trailing, `rewrite`: span is the comment itself. Replacement: `// text`, or the Vue form.
  Trailing `drop`: span from the end of the code's last non-space byte to the comment end.
- Inline `/* */`, `drop`: the comment plus one adjacent space when spaces sit on both sides.
  `rewrite` keeps `/* */`.
- Rendering:
  - Go: `// ` + line.
  - TS `//`: `// ` + line.
  - JSDoc: one line `/** text */`; else `/**`, ` * line`..., ` */` at indent.
  - Template: `<!-- text -->`, or `<!--`, lines at indent + 2, `-->`.
  - A Go `doc` keeps `//` even when the original was `/* */`.
  - A TS whole-line `/* */` that is not JSDoc renders as `//`.
- Format after splicing: Go `go/format.Source` in-process. TS/Vue: `bunx biome format --write`
  on the root's touched files, once per root. That is the same formatter the hook checks.
- File checks then run on the formatted text (see the gate). On failure:
  1. Restore the file.
  2. Re-apply its units one at a time, checking after each, to find the culprit units.
  3. Mark the culprits `kept` with reason `file-check: <check>`.
  4. Apply the rest.
- Tool output: changed source files plus updated ledger files only.

## Quality gate

### Rule checks, per unit (text level, in `rewrite`)

1. `lines` count ≤ original body line count. Body chars ≤ original body chars (markers excluded).
2. Every rendered line ≤ 100 columns with indent. For `trailing`, the code part plus `// text` ≤ 100,
   or ≤ the original line length when the code alone already passes 100.
3. `trailing` has exactly 1 line.
4. Go `doc` with `decl`: first word is `decl.name` (package doc: `Package <name>`), and the last
   line ends with `.`.
5. Every `mustKeep` token appears verbatim. A unit holding one is never dropped.
6. `drop` refused for `soleContent` and for `decl.exported` docs.
7. No hallucination:
   - every number in the new text appears in the original text;
   - every candidate name (backticked, CamelCase, dotted, `name()`) appears in the original text
     or context, or in the index and not in `missing`.
8. No process ref left: the new text must not match
   `\b(P\d{1,3}[a-z]?|[DFIT]\d{1,2}(-\d+)?)\b|§\s?\d|\b(round|iter|iteration|pass|stream|finding)\s+[0-9A-Z]\b`.
   Exception: a matching token that also occurs in the unit's context code. Example: the key name
   `F5` in a keymap. A real non-ref token that still trips it goes in `comments_scope.go`'s
   `refAllow` with a one-line reason.
9. No `→`, and no `TODO`/`FIXME`/`XXX`/`HACK` added.
10. JSDoc: the multiset of `@tag` names is unchanged.

### Rule checks, per file (in `apply`, after format)

1. Code unchanged:
   - Go: `go/scanner` token streams of before and after, comments skipped, equal as
     `(tok, lit)` pairs. For `SEMICOLON`, compare `tok` only (auto-inserted ones carry `"\n"`).
   - TS: `forEachChild` structural dump of both `SourceFile`s, `(kind, text-of-leaf-tokens)`.
     JSDoc is not visited by `forEachChild`.
   - Vue: SFC blocks equal (type, `lang`, attrs, `setup`); script blocks by the TS dump; template
     by `compileTemplate(..., { compilerOptions: { comments: false } }).code` string equality;
     `<style>` bytes equal.
2. Directives: the ordered list of frozen texts is byte-identical.
3. Comment-unit count after ≤ before. No unit gained lines.
4. Per-unit checks 2 and 4 re-run on the formatted text (gofmt realigns trailing comments).

### Opus judge (sampled)

`report` writes a Markdown file. Per sampled unit it shows:

- id, `path:line`, kind, action and `why`;
- before and after in fences, and the context (≤ 8 lines);
- a `[CHECK]` tag when `carried(original, new)` is false. That is the `verify.go` heuristic.

Header: wave, totals by action and kind, kept/rejected counts and reasons, spend.

Sample: 150 per wave, fixed seed, stratified:

- 50 `drop`;
- 60 `rewrite`;
- 10 `keep`;
- 30 risk units: `drop` or `rewrite` whose original matches
  `because|since|so that|otherwise|must|never|only|workaround|bug|race|deadlock|leak|quirk|invariant|unsafe|panic|ensure|careful`.

The orchestrator spawns one Opus subagent per report. Prompt: the style contract above and this
section. The judge:

1. Writes `docs/v2.8/plans/P316-judge-w<N>.md` (summary, counts, per-failure line).
2. Writes `docs/comment-runs/verdicts/w<N>.jsonl` with one verdict per sampled id:
   - `pass`;
   - `lost-why` (a non-obvious reason, constraint or workaround is gone);
   - `wrong` (the new text claims something false or not in the source);
   - `trivia-kept` (a restating or history comment survived);
   - `style` (form rule broken).

   A non-pass verdict carries a one-line `hint`.
3. Commits both files: `docs: P316 judge w<N>`.

Acting on verdicts:

- Each `lost-why` and `wrong` unit is redone: `rewrite --redo`, then a `--redo-only` report and a
  re-judge of those units. Up to 3 rounds; a unit still failing becomes `kept` with its original.
- If `lost-why` + `wrong` exceed 3% of the sample (5 of 150), the miss is systematic:
  1. Revise the prompt.
  2. Run `rewrite --systematic` on the wave.
  3. Judge a fresh 150 sample drawn from the re-asked units.
- `trivia-kept` and `style` above 10% of the sample: tighten the prompt for later waves. No redo:
  that is quality, not safety.
- A wave is accepted when its latest judge pass has 0 `lost-why` and 0 `wrong` among judged units.
  The orchestrator checks this against `verdicts/w<N>.jsonl` with a count, not prose.

The judge runs before `apply`, so redos never cost a second commit per root.

## Cost

- Input ≈ 5.35M comment chars + 5.85M context + ~10% JSON. That is ≈ 12.3M chars, ≈ 1,030 parts of
  12k.
- docshistory's measured envelope (`0.06 + 0.012/1k chars`) gives ≈ 0.20 USD per part:
  - W0 ≈ 6;
  - W1 ≈ 85;
  - W2 ≈ 65;
  - W3 ≈ 50;
  - total ≈ 210 USD for one pass.

  This envelope came from the 3-stage distill, so one call should cost less. W0 measures it.
- Caps are cumulative `--max-usd` values over `spend.jsonl`:

  | After step | Cap (USD) |
  |---|---|
  | W0 | 12 |
  | W1 | 110 |
  | W2 | 185 |
  | W3 | 245 |
  | Final redo reserve | 270 |

- After W0, `comments status` prints a projection from `commentEstimate`. If the projection passes
  270 USD, stop and hand back. The orchestrator asks the user before W1.
- Time: ~90 s per part at `--jobs 4` is ≈ 6 to 7 h of calls in total, spread over the waves.
  Container restarts are covered by the ledger.

## Commits

- Per root: `refactor: tighten comments in <root> (P316 W<N>)`. The commit holds the root's source
  files plus that root's `units/*.jsonl` and `applied.jsonl` lines.
- Use an explicit pathspec, never `git add -A`. The checkout may hold another session's files.
- The pre-commit hook must pass. No `--no-verify`. A hook failure on a root:
  1. Find the failing file.
  2. Run `apply` again after marking the offending units `kept` (`--redo-ids` with
     `--force-keep`).
  3. Recommit.
- Trailers on every commit: the attribution lines from the session's system reminder.

## Tests (only the complex parts)

Go, `scripts/docshistory/comments_apply_test.go` (table-driven):

- Multi-line `//` group rewrite keeps the tab indent.
- Whole-line drop removes the lines and nothing else.
- Trailing rewrite and trailing drop.
- Inline `/* */` drop with space handling.
- A group with `//go:embed` after a doc paragraph: the paragraph is rewritten, and the `//`
  separator and directive bytes are unchanged.
- Overlapping edits fail.
- An edit touching a frozen range fails.
- JSDoc and template rendering at indent.
- An edit on a CRLF file is refused.

Go, `scripts/docshistory/comments_directive_test.go`:

- Frozen: `//go:build`; `//go:embed`; `//nolint:errcheck // reason`; bare `//nolint`;
  `//lint:ignore`; `// +build`.
- cgo preamble group.
- `Example` with `// Output:`.
- `// Deprecated:` paragraph.
- Generated header skips the file.
- Look-alikes not frozen: `// see http://x`, `// nolint is ...` (space after `//`), `//foo bar`.

Bun, `scripts/comments/scan.spec.ts`:

- Directive detection for every TS/Vue form in the inventory, including `biome-ignore-all` and
  `<!-- biome-ignore -->`.
- `/*#__PURE__*/` frozen.
- `// biome-ignore x: reason` frozen whole.
- Vue offsets: a `<script setup>` comment and a template comment map to the right bytes of the
  whole file.
- `//` run grouping stops at a blank line and at a column change.
- `soleContent` on an empty `catch`.

No tests for: CLI wiring, ledger, status, report, the prompt, the code-equality dump (it is the

## Implementer

One sequential Sonnet implementer. No stream split:

- The tool is one dependency chain: refactor, then extract, render/apply, checks, rewrite.
- Waves must run in order, under one cumulative spend cap and one ledger.
- Every root commit runs hooks against the whole tree.

The implementer stops at each "Hand back" in "Steps". The orchestrator runs the Opus judge, then
spawns a fresh Sonnet implementer with this plan, which resumes from `comments status`. Every
handoff state is on disk: ledger, reports, verdicts.

Discovery note for the implementer: the plan names exact files and functions. Use
`codegraph_explore` (load it via `ToolSearch "codegraph"`) before reading any docshistory or
`internal/memory` file whose symbols you have not seen.
