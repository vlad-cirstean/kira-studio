## Ask

SPEC row: Claude is the only supported agent; introduce provider-neutral interfaces (runner, model
list, availability, MCP/tool wiring, cost reporting) so another harness or agent can be added
without touching callers. Claude stays the only implementation. Scope: memory, smart scripts and
every other Claude call site. No behavior change.

User intent: adding a provider later means implementing an interface and registering it in one
place, not editing every caller.

## Design

### 1. Packages

- `internal/harness`: neutral types and role interfaces, error kinds, `Registry`, `Selector`. Imports
  only stdlib, `ipcerr`. No provider code.
- `internal/harness/claude`: the only provider. Receives every Claude-specific piece (moved, not
  rewritten): `memory/claude.go` internals, `claudeheadless/{process,stream,env,usermcp}.go` and the
  Claude half of `result.go`, `claudemodel`, `toolexec/claude.go` plus `ClaudeCandidates`/
  `systemClaudePaths`/`SetSystemClaudePaths`, `mcpinstall` (as `internal/harness/claude/mcpinstall`),
  sandbox constants. Existing tests move with their code, assertions unchanged.
- `internal/harness/providers`: `New(extra ...harness.Provider) *harness.Registry` (claude first,
  then extra) and the static helpers in §2. The one registration line a new provider adds.
- `internal/agentmcp`: what is left of `claudeheadless` after the moves (the Kira MCP tool server:
  `mcp.go`, `gittool.go`, `review.go`, `sandboxgit.go`, `space.go`, `outcomes.go`, `suffix.go`,
  neutral half of `result.go`). Rename only; MCP is a cross-harness protocol.
- Amended: `internal/agenthooks` moves to `internal/harness/claude/hooks`; `internal/harness/hooks.go`
  is the neutral hook hub; `internal/harness/agentsvc` is the shared bound `AgentService`;
  `apps/kira-space/internal/claudeusage` becomes `apps/kira-space/internal/agentusage`.
- `ShellQuote` moves to `internal/loginshell.Quote` (same body). `ade/command.go:25` `quotePOSIX`
  and `claudeheadless/process.go:115` `quotePOSIX` call it instead of duplicating.

Import rules: `harness` imports no app package. `harness/claude` must not import `memory`,
`scripts`, `scriptruns`, `agentmcp`, `agentsandbox`, `ade`. Callers import `harness` (and
`providers` only at composition roots plus the static helpers).

### 2. Interfaces (Go)

`Provider` is the composition of role interfaces; each caller depends on the narrowest role.

```go

// Provider is one agent harness. ID is the agent.provider setting value.
type Provider interface {
	ID() string
	// Label is the display name in Go-rendered text (catalog leaf common.agent.<id>.label,
	// "Claude"); Command the CLI name ("claude"); HeadlessLabel the headless badge ("claude -p").
	Label() string
	Command() string
	HeadlessLabel() string
	Models() Catalog
	Locator
	Structured
	Headless
	Interactive
	MCPHost
	Sandboxed
}

// Catalog is a provider's model aliases; Default is used when none is chosen.
type Catalog struct {
	Aliases []string
	Default string
}

func (c Catalog) Valid(m string) bool
```

```go
type MCPHost interface {
	// MCPConfig renders servers in the provider's config file format.
	MCPConfig(servers []MCPServer) ([]byte, error)
	// MCPToolName is one MCP tool's name in tool permission lists.
	MCPToolName(t MCPTool) string
	// ToolArgs renders a smart script's tool policy as built-ins and allowed tools.
	ToolArgs(p ToolPolicy) (tools, allowed []string)
	UserMCPServers(getenv func(string) string) ([]UserServer, error)
	UserMCPTools(ctx context.Context, getenv func(string) string, name, cwd string) ([]UserTool, error)
	WriteUserMCPConfig(getenv func(string) string, dir, runID string, names []string) (path string, release func(), err error)
	MCPInstaller() MCPInstaller
}

// MCPServer is an http (URL, Headers) or stdio (Command, Args, Env) server.
type MCPServer struct {
	Name    string
	URL     string
	Headers map[string]string
	Command string
	Args    []string
	Env     map[string]string
}

type MCPTool struct{ Server, Tool string }

// ToolPolicy is a smart script's tools in Kira's tool vocabulary (Claude's built-in names).
type ToolPolicy struct {
	Builtins     []string
	BashPatterns []string
	MCP          []MCPTools // user servers and their ticked tools
	Extra        []string   // already-rendered names appended last (Kira tools)
}

type MCPTools struct {
	Server string
	Tools  []string
}

type MCPInstaller interface {
	Status() InstallStatus
	Install(ctx context.Context, name, url, helperPath string) InstallResult
	InstallStdio(ctx context.Context, name, command string, args []string) InstallResult
	Command(name, url, helperPath string) string
	StdioCommand(name, command string, args []string) string
}
```

## Resolved ambiguities

- "Runner" covers both one-shot structured calls (memory) and streamed headless runs (ADE, smart
  scripts): two roles, `Structured` and `Headless`, because their contracts differ (JSON schema on
  stdout versus a stream plus MCP report).
- "MCP/tool wiring" covers config rendering, tool permission names, user server discovery, the
  per-run user config copy and installing Kira's servers into the agent: all `MCPHost`.
- "Cost reporting": `Usage` on structured results, `Result.CostUSD` on headless runs, `RateLimits`
  for account windows. No new aggregation.
- Provider selection is a setting without UI, both apps. Unknown id falls back to `claude` at use,
  never rejected on boot.
- P314's model setting becomes `memory.models`, one map leaf keyed by provider id (amended).
- `scripts.ToolArgs` belongs to the provider: Kira's built-in tool vocabulary is Claude's names,
  which a new provider maps.
- `ScriptRunView` resume command moves to Go (new bound method) because it is the only client-side
  `claude` command.
- Amended scope (user: "Do all. Nobody uses the app so data loss is completely fine."): hooks and
  usage become optional roles; wire, settings, column and launch-kind names go neutral with no
  shims; sessions and script runs store their provider and resume by it; UI copy, models and
  badges come from `AgentService.Info`; outcome texts take the provider label.
- Provider display text is resolved in Go from the catalog and passed as a param into catalog
  templates; the UI never holds a per-provider copy map, so a provider adds catalog leaves only.
- Hooks and usage are optional interfaces (type assertion), not methods returning nil: a provider
  without them compiles without stubs.
- Migrations rename in place where SQLite allows (`RENAME COLUMN`, `UPDATE key`, `json_set`);
  only `memory.claudeModel` is dropped because its shape changes (data loss accepted).
- `fakeagent` keeps the `claude` persona (Claude CLI double) and gains a generic
  `kira-fake-agent` persona only for the fake provider's TUI sessions.
