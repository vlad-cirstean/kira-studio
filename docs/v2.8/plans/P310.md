# P310 plan: SQL column header tooltip, structured layout

Own stream, own git worktree off the chapter base. Runs beside Stream D (P312) and Stream E (P311).
Frontend only. No Go, no IPC, no catalog change.

## Ask

SPEC row: "SQL column tooltip: explanation and comment read as one run. Rearrange and format them."

User: "In sql — The tooltip for columns is hard to read. The explanation and comment are one after the
other. Arrange and format them differently."

## Root cause

Data path, one function feeds three grids:

- `apps/kira-studio/frontend/src/views/shared/page/columns.ts:386` `columnHeaderTooltip(col, dataType,
  comment?)` returns `{ title, meta, metaColor, body }`. `body` is
  `[typeDescription(dataType), comment].join('\n')`. Generated explanation and DB comment become one
  string. Nothing downstream can tell them apart.
- `columns.ts:403` `tooltipAttrs(content)` writes `data-kira-tip` (plain, newline-joined, also
  `aria-label`) and `data-kira-tip-parts` (JSON of `content`) onto a SlickGrid header cell.
- Callers: `SlickGridHost.vue:521` (table data tab; passes `metaByName.get(name)?.comment`),
  `ConsoleSlickGrid.vue:206` (console result; no comment), `proto/grid/CheetahProto.vue:514`
  (prototype). Only the data tab has a comment.

Render path:

- `packages/theme/src/components/AttributeTooltip.vue:123-139` renders parts inside shadcn
  `TooltipContent`: one `div` with title + meta, one `div` with body.
- `packages/theme/src/components/ui/tooltip/TooltipContent.vue:31` base classes are
  `inline-flex items-center gap-1.5 … max-w-xs whitespace-pre-line`. A row flex box: the title row and
  the body `div` sit side by side, vertically centred. Inside body, explanation and comment are one
  text run split only by a newline. So: no hierarchy, no label on the comment, 20rem cap squeezes both.
- Header furniture the user already sees (PK/FK badge, `SlickGridHost.vue:458 keyLabelFor`) and
  DESCRIBE facts (`ColumnMeta.nullable`, `packages/shared/domain/tree.ts:98`) never reach the tooltip.

`data-kira-tip-parts` has no other producer: grep finds it only in `columns.ts` and
`AttributeTooltip.vue`. git-ui and docker-ui (P311) use `AttributeTooltip` with plain `data-kira-tip`
only. Plain path must stay byte-identical.

## Design

Target layout, top to bottom, inside the existing inverted tooltip (`bg-fg text-bg`):

```
tenant_id   integer                 <- header: name (mono, medium), type (mono, type colour)
[PK] [NOT NULL]                     <- facts: small chips
Signed 32-bit whole number.         <- explanation: muted, own paragraph
────────────────────────────        <- Separator
COMMENT                             <- small muted label
Owning tenant; never reused …       <- comment text, wraps, keeps its own newlines
```

Rules:

- Vertical stack. Each section its own element with its own `data-testid`. Absent section renders
  nothing (no empty chip row, no separator without a comment).
- Width cap `max-w-sm` (24rem) for structured tips only; plain tips keep `max-w-xs`.
- Identifiers and type in `font-data` (repo's mono token, see `Badge.vue` `data` prop). Long names
  wrap with `wrap-anywhere` (Tailwind 4.3.3 ships it).
- Muted text on the inverted surface uses `text-bg/70`-style opacity of the surface's own token, not
  a new colour.
- No scoped `<style>`. Tailwind utilities only. Chips use shadcn `Badge`; divider uses shadcn
  `Separator` (both in `packages/theme/src/components/ui/`).

### Data shape (generic, theme stays column-agnostic)

`AttributeTooltip.vue` local interface `TooltipContentShape` gains two optional fields:

```ts
interface TooltipContentShape {
  title: string;
  meta?: string;
  metaColor?: string;
  /** Short fact chips, already translated. */
  tags?: string[];
  body?: string;
  /** A labelled block below a separator, e.g. a DB comment. Label already translated. */
  note?: { label: string; text: string };
}
```

Labels arrive pre-translated from the caller, so the theme component holds no column vocabulary.

### `columns.ts`

Replace `columnHeaderTooltip`'s third positional `comment` with an optional facts object. Existing
two-argument calls (console, proto) compile unchanged.

```ts
export interface ColumnTipFacts {
  comment?: string | null;
  key?: 'PK' | 'FK' | null;
  /** From DESCRIBE only; null/undefined when unknown (console results). */
  nullable?: boolean | null;
  generated?: boolean;
}
export function columnHeaderTooltip(
  col: { name: string; typeClass: TypeClass },
  dataType: string,
  facts: ColumnTipFacts = {},
): ColumnTooltipParts
```

- `body` = `typeDescription(dataType)` only. Comment never joins it.
- `tags`, in order: key label (`PK` → `studio.definition.primaryKey.label`, `FK` →
  `studio.definition.foreignKey.label`), nullability (`false` → `studio.definition.notNull.label`,
  `true` → `studio.definition.nullable.label`, unknown → none), `generated` →
  `studio.cellEditor.readOnly.generated.label`. Omit `tags` when empty.
- `note` = `{ label: t('common.comment.label'), text }` when `comment?.trim()` is non-empty; text
  trimmed, inner newlines kept.
- `ColumnTooltipParts` = the return type (title, meta, metaColor, tags, body, note), exported so
  `tooltipAttrs` keeps typing against it.
- `tooltipAttrs`: plain text = `[title, meta, ...tags, body, note?.label, note?.text]` filtered,
  `'\n'`-joined. Same attribute names. `data-kira-tip-parts` stays `JSON.stringify(content)`.
- `t()` runs inside the function (call time, per column per column build), never at module scope
  (U70). Same pattern `typeDescription` already uses. Not per cell.
- Update the comment block above the function (lines 380-385) to the new contract; keep it short.

### `SlickGridHost.vue`

- `buildColumns` (`:517-525`): pass facts:
  `{ comment: m?.comment, key: keyLabelFor(descriptor, name, fkNames), nullable: m?.nullable ?? null,
  generated: descriptor?.generated ?? false }` with `m = metaByName.get(name)`.
  `keyLabelFor` is already computed for `headerAwareMinWidth` on `:534`; compute once into a local and
  reuse both places.
- `dataTypeFor` param type (`:481`): widen `metaByName` value type to include `nullable: boolean`
  (it is already a `ColumnMeta` map; or type it as `Map<string, ColumnMeta>`).
- Nullability from DESCRIBE only, not `descriptor.nullable`: meta is authoritative and already drives
  the comment; header rebuilds when meta lands (`rebuildAndSetColumns`, `:1201`), so both appear
  together.

Console (`ConsoleSlickGrid.vue`) and proto (`CheetahProto.vue`): no edit. Console has no DESCRIBE, so
no chips and no note there; its descriptor `nullable`/`isPrimaryKey` are not reliable facts for an ad
hoc result set.

### `AttributeTooltip.vue` template

```vue
<TooltipContent :class="parts ? 'max-w-sm flex-col items-stretch gap-1.5 py-2' : undefined">
  <template v-if="parts">
    <div class="flex flex-wrap items-baseline gap-x-2 gap-y-0.5" data-testid="tooltip-header">
      <span class="font-data font-medium wrap-anywhere" data-testid="tooltip-title">…</span>
      <span v-if="parts.meta" class="font-data text-kira-sm" data-testid="tooltip-meta" :style="…">…</span>
    </div>
    <div v-if="parts.tags?.length" class="flex flex-wrap gap-1" data-testid="tooltip-tags">
      <Badge v-for="tag in parts.tags" :key="tag" variant="chip" data
        class="h-auto border border-bg/30 text-kira-xs" data-testid="tooltip-tag">{{ tag }}</Badge>
    </div>
    <p v-if="parts.body" class="text-kira-sm text-bg/75" data-testid="tooltip-body">…</p>
    <template v-if="parts.note">
      <Separator class="bg-bg/20" />
      <div class="flex flex-col gap-0.5" data-testid="tooltip-note">
        <span class="text-kira-xs font-medium uppercase tracking-wide text-bg/60"
          data-testid="tooltip-note-label">{{ parts.note.label }}</span>
        <p class="text-kira-sm wrap-anywhere" data-testid="tooltip-note-text">{{ parts.note.text }}</p>
      </div>
    </template>
  </template>
  <template v-else>{{ plainText }}</template>
</TooltipContent>
```

Exact utility choices may shift if lint/visual check shows a token is off (e.g. `text-bg/75` contrast);
structure and test ids are fixed. `cn()` in `TooltipContent` merges `items-stretch` over `items-center`;
`inline-flex` stays and works with `flex-col`. `whitespace-pre-line` stays inherited, so comment
newlines survive. Keep the existing file header comment; update the `TooltipContentShape` doc lines
for the two new fields only.
