# P309 plan: cell editor footer stays fixed, only the editor scrolls

Stream C. Runs beside Stream A (P306) and Stream B (P307). Own git worktree off same base commit.

## Ask

SPEC row: "SQL cell editor: date editor has a large min height and scrolls out of view. Footer controls
stay fixed; only the text editor scrolls."

User: "the cell editor for date has a min height that s quite big and it gets scrolled out of the view.
The bottom things should be static and scroll only the text editor in it."

## Root cause

All in `apps/kira-studio/frontend/src/views/shared/celleditor/`.

- `CellEditorDock.vue:43-48`: dock is `flex: 0 1 <height>px`, `overflow-hidden`. Default height 180
  (`packages/shared/domain/layout.ts:44`), drag min 120.
- `CellEditorView.vue:504` editor body is `flex-1 min-h-0 flex flex-col`. Inside it, for timestamp
  formats:
  - encoded Monaco wrapper (`:505-508`): `flex-1 basis-7/12 min-h-0`;
  - "Timestamp" title strip (`:559-564`): `shrink-0`, about 20px;
  - `TimestampPane` (`:565-566`): `flex-1 basis-5/12 min-h-0`.
- `TimestampPane.vue:111` root `flex flex-col h-full min-h-0`; reading `Alert` (`:112`, `py-2`) about
  34px; controls row (`:139`) `flex-1 min-h-0 ... py-1.5` with a `kira`-size input, about 38px. Natural
  height about 72px.
- Body at default 180: 180 − 34 (`ViewToolbar`, `--kira-bar-h`) − 20 (strip) = 126px, split 7:5. Pane
  gets about 53px, below its 72px content. `min-h-0` lets it shrink anyway, so the controls row (zone
  toggle, field, calendar) overflows and the dock's `overflow-hidden` clips it. At a tall dock the same
  5/12 basis makes the pane far taller than its content: the "big min height" with empty space.
- Wrong model: pane is a fixed-size footer, not a second flexible editor. Only Monaco should flex.

Other formats:

- text/json/xml/csv/sql: encoded wrapper `flex-auto min-h-0`, only Monaco. Already correct.
- hex/base64: two Monacos split 7:5, both `min-h-0`, both scroll internally. Correct: both are text
  editors. One gap: `cell-editor-decoded-empty` `Alert` (`:542-546`) has `flex-1 basis-5/12` without
  `min-h-0`, so a long hint can push the body past the dock. Fix for consistency.
- `ResponseFindBar` (`:575`) renders `FindBar` → `ViewToolbar` (`shrink-0`). Already a fixed bar; must
  stay visible with the timestamp pane open.

## Design

Rule for every format: toolbars, title strips and the timestamp pane are `shrink-0` at natural height.
Monaco wrappers are the only `min-h-0` flex children that grow and shrink. Monaco scrolls its own
content. Nothing else scrolls.

### `CellEditorView.vue`

1. Encoded wrapper class (`:506`), three cases instead of two:
   - decoded pane shown: `flex-1 basis-7/12 min-h-0 border-b border-border` (unchanged);
   - timestamp pane shown: `flex-1 basis-0 min-h-0 border-b border-border` (takes all space left);
   - otherwise: `flex-auto min-h-0` (unchanged).
   Replace the `showTranslatePane ? … : …` ternary with a `computed` returning the class string
   (`encodedClass`). `showTranslatePane` (`:182`) has no other reader; delete it.
2. `TimestampPane` call site (`:566`): class `shrink-0` (drop `flex-1 basis-5/12 min-h-0`).
3. Decoded-empty `Alert` (`:545`): add `min-h-0 overflow-auto`.
4. Editor body (`:504`): add `overflow-hidden` so a too-short dock clips at the body edge, never past the
   find bar.

### `TimestampPane.vue`

1. Root (`:111`): `flex flex-col` (drop `h-full min-h-0`; natural height now).
2. Controls row (`:139`): drop `flex-1 min-h-0`; change `items-start` to `items-center` (row no longer
   stretches, so top alignment has no purpose). Keep `gap-1 py-1.5 px-2`.
3. No markup or behaviour change otherwise. Readings `Alert` keeps `shrink-0`.

### `CellEditorDock.vue`

No change needed: `h-full` on the panel already resolves against the dock's definite flex basis
(current text formats prove it). Touch only if the UI spec shows the panel overflowing in WebKit; then
make the dock `flex flex-col` and the panel `flex-1 min-h-0` instead of `h-full`.

### Smallest dock

At drag min 120: 120 − 34 − 20 − 72 ≈ 0 left for Monaco. Controls stay fully visible; Monaco collapses.
Accepted: this is the user's own drag limit, and the ask is that controls stay put. Do not change
`:min="120"`: the handle serves every format and every mounting view (`DataView`, `ConsoleView`,
`StreamView`, `KeyValuePane`); a format-specific min is a separate design call, not this phase.

No new strings, no new components, no library choice involved (Tailwind utilities only).
