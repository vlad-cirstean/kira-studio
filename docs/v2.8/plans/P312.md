# P312 plan: per-module panel sizes

Stream: runs beside Stream B (P307) and Stream E (P311). Own worktree off the same base commit.

## Ask

User (as clarified via orchestrator): panel sizes today are shared across modules. Resizing a panel
in Studio also resizes it in API. Each module must keep its own independent sizes. Existing shared
values seed every module. Live sync must not cross modules.

SPEC row title says "share one panel size"; it is stale. Orchestrator fixes `SPEC.md`. This stream
never edits `SPEC.md`.

## Findings (current tree)

- One `Layout` per app, stored as leaves in SQLite `ui_layout`
  (`apps/kira-studio/internal/storage/repos/layout.go`): `panel.project.visible`,
  `panel.project.width`, `panel.operations.visible`, `panel.operations.height`,
  `panel.cellEditor.height`. No `localStorage` involved.
- `LayoutService.Set` (`apps/*/internal/bridge/layout.go`) merges a patch, then `Emit`s
  `kira:layout:changed` to every window.
- Frontend: one shared Pinia store, `packages/workbench/src/state/createLayoutStore.ts`, schema
  `packages/shared/domain/layout.ts`. Both apps' `workbench/WorkbenchShell.vue` pass
  `panel.project.width` / `panel.operations.height` to the shared
  `packages/workbench/src/components/WorkbenchShell.vue` regardless of `modeStore.active`. That
  is the bug: one key, every module.
- Kira Space Go `Layout` has `panel.project` and `panel.ade` only. Its Operations dock height and
  visibility are never persisted (pre-existing; see "Out of scope").
- Go already lists each app's modes: `model.WindowModes.Valid`
  (Studio `studio, api, automations, docker`; Space `git, automations, ade, memory`).

## Which panels become per-module

| Panel | Today | After P312 | Why |
|---|---|---|---|
| Left (project) panel width | one global leaf | per module | Same shell slot, different content per module. This is the user's case. |
| Operations dock height | one global leaf | per module | Same shell dock, shown in every module. User said "panel sizes", so all shell sizes split. |
| Left panel / dock visibility | global | stays global | A toggle, not a size. Menu command `toggleProjectPanel` is app-wide. Ask did not cover it. |
| Cell editor height | global | stays global | Mounted only by DB grid views, which live only in the Studio module. Already effectively Studio-only. |
| HTTP/gRPC request pane, Browse list width | per tab (`requestPaneHeight`, `listWidth`) | unchanged | Per tab is finer than per module; already independent. |
| Space ADE panel width (`panel.ade.width`) | Space `ade` module only | unchanged | Already module-specific. |
| Space ADE review left/right (`kira.ade.review.*`) | localStorage, review window only | unchanged | Own window, own module. |

Same module in two windows stays synced: per-module size is an app-wide preference for that
module, like before. Only cross-module propagation stops.

## Design

### Wire shape (`packages/shared/domain/layout.ts`)

```ts
const panelSizesSchema = z.object({
  project: z.object({ width: z.number(), widthUserSet: z.boolean().default(false) }),
  operations: z.object({ height: z.number() }),
});
export const layoutSchema = z.object({
  panel: z.object({
    project: z.object({ visible: z.boolean() }),
    operations: z.object({ visible: z.boolean() }),
    cellEditor: z.object({ height: z.number() }),
  }),
  modes: z.record(z.string(), panelSizesSchema),
});
```

- Patch: `panel` partials as today (minus width/height), plus
  `modes: z.record(z.string(), { project: partial, operations: partial }).optional()`.
- Export `defaultPanelSizes` (`width 260`, `widthUserSet false`, `height 200`).
  `defaultLayout.modes = {}`.
- `widthUserSet` stays TS-only, as today (Go never stored it).

### Store (`packages/workbench/src/state/createLayoutStore.ts`)

- `state.modes` reactive record. `sizesFor(mode)` getter returns `state.modes[mode]` or
  `defaultPanelSizes`.
- Actions take the mode: `setProjectWidth(mode, width)`, `setOperationsHeight(mode, height)`,
  `ensureReviewPanelWidth(mode, minWidth)`. Each patches `modes[mode]` only.
- `mergePatch` / `applyLocal` / `applyRemote` handle `modes` per key. `applyRemote` replaces each
  mode entry from the pushed layout, then reapplies `pendingPatch` (F10 rule kept).
- Mode stays `string` in the shared store. No mode-store import into the layout store: one store,
  one concern. The shell passes the active mode.

### Shells

- `apps/kira-studio/frontend/src/workbench/WorkbenchShell.vue` and
  `apps/kira-space/frontend/src/workbench/WorkbenchShell.vue`: compute
  `sizes = layoutStore.sizesFor(modeStore.active)`, bind `project-width` / `ops-height` to it,
  and call `setProjectWidth(modeStore.active, w)` / `setOperationsHeight(modeStore.active, h)`.
- Shared `packages/workbench/src/components/WorkbenchShell.vue`: no change. Its local
  `liveProject` / `liveOps` preview resets on commit/cancel. A mode switch mid-drag is not
  possible (pointer is captured).
- `apps/kira-space/frontend/src/repo/GitPanel.vue:100`: `ensureReviewPanelWidth('git', 320)`.

### Go, both apps

- `storage/model/layout.go`: `PanelProject{Visible}`, `PanelOperations{Visible}` (Space gains no
  operations visibility; see below), `PanelSizes{Project{Width}, Operations{Height}}`,
  `Layout.Modes map[string]PanelSizes` (`json:"modes"`). Patch: `LayoutPatch.Modes
  map[string]PanelSizesPatch`. `DefaultPanelSizes()` = 260 / 200.
- `storage/repos/layout.go`: leaf keys `modes.<mode>.project.width`,
  `modes.<mode>.operations.height`. `decodeLayout` fills `Modes` for every
  `model.WindowModes.Valid` entry, defaulting missing leaves. `Set` writes every leaf, as today.
  Space: also persist `modes.<mode>.operations.height` (the shared store sends it; dropping it
  would break the per-module rule for Space's dock).
- `bridge/layout.go` `Set`: reject a `Modes` key not in `model.WindowModes.Valid` with
  `ipcerr.Contract("layout: modes: unknown mode %q")`. Space keeps its ADE width check.
- Tests that compare `Layout` with `!=` stop compiling (map field). Switch to `reflect.DeepEqual`.

### Migration (each existing shared value seeds every module)

- Studio `apps/kira-studio/internal/storage/migrations/0039_p312_layout_per_mode.sql`:
  copy `panel.project.width` into `modes.<m>.project.width` and `panel.operations.height` into
  `modes.<m>.operations.height` for `studio, api, automations, docker`
  (`INSERT OR IGNORE ... SELECT 'modes.' || m.column1 || '.project.width', l.value FROM (VALUES
  ...) m, ui_layout l WHERE l.key = 'panel.project.width'`), then `DELETE` the two legacy keys.
- Space `apps/kira-space/internal/storage/migrations/0039_p312_layout_per_mode.sql`: same for
  `panel.project.width` over `git, automations, ade, memory`; delete the legacy key. No legacy
  ops-height leaf exists there.
- Rule chosen: the single current value seeds every module (no "most recent" choice exists: there
  is only one value). Fresh install: no rows, defaults apply.
- Before writing: `ls apps/*/internal/storage/migrations` on the stream's base. If 0039 is taken by
  then, take the next free number.
