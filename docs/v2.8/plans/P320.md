## Definition: longer comment

One unit is one comment block (`/* */`, `/** */`, `<!-- -->`) or one run of consecutive `//` lines
(Go: one `ast.CommentGroup`; TS: same column, only whitespace between lines, no blank line).

A unit is **eligible** when all hold:

1. 300 to 2000 characters (runes), measured on the unit text as sent (see "Unit text").
2. Whole-line: only whitespace before its first byte on that line and after its last byte.
3. No line matches a directive or licence form (list below). The whole unit is skipped, not split.
4. File in scope (below).

Why 300 to 2000: the range P315/P317 sampled and judged (bars, cost, gate behaviour). 2000 is the
tool's own limit. Below 300 nothing was measured. Owner may pick another lower bound from the table
in "Cost estimate"; the tool takes `--min-chars` (default 300).

Directive and licence forms (whole unit skipped): Go `//go:`, `//nolint`, `//lint:`, `// +build`,
`//export `, `//line `, `// Output:`, `// Unordered output:`, cgo preamble (doc of `import "C"`),
`Code generated ... DO NOT EDIT`; TS/Vue `biome-ignore`, `eslint-`, `@ts-expect-error`,
`@ts-ignore`, `/// <reference`, `#__PURE__`, `@__PURE__`, `@vite-ignore`, `webpackChunkName`,
`istanbul`, `prettier-ignore`, `@vitest-environment`, `@license`, `/*!`; all `Copyright`,
`SPDX-License-Identifier`. The rewrite gate's `directive` check stays as a second line of defence.

Scope (git-tracked only):

- In: `*.go` (nested modules `apps/*/tests/claude` included), `*.ts` (not `*.d.ts`), `*.vue`
  `<script>`, `<script setup>` and `<template>`. Test files included: the comment rule applies
  everywhere.
- Out: Go files with the generated header; `apps/kira-studio/internal/httpclient/cookiejar/`
  (vendored stdlib copy); any `/testdata/`; `docs/`; `.claude/`; `node_modules/`; Biome-ignored
  generated paths (`packages/shared/protocol/wire.ts`, `packages/shared/protocol/wire/`,
  `packages/git-ipc/src/generated/`, `apps/*/tests/contract/`); Vue `<style>`; `.js`, `.mjs`,
  `.astro`, shell, CSS. No Wails `bindings/` dir is tracked (0 files), so generated bindings add 0.

Over 2000 characters: **skip and list.** 49 units (Go 17, TS 25, Vue 7). The extractor writes
them to `over-limit.jsonl` and the report lists `path:line` and length. Splitting at paragraph
boundaries was considered and rejected: a split half of a `/** */` or `<!-- -->` has no opener or
closer, so the `form` gate either rejects it or judges it without its marker, and the pilot never
tested split units. 49 units is a hand-edit job if the owner wants one later; not in this phase.

## Tool: `scripts/commentsweep`

Go program, root module (imports the MCP go-sdk already in `go.mod`). TS/Vue parsing runs in a Bun
helper because the parsers are JS.

### Parsers

- Go: `go/parser` with `ParseComments`, `go/ast` (`CommentGroup`, `ast.File.Imports` for cgo),
  `go/token` offsets. Stdlib.
- TS: `typescript` 6.0.3 (Apache-2.0, root devDependency). `createSourceFile`, then walk every node
  with `getLeadingCommentRanges` / `getTrailingCommentRanges` plus the end-of-file token, dedup by
  position. Requirement that rules out a bare scanner or regex: a regex literal or template literal
  holding `//` or `/*` must not read as a comment, and only a full parse knows which `/` starts a
  regex. tree-sitter would add a native dependency; `oxc-parser` is not installed. The TS compiler
  is already the repo's typechecker.
- Vue: `@vue/compiler-sfc` 3.5.42 (MIT, root devDependency). `parse(src, { templateParseOptions:
  { comments: true } })`; script blocks go through the TS path over `block.content`, offsets
  shifted by `block.loc.start.offset`; template comments are AST nodes of type 3 (`loc.start.offset`,
  `loc.end.offset` are whole-file offsets).
- No hand-rolled lexer anywhere.

Helper: `scripts/commentsweep/scan.ts` reads file paths on stdin, writes one JSON line per raw
comment range (`{file, start, end, kind: line|block|template}`). Go does grouping, eligibility,
context, ids and everything else, so one implementation covers all languages.

### Unit text and context

- Unit text: bytes from the **start of the first line** (its indentation included) to the last
  comment byte. Including the first line's indent is what makes the `indent` gate pin every output
  line to the file's real indentation.
- Context: the 5 lines before the unit and the 25 after, verbatim, capped at 6000 runes (cut at a
  line boundary). Same shape as the pilot, so the cost model and the judged quality carry over. For
  a Vue template comment the lines come from the file the same way.
- Unit record: `{id, file, lang: go|ts|vue, start, end, text, context, textSha, fileSha}`.
  - `start` is the first line's first byte, `end` the last comment byte plus one (half-open).
  - `id` = first 16 hex chars of `sha256(file + ":" + start + ":" + end + ":" + textSha)`.
    Deterministic for a given tree.
  - `inputKey` = `sha256(text + "\x00" + context)`: the cache key for results, so a re-scan after
    an unrelated edit reuses results whose text and context did not change.

### Work dir (resumable, gitignored)

`.commentsweep/` at repo root; add the line to `.gitignore`. Not under `docs/v*`. Survives a
container restart with the checkout.

| File | Content |
|---|---|
| `meta.json` | `{base: <HEAD at scan>, minChars, maxChars, createdAt}`; written once by the first `scan` |
| `units.jsonl` | every eligible unit, file order |
| `over-limit.jsonl` | units over 2000 chars (listed, never sent) |
| `skipped.jsonl` | directive units and non-whole-line units, with the reason |
| `results.jsonl` | one line per finished call: `{id, inputKey, outcome, gate, text, reason, dropped, costUsd, wallMs, error}`; last line per `inputKey` wins; a torn last line is ignored |
| `spend.jsonl` | one line per call attempt, charged cost; `--max-usd` sums it across runs |
| `applied.jsonl` | `{lang, file, beforeSha, afterSha, units}` per written file |

### Commands

`go run ./scripts/commentsweep <cmd> [flags]`:

- `scan [--min-chars 300]`: extract only, no tokens. Prints units per language, test/non-test,
  over-limit and skipped counts, and the projected cost (formula below). Refuses a dirty tree for
  in-scope files.
- `run --max-usd X [--jobs 4] [--lang go|ts|vue]`: the token-spending step (below).
- `apply --lang go|ts|vue`: splice rewritten units, run the code-identity check, write
  `applied.jsonl`. Never commits.
- `report --sample 120 --seed 320 --out docs/v2.8/plans/P320-report.md`: totals and the sampled
  before/after for the judge.
- `restore --ids a,b`: put the original text back for named units (judge-flagged units in a
  passing language). No tokens.
- `status`: units, done per outcome, pending, spend against cap, applied files per language.

### Driver (`run`)

- Builds `kira-space` once with `-tags server` (as docshistory's `buildBinary`; needs
  `bun run build:space-mobile` first when `apps/kira-space/frontend/dist-mobile` is missing, see
  `docs/DEV_ENVIRONMENT.md`).
- `--jobs N` workers, default **N = 4** (the pilot's in-flight count, no rate-limit trouble). Each
  worker starts one `kira-space memory-mcp` with temp `KIRA_MEMORY_HOME`/`KIRA_SPACE_HOME` and keeps
  its MCP session for all its calls (docshistory spawns one per call; at 5,353 calls that start-up
  adds up). A worker whose server dies restarts it.
- One `ingest_files` call per unit: `{"distill": true, "mode": "rewrite", "text": <unit text>,
  "context": <context>}`. Never more than one comment per call.
- Skip a unit whose `inputKey` has a result line with an outcome; retry one whose last line is an
  error.
- Spend: reuse docshistory's ledger semantics. Move `ledger`, `spendLine`, `appendLine`,
  `totalCharged`, `isRateLimit`/`isRefusal`/`failedCharge` from `scripts/docshistory/distill.go`
  into `scripts/internal/runledger` and use it from both tools (no copy). Reserve 0.05 USD per call
  before starting it, settle with the reported `costUsd`. Stop starting calls once `spent +
  inflight + 0.05 > --max-usd`; in-flight calls finish. Worst overshoot is N × 0.50 (two calls at
  the 0.25 per-call budget).
- Rate limit: wait and retry the same unit, charge nothing (docshistory backoff). Any other error:
  one retry after 30 s, then record the error and move on.
- Progress line every 50 units: done, outcomes, spend, ETA.
- `run` writes nothing to source files.

### Apply

Per file, units with outcome `rewritten` only (unchanged and kept units ship the original; a kept
unit's draft is never used):

1. Refuse the file when its current sha is not the scan's `fileSha` (another change landed):
   list it, skip it, go on. The implementer re-runs `scan` and `run` for those files only (results
   are reused by `inputKey`).
2. Splice each unit's `text` into `[start, end)`, highest `start` first. Overlap is an error.
3. Code-identity check on before and after:
   - Go: `go/scanner` token streams with comments skipped, equal as `(tok, lit)` pairs (for
     auto-inserted `SEMICOLON` compare `tok` only); and `go/format.Source(after) == after` (gofmt
     clean).
   - TS: `ts.createPrinter({ removeComments: true }).printFile(sourceFile)` equal for before and
     after (helper call `scan.ts --print`).
   - Vue: SFC block list equal (type, `lang`, attrs, `setup`); script blocks by the TS printer;
     template by `compileTemplate(..., { compilerOptions: { comments: false } }).code` equal;
     `<style>` bytes equal.
   - Re-extract the after file: the comment ranges match the before file one to one (a rewrite
     that ends a block early, for example a `*/` or `-->` inside the text, fails here).
4. On failure: restore the file, apply its units one at a time to find the culprit, record it
   in `results.jsonl` as outcome `kept`, gate `apply`, write the rest.

## Quality gate

### Rule-based (every unit, every file, automatic)

- Per unit: the product gates (`grew`, `form`, `indent`, `width`, `directive`, `tokens`, `hedge`,
  `output`). Only accepted text reaches apply.
- Per file: the code-identity check above.
- Per language commit: the repo checks under "Phasing". Any failure is fixed on the spot: a
  failing unit is marked `kept` (gate `check`) and the file re-applied without it. The hook passes
  without `--no-verify`.

### Opus judge (one review, after all three commits)

- Sample: **120 rewritten units per language, 360 in all**, seed 320, uniform over that
  language's rewritten units, test and non-test mixed by share. Only rewritten units can lose
  meaning; unchanged and kept units ship the original.
- `report` writes `docs/v2.8/plans/P320-report.md`:
  - header: units per language, outcomes (rewritten, unchanged, kept per gate), over-limit and
    skipped counts, spend, cost per unit, wall time;
  - per sampled unit: id, `path:line`, before and after in fences, context (up to 8 lines), the
    `dropped` list and `reason`;
  - full list of over-limit units (`path:line`, length).
- Rubric (P315/P317 pilots): good, neutral, bad-lost-why, bad-wrong, bad-style (not graded),
  missed-trivia. Judged from before/after and context only. Shorter is not better.
- Bars per language, denominator 120:
  - **meaning-level bad (bad-lost-why + bad-wrong) at most 3.** Same bar as P315/P317. Round 9
    scored 0/120 and round 5 2/120 on the same path, so 3 leaves room for variance without
    accepting a systematic loss. Stricter than the pilot in one way: the denominator holds
    rewritten units only (the pilot's 120 included about 15% unchanged units that cannot fail).
  - missed-trivia and bad-style: reported, not gated. They ship text no worse than today's, so a
    revert would not fix them.
- Judge output: `docs/v2.8/plans/P320-judge.md` (counts per language and verdict, one line per
  non-good unit with id, `path:line`, verdict, reason; no full comment text), committed `docs: P320
  judge`.
- Acting on it:
  - Language fails its bar: `git revert` that language's commit. Nothing is redone in P320.
  - Language passes: every meaning-level-bad unit in its sample goes back to the original with
    `restore --ids`, one commit `fix: restore P320 comments the judge flagged`. No tokens.
- The orchestrator checks the bar against the judge file's counts, not prose.

## Phasing

Each step ends in a commit. Steps 1 and 2 cost no tokens.

1. **Ledger refactor**: `scripts/internal/runledger` out of `scripts/docshistory`. Commit
   `refactor: share docshistory spend ledger`. Guard: `go test ./scripts/docshistory/...` green,
   `go run ./scripts/docshistory units v2.8` output unchanged.
2. **Tool**: `scripts/commentsweep` (Go), `scan.ts`, `.gitignore` line, wiring (below), tests
   (below). Commits per group: extraction, apply and checks, driver and report. Then `scan` and
   paste its per-language counts and projection into the hand-back. **Hand back. The orchestrator
   puts the estimate to the owner; nothing below runs without acceptance.**
3. **Run** (accepted cap): `run --max-usd <cap> --jobs 4`. Order Go, TS, Vue. Resumable: rerun the
   same command after any halt. No commit (state on disk under `.commentsweep/`).
4. **Apply and commit per language**, Go then TS then Vue:
   - `apply --lang <l>`;
   - repo checks for that language (below), fix on the spot;
   - one commit: `refactor: tighten long Go comments (P320)` (TS, Vue alike), explicit pathspec
     from `applied.jsonl`, never `git add -A`.
   - Repo checks:
     - Go: `gofmt -l` empty on touched files, `go build ./...`, `go vet ./...`, `bun run lint:go`,
       `bun run lint:claude`, `go test ./...` with the container-backed suites as
       `docs/DEV_ENVIRONMENT.md` describes.
     - TS and Vue: `bun run lint`, `bun run typecheck`, `bun run lint:dead`, `bun run test:unit`.
5. **Report**: `report`, commit `docs: P320 report`. **Hand back.**
6. **Judge** (orchestrator spawns one Opus subagent): writes and commits `P320-judge.md`.
7. **Act**: revert failing languages, `restore` flagged units of passing ones, commit.
8. **Close**: SPEC row Done and `**P320.**` Result (units per language, outcomes, kept per gate,
   over-limit count, spend, cost per unit, judge counts, reverts), commit `docs: P320 done`. Delete
   `.commentsweep/` only after this commit.

## Risks

- Kept by gate: round 9 kept 5 of 120 (4%: hedge 2, width 1, form 1, grew 1). Expect about 200
  kept units at >=300; they ship the original and appear in the report by gate. `width` keeps any
  unit with an inherited over-width line the model does not fix.
- Over-width: the `width` gate rejects any accepted line over 100 columns, so the sweep adds none.
  It can leave existing ones (kept units).
- Concurrent work: P320 assumes no other commit to in-scope files between `scan` and the last
  `apply`. Apply refuses changed files by sha; a rerun reuses results by `inputKey`, so only new
  text costs tokens. P322 (close) waits for P320 anyway.
- Generated bindings: none tracked (0 `bindings/` files); generated Go and TS paths are excluded
  by header and by Biome's ignore list.
- Load-bearing comments: an empty `catch` must hold a comment (U61, `scripts/check-ui-primitives.sh`).
  A rewrite never removes a unit (the gates keep markers), so the comment stays.
- Revert granularity: one commit per language means a failed bar reverts that whole language,
  including its good rewrites. Accepted by the owner as the simple recovery.
- Variance: the judge sees 120 of about 2,500 Go rewrites. 0 to 3 bad in 120 does not prove the
  rate under 3% for the rest; it matches the evidence the owner accepted for P317.
- Review base: the next code review's diff includes these three large comment-only commits. The
  reviewer excludes them by hash; the token check proves they hold no code change.
