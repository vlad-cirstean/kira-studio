- `AGENTS.md` in the workflows folder lists all available options and how to update them, enough for an AI

- Generated or checked against the workflow schema (P450 convention) so it cannot drift from the validator.
- Test: flow test asserts every schema option appears in the file.

## 1. What exists today

- `configfs.DocModel{App, Title, Intro, Pattern, Format, Options []DocOption, Rules []string, Refs}` and
  `RenderAgentsMD` render the fixed sections (header, intro, Files, Options, Rules, References, How changes
  apply). `Folder.WriteDocs(m)` writes `AGENTS.md` atomically when bytes differ, creating the folder.
  `DocFromSchema` builds `Options` from a JSON Schema. No production caller of any of it.
- `RenderAgentsMD` always prints "Keep per-machine values in `<name>.local.yaml` …". No module reads
  `.local.yaml` yet (P461 is first). For workflows that line is false.
- Workflows have no JSON Schema. `adeflow.Parse` is a hand-written `yaml.Node` validator. Its key facts are
  scattered literals:
  - top level: `fields(root, "", "id", "name", "kira_space_mcp", "steps")`; `stages` refused by name;
    `kira_space_mcp` legacy (accepted, ignored, dropped on save).
  - steps: `stepKeys` per kind plus head keys `id, name, kind, status, skip`; `stepHead` repeats a 14-key
    literal list of non-head keys.
  - nested: `results[]` `id, ok, description, next`; `sandbox` `access, read, allow, network`; `review`
    `send_to, implementer`; `params.*` (name pattern, text or list); `settings.<agent>.<key>` from
    `providers.StageCatalog()` (today `claude.autoCompactWindow`, int, min/max, i18n label and hint).
  - enums and limits: `kind`, `before` (`auto|approval`), `sandbox.access` (`write|read|off`),
    `review.send_to` (`implementer|new`), `runs_on` (`once|each repo|only <repo>`), `timeout` (Go duration,
    at most 24h), `max_returns` (1 to 10, review 0 to 10), results 1 to 12, description 200 chars,
    smart script name 200, status id 40, sandbox lists 32 entries of 4096.
  - required: `runs_on` and `timeout` on agent, script and review steps (`str(…, true)`); `command` on
    script; `prompt` on agent without `smart_script`; `ok` on every declared result.
- `writer.go` keeps its own `topOrder`, `stepOrder`, `resultOrder` key lists and `applyStep` keeps
  `stepKeys[kind]`.
- `TaskBoard.Start` (`ade/workflows.go`) starts the folder watch; `wireAdeTask` calls `Recover` then
  `Start`, and the flow harness runs that path.
- `ConfigFileBar` has an optional `about` prop (opens `AGENTS.md`); `AdeWorkflowEditor` does not pass it.
  `configsvc.resolve` already accepts `AGENTS.md` (plain, not hidden, regular file).
- `flows/adeflow/workflowfiles_test.go` asserts nothing but `saved.yaml` sits in the workflows folder after
  a save. An `AGENTS.md` written at start breaks that check.

## 2. Spec issues

- "the workflow schema" does not exist. Workflows validate through `adeflow.Parse`, not JSON Schema (P450
  §2.3 kept it on purpose). Writing a JSON Schema beside it would add a second validator that can drift
  from the first, the opposite of the row's goal. The plan reads "schema" as one declarative option table
  in `adeflow` that the parser and writer derive their key sets and enums from, and the docs are generated
  from the same table. P450's plan already said so ("P451 builds its DocModel from adeflow's key tables").
- "cannot drift" is fully mechanical for keys, nesting, kinds, enums, defaults and limits (one source, §3.2).
  Rules (cross-field checks) stay hand-written code; their docs are bound by a test that fails when a
  documented rule stops rejecting its example. A new check added to the validator without a rule doc is
  not caught mechanically. Stated plainly, not papered over.
- P450's shared "How changes apply" text claims `.local.yaml` support every folder has. Fixed here by making
  that line opt-in (§3.4).

## 3. Decisions

### 3.1 Option table (`adeflow/options.go`)

```go
type option struct {
	Path       string             // DocOption path: dotted, [] for list items, * for any key
	Type       string             // "text", "boolean", "whole number", "list of text", "mapping", "duration"
	Kinds      []adewire.StepKind // steps[] keys only; nil = every kind
	Required   bool               // always required where the key may appear
	RequiredOn []adewire.StepKind // required on these kinds only
	Default    string             // rendered text, from adewire constants
	Enum       []string
	Range      string             // built from the same constants the validator uses
	Legacy     bool               // accepted and ignored; the writer drops it
	Doc        string             // one line, English (backend text is English-only, P265)
}
var options = []option{ … }
```

- One entry per key at every level: `id`, `name`, `kira_space_mcp` (Legacy), `steps`, `steps[]`,
  `steps[].id` … `steps[].allowed_tools`, `steps[].results[]`, `steps[].results[].id/ok/description/next`,
  `steps[].params`, `steps[].params.*`, `steps[].review`, `steps[].review.send_to/implementer`,
  `steps[].sandbox`, `steps[].sandbox.access/read/allow/network`, `steps[].settings`. Table order within
  `steps[]` is today's `stepOrder`; within results, `resultOrder`; top level `id, name, steps` then legacy.
- Enum slices are package vars shared with the validator (`kinds`, `beforeValues`, `accessValues`,
  `sendToValues`). Range strings format the existing constants (`maxStepTimeout`, `adewire.MaxMaxReturns`,
  `maxResults`, `maxResultDescription`, `maxSmartScriptName`, `maxStatusID`, `maxSandboxPaths`,
  `maxSandboxPath`) and patterns (`idPattern`, `paramNamePattern`). Defaults format `adewire` constants
  (`DefaultMaxReturns`, `DefaultRoute`, `DefaultSandbox`, `ReviewSendImplementer`, `"auto"`).
- `settings.<agent>.<key>` is not in the static table: it is generated from `stageCatalog` (already a
  package var in `parse.go`) at doc build time: path `steps[].settings.<id>.<key>`, type whole number,
  range `minimum Min, maximum Max`, doc `i18n.T(LabelKey)` plus `i18n.T(HintKey, {min, max})`. A provider
  P448/P449 adds shows up with no `adeflow` change.

### 3.2 Parser and writer derive from the table (the drift guarantee)

- Derived once at init in `options.go`: `topKeys` (non-legacy plus legacy), `stepHeadKeys`,
  `stepKeys map[kind][]string` (replaces the literal map), `allStepKeys`, `bodyKeys` (replaces
  `stepHead`'s 14-key literal), `resultKeys`, `sandboxKeys`, `reviewKeys`, and the writer's `topOrder`,
  `stepOrder`, `resultOrder`. A helper `childKeys(parent string) []string` reads them off `Path`.
- `fields(…)` calls pass the derived sets. `fields` refuses any key outside them, so the validator cannot
  accept a key the table (and so `AGENTS.md`) lacks. A later phase adding a step key (P449's per-step agent
  override) must add a table row or the parser refuses the key.
- Enum checks use the shared slices with a helper `oneOf(vals) string` ("a, b or c"). Messages stay
  byte-identical ("kind must be agent, script, review or manual", "before must be auto or approval",
  "access must be write, read or off", "send_to must be implementer or new"). Existing `adeflow` tests and
  the UI spec asserting the kind message prove it.
- Behaviour change: none. Same accepted files, same messages, same writer output. `adeflow` unit tests and
  `flows/adeflow` pass unchanged; that is the commit's check.
- Declined: generating a JSON Schema from the table and validating through `configfs.YAMLSchema` first. It
  would change error text and order for every bad file (schema errors fire before `Parse`'s), and the many
  interacting rules still need `Parse`. Nothing gained over §3.2.

### 3.3 Doc model (`adeflow/docs.go`, `adeflow/agents_intro.md`)

- `func DocModel() configfs.DocModel`: `App: "Space"`, `Title: "Workflows"`, `Pattern: "<id>.yaml"`,
  `Format: "YAML"`, `Intro` from `//go:embed agents_intro.md`, `Options` from §3.1 (static table plus
  catalog settings), `Rules` from `rules`, `Refs: false` (workflows take no `${…}`), `LocalOverrides: false`.
- Per-option text generated from the table, never hand-written per entry: Kinds become "Agent, script and
  review steps."; RequiredOn becomes "Required on agent, script and review steps."; Legacy becomes
  "Legacy: accepted and ignored; Kira drops it on save." These go in front of `Doc` in `Description`.
- `rules`: `[]rule{ID, Doc string}` next to the validator, one per cross-field check: file stem equals
  `id`; `stages` refused; `steps` non-empty and one step not skipped; step ids unique; a step takes only its
  kind's keys; agent step runs `prompt` (with `allowed_tools`) or `smart_script` (with `params`), never
  both; manual `prompt`/`settings` only with `session: true`; script results, when given, are exactly `done`
  (ok) then `failed` (not ok); result ids unique, `needs_input` reserved; `next` is `next`, `end`, `stop`
  or a step id, `stop` only when not ok, a route to the same or an earlier step is a return counted against
  `max_returns`, never to a manual or skipped step; one result leads forward; `review.implementer` is an
  earlier agent step without `smart_script`; `sandbox` `access: off` takes no other key; sandbox paths are
  absolute or `~/`, never the root, the home folder or an ancestor, an agent config folder or the keychain
  folder; legacy status names (`To do`, `In progress`, `In review`, `Done`) read as their ids; `status`
  membership and `only <repo>` repos are checked at run time, not load.
- Intro template (prose, plus examples): what a workflow is (a task runs its steps top to bottom), the four
  kinds in one line each, how to add or change one (write `<id>.yaml` here in any editor, or the Workflows
  page; `id` must equal the file stem; renaming the file changes the id), what an edit affects (new tasks
  only; running tasks keep the snapshot they started with), statuses come from the Workflows page's
  Statuses list, one complete example workflow (agent, script, review, manual steps, a result with `next`
  back to an earlier step) in a ```yaml fence. P450 §2.7 said intro is "prose only, no option facts": the
  example breaks that letter on purpose, and the flow test parses it (§5), so it cannot rot.
- `Reader.WriteDocs() error` = `r.folder().WriteDocs(DocModel())`. `reader.go`'s comment "Only the writer
  methods create the directory" gains "and WriteDocs".
