# P447 plan: shared keychain secret layer; Runs secret params stored encrypted

Base: `chapter/v0.2.26` at `755cfce91`. One phase, one sequential Sonnet implementer (orchestrator
decision: parallelism runs across phases, not inside this one). Discovery used `codegraph_explore`
over `internal/secrets`, `internal/scripts`, `internal/scriptruns`, `termtext`, `linewriter`,
`harness/claude` stream, both appwires and `apivars`/`localauth`.

## 1. What the code does today (re-read, not from spec prose)

- `apps/kira-studio/internal/secrets`: `cipher.go` (AES-256-GCM, `envelopePrefix = "kira:v3:"`, AAD =
  prefix + scope), `scope.go` (5 scopes, `valid()`), `status.go` (`Status`, i18n reasons under
  `backend.studio.secrets.*`), `keyring_darwin.go` (go-keychain, item `Kira Studio Secrets` /
  `Kira Studio`), `keyring_nocgo_darwin.go`, `keyring_other.go`, `cipher_test.go` (freezes prefix and
  scope strings), `keychain_darwin_test.go`. Importers: Studio `appwire`, `main.go`, `connections`,
  `flowharness`, `ipcfixture`, `storage/repos/{secrets,variables,maskkeys}.go` and their tests,
  `apivars/resolve_test.go`, `bridge/{grpc,collections_import_atomicity}_test.go`. Space: none.
- `scripts.Param.Secret` (text only, no default). A secret value reaches the run only as
  `KIRA_PARAM_<NAME>` (`planned.envList`); `RunParam` stores `scripts.SecretMask` (`••••`);
  `Preview.Env[].Value` is `""` for a secret; a smart prompt naming a secret is refused
  (`validParams`, `checkPromptEdit`).
- Nothing masks output today. A process that echoes a typed secret puts plaintext in
  `script_run_logs`, the `kira:scriptRuns:log` push, and `outcome_json` (`lastError`, `outputTail`,
  `summary`, `reason`).
- Resume/restore: `resumeArgs` names every secret param, so `resume` and `restoreItem` refuse.
- Schedule: `validScheduleParams` refuses a secret in `schedule.params`, and refuses any secret param
  unless `confirm`. `unstartable` lets a missing secret through only under confirm; the popup asks.
- Output paths: headless normal run (`runHeadless`, `linewriter` -> `logSink.add`), smart run
  (`harness.Handler.OnLine` -> `logSink.add`; claude lines are decoded stream-json text, a tool input
  can carry JSON-escaped text), terminal run (PTY to xterm live; `Service.Output` -> `termtext.Tail`
  -> `outputTail` on failure).
- Script runs are never `op_log` rows in either app (projection of `script_runs`). The scriptruns MCP
  server has no `OnToolCall`, so smart-script tool calls are not op-logged.
- No duplicate or export path exists for scripts (checked `internal/scripts`, both bridges,
  `packages/workbench/src/automations`).
- Delete: `Repo.Delete` (script) and `Repo.DeleteCollection` (FK cascade to scripts). An `Update`
  can drop, rename or un-secret a param.
- Reveal: `apivars.Reveal` / `connections.Reveal` via `localauth.Gated`; `localauth` is Studio-only.

## 2. Decisions

### 2.1 Hoist (byte-identical)

`git mv apps/kira-studio/internal/secrets internal/secrets` (all 8 files). Package name stays
`secrets`; import path becomes `github.com/kirathecat/kira-studio/internal/secrets`. Unchanged bytes:
`envelopePrefix`, every scope string, `insecureKeyMaterial`, `keychainService`, `keychainAccount`,
`keychainLabel`, the `KIRA_INSECURE_SECRETS` parsing. `cipher_test.go` keeps freezing them and gains
the new scope.

i18n keys move `backend.studio.secrets.*` -> `backend.core.secrets.*` with text verbatim (the
package is no longer Studio's). Only `status.go`/`cipher.go` read them.

Kira Space builds its own `*secrets.Cipher` with `secrets.New()` in `main.go` and passes it through
`appwire.Options.Cipher`. Both apps use the same keychain item and so the same key: this is the
"shared keychain" P453 needs, and it costs no new API. Cost: on macOS, whichever app did not create
the item gets one "wants to use your confidential information" prompt per ad-hoc build (`Always
Allow`), the same cost `docs/PACKAGING.md` already records. See question Q1.

### 2.2 Stored secrets: one table, namespace = scope + owner

New migration in each app: Studio `0052_p447_secret_values.sql`, Space `0062_p447_secret_values.sql`.

```sql
CREATE TABLE secret_values (
  scope      TEXT NOT NULL,   -- secrets.Scope; the AAD the value is sealed under
  owner      TEXT NOT NULL,   -- owner id within the scope (custom_scripts.id for script-param)
  name       TEXT NOT NULL,   -- param name
  value      TEXT NOT NULL,   -- kira:v3: envelope, never plaintext
  updated_at TEXT NOT NULL,
  PRIMARY KEY (scope, owner, name)
) WITHOUT ROWID;
```

New scope `ScopeScriptParam Scope = "script-param"` (added to `valid()` and the frozen-string test).
AAD stays bound to kind, not row (the repo-wide rule): DB write access can move one script's sealed
value to another script of the same scope, same as today's connection columns. Stated, not changed.

`internal/secrets/store.go`, the only reader and writer of `secret_values`. Only methods scripts use:

```go
type Execer interface{ Exec(query string, args ...any) (sql.Result, error) }

type Store struct{ db *sql.DB; c *Cipher }
func NewStore(db *sql.DB, c *Cipher) *Store
func (s *Store) Status() Status
// Put seals plain under scope and upserts it through q (a *sql.Tx or the DB).
func (s *Store) Put(q Execer, scope Scope, owner, name, plain string) error
// Prune deletes the owner's names not in keep; keep nil deletes them all.
func (s *Store) Prune(q Execer, scope Scope, owner string, keep []string) error
// Names lists saved names per owner, for snapshots. No decrypt.
func (s *Store) Names(scope Scope) (map[string][]string, error)
// Open decrypts one owner's values; unreadable holds names whose value failed to decrypt.
func (s *Store) Open(scope Scope, owner string) (vals map[string]string, unreadable map[string]error, err error)
```

P453 shape: it adds its own scope (agent credentials) and its own owner ids, and calls the same
`Put`/`Prune`/`Open`. Nothing for it is added now.

`internal/secrets/mask.go` (used now by scriptruns; P453 reuses it for agent output):

```go
const Mask = "••••"           // scripts.SecretMask becomes = secrets.Mask
type Masker struct{ r *strings.Replacer }   // nil Masker masks nothing
func NewMasker(values ...string) *Masker
func (m *Masker) Mask(s string) string
```

Forms masked per non-empty value: the value; each non-empty line of a multi-line value (a text
param allows `\n`); the JSON-escaped form of each (`json.Marshal` minus quotes; covers `\"`, `\\`,
`<`). Deduped and sorted longest first (`strings.Replacer` tries patterns in argument order at
each position). Over-masking only, never under-masking (the `apivars` precedent); a 1- or 2-char
secret masks those chars everywhere. Stated in ARCHITECTURE.

No library: `strings.Replacer` is stdlib and enough; no masking library adds anything here.

### 2.3 Scripts: write-only saved value

- `scripts.CreateArgs` and `UpdateArgs` gain `SecretValues map[string]*string \`json:"secretValues"\``:
  a string saves, `null` clears, an absent name keeps. On Args, not `CustomScriptFields`, so
  `customScriptSchema` (which extends the fields schema) never carries a value.
- `scripts.CustomScript` gains `SavedSecrets []string \`json:"savedSecrets"\`` (names only).
  `scripts.Snapshot` gains `SecretStorage secrets.Status \`json:"secretStorage"\`` (fixed for the
  process; lets the editor disable the field without a new bound method).
- `scripts.Repo` gains `Secrets *secrets.Store` (set in each appwire). `Create`/`Update` run in one
  tx: write the row, `Prune(tx, ScopeScriptParam, id, <current secret param names>)` (drops removed,
  renamed and un-secreted params), then `Put` each set value, delete each cleared one. A value for a
  name that is not a secret text param is refused. Values pass `checkText`.
- `Repo.Delete` and `Repo.DeleteCollection` prune in the same tx (`DeleteCollection` first selects
  the collection's script ids). `Repo.List`/`Get` fill `SavedSecrets` from `Store.Names`.
- New `Repo.SecretValues(id)` -> `Store.Open`, used by `scriptruns.plan`.
- Plaintext reaches only: the bound Create/Update args (renderer to Go), `Store.Put`, `Store.Open`,
  `planned.envList`, the child env. Never the DB (ciphertext only), `slog`, `op_log`, `script_runs`,
  `script_run_logs`, previews, snapshots, pushes or any bound read.
- No reveal. The field stays write-only (replace or clear). Reusing the gated reveal would mean
  hoisting `localauth` too, for a value the user typed and can retype; the spec makes reveal
  optional. P453 keeps the same answer unless the user asks.

### 2.4 Run: saved value used when none typed

In `scriptruns.plan`, before `scripts.ParamValues`: for each secret param with no typed value, fill
it from `Repo.SecretValues`. Typed wins. Unreadable values count as absent; `Preview` gains
`SecretIssue string` (new key `backend.core.scriptRun.savedSecretUnreadable.body`: "The saved value
of {names} can’t be read ({detail}). Type it, or save it again."). `EnvVar` gains `Saved bool`.
`planned` gains `mask *secrets.Masker` built from every secret value the run gets (typed or saved).
Still env-only: no change to prompt rules. Hash unchanged (secret env values are `""` in it).

This covers Start, Preview, scheduled fire, confirm accept, run now, resume and restore: all call
`plan`.

### 2.5 Masking: where, and what stays unmasked

Masked (Go side, before store or push):
1. `logSink.add` masks `text` before the 2 KiB truncation and before tail, `lastErr`, store and
   `EmitLog`. `newLogSink(svc, runID, mask)`. Covers headless normal runs and smart runs, stored log
   and live push alike.
2. Outcome text: helper `maskOutcome(o, m)` over `Reason`, `LastError`, `OutputTail`, `Summary`,
   applied before every `FinishByRun`/`FinishByTerminal` (`headless.go`, `smart_run.go`,
   `service.go` `Exited`). So `outcome_json`, the run push, Space notifications and Copy for agent see
   only the mask.
3. Terminal runs: `launch` carries the masker; `Begin` stores it beside the tail
   (`tails map[string]*termTail{tail, mask}`); `Exited` masks `Tail.Lines` output.

Chunk boundaries: `linewriter` hands whole lines, so a single-line secret never splits across two
`add` calls; each line of a multi-line secret is its own pattern. `Tail.Lines` works on the joined
ring and drops the partial first line after a wrap. Masking runs before every truncation.

Not masked, stated plainly in ARCHITECTURE and the copy where it shows:
- The live terminal tab (PTY bytes go straight to xterm; the app filters nothing there), and Kira
  Space's phone terminal ring (`mobileterm`) for the same session.
- A line cut at `linewriter.MaxLine` (16 MiB) keeps the part of a secret before the cut.
- What an agent writes through Space task tools (comments, artifacts, step results, git tool argv in
  `op_log`) for a task-bound smart run. Out of the run record; the env-only rule keeps it out of the
  prompt.
- What the process itself writes elsewhere (files, network).

### 2.6 Resume and schedule rules

  it is named missing only when the run had a value (`••••`) and no readable saved value exists.
