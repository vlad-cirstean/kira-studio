## Design

### Interactive launch returns env and the assigned id

```go
// internal/harness/interactive.go
type Launch struct {
    Command string
    // Env is KEY=value entries the agent process gets; never sent over the bridge.
    Env []string
    // SessionID is the id the agent runs under, "" when only known after launch.
    SessionID string
}
type Interactive interface {
    InteractiveCommand(s InteractiveSpec) Launch
    WithPrompt(command, prompt string) string
}
```

- `InteractiveSpec.SessionID` becomes the proposed id on a new session and the required id on a
  resume. Doc says so. Claude returns `Launch{Command: <today's string>, SessionID: s.SessionID}`.
- `InteractiveSpec.MCPConfig`: rename doc to "path of a file holding `MCPHost.MCPConfig`'s
  document; the provider passes it as a flag or env". Field name stays (no churn).
- `Tracker.Prepare` stores `Launch.Env` and `Launch.SessionID` on its pending intent. The adewire
  command sent to the renderer is `Launch.Command`, unchanged.
- `Tracker.Compose` returns intent env first, then hooks env (`Compose` already returns `[]string`).
  `terminal.BoundService.Open` is unchanged for this path.
- Continue in terminal (`scriptruns.ResumeCommand`): Studio has no `ComposeAgent`, so env cannot
  ride the Tracker. Reuse scriptruns' own launch-token store (`launch.go`), already wired as
  `terminal.BoundService.Scripts` in both apps:
  - `ResumeCommand(runID) (ResumeLaunch, error)`, `ResumeLaunch{Command string; Token string}`.
    Token is `""` when `Launch.Env` is empty (Claude), so Claude opens exactly as today.
  - A non-empty env is stored under a single-use token with `LaunchTTL`, keyed to the command.
  - `terminal.ScriptLauncher` gains `BeginAgent(token, command string) ([]string, error)`.
    `OpenArgs` gains `AgentLaunchToken` (bounded by `MaxLaunchTokenBytes`, `validate.go`). `Open`
    with `LaunchKindAgent` and a token calls `BeginAgent`; a stale token or a command mismatch is the
    existing `backend.core.scriptRun.expired.body` conflict. Env is prepended before `ComposeAgent`
    env, same order as the Tracker path.
  - Frontend: `ScriptRunView.vue` `continueInTerminal` passes `launch.agentLaunchToken`. The
    terminal open path forwards it (same plumbing as `scriptLaunchToken`).

### Late session id

- `model.AdeSession.Validate`: `AgentSessionID` required for headless only; TUI may be `""`.
- New optional role in `internal/harness/session.go`:

  ```go
  // SessionLocator finds the id of a session the agent assigned itself after launch.
  type SessionLocator interface {
      FindSession(ctx context.Context, q SessionQuery) (string, error) // "" when not found yet
  }
  type SessionQuery struct { Cwd string; Since time.Time }
  func ValidSessionID(id string) bool // 1..128 of [A-Za-z0-9_.-]
  ```

- `Tracker.HandleEvent`: `uuid.Parse` becomes `harness.ValidSessionID`. A `SessionStart`-kind event
  fills an empty id as well as replacing a changed one (Claude `/clear`), via
  `repos.SetAgentSessionID`. Claude ids are uuids, so Claude behaviour is unchanged.
- Discovery: one Tracker method `learnSessionID(recordID)` that, when the stored id is `""` and the
  provider is a `SessionLocator`, calls `FindSession{Cwd, Since: StartedAt}` and stores a valid
  result. Called at stop (`Tracker.Stop`, `Reconcile`) and lazily at the two resume points
  (`resumeTarget` in `tracker.go`, `takeOverLocked` in `launches.go`).
- Still `""` at a resume point: refuse with a clear `invalid(...)` error, new i18n key
  `backend.ade.session.idUnknown.body` ("The agent has not reported its session id yet. Try again
  once it has started."). No new error kind; same path as other refusals there.
- `repos.ProviderOfAgentSession("")` returns `""` without querying; `agentForResume` never matches
  an empty id against stored empty rows.

### Optional Structured and Headless

- `harness.Provider` drops `Structured` and `Headless` from its embed. Helpers:
  `harness.StructuredOf(p) (Structured, bool)` and `harness.HeadlessOf(p) (Headless, bool)`, same
  pattern as `ReportsUsage`.
- New `harness.ErrUnsupported` kind plus `harness.MissingRole{Agent, Role string}` error
  (`Error()` from i18n key `backend.core.agent.missingRole.body`: "{agent} cannot run {role}.").
- Per caller:
  - Memory (`internal/memory/agentrunner.go`): fall back to the registry default (claude, what
    `Selector.Active` already falls back to). `RunResult`, `Fail`, `Available` and the model alias
    all resolve the same provider through one `structured()` helper, so a model alias never pairs
    with the wrong provider. Reason: memory is background work with no per-run provider choice; a
    refusal would silently stop distillation for a user who picked a lean agent.
  - Smart scripts (`internal/scriptruns/preview.go` `plan`): refuse through `Preview.Blocker`
    (`MissingRole` text) when the resolved provider lacks `Headless`. One check covers Start,
    schedule and resume, all of which go through `plan`. `planned.agent` keeps
    `harness.Provider`; `planned.headless harness.Headless` holds the asserted role for
    `smart_run.go`. Reason: the user picked the provider; a silent swap would run a different
    agent than the dialog shows.
  - ADE steps, smart steps, rebase, review rounds (`ade/runs.go` `superviseAgent`): one check before
    `prepareSandbox`; missing `Headless` calls the existing `fail(err)` with `MissingRole`, so the
    run is recorded failed with that note and the log line "could not start: ...". Reason: one
    choke point for all four purposes; same visible failure as any start error.

### Neutral hook event kinds

- `internal/harness/hooks.go`:

  ```go
  type EventKind string
  const (
      EventSessionStart EventKind = "SessionStart"
      EventSessionEnd   EventKind = "SessionEnd"
      EventPrompt       EventKind = "UserPromptSubmit"
      EventToolStart    EventKind = "PreToolUse"
      EventToolEnd      EventKind = "PostToolUse"
      EventNotification EventKind = "Notification"
      EventTurnEnd      EventKind = "Stop"
  )
  ```

  Wire values equal today's strings, so the bridge, contracts and frontend see no change.
  `AgentEvent.Event` becomes `EventKind`. Two neutral flags the provider sets:
  `Wakes bool` (tool start of a self-wake tool) and `NeedsInput bool` (notification asks the user).
- `claude/hooks/http.go` maps `hook_event_name` through a table to `EventKind`, drops unknown names
  (200, no `OnEvent`), and sets `Wakes` (`Monitor`, `ScheduleWakeup`) and `NeedsInput` (today's
  `agentnotify.needsInput` rule: `permission_prompt`, `elicitation_dialog`, `""`).
- `agentnotify.HandleEvent` and `Tracker.HandleEvent` switch on the constants and flags; the
  `wakeTools` set and `needsInput` move out of `agentnotify` into the Claude hooks package.
- Frontend unchanged (user question 3).
