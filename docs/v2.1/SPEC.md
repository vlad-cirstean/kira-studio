# Kira Studio — v2.1

v2.0 closed with `P184` (SQS read-only poll visibility setting). This chapter continues `P`
numbering from `P185`, per `CLAUDE.md`'s one-running-sequence rule. Rows come from twelve user
requests; requests 11 (P195) and 12 (P196) arrived after the first ten were numbered and sit last.

**Three parallel streams, one plan.** `plans/P185-P196-plan.md` splits the rows into Stream A
(P185-P188), Stream B (P189, P195) and Stream C (P190-P194, P196), each its own git worktree off the same
base commit, with a per-stream file-ownership table of zero overlap and no ordering dependency
between streams (`CLAUDE.md`'s streams rule). Inside a stream, rows run in table order. Request 7's
git-module dialog and its `ade`-side removal stay in one row (P190, Stream C): split across streams,
the two halves would share `ade/v2/queries.ts` and `AdeReposPage.vue` and depend on each other.

**P200 (request 13), Docker module.** Runs in Stream B's worktree after P195, concurrent with A and C, from its own plan (`plans/P200-plan.md`). Its few edits to Stream A files sit in one seam commit, listed line by line in that plan, re-applied on rebase. P197-P199 are reserved for the three queued requests in `plans/queued-requests.md`.

**P203-P207 (stream F), rework round.** User feedback on shipped v2.1 work, one plan (`plans/P203-P207-plan.md`), one sequential implementer in `v2.1-stream-F`, rows in the user's priority order. P203-P204 may run beside stream E; P205-P207 start after E lands (shared `ade` wire and files). Previously queued audit and review renumbered P208/P209 (`plans/queued-requests.md`).
