# P343 plan: keep commit detail panel open when opening a diff

Spec row: `docs/v0.2.15/SPEC.md` P343. Bug: in Kira Space's git graph, opening a file diff from a
commit hides the commit detail panel. Returning to the graph tab shows no panel. Panel must stay.

## Root cause

Not in `openRepoCommitDiffTab` (`apps/kira-space/frontend/src/state/repoTabs.ts:179`) or
`reuseOrOpenRepoDiffTab` (`:119`). Those only open or activate a `repo-diff` tab in the repo
workspace. The pinned `repo-graph` tab is never evicted; it stays mounted but hidden.

Chain, as the source stands:

1. `DetailPane.vue:56` `onOpenFile` calls `actions.openInEditor`. Host handler
   `apps/kira-space/frontend/src/repo/git/hostHandlers.ts:199` (`editor.openDiff`) calls
   `openRepoCommitDiffTab`. New diff tab becomes active.
2. `apps/kira-space/frontend/src/views/repo/RepoGraphView.vue:71-77` calls
   `handle.setVisible(false)` (sync), then MainView hides the host with `v-show`. Host is now 0×0.
3. `packages/git-ui/src/App.vue:1635` `useResizeObserver(rootEl, scheduleBreakpointUpdate)` fires
   for the 0×0 transition. `scheduleBreakpointUpdate` (`App.vue:1591-1597`) reads
   `clientWidth` 0, and `breakpointFor(0)` (`:1403`) returns `'overlay'`.
4. Two effects of the bogus `'overlay'`:
   - Template swaps branches. Docked `<aside v-if="detailOpen && breakpoint !== 'overlay'">`
     (`App.vue:1820`) unmounts; overlay drawer (`:1867`) mounts, hidden. `DetailPane` remounts.
   - `onClickOutside(overlayDetailRegionEl, …)` (`App.vue:1578-1589`) now arms:
     `breakpoint === 'overlay' && detailOpen`. Any pointerdown elsewhere in the document — inside
     the diff editor, or the click on the graph tab itself to go back — calls `closeDetail()`.
     `detailOpen` goes `false`. On return the observer restores `'wide'`, but the panel stays
     closed. This is the reported bug.
5. Secondary: `watch(breakpoint, …)` (`App.vue:1430-1432`) runs
   `collapseIfNarrowWithNoSelection()` on the `wide` to `overlay` flip. A stash or working-tree
   selection has `selection.row < 0` (`:1423`), so the panel closes on hide even with no click.

`CommitGrid.vue:714-746` (`scheduleResize`) already fixed the same class of bug for the grid: it
skips work while `!graphVisible.value`, because a hidden host's 0×0 size is not a real layout.
`App.vue`'s breakpoint logic never got that guard. `graphVisible` is already injected in
`App.vue:1414` (`useGraphVisible()`) but only `onDocumentKeydown` reads it.

`ReviewView` and git-ui's own tests never provide `GRAPH_VISIBLE_KEY`, so `graphVisible` stays
`true` there (`graphVisibility.ts:17`). The fix changes nothing for them.

## Change

One file: `packages/git-ui/src/App.vue`. No change to `repoTabs.ts`, `hostHandlers.ts`,
`RepoGraphView.vue`, `main.ts` or any IPC contract.

1. Add one function next to `scheduleBreakpointUpdate` (`:1591`):

   ```ts
   // A hidden kept-mounted host reads 0×0, not a real width (CommitGrid's scheduleResize guard).
   function syncBreakpoint(): void {
     if (!graphVisible.value || !rootEl.value) return;
     breakpoint.value = breakpointFor(rootEl.value.clientWidth);
   }
   ```

   Use it in the rAF body of `scheduleBreakpointUpdate` (`:1595`) and in `onMounted` (`:1638`)
   instead of the two inline `if (rootEl.value) breakpoint.value = …` lines. Breakpoint now
   freezes at its last visible value while hidden. No docked/overlay swap, no `DetailPane`
   remount, no `collapseIfNarrowWithNoSelection` on hide.

2. Re-sync on show: `watch(graphVisible, (v) => { if (v) scheduleBreakpointUpdate(); })`. The
   observer also fires on 0 to real-size, so this is a cheap backstop for a hide/show where the
   observer callback ran while hidden and the shown size equals the pre-hide size. Put it beside
   `useResizeObserver` (`:1635`).

3. Guard click-outside (`:1580-1582`): return early when `!graphVisible.value`. Covers a graph
   that was genuinely at the overlay breakpoint (narrow window) before the diff opened. A click in
   another tab is not a dismissal of a drawer nobody can see.

4. Update the `graphVisible` comment (`:1410-1413`). It says only `onDocumentKeydown` reads it;
   it now also gates breakpoint sync and the overlay click-outside. Keep it short.

Libraries: VueUse already provides `useResizeObserver` and `onClickOutside` here; the fix keeps
both and adds no hand-rolled observer. No new UI surface, so no shadcn-vue/Tailwind work. No Pinia
or TanStack Query state is involved (`detailOpen` is component-local view state persisted through
`viewState`, unchanged).

Not in scope: the case where the graph mounts while already hidden (`onMounted` runs before
`RepoGraphView.vue:63`'s `setVisible`). Today that reads 0×0 once; the show-time re-sync in step 2
corrects the breakpoint. No report of a bug there; do not widen.

## Tests

Unit test: none. Two visibility guards and a sync helper are not complex logic per CLAUDE.md's
unit-test bar.

Backend flow test: none. No backend, IPC contract or host-handler change. `editor.openDiff`'s
params and result stay byte-identical; the bug and fix live entirely inside the webview's own
layout state. The split-at-IPC rule has no backend half to write.

UI spec: warranted. The bug is an interaction between a kept-mounted `v-show` tab, a
ResizeObserver, and a document-level click-outside listener. No typecheck or Go test can reach
that, and it already regressed silently once. Keep it to one test.

Extend `apps/kira-space/tests/ui/repo-graph-keep-state.spec.ts`, whose header already states the
invariant ("opening a diff and returning must not … lose scroll/selection"). Add one test, not a
new file:

- `boot(relaunch)`, click a visible grid row, `expect(page.locator('[data-testid="detail-region"]'))
  .toBeVisible()`.
- Tag the detail region like `tag()` does the grid (`dataset.p343 = 'kept'`), to prove no remount.
- `openDiff(page)` (existing helper; graph host hidden, diff editor visible).
- Click inside the diff editor (`[data-testid="repo-diff-editor"]`) to land a pointerdown outside
  the hidden graph.
- `repoTab(page, 'repo-graph').click()`.
- Expect `detail-region` visible and still carrying `data-p343="kept"`; `trackErrors` empty.

Use the existing `openDiff` helper (files panel, "Open changes") rather than a `file-tree-row`
click in the detail pane. Fault and fix are independent of which caller opened the diff tab; the
helper's fixture is already proven in this file. Opening from the detail pane would need extra
`commit.detail` plus commit-revision content mocking for no added coverage.

Confirm the new test fails with the `App.vue` change stashed, then passes with it.
