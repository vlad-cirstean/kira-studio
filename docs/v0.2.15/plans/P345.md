## Fix: stamp dev binary's SDK field to release's value

Post-link, rewrite `LC_BUILD_VERSION` with `vtool` (ships with Xcode CLT, present on `macos-15`
runner and user's Mac). Binary then reports `sdk 15.5`, same as release, so AppKit picks same chrome.
No Xcode 16 install, no plist dependence, works whatever SDK user has.

Apply to both builds in `build:native`, so dev and release stay identical when runner's default
Xcode moves to 26. Release today already `15.5`, so stamp is a no-op for release output.

In both `apps/kira-studio/build/darwin/Taskfile.yml` and `apps/kira-space/build/darwin/Taskfile.yml`,
`build:native`:

1. Add vars `MACOS_MIN: "14.0"` and `MACOS_SDK_STAMP: "15.5"`. Use `MACOS_MIN` in existing
   `CGO_CFLAGS`/`CGO_LDFLAGS`/`MACOSX_DEPLOYMENT_TARGET` env so one literal holds floor.
2. After `go build` cmd, add:

   ```yaml
      # P345: AppKit picks window chrome by the main executable's linked-SDK field. Release links the
      # runner's 15.5 SDK; a dev build on Xcode 26+ would get larger traffic lights. Stamp both alike.
      - vtool -set-build-version macos {{.MACOS_MIN}} {{.MACOS_SDK_STAMP}} -replace -output "{{.OUTPUT}}.stamped" "{{.OUTPUT}}"
      - mv "{{.OUTPUT}}.stamped" "{{.OUTPUT}}"
      # vtool invalidates the linker's ad-hoc signature; arm64 refuses to exec an unsigned binary.
      - codesign --force --sign - "{{.OUTPUT}}"
   ```

   Separate output file: vtool in-place behaviour not relied on. Re-sign: raw `bin/<APP_NAME>` stays
   runnable; `run`/`create:app:bundle` re-sign bundle after anyway.
3. Universal build (`build:universal`) calls `build` per arch, so each thin slice is stamped before
   `lipo`. No change there.
4. Add precondition to `build:native`: `command -v vtool >/dev/null 2>&1`, msg
   `"vtool missing — install Xcode Command Line Tools (xcode-select --install)"`.

Declined:

- Plist key (P344). Released app had it and dev still differs; and once binary reports 15.5 SDK,
  AppKit ignores key anyway.
- `-sectcreate __TEXT __info_plist` embedded plist. Only matters for unbundled launch; dev runs from a
  bundle. Would embed same ineffective key.
- Pin SDK via `SDKROOT`/`DEVELOPER_DIR`. Needs a 15.x SDK on user's Mac (Xcode 16 install); CLT 26
  ships no 15 SDK reliably. Drifts with runner.
- Second `-Wl,-platform_version,macos,14.0,15.5` via `CGO_LDFLAGS`/`-extldflags`. clang already passes
  its own `-platform_version`; duplicate same-platform flag behaviour in ld-prime unverified. vtool
  post-link is deterministic and checkable.
- Env var. No documented AppKit env var for compatibility design; not inventing one.
- Custom-drawn traffic lights (`Frameless`). `window.go:82` already declines; loses native behaviour.
