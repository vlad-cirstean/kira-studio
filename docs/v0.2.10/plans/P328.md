## (b) Partitioned tables nest under their parent

### Audit

- Postgres `listRelationsAndFunctions` (`postgres/catalog.go:129`) lists `relkind IN (r,p,v,m,S)`
  flat; `p` maps to `table`; partitions (`relispartition = true`, relkind `r` or `p`) appear as
  siblings of their parent. Every relation is `HasChildren: false`.
- `Adapter.Children` depth 3 (`postgres/adapter.go:173-180`) returns `LeafChildren` for table.
  `Describe`/`Read`/`Definition` require a 3-segment `database/schema/<object>` path
  (`adapters.RequirePath`).
- MySQL/MariaDB: `information_schema.TABLES` has one row per partitioned table; partitions live in
  `information_schema.PARTITIONS`, are not addressable as a table path, and never show today.
  ClickHouse partitions are parts, not tables. SQLite has none. Kafka `partition` kind is unrelated.
  So only Postgres changes. Out of scope: listing MySQL partitions (nothing flattens today).
- Frontend: `project/grouping.ts` `isLeafKind` forces `table` to leaf regardless of
  `hasChildren` (P19 stale-cache guard). Callers: `project/state/tree.ts` `buildNodeRow`,
  `project/filterTree.ts` `childrenOf` and `emit`. `ProjectTree.vue` twisty calls
  `treeStore.expand` (lazy `control.treeChildren`); double-click on `table` opens a data tab
  (`OPENABLE_KINDS`), unchanged.
- Cache: `tree.Service.Children` caches per (connection, path) and `Invalidate` drops by path
  prefix, so a parent's partition list caches under the parent path and drops with its schema.
- Search (`buildNodeRow`) only walks cached children; an unexpanded parent with
  `hasChildren && !childNodes` sets `stats.incomplete`, so the existing
  `studio.project.tree.searchIncomplete.body` note shows. Unchanged behaviour, correct.
- `revealPath` (`tree.ts:373`) expands path-prefix ancestors. A partition's path is
  `database/schema:<its schema>/table:<name>`, not under its parent, so after the ancestor loop the
  target row may not render.

### Changes

1. `postgres/catalog.go` `listRelationsAndFunctions`: add `AND NOT c.relispartition` to the WHERE;
   select `c.relkind`; node `HasChildren: relkind == "p"`. Update the P19 D5 comment: a partitioned
   table is the one relation with children, its partitions.
2. New `listPartitions(ctx, exec, databaseSegment, schema, table string) ([]model.TreeNode, error)`
   in `postgres/catalog.go`:

   ```sql
   SELECT c.relname, n.nspname, c.relkind, c.reltuples::bigint
     FROM pg_inherits i
     JOIN pg_class c ON c.oid = i.inhrelid
     JOIN pg_namespace n ON n.oid = c.relnamespace
    WHERE c.relispartition
      AND i.inhparent = (SELECT pc.oid FROM pg_class pc
                           JOIN pg_namespace pn ON pn.oid = pc.relnamespace
                          WHERE pn.nspname = $1 AND pc.relname = $2)
    ORDER BY c.relname
   ```

   Each node: `Kind: "table"`, path `database/schema:<n.nspname>/table:<relname>` (the partition's
   own schema, so Describe/Read work unchanged), `HasChildren: relkind == "p"` (sub-partitions),
   detail `~N` from reltuples when `>= 0` (same rule as item a). Legacy inheritance children
   (`relispartition = false`) stay top-level: only declarative partitions nest.
3. `postgres/adapter.go` depth 3: `if objectSegment.Kind == "table" { listPartitions(...) }`
   (non-partitioned table returns `[]`), else `LeafChildren`. Update the comment.
4. `project/grouping.ts`: drop `table` from `isLeafKind`; add

   ```ts
   /** A table expands only when the adapter says so: a Postgres partitioned table lists its
    *  partitions. view/matview/topic stay leaves whatever a cached node says (P19 D5). */
   export function isLeafNode(node: Pick<TreeNode, 'kind' | 'hasChildren'>, keyBrowser = false): boolean {
     return node.kind === 'table' ? !node.hasChildren : isLeafKind(node.kind, keyBrowser);
   }
   ```

   Replace the three `isLeafKind(node.kind, …)` call sites with `isLeafNode(node, …)`. Fix the
   `isLeafKind` doc comment (no longer lists table). A pre-P19 cached table with stale
   `hasChildren: true` now shows a twisty that expands to nothing until the next connect
   refreshes the cache; acceptable, no guard.
5. `tree.ts` `revealPath`: after the ancestor loop, if `rowKey(connectionId, path)` is not in the
   last ancestor's `treeState.children` nodes, select the last ancestor key instead (the deepest
   rendered ancestor, matching the function's own doc comment). One `if`.
6. `docs/ARCHITECTURE.md` adapter facts: one line: Postgres declarative partitions list as children
   of their partitioned parent (`pg_inherits`, `relispartition`), not at schema level; a partition's
   path uses its own schema.

### Tests

- Backend half (conformance, P25 rule): `TestPostgres_PartitionsNestUnderParent` in
  `postgres/postgres_test.go`: in a fresh schema created by the test (`CREATE SCHEMA p328`,
  dropped via `t.Cleanup`), `CREATE TABLE p328.events (id int, at date) PARTITION BY RANGE (at)` plus
  two partitions. Assert schema children contain `events` with `HasChildren` true and no partition;
  `Children(.../table:events)` returns both partitions in name order with their own paths; a plain
