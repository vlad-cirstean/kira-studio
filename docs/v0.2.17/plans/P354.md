### Crash root cause

- Go flow already proves the logic path: `adeflow/lifecycle_test.go` `TestReviewWindowAndAgent`
  calls `OpenReviewWindow` twice; second returns `false` and records `WindowMgr.Focused`. Engine
  (`internal/ade/review.go:105-109`) returns `Existing`; bridge `internal/bridge/adetask.go:993-996`
  calls `s.FocusWindow(res.Key)`. The flowharness fake never touches AppKit, so the crash is native.
- `FocusWindow` = `shell.WindowRegistry.Focus` (`apps/kira-space/internal/appwire/appwire.go:347`,
  `:390-400`; main.go `BindShell` passes no FocusWindow, so the default wins).
- `internal/shell/registry.go:148-162` `Focus`: `unhideApp()` then `e.win.Show()`,
  `e.win.UnMinimise()`, `e.win.Focus()`. The comment claims all are safe off the main thread. True
  only for the three window calls: Wails `WebviewWindow.Show/UnMinimise/Focus` wrap work in
  `InvokeSync` (`wails/v3@v3.0.0-beta.28/pkg/application/webview_window.go:514-525, 1301-1308,
  1688-1693`).
- `internal/shell/unhide_darwin.go:8-12` calls `application.Get().Show()` directly.
  `App.Show` (`application.go:1002-1006`) calls `impl.show()` with no dispatch;
  `macosApp.show` (`application_darwin.go:281-283`) calls C `show()` = `[NSApp unhide:nil]`
  (`application_darwin.go:218-220`).
- Bound service calls run on Go goroutines (`messageprocessor_call.go:139` `boundMethod.Call`), never
  the AppKit main thread. So the second press runs `-[NSApp unhide:]` off the main thread. AppKit
  window ordering off the main thread raises `NSInternalInconsistencyException` and aborts the whole
  process. First press never reaches `Focus`, which is why only the second press crashes.
- Same path: `FocusSession` (`adetask.go:955`, the review panel's Focus button and session Show
  buttons) and `revealNote` (`appwire/wire.go:454`). The fix in `Focus` covers all.
- Only direct App-level AppKit call in `internal/shell` (grep `application.Get()`): `unhide_darwin.go`.
  `closeflush.go:156` `win.Hide()` self-dispatches.

## Design

### 1. Crash fix (root cause)

- `internal/shell/registry.go` `Focus`: extract the raise sequence into an unexported
  `func raise(onMain func(func()), unhide func(), w focuser)` with
  `type focuser interface { Show() application.Window; UnMinimise(); Focus() }`. Body:
  `onMain(unhide); w.Show(); w.UnMinimise(); w.Focus()`. `Focus` calls
  `raise(application.InvokeSync, unhideApp, e.win)`. Fix the doc comment: the window calls
  self-dispatch, App-level unhide does not, so it goes through `InvokeSync`. One short comment line on
  why (AppKit aborts off the main thread).
- `InvokeSync` from the main thread runs inline (`application.go:981-986`), so notification-click
  callers stay safe. No deadlock: the window calls re-enter `dispatchOnMainThread`, which runs
  inline only on the main thread; from a goroutine they queue as today.
- `unhide_darwin.go`/`unhide_other.go` unchanged.
- Regression test `internal/shell/registry_internal_test.go` (package `shell`): fake `onMain` that
  sets a flag around its callback; fake `unhide` records whether the flag was set; fake focuser
  records call order. Assert unhide ran inside `onMain` and before Show/UnMinimise/Focus. Name it so
  it reads as the P354 crash guard. This is the user-requested regression test; the native abort
  itself cannot run in this container (no AppKit).
- Go flow (split-at-IPC backend half): extend `adeflow/lifecycle_test.go` `TestReviewWindowAndAgent`:
  after the second press assert `len(WindowMgr.Opened)` unchanged and the windows repo still holds
  one row for the key. Add `app.Contract(t, "ade-review-open", "AdeTaskService.OpenReviewWindow#existing", again)`
  (value `false`).
- UI spec (frontend half), `tests/ui/ade-v2-review-open.spec.ts`: test "Review code on an open
  review window only focuses it": `OpenReviewWindow` response from the contract
  (`contract<boolean>('ade-review-open', 'AdeTaskService.OpenReviewWindow#existing')`), press the card
  button twice; assert two calls with `{branchId: 'b_deps'}`, no `ade-panel-action-error`, the plan
  still rendered, focus back on the button.
- Docs: `docs/ARCHITECTURE.md` "Review code (P150)" first bullet: add that the focus path dispatches
  App unhide to the main thread. Keep "Native close/hide wiring ... unobserved" known item; append
  that the P354 focus fix is unobserved on a desktop build too.
