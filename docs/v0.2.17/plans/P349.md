# P349 plan: macOS app icon without white padding

Spec row: `docs/v0.2.17/SPEC.md` P349. Both apps (Kira Studio, Kira Space) show a white ring inside the
icon in Dock, Finder and the bundle.

## Evidence (checked this session, Linux)

- Sources per app, `apps/<app>/build/`: `appicon.png` (1024x1024 RGBA), `appicon.icon/` (Icon Composer
  bundle: `icon.json` + `Assets/kira_icon_vector.svg`), `darwin/icons.icns` (tracked). No `Assets.car`
  tracked or ignored.
- Both SVGs draw the classic Big Sur grid themselves: `<clipPath id="squircle"><rect x="100" y="100"
  width="824" height="824" rx="185"/>` on a 1024 canvas, every layer under `clip-path="url(#squircle)"`.
  So the artwork carries its own mask and a 100 px fully transparent margin (about 10% per side).
- `icon.json` (both): one group, one layer, scale 1.0, `specular: false`, translucency off, **no
  `fill`**. Icon Composer then uses its default fill (light, automatic) behind every layer.
- `appicon.png` and checked-in `icons.icns` (all 8 sizes): alpha bbox `(100,100)-(924,924)` (Space) and
  `(97,97)-(927,927)` (Studio; faint white fringe, alpha <= 17, at x 97-99). Transparent margin, no
  opaque white baked in.
- Generation: `build/Taskfile.yml` `generate:icons` runs
  `wails3 generate icons -input appicon.png -macfilename darwin/icons.icns ... -iconcomposerinput appicon.icon -macassetdir darwin`.
  Wails v3.0.0-beta.28 `internal/commands/icons.go`: when the host is macOS 26+ and `/usr/bin/actool`
  reports 26+, `generateMacAsset` compiles `appicon.icon` with `actool --app-icon appicon
  --minimum-deployment-target 26.0`, writes `darwin/Assets.car`, and **renames actool's own `.icns`
  over `darwin/icons.icns`**. The `appicon.png` path runs only when that fails (`!macIconsGenerated`).
- So on every Xcode 26 host (user's dev Mac; release runners since P346 moved them to `macos-26`) the
  shipped `icons.icns` is actool's render of `appicon.icon`, not the PNG. `create:app:bundle` and `run`
  also copy `darwin/Assets.car` into the bundle when present.
- No plist (`apps/*/build/darwin/Info.plist`, `Info.dev.plist`) has `CFBundleIconName`;
  `CFBundleIconFile` is `icons`. `docs/PACKAGING.md` §6 still says "no Assets.car ships", written before
  the runner move.

## Root cause

`appicon.icon` holds pre-masked artwork: a squircle at 824/1024 with a transparent 100 px margin.
Icon Composer (and actool) treat a layer as full-bleed artwork and apply the system squircle mask to
the whole 1024 canvas. The margin shows the default (light) group fill, so the rendered icon is a
white squircle with the smaller tan or blue squircle inside it. actool bakes that into both
`Assets.car` and the `icons.icns` it writes over the tracked one. This went live on release builds
when P346 moved runners to `macos-26`, where actool 26 exists; Linux and pre-26 hosts still use the
PNG path.

Second, independent cause for the PNG path: macOS 26 puts a legacy `.icns` icon whose alpha does not
match its squircle mask onto a light plate, shrunk ("squircle jail"). The PNG uses a circular-arc
`rx=185` rounded rect, not Apple's continuous-corner shape, so it does not reliably match.

## Decision: Icon Composer `.icon`, full-bleed, compiled to `Assets.car`

macOS 26 expects an Icon Composer `.icon` compiled to `Assets.car` and named by `CFBundleIconName`.
The system renders that one natively: never jailed, plus dark, clear and tinted variants. Both apps'
floor is macOS 26.0 (P346), so no pre-26 rendering needs serving. The pipeline already compiles the
`.icon` on every 26 host; only the artwork and the plist key are wrong.

Rejected: a full-bleed square `.icns`. Its alpha does not match the squircle mask either, so macOS 26
jails it the same way. Rejected: an exact Apple-squircle `.icns`. It relies on undocumented shape
detection and never gets the appearance variants.

## Changes

1. `apps/kira-studio/build/appicon.icon/Assets/kira_icon_vector.svg` and
   `apps/kira-space/build/appicon.icon/Assets/kira_icon_vector.svg`, same edit in each:
   - Replace the `squircle` clipPath's `<rect ... rx="185"/>` with a square
     `<rect x="100" y="100" width="824" height="824"/>` (no `rx`). Rename the id to `artBounds`, and
     update the one `clip-path="url(#squircle)"` reference.
   - Wrap that clipped `<g>` in `<g transform="matrix(1.242718 0 0 1.242718 -124.2718 -124.2718)">`.
     This maps 100..924 onto 0..1024, so the background covers the whole canvas. Glyph proportions
     inside the system mask stay what the old squircle showed. Scale is 1024/824; offset is
     -100 x scale.
   - Keep `viewBox="0 0 1024 1024"` and every glyph untouched. HISTORY's P100-era rules hold: Space
     colours and glyph set unchanged, Studio artwork unchanged apart from this framing.
   - Add one comment at the transform: the layer is full-bleed because the system applies the mask.
2. Both `icon.json`: add a group-level fill matching each background's top stop, so no light default
   can show through antialiased edges:
   - Studio: `"fill": { "solid": "srgb:0.82353,0.66275,0.48627,1.00000" }` (#D2A97C).
   - Space: `"fill": { "solid": "srgb:0.23137,0.60784,0.90980,1.00000" }` (#3B9BE8).
   Put it at document root (Icon Composer's document-level `fill`, beside `groups`), not inside a layer.
   If actool rejects the key or the value form on the macOS runner, take the form Icon Composer 26
   itself writes: open the `.icon` in Icon Composer, set Fill to Solid, save, copy the key. Do not
   drop the fill.
3. Four plists: `apps/kira-studio/build/darwin/Info.plist`, `Info.dev.plist`,
   `apps/kira-space/build/darwin/Info.plist`, `Info.dev.plist`. Add
   `<key>CFBundleIconName</key><string>appicon</string>` right after `CFBundleIconFile`, which stays.
   `appicon` is the `--app-icon` name Wails passes (the `.icon` basename). `CFBundleIconFile` remains
   the fallback for a bundle built on a host without actool 26 (no `Assets.car`).
4. `apps/kira-studio/.gitignore`, `apps/kira-space/.gitignore`: add `build/darwin/Assets.car` and
   `build/darwin/temp.plist` (generated, and machine-dependent).
5. Leave `appicon.png` and the tracked `darwin/icons.icns` as they are. They are the PNG-path fallback
   only (non-26 or Linux hosts, never a shipped macOS build). Regenerating them needs actool, which this
   Linux session lacks.
6. `scripts/verify-packaging.sh`:
   - New static check `S15`, next to S14, for both apps:
     - The SVG has no `rx=` inside a `<clipPath` and has the `matrix(1.242718` transform (full-bleed
       layer).
     - `icon.json` has a top-level `"fill"` (use `jq -e '.fill'` when jq is present, else `grep -q '"fill"'`).
     - Each of the four plists has `CFBundleIconName` = `appicon`, the S14 grep shape.
     Failure text names P349.
   - New artifact check `A7` beside A6, over both `.app` bundles:
     - `Contents/Resources/Assets.car` exists.
     - `PlistBuddy -c 'Print :CFBundleIconName'` prints `appicon`.
     - `xcrun --sdk macosx assetutil --info Contents/Resources/Assets.car` output contains
       `"Name" : "appicon"`.
     Fail on the `macos-26` runner (actool 26 present). Only note when `xcrun assetutil` is missing.
7. Docs:
   - `docs/PACKAGING.md` §6: rewrite the "bundle has no Assets.car" bullet. Assets.car ships, compiled
     from a full-bleed `appicon.icon` by actool 26 on `macos-26`. `CFBundleIconName` and `Assets.car`
     came back together, as that bullet required. The tracked `icons.icns` is the non-26 fallback.
     Also update the §1 tree line (`icons.icns  the only icon the bundle carries`) and the
     `create:app:bundle` row wording.
   - `docs/ARCHITECTURE.md`: one bullet under packaging facts, if one exists: the icon is an Icon
     Composer full-bleed layer, and the system applies the mask.

## Tests

No unit test (asset and config only; CLAUDE.md bar).

Asset verification, this Linux session:

```sh
sh scripts/verify-packaging.sh            # S15 passes; A7 skips with a note (no bundle here)
# one-off raster proof the layer is full-bleed (ImageMagick is installed here):
for app in kira-studio kira-space; do
  convert -background none "apps/$app/build/appicon.icon/Assets/kira_icon_vector.svg" -resize 1024x1024 "$SCRATCH/$app.png"
done
python3 -I -c "
from PIL import Image; import sys
for p in sys.argv[1:]:
    a=Image.open(p).convert('RGBA').getchannel('A')
    assert all(a.getpixel(xy)==255 for xy in [(0,0),(1023,0),(0,1023),(1023,1023),(512,2),(2,512)]), p
print('full-bleed ok')" "$SCRATCH/kira-studio.png" "$SCRATCH/kira-space.png"
xmllint --noout apps/*/build/darwin/Info*.plist apps/*/build/appicon.icon/Assets/kira_icon_vector.svg
```
