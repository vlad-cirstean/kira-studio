## Design

### 1. New task lands Today, no repo selection

Wire: add `Day *string \`json:"day"\`` to `adewire.CreateTaskArgs` (wire.go 645-654; nil = Later)
and `day: string | null` to TS `CreateTaskArgs` (wire.ts 636-645). Keep `CodeRepoIDs`/`Bases`:
Go flow helpers and agent paths still create with repos.

Go:
- `bridge/adetask.go` `validateCreateTask` (169-197): `if a.Day != nil` run
  `validateAdeISODate(*a.Day)` (same as `validateSetPlan` 267-287).
- `board_writes.go`: delete empty-repo refusal (123-125); pass `args.Day` to
  `b.deps.Tasks.CreateTask(task, branches, args.Day)`; fix comment 116 ("appended to the plan on
  `Day`, Later when nil").
- `repos/adetask.go`: `insertTask(..., day *string)` writes day into the plan row; `CreateTask`
  gains `day *string`; Promote (`adebacklog.go`) passes nil. Fix comment 256. Plan position stays
  append-at-end of that day bucket (same order logic as today; check `insertTask` position query
  scopes by day, adjust if it scopes by NULL only).
- Update any other `Tasks.CreateTask` caller/fake (grep `CreateTask(` in `internal/ade`,
  `internal/flows`) to the new signature.

Frontend `AdeAddPopover.vue`:
- Remove `picked`, `bases`, `MAIN`, `toggleRepo`, `tintOf`, the watch's preselect block (71-74),
  template 178-209, imports `Toggle`, `AdeBasePicker`, `repoTint`, `useRepoLinksStore`,
  `BaseChoice`. Keep `useRepos`/`repoLabel` (candidate filter).
- `cantAdd`: title empty or pending only.
- `addNew` sends `codeRepoIds: []`, `bases: {}`, `day: todayIso()` where day =
  `offsetToIso(model.today, firstWork(model.cal, 0))`. Source `today`/`cal` from the same place
  `usePlanModel` reads them (reuse its calendar composable or export a small `todayPlanDay()`
  helper from `plan/usePlanModel.ts`; do not instantiate a second full plan model in the popover).
- Comment 28: "new task (lands Today, or next work day; repos added later) or existing branch".
- Button key rename `space.ade.add.addToLater` to `space.ade.add.addToToday` "Add to today".
  Hint `noBranchesYet` rewrite: "Add repositories from the task panel, or {agent} declares them."
  (keep `{agent}` slot if CatalogText used; it is plain `t()` now, so drop the slot if unused).
  Delete `space.ade.add.base` (6746).
- `adeAddUi.ts`: no change.

Repoless task start stays refused by `stepTargets`/`launchDirs` until a repo is added; that error
already reaches the panel action error. Add `docs/ARCHITECTURE.md` note under ADE (not Known open
items: it is designed behavior).
