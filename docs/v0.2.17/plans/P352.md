# P352 plan: GitHub PR sync, persistent per-repo cache

Spec row: `docs/v0.2.17/SPEC.md` P352.

## Evidence (codegraph_explore over `hostState`, `RepoEntry.ensureSnapshot`, `ForBranch`, `OpenPulls`, `PullsForBranch`, `ChangeRequestState`, `ensureSnapshot`, `resolveBranch`, `setRepoId`, `fakehost.Forge`)

Backend, `apps/kira-space/internal/gitsession/changerequests.go`:
- `hostState` lives on `RepoEntry` (`entry.go` `newRepoEntry`, `host: newHostState()`). In memory only.
  It dies with the entry, so every app restart starts cold.
- TTLs: snapshot 5 m, branch 5 m, commit 10 m, `staleMax` 1 h, breaker 15 m.
  Stale-while-revalidate through `refreshInBackground`.
- `ensureSnapshot` calls `Provider.Open`. GitHub's `Client.OpenPulls`
  (`internal/githost/github/pr.go:155`) pages `pulls?state=open`, capped by `maxSnapshotPages` (300 PRs).
  Open only: a merged or closed PR never enters the snapshot.
- `ForBranch` (`PullsForBranch`, `pr.go:129`) costs one REST call per branch:
  `pulls?head=owner:branch&state=all&sort=updated&direction=desc&per_page=5`.
- `githost.ChangeRequest` carries `Number, Title, URL, State, HeadRef, HeadSha, HeadOwner, BaseRef,
  UpdatedAt`. It has no draft flag, review decision or CI checks state.

Frontend, `packages/git-ui/src/state/changeRequests.ts` (`ChangeRequestState`):
- `byBranch` fills only through `resolveBranch` / `ensureSnapshot` (`branch.resolveChangeRequest` RPC,
  6-worker pool). Callers:
  - `BranchPicker.vue:408`: only while the picker is open, only visible rows.
  - `search.ts:336`: on entering the refs scope.
  - `stack.ts:107`: the stack list.
- `bySha` holds only the selected commit (`#requestCommit`).
- Graph badges (`CommitGrid` via `changeRequestsHeadedAt`) read `byBranch` plus `bySha`.
- `#repoFacts` stashes per-repo facts in memory, cap 8. A `refsChanged` runs `#revalidate`, which
  clears `#noBranchChangeRequest`.

## Root cause of "not loaded for each branch"

The graph never asks for every branch. `byBranch` is warmed only by three UI surfaces (the open
branch picker's visible rows, the search refs scope, the stack list). The graph badge reads `byBranch`
and the one selected sha. So a branch nobody opened in the picker shows no badge. Even a warmed
branch needs one REST call each, because the bulk snapshot is open-only and capped. Nothing persists:
backend `hostState` and frontend `#repoFacts` are memory only, so each session repeats the whole cost.

## Design

One backend-owned, persistent index per repo. The frontend reads it in one call and gets pushes.

### Cache schema

New migration `apps/kira-space/internal/storage/migrations/0047_p352_git_host_change_requests.sql`
(confirm 0046 is still latest before writing; take the next free number):

```sql
CREATE TABLE git_host_change_requests (
  repo_key        TEXT    NOT NULL,           -- provider|host|owner/name, lower-cased
  number          INTEGER NOT NULL,
  head_ref        TEXT    NOT NULL,
  head_owner      TEXT    NOT NULL,
  head_sha        TEXT    NOT NULL,
  base_ref        TEXT    NOT NULL,
  state           TEXT    NOT NULL,           -- open | closed | merged
  draft           INTEGER NOT NULL DEFAULT 0,
  title           TEXT    NOT NULL,
  url             TEXT    NOT NULL,
  review_decision TEXT    NOT NULL DEFAULT '', -- '' | APPROVED | CHANGES_REQUESTED | REVIEW_REQUIRED
  checks_state    TEXT    NOT NULL DEFAULT '', -- '' | SUCCESS | FAILURE | PENDING | ERROR | EXPECTED
  updated_at      TEXT    NOT NULL,           -- host's updatedAt, RFC 3339
  synced_at       TEXT    NOT NULL,           -- when this row was last written
  PRIMARY KEY (repo_key, number)
) STRICT;
CREATE INDEX git_host_change_requests_head
  ON git_host_change_requests (repo_key, head_owner, head_ref);

CREATE TABLE git_host_sync_state (
  repo_key             TEXT PRIMARY KEY,
  account              TEXT    NOT NULL,       -- gh account the rows were read as
  watermark_updated_at TEXT    NOT NULL DEFAULT '', -- newest updatedAt fully ingested
  etag                 TEXT    NOT NULL DEFAULT '', -- probe ETag
  last_full_sync_at    TEXT    NOT NULL DEFAULT '',
  last_delta_at        TEXT    NOT NULL DEFAULT '',
  last_checks_at       TEXT    NOT NULL DEFAULT '',
  backfill_cursor      TEXT    NOT NULL DEFAULT '', -- GraphQL endCursor, resumable
  backfill_complete    INTEGER NOT NULL DEFAULT 0,
  schema_version       INTEGER NOT NULL DEFAULT 1
) STRICT;
```

Match the `STRICT` and naming style of 0043/0044 (`git_host_*`); drop `STRICT` if those migrations do
not use it. Keyed per head branch through the `(repo_key, head_owner, head_ref)` index: a branch's PRs
are one indexed lookup. Keyed by `repo_key`, not repo path, so two clones of one GitHub repo share rows.

Store: `apps/kira-space/internal/storage/repos/githostchangerequests.go`, shaped like
`adeviewedsync.go` (`sqlitex.QueryAll`, one struct per table). Methods:
- `UpsertChangeRequests(repoKey string, rows []model.GitHostChangeRequest) error` (one transaction).
- `DeleteChangeRequest(repoKey string, number int) error`.
- `ChangeRequestsForRepo(repoKey, headOwner string) ([]model.GitHostChangeRequest, error)`.
- `ChangeRequestsForBranch(repoKey, headOwner, headRef string) (...)`.
- `SyncState(repoKey string) (model.GitHostSyncState, bool, error)`, `PutSyncState(...)`.
- `DropRepo(repoKey string) error` (both tables, one transaction).
Model types in `apps/kira-space/internal/storage/model/githostchangerequest.go`.

### Provider seam

`apps/kira-space/internal/githost/githost.go`:
- Widen `ChangeRequest` with `Draft bool`, `ReviewDecision string`, `ChecksState string`. Existing
  callers ignore them; `toChangeRequests` fills them where the REST shape has `draft`.
- New optional role, checked by type assertion like `FileReviewSync`:
  ```go
  // ChangeRequestSync is a provider that pages every change request by recency.
  type ChangeRequestSync interface {
      // Page returns change requests ordered by updatedAt DESC, after cursor ("" = newest).
      Page(ctx context.Context, r Repo, cursor string, first int) (ChangeRequestPage, Status)
      // Probe reports whether anything changed since etag. A 304 costs no rate limit.
      Probe(ctx context.Context, r Repo, etag string) (changed bool, newETag string, s Status)
      // Checks refreshes draft, review and checks state for the given open change requests.
      Checks(ctx context.Context, r Repo, numbers []int) ([]ChangeRequest, Status)
  }
  type ChangeRequestPage struct {
      Items      []ChangeRequest
      EndCursor  string
      HasNext    bool
      RateLimit  RateLimit // remaining, resetAt; zero when unknown
  }
  ```
  A provider without it keeps today's behaviour (snapshot plus per-branch).

GitHub implementation, new `apps/kira-space/internal/githost/github/sync.go`:
- `Page`: `gh api graphql` through `commonArgv` (`api.go`), query:
  ```graphql
  query($owner:String!,$name:String!,$first:Int!,$after:String){
    repository(owner:$owner,name:$name){
      pullRequests(states:[OPEN,CLOSED,MERGED],orderBy:{field:UPDATED_AT,direction:DESC},first:$first,after:$after){
        pageInfo{endCursor hasNextPage}
        nodes{ id number title url state isDraft reviewDecision updatedAt
               headRefName headRefOid baseRefName headRepositoryOwner{login}
               commits(last:1){nodes{commit{statusCheckRollup{state}}}} }
      }
    }
    rateLimit{remaining resetAt cost}
  }
  ```
  Variables go as `-F`/`-f` fields, never string-interpolated. `first` is 100.
- `Probe`: `gh api -i repos/{owner}/{repo}/pulls?state=all&sort=updated&direction=desc&per_page=1`
  with `-H 'If-None-Match: <etag>'`. Parse status line and `ETag` from the `-i` header block.
  `gh api` exits non-zero on 304; treat exit plus `HTTP/2.0 304` (or `HTTP/1.1 304`) in the header
  block as "unchanged", never as a failure. Confirm this exact behaviour once with real `gh` and pin
  it in a golden test of the parser (captured header block in `testdata/`).
- `Checks`: one GraphQL `nodes(ids:[…])` per batch of 50 open PR node ids, same fields as `Page`.
  Needs the node `id`; store it: add `node_id TEXT NOT NULL DEFAULT ''` to the change-request table.
- `Status`/rate limit: map a GraphQL `RATE_LIMITED` error and REST 403/429 with
  `x-ratelimit-remaining: 0` to `Status.RateLimited` (the existing `isRateLimited` path), and carry
  `resetAt` / `retry-after` in `RateLimit`.

`apps/kira-space/internal/flowharness/fakehost/fakehost.go`: `Forge` implements
`ChangeRequestSync` over its `crs` slice: sorted by `UpdatedAt` desc, opaque cursor = index, `Probe`
keyed by a revision counter bumped on every mutation, recorded calls (`Page:<cursor>`, `Probe:304`,
`Probe:200`, `Checks:n`). Add mutators `SetChangeRequest(cr)`, `RemoveChangeRequest(n)`,
`SetRateLimited(until time.Time)`.

### Sync algorithm

New `apps/kira-space/internal/gitsession/crsync.go`, one `crSyncer` per open `RepoEntry` (created in
`newRepoEntry` beside `host`, stopped by `lifeStop`). Single-flight: one sync run at a time per entry;
a request while running sets a `again` flag and runs once more after.

1. **Resolve key.** `repo_key = provider|host|owner/name` from the selected provider and parsed
   remote. `account = Provider.Account(host)`.
2. **Invalidate** (before any read): drop the repo's rows (`DropRepo`) when
   - stored `account` differs from current `account` (auth change: visibility may differ);
   - `schema_version` < current;
   - the provider setting for the repo is `off` (also stop the syncer).
   A repo switch needs no drop: rows are keyed by `repo_key`, and the frontend reads by `repoId`.
   A remote URL change yields a new `repo_key`; the old key's rows stay until the 30-day sweep below.
3. **Serve.** `ChangeRequestsForRepo` answers `branch.changeRequestIndex` at once from SQLite, cold or
   not. An empty, never-synced repo answers `{complete:false}` so the UI can show the old per-branch path.
4. **Backfill** (while `backfill_complete = 0`): `Page(cursor = backfill_cursor)`, upsert, persist
   `backfill_cursor = EndCursor` after every page (resumable across restart). Cap: 10 pages per run
   (1000 PRs), then yield and continue next tick. On the first page of a fresh backfill, set
   `watermark_updated_at` to the newest item's `updatedAt`. When `HasNext` is false, set
   `backfill_complete = 1`, `last_full_sync_at = now`, clear the cursor.
5. **Delta** (after backfill): `Probe(etag)`.
   - Unchanged (304): set `last_delta_at = now`, stop. No rate-limit cost.
   - Changed: page from the newest (`cursor = ""`), upsert each item, stop at the first item with
     `updatedAt < watermark − 2 min` (skew allowance: GitHub `updatedAt` is not strictly monotonic
     across writes landing in the same second). Cap 10 pages; hitting the cap without reaching the stop
     item resets `backfill_complete = 0` (falls back to a resumable full backfill). Then
     `watermark = max(updatedAt seen)`, store the new ETag.
   The stop rule is pure arithmetic; put it in `deltaStop(items, watermark, skew) (keep int, done bool)`.
6. **Checks refresh**: CI results do not bump a PR's `updatedAt`, so delta misses them. Every
   `checksInterval` (2 min while the window is focused, else skipped) call `Checks` for open,
   non-draft rows whose `checks_state` is `PENDING` or `EXPECTED` or whose `head_sha` changed in the
   last delta, plus a full open-row sweep every 15 min. Batches of 50.
7. **Deletions**: GitHub never deletes a PR; it can vanish only on a transfer or a repo going private.
   Two signals drop a row:
   - a `ForBranch` lookup (still used for the branch picker's exact match) that returns no PR with
     that number for its head;
   - `Checks` returning `null` for a node id.
   Delete only that row. A 404 for the whole repo drops the repo (`DropRepo`).
8. **Emit.** After any run that changed rows, push `repo.changed` with a new kind
   `changeRequestsChanged` and the repo id, through the entry's existing subscriber fan-out (the same
   path `refsChanged` uses). Payload carries no rows; the frontend re-reads the index.

### Staleness and refresh triggers

- Serve from SQLite always. Rows are never hidden for age; staleness only schedules work.
- Periodic: a `cancellableTimer` (existing helper; reuse it) per entry, 5 min while the app window is
  focused, 15 min while blurred. Stops with the entry.
- On focus: frontend `useWindowFocus` + `useDocumentVisibility` (VueUse) call `branch.syncChangeRequests
  {repoId}` on regain, debounced 1 s (`useDebounceFn`). Backend enforces a 30 s minimum gap per entry
  (an early call returns at once; single-flight already dedups).
- On `refsChanged` that adds or moves a branch: schedule a delta (same 30 s gap).
- Startup: the first `Acquire` of an entry runs one sync after a 2 s delay, so git work goes first.

### Rate-limit backoff

- `cenkalti/backoff/v4` (already in `go.mod`): `ExponentialBackOff` with 30 s initial, 15 min max,
  jitter on, around each sync run's host calls.
- A response that carries a reset (`RateLimit.ResetAt`, REST `x-ratelimit-reset`, `retry-after`) sets
  the next attempt to `max(backoff, resetAt)`; no call before it.
- GraphQL `rateLimit.remaining < 200` after a page: stop the run, resume after `resetAt`.
- The existing per-repo breaker (15 m) stays authoritative for the per-branch/per-commit paths;
  when tripped, the syncer also waits.
- Failure never clears rows (fail-open, matching today's posture).

### Bridge

`apps/kira-space/internal/bridge/` git branch service, beside `branch.resolveChangeRequest`:
- `branch.changeRequestIndex {repoId} -> {complete: bool, syncedAt: string,
  branches: {name: string, changeRequests: ChangeRequest[]}[]}`. Same-owner PRs only, matching
  `ForBranch`'s `head=owner:branch` semantics; fork PRs with a clashing `head_ref` are not this repo's
  branch. Sorted newest first per branch, same order `resolveBranch` shows.
- `branch.syncChangeRequests {repoId} -> {}`: request a sync now (rules above).
- Wire types in `apps/kira-space/internal/bridge/adewire/wire.go` `ChangeRequest` gain `draft`,
  `reviewDecision`, `checksState`. Regenerate the TS bindings the repo's usual way (check
  `docs/DEV_ENVIRONMENT.md`).
- `RepoEntry.ensureSnapshot` and `ForBranch` lookups read the persisted rows first when the sync is
  `complete`, so the existing per-branch RPC also stops hitting the host for a covered branch. Keep
  `hostState`'s in-memory commit cache (sha lookups are a different query).

### Frontend

`packages/git-ui/src/state/changeRequests.ts`:
- `setRepoId(repoId)`: after the existing stash/restore, call `#loadIndex(repoId)`: one
  `branch.changeRequestIndex`, then fill `byBranch` for every branch in one assignment (one
  `generation` bump), and add every local branch with no entry to `#noBranchChangeRequest` only when
  `complete` is true. Guard with the existing `#clearGeneration` / `#repoId` capture.
- On `repo.changed` kind `changeRequestsChanged` for the current repo: `#loadIndex` again (coalesced:
  one in flight, one queued).
- `ensureSnapshot` / `resolveBranch` stay for incomplete indexes and non-sync providers; when the
  index is `complete`, they are no-ops for covered names.
- Focus refresh: wire in the git-ui `App.vue` (where `setRepoId` is applied) with VueUse as above.
- Badge: `changeRequestsHeadedAt` already reads `byBranch`, so every branch's tip gets its badge with no
  `CommitGrid` change. Draft shows through the existing `draft` state label
  (`changeRequestStateLabel`) when `draft` is true and state is open.

State stays a plain class with `shallowRef` maps, not TanStack Query. Requirement TanStack cannot
meet here: SlickGrid formatters read `byBranch` synchronously per cell render, and invalidation is
push-driven from the backend stream, not query-key staleness. Wrapping it adds a second cache over one
that already owns these rules.

## Tests

- `deltaStop`: watermark inside a page; exactly at `watermark − skew`; all items newer (continue);
  first item already older (done, keep 0); equal `updatedAt` ties around the boundary.
- Page cap hit without reaching the stop item forces backfill.
- Probe header parser golden tests (`apps/kira-space/internal/githost/github/testdata/probe_304.txt`,

  `x-ratelimit-remaining: 0` yields rate-limited plus reset.

Flow (Go, backend half), new `apps/kira-space/internal/flows/githostflow/sync_test.go` beside
`host_test.go`, over `fakehost.Forge` and the real SQLite store:
1. Cold load: 3 PRs on 3 branches (one open, one merged, one closed draft). `branch.changeRequestIndex`
   after sync returns all 3 branches with correct state and draft. Calls: `Page` only, no `ForBranch`.
2. Persisted restart: close and reopen the registry on the same DB. The index answers before any host
   call (assert `Calls()` empty at read time), then a `Probe:304` and nothing else.
3. Delta: `SetChangeRequest` a new PR and change another's state to merged. Next sync: `Probe:200`, one
   `Page`, stops at the watermark; index shows both changes; `changeRequestsChanged` emitted once.
4. Checks: set `ChecksState` PENDING to SUCCESS without bumping `UpdatedAt`. Delta sees nothing;
   checks refresh updates the row.
5. Deletion: `RemoveChangeRequest`; a `ForBranch` lookup for that head drops the row.
6. Invalidation: change the fake's account; next sync drops and backfills.
7. Rate limit: `SetRateLimited`; no host call before reset; rows still served.
