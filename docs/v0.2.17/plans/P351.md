Spec row: `docs/v0.2.17/SPEC.md` P351.

## Evidence (codegraph_explore over `AppToolbar`, `ViewToolbar`, `Separator`, `DataToolbar`, `RefreshButton`, `PickerTrigger`)

- Graph toolbar: `packages/git-ui/src/components/AppToolbar.vue`. It sits inside `ViewToolbar`
  (`packages/workbench/src/components/ViewToolbar.vue`, cva `h-bar shrink-0 flex items-center gap-1.5
  px-2`, plus a border variant), same as Studio toolbars.
- Its three dividers (template lines 315, 324, 386) use the shadcn-vue `Separator`
  (`packages/theme/src/components/ui/separator/Separator.vue`, reka-ui):
  `<Separator orientation="vertical" class="h-3.5 self-center mx-0.5 bg-border-strong" />`.
- `Separator`'s base classes include `data-[orientation=vertical]:h-full` and
  `data-[orientation=vertical]:self-stretch`. A `data-[…]` variant selector outranks plain `self-center`
  and `h-3.5` on specificity, and tailwind-merge does not dedupe across variants. So the graph dividers
  stretch to full bar height (or sit top-aligned), unlike every other toolbar.
- Every other toolbar hand-rolls the divider:
  `<div class="w-px h-3.5 bg-border-strong mx-0.5 shrink-0" />`. Sites:
  - `SearchToolbar.vue:250,259`
  - `KeyValueToolbar.vue:126,138,149`
  - `DefinitionView.vue:276,301`
  - `DataToolbar.vue:286,316,374`
  - `StreamToolbar.vue:188,281,291`
  - `StreamSearchToolbar.vue:100`
  - `DocumentToolbar.vue:79,100,173`
  - `ConsoleView.vue:328,339,364`
  Re-grep `w-px h-3.5` and `orientation="vertical"` across `apps/*/frontend/src` and `packages/*/src`
  before editing; the list above is the discovery snapshot, not a quota.
- Not toolbar dividers, out of scope: `AdeBranchRow.vue:248` (`h-2.5 w-px`, an inline row glyph),
  `TabStrip.vue:251` (tab strip edge).
- Buttons already match: `RefreshButton` and the rest use `Button variant="toolbar" size="kira-icon"` /
  `size="kira"` and `TooltipIconButton`, same as `DataToolbar`. `BranchPicker` uses shared
  `PickerTrigger`. Drift beyond the dividers is confirmed (or ruled out) by the screenshot step below,
  not assumed.

## Change

1. New `packages/workbench/src/components/ToolbarSeparator.vue` (`<script setup lang="ts">`, no props):
   ```vue
   <script setup lang="ts">
   import { Separator } from '@theme/components/ui/separator';
   </script>

   <template>
     <Separator
       orientation="vertical"
       decorative
       class="mx-0.5 shrink-0 bg-border-strong data-[orientation=vertical]:h-3.5 data-[orientation=vertical]:self-center"
     />
   </template>
   ```
   Same-variant classes let tailwind-merge (`cn` in `Separator.vue`) drop the base `h-full` /
   `self-stretch`. Box: 1 px wide, 14 px tall, `border-strong`, centred. Identical to the hand-rolled div.
   Keep shadcn-vue `Separator` underneath (CLAUDE.md primitive rule); `decorative` keeps it out of the
   accessibility tree, as the bare div was.
2. `AppToolbar.vue`: replace the three `<Separator …>` with `<ToolbarSeparator />`. Drop the now-unused
   `Separator` import.
3. Every hand-rolled site in the list: replace the div with `<ToolbarSeparator />` and import it from
   `@workbench/components/ToolbarSeparator.vue`. Check each package can import `@workbench` (Studio
   views and `git-ui` already do; add the path alias only where missing, mirroring an existing one).
4. Screenshot diff, before code changes: capture the Space git graph toolbar and the Studio
   `DataToolbar` at the same zoom (`bun run test:visual:space` / `:studio` baselines, or a one-off
   Playwright `locator.screenshot()` into the scratchpad). Compare bar height, padding, gap, button
   box, icon size, divider. Fix every real drift in `AppToolbar.vue` with the shared token (e.g. a
   stray `gap-*` or `px-*` override on its root). Name each one in the commit body. If the divider is
