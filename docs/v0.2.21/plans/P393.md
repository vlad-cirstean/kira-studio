- Why nothing opens: the addon's default handler (`WebLinksAddon.ts` `handleLink`) calls

- External-URL bridge exists: `LinkService.OpenExternal({url})` in both apps
  (`apps/*/internal/bridge/link.go`), both calling `internal/shell/link.go` `OpenExternalURL`: accepts
  `http`/`https` with a non-empty host, refuses everything else (`backend.core.link.invalidUrl.body`).
  Renderer wrapper `packages/workbench/src/bridge/openExternal.ts` `createOpenExternal` (logs and
  announces failures, never throws). Space: `control.openExternal` (`bridge/index.ts:183`). Studio:
  no `control.openExternal`; its only call is `docker/context.ts:13`. Lint U79
  (`scripts/check-ui-primitives.sh:215`) allows a direct `LinkService.OpenExternal(` only in Space
  `bridge/index.ts` and Studio `docker/context.ts`.
- Existing Go coverage: Studio `internal/flows/appflow/app_test.go` `TestOpenExternal` (contract
  `tests/contract/link-open.json`), Space `internal/flows/appflow/misc_test.go` `TestOpenLinks`.
- Modifier helper: `packages/workbench/src/shortcuts/keys.ts` `isPrimaryModifier(e)` (Cmd on mac UA,
  Ctrl elsewhere). Lint U41 forbids raw `metaKey`/`ctrlKey` reads outside `keys.ts`; use the helper.

## Decisions

- Modifier: Cmd-click on macOS, Ctrl-click on Linux/Windows, via `isPrimaryModifier`. Same as VS
  Code. Plain click never opens (it still selects text as before).
- Schemes: `http`/`https` only, both renderer-side (before the call) and Go-side (existing
  `OpenExternalURL`, unchanged). `mailto` is not added: the web-links regex never matches it, and
  OSC 8 non-http links stay off (`allowNonHttpProtocols: false`). So no Go change and no contract
  version bump.
- Desktop opens through `LinkService.OpenExternal` (OS browser). No new bridge method.
- Phone (browser over LAN, touch, no modifier): a plain tap on a link opens it in a new browser tab
  with `window.open(url, '_blank', 'noopener,noreferrer')`. The link opens on the phone, not on the
  desktop. No hover hint (no hover on touch). Desktop terminals keep the modifier rule.
- Hover hint (desktop only): a small tooltip inside the terminal element showing the target URL and
  `Cmd-click to open` / `Ctrl-click to open`. Shows for OSC 8 links too, where the visible text may
  differ from the target (xterm's own security advice for `linkHandler`).
- Library: keep `@xterm/addon-web-links` (already a dependency) for plain-text URLs; use xterm's own
  `linkHandler` option for OSC 8. No new dependency, so no license check needed.
- shadcn `Tooltip` declined for the hint: `terminalRenderer.ts` is plain TS behind a lazy import
  boundary, and a link is a cell range, not a DOM element a `TooltipTrigger` can wrap. Reuse the
  shadcn tooltip's own classes (`tooltipContentVariants()`) on a plain element so it looks the same.
- xterm still shows its pointer cursor over any link on hover (its own `xterm-cursor-pointer`
  class). Kept: the hint explains the modifier.

## Changes

### 1. `packages/workbench/src/shortcuts/keys.ts`

Add next to `isPrimaryModifier`:

```ts
/** 'Cmd' on mac, 'Ctrl' elsewhere: copy like "Cmd-click". */
export function primaryModifierName(): 'Cmd' | 'Ctrl' {
  return isMac ? 'Cmd' : 'Ctrl';
}
```

### 2. `packages/workbench/src/terminal/terminalRenderer.ts`

- Extend `TerminalRendererDeps`:
  ```ts
  /** Opens an http(s) link from terminal output; never throws. */
  openLink(url: string): void;
  /** 'modifier': Cmd-click (mac) or Ctrl-click, with a hover hint. 'tap': plain click/tap (phone). */
  linkActivation: 'modifier' | 'tap';
  ```
- Add a module-local `isWebUrl(uri)`: `URL.canParse(uri)` and protocol `http:` or `https:` and
  non-empty host. Mirrors Go's rule; Go stays the authority.
- Add a small hint helper (module-local, one per terminal): creates a `div` once, appended to
  `term.element` after `term.open(host)`, classes `xterm-hover absolute hidden` plus
  `tooltipContentVariants()` from `@theme/components/ui/tooltip`, `data-testid="terminal-link-hint"`.
  `xterm-hover` keeps the hint's own mouse events from activating links under it (xterm docs).
  - `show(event, uri)`: text `${uri}\n${t('workbench.terminal.link.tooltip', { modifier:
    primaryModifierName() })}` (default variant already has `whitespace-pre-line`), position from
    `event.clientX/Y` minus `term.element.getBoundingClientRect()`, 16px below the pointer, clamped
    so it stays inside the element's width; remove `hidden`.
  - `hide()`: add `hidden`.
  - Only created when `deps.linkActivation === 'modifier'`.
- One activation function for both link sources:
  ```ts
  function activate(event: MouseEvent, uri: string): void {
    if (deps.linkActivation === 'modifier' && !isPrimaryModifier(event)) return;
    if (!isWebUrl(uri)) return;
    hint?.hide();
    deps.openLink(uri);
  }
  ```
- Wire it:
  - `new WebLinksAddon(activate, { hover: (e, uri) => hint?.show(e, uri), leave: () => hint?.hide() })`.
  - Terminal option `linkHandler: { activate, hover: (e, uri) => hint?.show(e, uri), leave: () =>
    hint?.hide(), allowNonHttpProtocols: false }`. The hint is created after `term.open`, so the
    callbacks read a `let hint` declared before `new Terminal` (only called after open).
- Update the file's U41 exemption comment in `scripts/check-ui-primitives.sh:92` only if the lint
  flags the new code; `isPrimaryModifier` is not a raw read, so it should not.
