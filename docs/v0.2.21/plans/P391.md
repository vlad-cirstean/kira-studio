## WebKit support (spike, Playwright WebKit 26.6 `webkit-2359`; Chromium 1243 with `--hide-scrollbars` dropped)

Spike: 200px `overflow: auto` boxes on a solid background, 1000px content, one nested scroller.
Screenshot the 12px right strip, decode it in-page through a canvas, count pixels off the
background.

- `CSS.supports` true in WebKit for `scrollbar-color`, `scrollbar-width`, `scrollbar-gutter`. Do not
  use `scrollbar-color`/`scrollbar-width` here: once set they replace `::-webkit-scrollbar` styling
  (box lost its 12px gutter, `clientWidth` 188 to 200), and `*:hover { scrollbar-color: ... }` never
  repainted (0 pixels on hover). Same for `thin`.
- `:hover::-webkit-scrollbar-thumb { background: X }` (classic trick) and
  `[data-h]::-webkit-scrollbar-thumb` both never repainted in WebKit (0 pixels on hover). Rejected.
- Works in both engines: drive the thumb colour through a custom property set on the scroller
  element itself, reset on every element:
  ```css
  :where(*) { --t: transparent; }
  :where(:hover) { --t: #797979; }
  ::-webkit-scrollbar-thumb { background: var(--t); }
  ::-webkit-scrollbar-thumb:active { background: #bfbfbf; }
  ```
  Results (WebKit and Chromium): idle 0; hover A 420, B 0; leave 0; pointer in nested inner
  scroller: inner and outer both shown; pointer in outer only: outer shown, inner 0; drag thumb then
  move pointer 50px outside: still shown and scrolled (812px); mouse up outside: 0. `clientWidth`
  188 hidden and shown, so no layout shift.
- Two cheaper variants failed in both engines: a registered non-inherited `@property` with
  `--t: inherit` on the thumb, and a hover-chain reset (`:root` default, `:hover > :not(:hover)`
  reset). The reset on every element is required: without it a scroller inside a hovered panel
  inherits the shown value.
- The exact section 1 CSS (tokens inlined) re-ran in both engines with the same pass pattern:
  idle 0, hover shown, sibling 0, nested inner only while pointed, drag outside kept, mouse up 0.
- Overlay vs classic: a styled `::-webkit-scrollbar` is always a classic bar in WebKit (macOS
  overlay setting ignored), so the 12px gutter stays reserved and only the thumb fades. This is the
  no-shift design. True overlay would need `scrollbar-width`, which kills the styling (above).
- Nested scrollers: every ancestor of the pointer is `:hover`, so an outer scroller containing the
  pointer shows too. That matches the row: the pointer is inside that panel.

## Changes

### 1. `packages/theme/src/base.css` (the whole mechanism)

Inside the existing `@media (pointer: fine)` block, replace lines 49-80 with:

```css
  /* P391: thumb hidden until the pointer is inside its scroller. WebKit repaints the thumb only
     when the owner's own style changes, so the colour rides a custom property set by :hover on the
     scroller (a :hover::-webkit-scrollbar-thumb rule never repaints). Reset on every element so a
     scroller inside a hovered panel stays hidden. :active keeps a dragged thumb shown outside. */
  :where(*) {
    --kira-scrollbar-thumb: transparent;
  }

  :where(:hover) {
    --kira-scrollbar-thumb: var(--kira-scrollbar);
  }

  ::-webkit-scrollbar {
    width: 12px;
    height: 12px;
  }

  ::-webkit-scrollbar-thumb {
    background: var(--kira-scrollbar-thumb);
    border-radius: var(--kira-radius);
    border: 3px solid transparent;
    background-clip: padding-box;
  }

  ::-webkit-scrollbar-thumb:hover {
    background: var(--kira-scrollbar-hover);
    background-clip: padding-box;
  }

  ::-webkit-scrollbar-thumb:active {
    background: var(--kira-scrollbar-active);
    background-clip: padding-box;
  }

  ::-webkit-scrollbar-track {
    background: transparent;
  }

  /* Chromium's own unstyled defaults for these two are opaque white, which survives every theme —
     most visible where a scroll container shows both scrollbars at once (P42). */
  ::-webkit-scrollbar-corner,
  ::-webkit-resizer {
    background: transparent;
  }
```

Notes for the implementer:
- `:where()` keeps specificity 0, so any later rule may override. Do not put the new property in
  `tokens.css`: it is state, not a theme token, and must reset per element.
- Horizontal bars use the same thumb rule; nothing extra.
- No transition: a non-registered custom property does not animate and scrollbar parts do not
  transition in WebKit. Show/hide is instant. Do not add JS for a fade.
- No Vue, no VueUse, no Tailwind class: the rule is global pseudo-element CSS, which Tailwind
  utilities cannot express and U32 keeps out of components. shadcn `ScrollArea` would mean
  wrapping every scroller (SlickGrid, virtual lists, trees) in a JS-driven viewport, so it is
  declined: the requirement is every native scroller in both apps, which only global CSS meets.
- Monaco, xterm: no change (already hover-reveal, overlaid, persist while dragging).
- `scrollbar-none` users: unchanged (still never shown).
- Keyboard scrolling with the pointer elsewhere shows no bar. Accepted: the row asks for pointer.

### 2. Shared UI scenario: `packages/workbench/src/testing/ui/scenarios/scrollbars.ts`

New file, `registerScrollbarScenarios(env: { test: ScenarioTest })` (type from `./env`). Both apps
load the same `base.css`, so one scenario runs in both (pattern: `quitConfirm.ts`). The probe is
injected into the real app page after `relaunch()`, so it runs the real bundled CSS with no fixture
data dependency. A real panel would need per-app overflow data and gives no extra proof of the
rule.

Helpers (module-local):
- `addProbe(page, id, left)`: append to `document.body` a `div` with inline style
  `position:fixed; z-index:2147483647; top:80px; left:<left>px; width:200px; height:200px;
  overflow:auto; background:rgb(0, 0, 0)`, child `div` `width:600px; height:1000px`. Return the
  locator. Use `rgb()` text, not hex (U34 checks hex literals in `.ts`).
- `thumbPixels(page, box, edge: 'right' | 'bottom')`: `page.screenshot({ clip })` of the 12px strip
  (right: `x = box.x + box.width - 12`, `height = box.height - 12`; bottom: `y = box.y +
  box.height - 12`, `width = box.width - 12`), then in `page.evaluate` decode the base64 PNG through
  `Image` + canvas `getImageData` and count pixels whose red channel differs from 0 by more than 8.
  No new dependency (no pngjs/pixelmatch in the tree).
- Park the mouse at a point outside every probe (e.g. `page.mouse.move(5, 5)`) before an idle read.

Tests (titles as below):
1. `'a scrollbar is hidden until the pointer is inside its scroller, and keeps its gutter'`:
   probe A at left 40, probe B at left 300. Idle: right and bottom strips of A are 0. `clientWidth`
   and `clientHeight` of A read once. Hover A (`page.mouse.move` to A's centre): A right > 0 and
   bottom > 0; B right 0. Same `clientWidth`/`clientHeight` (no shift). Move out: A right 0.
2. `'a nested scroller shows only while the pointer is inside it'`: probe B with a child probe
   (static, 150x100, `overflow:auto`, tall content) as its first child. Pointer over the inner
   probe: inner right > 0, outer right > 0. Pointer over outer below the inner: outer > 0, inner 0.
3. `'a dragged thumb stays shown after the pointer leaves the scroller'`: mouse down at A's right
   strip, 10px from its top; move 50px right of A and 150px down in 5 steps; A right > 0 and
   `scrollTop > 0`; mouse up; A right 0.

Wrap each read in `expect.poll` (paint lands a frame after the move).
