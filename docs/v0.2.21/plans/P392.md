### Why others' PRs show no actions

The review window target's `branch` is a ref spelling, not the host's head name.
`ade/review.go` `reviewSpellings` uses `refSpelling(row)`: a local branch is `feat/x`, a
remote-only branch is `origin/feat/x`. The PR lookup then misses in two cases, both typical for
someone else's work:

1. **Remote-only branch** (foreign branch review task, P377; tree link; same-repo PR link whose
   branch was fetched only as `refs/remotes/origin/<head>` by `planChangeRequest`). Lookup asks
   for head `origin/feat/x`: the snapshot loop compares `cr.HeadRef == branch`, GitHub
   `PullsForBranch` asks `head=acme:origin/feat/x`. Both find nothing: kind `none`, no buttons.
2. **Fork PR** (`hostlink.go` `planChangeRequest`, `t.Fork`): the local branch is
   `<headOwner>/<headRef>` (or `pr-<n>`), fetched from `refs/pull/<n>/head`. Lookup by that name
   under the base repo owner never matches (`resolveBranchChangeRequest` filters
   `HeadOwner == repo.Owner`; `PullsForBranch` sends `head=<repo owner>:<name>`). Kind `none`.

Own PRs work because the user's own branch is local and pushed under the same name.

The task already knows the PR for case 2: `AddHostLink` stores the link on the task
(`model.AdeTask.HostURL`), and a task holds one branch per repo (TestHostLink comment), so a
change request link whose repo is the branch repo's host repo names exactly that branch's PR.

### Comments

Existing support: a review body (event `comment`, `approve`, `requestChanges`) and a conversation
comment (`POST issues/{n}/comments`). Local inline review comments stay agent-only (P370 A1:
GitHub refuses a whole review for one out-of-diff line). Others' PRs get exactly the same set as
own PRs; no inline PR comments added.

### Auth and token scope

All calls go through `gh api` with the user's `gh` login; no new token. Posting a review or a
comment needs `repo` scope (classic) or Pull requests: write (fine-grained) on the base repo. A
missing scope or a fork the user cannot write to returns 403/404/422; `classify` turns it into a
`Status` reason that the dialog already shows inline (`ade-review-submit-error`). Nothing to add.

### Agent panel button

The only "agent panel" button is `ade-review-toggle-agent` (label key
`space.ade.review.agentPanel.toggle.label`) in `AdeReviewHeader.vue`. Today it sits left of the
Review dropdown. The main window's title bar has no agent toggle (its `toggle-operations-panel` is
the Operations panel). Decision: "very right" = last child of the review window title bar, after
Comment on {short}, right edge at the bar's `pr-1.5` padding. It then sits above the right pane it
toggles. Traffic lights are on the left (macOS inset), so nothing else claims the right edge.

## Design decisions

1. **Branch lookup uses the host head name.** In `ChangeRequestReviewState`, a branch spelled as a
   remote-tracking ref of `origin` (refname `refs/remotes/origin/<head>`) is looked up as
   `<head>`. Only `origin`: the host repo is resolved from `origin` (`hostRepoGen`), so another
   remote names a different repo and keeps today's behaviour. Local tip still reads from the
   original spelling.
2. **Known PR number wins.** `changeRequest.reviewState` gains optional `number`. When > 0 the
   server skips the branch lookup and reads `ReviewTarget(number)` directly. The ADE review target
   carries that number (`changeRequest`, 0 = find by branch), set from the task's `HostURL` only
   when it is a change request link of the branch repo's host repo. Covers forks and `pr-<n>`.
3. **Title** comes from `ReviewTarget` on the number path: `githost.ReviewTarget` gains `Title`
   (GitHub `title` of `GET pulls/{n}`, already fetched).
4. **No PR found shows a reason.** Kind `none` renders the same disabled Review button as
   `unavailable`, tooltip "No {short} found for this branch." Kind `disabled` (host off) stays
   hidden.
5. **Contract 54 to 55, additive** (precedent P352, P370): one optional param.
6. **Own-PR rule unchanged**: `reviewGate` disables approve and request changes when `own`; the
   host 422 stays the backstop.
