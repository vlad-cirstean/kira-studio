# v1.1 P16

DB adapter min/max version compatibility suite

For each database/queue adapter, determine the oldest and newest server version its Go client library actually supports, and add an on-demand compatibility suite (not run as part of the regular CI/test run) that runs the adapter's existing conformance tests against both the oldest and the newest supported server image for that kind — the same coverage that exists today, just run against the version extremes instead of one pinned version. Also add a note to the connection-add UI, per connection kind, stating its minimum supported server version. Once built, actually run the new suite once against real containers and fix whatever it finds

Version-boundary bugs are exactly the kind of thing development against one pinned test-fixture version never catches, and it's cheap to build once the adapters are otherwise stable
