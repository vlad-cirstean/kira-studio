# v1.2 P15

(new) Request builder UX pass — part 1: layout, primitives and body mode

A user-driven follow-up polish pass over the request builder's own surfaces, split from the editor-behaviour half below (see the two plan docs for the split's own rationale). Part 1 is the presentation half, eight of the twelve reported items: the response panel present — chrome and pane switcher included — from the moment a request tab opens rather than appearing only after a first send; a status code's meaning on its own always-visible line rather than a truncatable caption plus a hover; the Studio/Api mode-switch buttons sized up to the app's own tab metrics (and finally rendering the icon `modes.ts` has declared unused since P1); the headers/params/form-data tables' fields actually filling the cells they sit in (`.p-input` is `inline-flex`, so a `TextField` is ~20 characters wide wherever it is put unless its call site says otherwise — the same root cause as the URL field never growing); a new shared Checkbox primitive matching this app's own design system, replacing all fourteen raw `<input type="checkbox">` call sites app-wide (Studio included, since primitives already live in the shared theme layer — `AppButton`/`TextField`/`SegmentedControl` are precedent); JSON promoted to its own top-level body mode, as a UI-level promotion over unchanged `code`+`codeLanguage` storage rather than a new wire/Go/Postman vocabulary and a data migration; a body-present indicator on a request's tab, via a new optional `badge()` member on the tab-kind registry (which is the thing P4 D15 declined, answered rather than ignored); and the toolbar reflowed so Save sits with the request's name in the view head and the URL field takes the row

Sequenced after P12/P13 so it refines a surface that has already settled into its final module shape and design-system pass, rather than polishing files about to be renamed or restyled out from under it — the same role P13 played, but driven by concrete user-reported friction rather than a self-directed audit. Split from P15b because the two halves fail differently (a rule is present or absent here; a caret, a swallowed key or a stale decoration range there), because P15b opens with a `packages/api-core` foundation commit these eight fixes have nothing to do with, and because this half is the one that touches Studio — nine checkbox call sites and the title bar — so one review pass carries that risk instead of two. Plan: `plans/P15-request-builder-ux.md`
