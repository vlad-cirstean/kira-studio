## Findings (current tree)

### Status bar

- Shared chrome: `packages/workbench/src/components/StatusBar.vue` (`h-statusbar`, slots `left-extra`, `right`,
  `gap-0.5`, `px-1.5`, `text-muted-foreground`). `--kira-statusbar-h: 20px` (`packages/theme/src/tokens.css`).
- Kira Space: `apps/kira-space/frontend/src/workbench/StatusBar.vue`. Left: blame item, `AgentUsageItem` (ADE mode
  only). Right: `RunsStatusItem`, `UpdateAvailableItem`, `AppMetricsItem`.
- Kira Studio: `apps/kira-studio/frontend/src/workbench/StatusBar.vue`. Right: `RunsStatusItem`,
  `UpdateAvailableItem`, `AppMetricsItem`. Studio has no ADE module: the agents item is Kira Space only.
- "Running processes" widget = `packages/workbench/src/automations/runs/RunsStatusItem.vue`: `Running: {count}`,
  hidden at zero, click opens Automations Runs. No tooltip.
- Items are `Button variant="toolbar" size="status"` (`h-control-sm` 18px, `text-kira-sm`, `font-normal`). Mixed
  colour: blame and metrics force `text-fg`, runs stay muted, update `text-info`, usage tone-coloured.
- Font: body is `font-ui` (`base.css`). Items opt into the data font: `AppMetricsItem` cpu/mem spans `font-data`,
  `AgentUsageItem` text `font-data`. These render in the user's monospace Data font, unlike the rest of the chrome.
- `AppMetricsItem` tooltip is a hard-coded English string (not in `en.json`): `12.3% of 8 cores · 1.2 GB across 14
  processes · every 5s`. "of 8 cores" is wrong: the figure is normalized to the whole machine (ARCHITECTURE
  "status bar CPU readout uses the normalized convention").

### ADE running agents source

- Sessions: `useSessions()` (`ade/v2/readQueries.ts`, TanStack Query `['adetask','sessions']`). Kept fresh app-wide:
  `installAdeSignals` (`ade/queries.ts`, called once from `main.ts`) invalidates it on every sessions push.
  `adeReaderKey` is provided app-wide in `main.ts`, so the status bar can call it outside the ADE view.
- TUI activity is not on the wire: `useAgentSessionsStore().activity` (Pinia, `createAgentSessionsStore`) merged by
  `withTuiActivity(sessions, activity)`; `activityKind(s)` gives `input | working | waiting | idle | stopped`;
  `activityLabel`, `ACTIVITY_RANK` in `ade/v2/activity.ts`.
- Labels: `useSessionViews()` → `sessionView(s)` gives `tabName`, `repo`, `branch`, `kind`. It pulls
  `usePlanModel()` (board, change requests, workflows, repos). Too heavy to keep alive in an always-mounted bar;
  fine inside a popover that mounts only when open.
- Open a session: `useNeedsAction().openSession(sessionId, taskId, branchId)` raises a terminal another window holds
  (`useFocusSession`), else `useAdeBoardUiStore().openSession`. Mode switch precedent: `agentNotify.ts`
  (`mode.setMode('ade'); board.openTask(taskId)`).
- All sessions list: `ade/v2/needs/AdeAllSessions.vue` inside `AdeNeedsPage.vue`, toggled by a local
  `showAll` ref. Not reachable from outside the page today.
- Task card precedent: `AdeTaskSessions.vue` + `taskSessionsOf` (excludes review sessions).

- Text: multi-fact tooltips join facts on one line with ` — ` or ` · `, so label and value blur together.

## Design

### 1. Tooltip ground (shared, every tooltip in both apps)

`packages/theme/src/components/ui/tooltip/index.ts`:

- Base: drop `zoom-in-95`/`zoom-out-95` and every `slide-in-from-*`; keep `fade-in-0`/`fade-out-0`, add
  `duration-100`. Keep z-index, `pointer-events-none`, `break-words`, origin.
- Shared ground for both variants: `rounded-kira-sm bg-elevated text-fg ring-1 ring-fg/10 shadow-kira`.
- `default`: `inline-flex items-center gap-1.5 px-2 py-1 text-kira-md leading-snug w-fit max-w-sm
  whitespace-pre-line`, plus `has-data-[slot=kbd]:pr-1`. Delete every `**:data-[slot=kbd]:*` and
  `**:data-[chip=branch]:*` override: `Kbd` and the branch chip render their own style on the elevated ground.
- `surface`: keep layout only (`flex w-80 max-w-(--reka-tooltip-content-available-width) flex-col items-stretch
  gap-1.5 p-2`). Update its comment: it is now a layout variant, not a ground.

`TooltipContent.vue`: default `sideOffset: 4`; delete the `TooltipArrow` (an arrow on a ringed elevated box draws a
seam; VS Code hovers have none). Remove `TooltipArrow` from the import.

`AttributeTooltip.vue`: `text-bg/75` → `text-muted-foreground`, `text-bg/60` → `text-muted-foreground`,
`bg-bg/20` → drop the class (Separator default), `border-bg/30` → `border-border`.

Grep both apps and packages for any other class written for the inverted ground inside a `TooltipContent`
(`text-bg`, `bg-bg/`, `border-bg/`, `text-subtle` reliance is fine) and convert it. The grep at plan time found
only the four above.

### 2. `TooltipDetails.vue` (shared structured body)

New `packages/theme/src/components/TooltipDetails.vue`, `<script setup lang="ts">`:

```ts
defineProps<{
  title?: string;
  rows?: readonly { label: string; value: string; class?: string }[];
  hint?: string;
}>();
```

Template (Tailwind only):

- root `flex flex-col gap-1 py-0.5 text-left whitespace-normal` (`data-testid="tooltip-details"`)
- title `font-medium text-fg` (`tooltip-details-title`)
- rows `grid grid-cols-[auto_1fr] gap-x-3 gap-y-0.5`; label `text-muted-foreground`, value `tabular-nums` plus
  the row's `class` (`tooltip-details-row`, `data-label`)
- hint `text-kira-sm text-muted-foreground` (`tooltip-details-hint`)

Used by every status bar item and the joined tooltips in the audit. Copy roles (ARCHITECTURE copy rules): title
`.tooltip` (no period), row labels `.label`, hint `.hint` (sentence, period).

### 3. Status bar chrome and items

- `tokens.css`: `--kira-statusbar-h: 22px` (VS Code's height; leaves 2px around the 18px items, which touch both
  edges at 20px).
- Shared `StatusBar.vue`: root `h-statusbar shrink-0 flex items-center gap-2 px-2 font-ui text-kira-sm
  text-muted-foreground`; groups `flex items-center gap-1`.
- `buttonVariants` size `status`: `h-control-sm gap-1 px-1.5 text-kira-sm font-normal font-ui tabular-nums`.
- New `packages/workbench/src/components/StatusBarItem.vue` (`<script setup lang="ts">`), one place for the item
  shape:
  - props `icon: string`, `tone?: 'info' | 'warn' | 'error'`, `as?: string`, `disabled?: boolean`; default slot
    = label; named slot `tip` = tooltip body. Attributes (`data-testid`, `@click`) fall through to the `Button`
    (`inheritAttrs: false`, like `TooltipIconButton`).
  - renders `Tooltip > TooltipTrigger as-child > [TooltipDisabledTrigger when disabled] > Button variant="toolbar"
    size="status"` with `CodiconIcon :size="12"`; the `tip` slot goes into `TooltipContent`; no tooltip when the
    slot is absent.
  - colour: muted by default, `hover:text-fg` from the toolbar variant; tone maps `info → text-info`,
    `warn → text-warn-text`, `error → text-error`. No item forces `text-fg` any more.
  - exposes the button element for a popover anchor (same `defineExpose` approach as `TooltipIconButton`), or
    accepts being wrapped by `PopoverTrigger as-child`; implementer picks whichever keeps Tooltip + Popover on one
    trigger working (precedent: `RefsPopover.vue` nests `TooltipTrigger as-child > PopoverTrigger as-child`).
- Port onto `StatusBarItem`: blame (Space), `AgentUsageItem`, `RunsStatusItem`, `UpdateAvailableItem`,
  `AppMetricsItem`. Keep every existing `data-testid`.
- Interface font: drop `font-data` from `AppMetricsItem` cpu/mem spans and `AgentUsageItem` text; keep the
  `min-w-[5ch]`/`min-w-[9ch]` right-aligned spans (tabular-nums keeps the width stable).
- Item text and tooltips (keys under each item's existing namespace; new status-bar keys under
  `workbench.statusBar.*`; agents under `space.statusBar.agents.*`):
  - Runs: label `{count} running` (icon `play`). Tip: title `Automation runs`, row `Running` → count, hint `Click
    to show them in Automations.`
  - Update: label unchanged. Tip: title `Update available`, rows `New version`, `Installed`; hint `Click to review
    and install.`
  - App metrics: label unchanged. Tip: title `{app} resource use` (app name from the existing product-name
    message, implementer finds the key), rows `CPU` → `12.3% of total capacity`, `Cores` → `8`, `Memory` → `1.2 GB`,
    `Processes` → `14`; hint `Includes helper processes. Updates every 5 seconds.` Move the string into `en.json`.
  - Blame: label unchanged. Tip: title = clamped subject (or `No message`), rows `Author`, `Date`; hint `Click to
    show the commit.` only when `blameStatusStore.reveal` exists. `blameLineTooltip` returns the parts (object)
    instead of a string array; `blameAnnotation.ts` hover keeps its own text by joining the parts there.
  - Agent usage: bar text unchanged (`Session 40% · Weekly 12%`). Tip: title `{product} usage limits`, rows
    `Session (5-hour)` and `Weekly` → `40% used, resets in 2h 3m (Oct 31, 14:00)`, value class carries the
    window's own tone (80/95 thresholds); hint = source line (`From a {product} session, 3 min ago.`), or the
    waiting/error text. Delete keys left unused (`fiveHourLong`, `weeklyLong`, `line.status` if replaced).
- The joined tooltips from the audit (ApprovalResponse column header and the three `en.json` keys) move to
  `TooltipDetails` (title + rows). Update their callers.

### 4. Running ADE agents item (Kira Space)

New `apps/kira-space/frontend/src/ade/v2/status/AdeAgentsStatusItem.vue` plus
`AdeAgentsStatusList.vue`, both `<script setup lang="ts">`; mounted in Space `StatusBar.vue` `#right` before
`RunsStatusItem`, in every mode (running processes show in every mode too).

- Data (bar): `useSessions()` + `useAgentSessionsStore().activity` → `withTuiActivity` → `state === 'running'`.
  All running sessions count: headless runs, interactive TUI, review agent. Pure helper
  `agentsSummary(sessions)` in `ade/v2/status/agentsSummary.ts` returns `{ total, byKind: Record<ActivityKind,
  number>, top: ActivityKind }` (`top` = lowest `ACTIVITY_RANK` present).
- Hidden at zero (like runs).
- Bar: icon `robot`, label `1 agent` / `{count} agents`; when `byKind.input > 0` add ` · {n} need input` and tone
  `warn`. `data-testid="status-agents"`, `data-state="{top}"`.
- Tooltip (`TooltipDetails`): title `Running agents`; one row per non-zero kind in rank order, label =
  `activityLabel(kind)`, value = count; hint `Click to list them.`
- Click: shadcn-vue `Popover` (`PopoverContent side="top" align="end" class="w-96 p-1"`) with
  `AdeAgentsStatusList`, mounted only while open, so `useSessionViews()` (plan model) loads on demand.
  - Rows sorted by `ACTIVITY_RANK`, then `lastActiveAt` desc. Each row is a `Button variant="ghost"` full width:
    `AdeActivityIcon :kind`, task title (`truncate`, `text-fg`), second line `text-kira-sm text-muted-foreground`:
    `view.tabName · activityLabel · age` (`useRelativeTime`). `data-testid="status-agents-row"`,
    `data-session-id`, `data-kind`.
  - Row click: close popover, `modeStore.setMode('ade')`, `openSession(id, taskId, branchId)`.
  - Footer `Button variant="link"` `Show all sessions` (`status-agents-all`): `setMode('ade')`,
    `ui.view = 'needs'`, `ui.showAllSessions = true`.
  - Loading state while the plan model is empty: `InlineState kind="loading"`.
- `openSession` extraction: move it out of `needs/useNeedsAction.ts` into new
  `ade/v2/sessions/useOpenSession.ts` (reads `terminalId` from `useSessions().data`, not `useSessionViews`).
  `useNeedsAction` and the popover both call it. No behaviour change for the Needs page.
- `adeBoardUi.ts`: new in-memory `showAllSessions` ref; `AdeNeedsPage.vue` replaces its local `showAll` with it.
- No new Pinia store (bar state is derived); server state stays in the existing TanStack query; no backend change.

Libraries: shadcn-vue (`Button`, `Popover`, `Tooltip`), Tailwind classes only (no scoped `<style>`), VueUse
(`useRelativeTime` already wraps it), Pinia (existing stores), TanStack Query (existing `useSessions`).
