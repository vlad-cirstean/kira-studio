# P417 Jira via acli behind an issue-tracker abstraction, CLI setup in Settings

Plan for `docs/v0.2.23/SPEC.md` row P417. Base: `dd762c9`. Discovery ran through `codegraph_explore` (githost and
`githost/github` discovery, runner, provider, registry; `gitclient` discovery; `internal/toolexec`; ADE artifacts
aggregator; Jira fields on tasks, frontend `jira.ts`, `useLinkFields.ts`; Settings dialog and panes; flowharness gh

One sequential Sonnet implementer inside P417. Runs as a third stream beside P414 and P415 Part 1; see "Streams".

## User ask

"Use acli to make jira calls. Like we use already gh cli. All we care about jira is based on the jira id link to fetch
the title the status and very importantly the associated prs from the dedicated section. In settings add a section
about how to install and login into gh and acli. For acli make sure it's abstracted as it will support other issue
trakers in the future."

## Gate: user decision on the PR list (orchestrator asks before the implementer starts)

acli cannot read the PR list of Jira's Development section today:

- `acli jira workitem view KEY [--fields ...] [--json] [--web]` is the only read. No raw API command, no dev-info
  command ([reference](https://developer.atlassian.com/cloud/acli/reference/commands/jira-workitem-view/)).
- The issue's `Development` field (a custom field, often `customfield_10000`) holds only a summary: PR count, overall
  state, per-provider counts. No titles, no URLs.
- The PR rows come from `/rest/dev-status/latest/issue/detail?issueId=…&applicationType=…&dataType=pullrequest`, an
  internal, undocumented endpoint. acli keeps its token in its own store; Kira cannot borrow it.

Options for the user:

- **A (recommended, this plan's design).** acli gives key, title, status and the Development summary (count, state,
  providers). PR rows come from the code-host provider (`gh`) by the same rule the Jira GitHub app links them: the key
  in the PR title or head branch. Count from Jira vs rows found are compared; a shortfall shows as a gap with the
  numbers. Stays on acli and gh, no new credential.
- **B.** Call dev-status detail over HTTPS with an Atlassian API token the user stores in Settings (OS keychain).
  Exact panel rows, but bypasses acli for that call and relies on an internal endpoint.
- **C.** Ship title and status plus the Development summary only; PR rows wait for acli support.

The design below is A. B would replace only `jira.prRows` (section 3) and add a token field to the Settings pane. If
the user picks B or C, the orchestrator sends this plan back for that change; nothing else moves.

## Design

### 1. Neutral contract: `apps/kira-space/internal/issuetracker`

Mirrors `githost` (P318): neutral types, roles, a registry, one registration package.

```go
type Ref struct {
	Provider string `json:"provider"`
	Key      string `json:"key"`  // PROJ-12
	URL      string `json:"url"`  // browse URL; built from the signed-in site when only a key was given
	Site     string `json:"site"` // host of a pasted URL; '' for a bare key
}
type ChangeRequest struct { // a PR the tracker associates with the issue
	Title, URL, Ref, State, Repo, Provider string // Provider = code-host id
}
type ChangeRequestSummary struct {
	Known     bool     `json:"known"`     // the tracker reported a summary at all
	Count     int      `json:"count"`
	State     string   `json:"state"`     // OPEN | MERGED | DECLINED | '' as the tracker says, lower-cased
	Providers []string `json:"providers"` // e.g. GitHub, Bitbucket
}
type Issue struct {
	Ref            Ref
	Title          string
	Status         string // workflow status name
	StatusCategory string // new | indeterminate | done | ''
	Summary        ChangeRequestSummary
	ChangeRequests []ChangeRequest
}
type Status struct { // CLI discovery and auth; same Kind words as githost.Status
	Kind, Path, Version, Account, Site, Reason string
	Probed []string
}
type Terms struct{ Label, Issue, CLI string } // Jira, Work item, Atlassian CLI (acli)
type Setup struct { // provider-owned how-to, rendered by the Settings pane
	DocsURL string
	Steps   []SetupStep // in order
}
type SetupStep struct {
	Purpose string // install | login | loginToken | check  (label from en.json)
	Command string // shown verbatim, copyable
}

type Provider interface {
	ID() string
	Terms() Terms
	Setup() Setup
	ParseRef(raw string) (Ref, bool) // no CLI call
	Status(ctx context.Context, refresh bool) Status
	Issue(ctx context.Context, ref Ref) (Issue, error)
}
```

- Errors: `Issue` returns typed errors so callers name the gap: `ErrUnavailable` (CLI missing),
  `ErrUnauthenticated`, `ErrNotFound` (no such issue or no access), `ErrOtherSite` (pasted URL host is not the
  signed-in site), `ErrTimeout`, else wrapped `*toolexec.ExecError`. `issuetracker.Reason(err) string` maps each to a
  short stable reason word (`unavailable`, `unauthenticated`, `notFound`, `otherSite`, `timeout`, `failed`).
- `Registry`: `NewRegistry(ps...)` (duplicate id panics), `Get`, `All`, `ParseRef(raw)` (first provider in order),
  `Infos()` (`Info{ID, Terms, Setup}`). Nil-safe like `githost.Registry`.
- `issuetracker/providers.New(jira.Options, extra ...Provider) *Registry`: Jira first. Composition roots import it;
  callers depend on `issuetracker` only.
- PR rows need a code host. `Issue` takes no githost dependency: the Jira provider gets
  `Options.ChangeRequests func(ctx, key string) ([]ChangeRequest, error)`, wired in appwire to the githost search
  below. Another tracker that lists PRs itself ignores it.

### 2. Code-host search for a key (`githost`, optional role)

- New optional role `githost.ChangeRequestSearch { SearchChangeRequests(ctx, host, text string, limit int)
  ([]ChangeRequest, Status) }`, same "failure in Status, never error" rule.
- GitHub: `gh search prs <text> --match title --json number,title,state,url,repository,headRefName --limit <n>`
  (10 s, `apiTimeout`). Parse into `githost.ChangeRequest` (repo from `repository`). GitHub search cannot match head
  branch names; that match comes from the local index (next bullet).
- Head-branch match: `repos.GitHostChangeRequestsRepo` gains `ByHeadContaining(key string, limit int)` (SQL `LIKE`
  with `ESCAPE`, case-sensitive key, newest first) over `git_host_change_requests`, so PRs of every synced repo whose
  head branch carries the key are found without a host call.
- `ade` composes both (dedup by URL) into `issuetracker.ChangeRequest` with the host's `Terms().ChangeRequestShort`
  ref `#<n>`; that func is what appwire passes as `jira.Options.ChangeRequests`. fakehost `Forge` implements the role
  for flows.
- Why the key rule: it is the rule the Jira GitHub app itself uses to fill the Development section (key in branch,
  title or commit). Commits-only links are not found; the count comparison in section 3 surfaces that as a gap.

### 3. Jira provider over acli: `apps/kira-space/internal/issuetracker/jira`

- `Options{Locator, Runner, Clock, ChangeRequests}`; nil takes the real one. `Locator` = `toolexec.Locate` for `acli`
  with candidates `/opt/homebrew/bin/acli`, `/usr/local/bin/acli`. `Runner interface { Run(ctx, path string, args
  []string) ([]byte, error) }`; real one is `toolexec.RunIO(ctx, path, args, "", os.Environ(), nil)` (acli needs the
  user's HOME for its config and keychain). One runner value per app, built in appwire (op-log seam, section 8).
- **Discovery** (`Status`): locate, `acli --version` (5 s, parse first dotted version), `acli jira auth status`
  (10 s). Exit 0 = `ok`, parse `Site:`/`Email:` style lines best-effort into `Site`, `Account` (implementer confirms
  the real format, see "acli output"); non-zero = `unauthenticated`, reason "run `acli jira auth login --web`". Cache
  one entry, 5 min ok / 30 s not ok, caller-cancel never cached (copy the gh rule, not the code). `refresh` drops the
  cache first.
- **ParseRef**: bare key `^[A-Z][A-Z0-9]+-\d+$`; URL forms `https://<host>/browse/KEY`,
  `https://<host>/jira/.../issues/KEY`, any Jira URL with `selectedIssue=KEY`; host must end `.atlassian.net` or be
  the signed-in site (checked at fetch, not parse). The key regex lives here once; `bridge.adeJiraKeyRe` stays (input
  validation) and the frontend `parseJira` stays (no new rule needed there).
- **Issue(ctx, ref)**:
  1. `Status` must be ok, else `ErrUnavailable`/`ErrUnauthenticated`. A ref `Site` that differs from the signed-in
     site is `ErrOtherSite` (acli has one site per login).
  2. Field read. First call per site: `acli jira workitem view KEY --json --fields
     '*all,-comment,-attachment,-worklog,-description'`; find the Development field (value is the
     `{pullrequest={...}, json={...}}` string or an object holding `cachedValue.summary.pullrequest`) and remember its
     field id per site. Later calls: `--fields summary,status,<devFieldId>`. 10 s timeout. Exit code with "does not
     exist" / "permission" in stderr is `ErrNotFound`. `toolexec.ErrOutputTooLarge` on the first call retries once with
     `summary,status,*navigable` and marks the site "no dev field" for 10 min.
  3. Parse `key`, `fields.summary`, `fields.status.name`, `fields.status.statusCategory.key` and the dev summary
     (`overall.count`, `overall.state`, `byInstanceType` names). Unknown shape = summary `Known: false`, not an error.
  4. PR rows: `Options.ChangeRequests(ctx, key)` when set and `Summary.Count > 0` or summary unknown. Its error stays
     inside: `Issue` returns the issue with `ChangeRequests: nil` and a `PRLookupErr` field set (reason word), so the
     title and status are never lost to a host failure.
  5. URL: pasted URL kept; else `https://<site>/browse/KEY`.
- **Cache and timeouts** (`client.go`): results cached per `site|key`: 60 s ok, 15 s on error; `singleflight` per
  key. The fetch runs on a detached ctx with its own 20 s bound (`DoChan`), so a caller that gives up (the 5 s
  artifact source budget) leaves the fetch running and the next listing hits the cache. Caller-cancel is not cached.
  `golang.org/x/sync/singleflight` (already a dependency via errgroup); no hand-rolled coalescing.
- Terms `{Jira, Work item, Atlassian CLI (acli)}`. Setup: docs URL above; steps `install` `brew tap
  atlassian/homebrew-acli && brew install acli`, `login` `acli jira auth login --web`, `loginToken` `acli jira auth
  login --site <your-site>.atlassian.net --email <you@example.com> --token < token.txt`, `check` `acli jira auth
  status`.

### 4. gh setup info (`githost`)

- New optional role `githost.CLISetup { Setup() clisetup.Setup; CLIStatus(ctx, refresh bool) Status }`. The
  `Setup`/`SetupStep` types live in a tiny shared package `apps/kira-space/internal/clisetup` so both `githost` and
  `issuetracker` use one shape (no import between them).
- GitHub: docs `https://cli.github.com`; steps `install` `brew install gh`, `login` `gh auth login`, `check` `gh auth
  status`. `CLIStatus` = `Discovery.Status(ctx, "github.com")`, `refresh` calls new `Discovery.Forget(host)`.
- fakehost Forge implements it for the flow.

### 5. ADE: tracker artifacts (`apps/kira-space/internal/ade/issuetracker.go`, new)

- `TaskBoardDeps.Trackers *issuetracker.Registry`. `builtinArtifactSources` adds `trackerSource{b}` when
  `Trackers != nil`, after `repoSource` (host PR rows win dedup) and before `storedSource`. Wiring through a deps field,
  not `ArtifactSources`, because the source needs the board (ref parsing from task fields); `ArtifactSources` stays
  for external sources and its comment drops "P417".
- `taskLinkSource` loses its Jira half. `trackerSource` (`Name()` = provider id, e.g. `jira`):
  - ref from `JiraURL` else `JiraKey` via `Registry.ParseRef`; none = no rows.
  - success: kind `issue`, title = `Title`, ref = key, status = `Status`, url, source = provider id; one
    `changeRequest` row per PR (title, url, ref, status = state, repo = nickname when the repo is a task repo else
    `owner/name`, source = provider id).
  - failure: the static row (title = key, url as stored) plus gap `{Source: id, Reason: Reason(err)}`; never an
    error return, so the row survives a timeout.
  - `Summary.Known && Summary.Count > len(PR rows)`: gap `{Source: id, Reason: "changeRequestsMissing", Count:
    Summary.Count - n}`. `PRLookupErr` set: gap with that reason.
- `adewire.ArtifactGap` and `agentmcp.ArtifactGap` gain `Reason string` (`reason,omitempty`) and `Count int`
  (`count,omitempty`). Existing gaps leave both empty. Finish replies carry them; agents see why a list is partial.
- `TaskBoard.TaskIssue(ctx, taskID) (adewire.TaskIssue, error)`: the task's ref, `Issue` with the 10 s bound, as
  `adewire.TaskIssue{Provider, Key, URL, Title, Status, StatusCategory, Summary, ChangeRequests, Reason}`; `Reason`
  set instead of a call error for tracker failures. For the task tab line.
