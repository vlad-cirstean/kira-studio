# P404 Board: archived tasks inline, session indicator, weekend pattern, branch status colors

Plan for `docs/v0.2.23/SPEC.md` row P404. Base: `60d0803`. Discovery ran through `codegraph_explore`.

One sequential Sonnet implementer. No stream split: commits 2, 3 and 4 all edit `AdePlanView.vue`,
`AdeDayBand.vue`, `timeline.ts` or `AdeArchivedPanel.vue`, and commit 4's UI spec builds on commit 3's
finder. Real overlap, so no split.

## Findings

- **Archived names missing.** `toWireHistory` (`apps/kira-space/internal/ade/board.go:571`) sets
  `Title = t.Title`, else `t.JiraKey`. An untitled task (name derived from its branch) arrives with
  `title: ''`. The live board uses `taskTitle` (`internal/ade/setup.go:60`: title, Jira key, first
  branch name, `New task`). History rows (`AdeDayBand.vue:134-152`) also put `how` and `repos`
  before the title, so a long repo list squeezes the `truncate` title to nothing.
- **History rows show only after Load history.** `buildBand` (`board/timeline.ts:361`) filters
  `history` by `ctx.showHistory` for every band, today included. A task archived today vanishes
  until Load history.
- **Archived tab.** `AdeShell.vue:132-145` (`ade-tab-archived`, `ade-archived-count`) and `:164`
  render `archived/AdeArchivedPage.vue`: a filterable list over `board.history` beside
  `AdeArchivedPanel`. Store `state/adeArchiveUi.ts` holds its selection, filter and panel tab.
  `AdePanel.vue:20-24` already opens `AdeArchivedPanel` for a selected archived task beside the
  Plan. So the tab duplicates a reachable surface. Its one unique job is search across all history.
- **Load history.** `AdePlanView.vue:331-342`: full-width `toolbar` button, `kira-lg`, `mb-2`,
  label `historyButtonLabel` (`timeline.ts:481, 487-492`) = "Load history · 5 archived tasks in the
  last 2 weeks".
- **Resume.** `AdeStoppedRow.vue:50-61` hides Take over when `archived`. Backend `TakeOver`
  (`internal/ade/launches.go:131`) goes through `loadTaskCtx` (`runs.go:113`), which refuses an
  archived task; `ArchiveTask` (`archive.go:136`) removed the worktrees. `RestoreTask`
  (`archived.go:178`, repo `adetask.go:1367`) brings task and branch rows back into Later;
  worktrees return on next launch through `launchGate` inside `takeOverCwd` (`launches.go:280`).
  `useAdeTakeOverStore` (`state/adeTakeOver.ts`) already handles the preparing wait and opens the
  Sessions tab via `ui.openSession`. Resume = Restore, then the existing Take over. No new backend
  method needed.
- **Weekend.** `TimelineBand.weekend` exists (`timeline.ts:95, 348`). `AdeDayBand.vue:61`
  only greys label and ruler (`greyed`). No pattern.
- **Branch status colours regressed in v0.2.21 (`4f27707`, HISTORY "ADE task list calmer").**
  `AdeActionCell.vue:35-37`:
  `tone = !row || tone red|amber ? tag.tone : 'grey'`. So on branch rows `merged` (purple), `clean`
  (green), `rebasing`/`waiting` (blue) all render grey. Rules in `board/actions.ts:291-636` still
  carry the right tones.
- **Session state source.** `usePlanModel.ts:262-278` builds `sessions` from `useSessions()` merged
  with TUI phases from `useAgentSessionsStore` (`ade/state.ts`, factory
  `packages/workbench/src/state/createAgentSessionsStore.ts`) via `withTuiActivity`
  (`activity.ts:44`). `buildCard` (`usePlanModel.ts:190`) already filters them per task.
  `activityKind` (`activity.ts:55`) maps to `input|working|waiting|idle|stopped`.
- **Tokens.** Tones are literal `@theme` tokens in `ade/v2/tones.css`, pinned by
  `scripts/check-ade-colours.sh` (no other colour literal under `ade/`). `check-tokens.sh` resolves
  `var(--kira-*)` only. `--color-border` comes from `packages/theme/src/shadcn-bridge.css:37`;
  `AdeActivityIcon.vue:27` is precedent for `var(--color-*)` inside an arbitrary Tailwind value.

## Design

### 1. Archived names (Go)

- `board.go` `toWireHistory`: `title := taskTitle(t, byTask[t.ID])`. Drop the hand-rolled fallback.
- Extend `internal/flows/adeflow/lifecycle_test.go` (the archive assertion at `:65`): assert
  `b.History[0].Title` equals the task's live title before archive. Add a second untitled task case
  only if the fixture has one cheaply; otherwise rename the task to `""` via `UpdateTask` first and
  assert the branch name comes back.

### 2. Archived tasks inline

- `timeline.ts` `buildBand`: `history: ctx.showHistory || dk >= 0 ? ctx.history.filter(h => h.day === dk) : []`.
  Today's band always lists what was archived today; Load history adds past days. No extra data:
  `board.history` is already in the snapshot.
- `AdeDayBand.vue` history row: title first (`min-w-0 flex-1 truncate font-medium text-fg`), then
  one muted `shrink-0 text-kira-sm text-muted-foreground` span `how · repos`. Icon: codicon
  `archive` (`check` when merged). Add `:data-task-id="h.key"`. Keep `ade-history-row`, the
  `ml-54.5 h-row` geometry and the U37 `bg-select` exemption.
- `AdePlanView.vue` `bandHistory`: pass `meta: [how, repos].filter(Boolean).join(' · ')` instead of
  separate `how`/`repos`; update the `history` prop type in `AdeDayBand.vue:28`.

### 3. Drop the Archived tab; archived finder; compact Load history

Where archived tasks live: in the Plan. Three paths, all over the `board.history` already loaded:
inline rows on their archive day (section 2), the history region (Load history), and a search popover
in the Plan's history control. Selecting one sets `ui.select(taskId)`; `AdePanel` already renders
`AdeArchivedPanel` for it. Why this beats a tab: no page switch, no second list component or store,
no extra query; the panel and Plan stay visible together. The search popover keeps the tab's one
unique job (find any archived task by name or repo).

- Delete `ade/v2/archived/AdeArchivedPage.vue` (and the empty `archived/` dir) and
  `ade/v2/state/adeArchiveUi.ts`.
- `AdeShell.vue`: remove the `archived` trigger, `archivedCount`, the `AdeArchivedPage` import and
  branch.
- `state/adeBoardUi.ts`: drop `'archived'` from `view`'s union.
- `panel/AdeArchivedPanel.vue`: replace `useAdeArchiveUiStore` with a local
  `const tab = ref<'task' | 'notes' | 'sessions'>('task')` reset by the existing `taskId` watch.
  `onRestore` keeps `boardUi.openTask(props.taskId)`; drop the `archive.select(null)` line.
- `board/timeline.ts`: add `history: TimelineHistoryItem[]` to `TimelineView` (return the computed
  `history`). Rename `historyButtonLabel` to `historyTip` and `historyLabel` to return only
  "{tasks} in the last N days/weeks" (no "Load history · " prefix).
- New `plan/AdeArchivedFinder.vue` (`<script setup lang="ts">`, Tailwind only): shadcn-vue
  `Popover`/`PopoverTrigger`/`PopoverContent` (`@theme/components/ui/popover`) around `Command`,
  `CommandInput`, `CommandList`, `CommandEmpty`, `CommandItem` (`@theme/components/ui/command`).
  Not `PickerPopover`/`PickerCombobox`: both are documented internal to `workbench/components/pickers/`
  and are value pickers with a field trigger, not a navigation search. Trigger:
  `TooltipIconButton` icon `search`, label `space.ade.plan.history.find.label` ("Find archived
  task"), `data-testid="ade-archived-find"`. Items from `model.board.history` (newest first): title,
  muted detail `repos · formatDateTime(archivedAt)` (`@workbench/behaviour/format`), merged items
  get the `common.merged.status` muted suffix. Filter on title and repos (Command's built-in filter
  with `value` = `${title} ${repos}`). Item testid `ade-archived-find-item` + `data-task-id`; empty
  `ade-archived-find-empty` (`common.state.noMatches.empty`). Hidden when history is empty. Emits
  `pick: [taskId]`.
- New `plan/AdeHistoryControl.vue`: one row, `ml-15 mb-1 flex h-row items-center gap-1`.
  - Toggle: `Button variant="toolbar" size="kira"`, `h-row gap-1 px-1.5 text-kira-sm
    text-muted-foreground`, codicon `history` 12, text `common.module.history.label` ("History")
    plus muted count `historyCount` when > 0. Wrapped in `AdeTip` with `historyTip`. When
    `ui.showHistory`: text `space.ade.plan.history.hide.label`, emits `hide`; else emits `load`.
    `data-testid="ade-load-history"`, `:data-open="ui.showHistory || undefined"`.
  - Then `AdeArchivedFinder`.
  - Props: `count`, `tip`, `open`; emits `load`, `hide`, `pick`.
- `AdePlanView.vue`: replace lines 331-342 with `<AdeHistoryControl>` (always rendered).
  `load` → `openHistory`, `hide` → `hideHistory`, `pick` → new `onFindArchived(taskId)`:
  `ui.select(taskId)`; read `model.view.history` item; if `day < 0` set `ui.showHistory = true` and
  route through a shared `revealDay(k)` extracted from `onGoToDate` (historyReach widening, then
  `nextTick`, `scrollToDay`); `onGoToDate` calls `revealDay` too.
- i18n (`packages/theme/src/i18n/en.json`): add `space.ade.plan.history.find.label`; rewrite
  `space.ade.plan.view.loadHistoryDays/Weeks.label` text to the tooltip wording ("{tasks} in the

- `docs/ARCHITECTURE.md`: line 2078 now describes the inline rows, history control and finder;

### 4. Resume an archived task's session

- `state/adeTakeOver.ts`: add `resumeArchived(taskId, sessionId): Promise<void>`. Uses
  `useRestoreTask()` (`queries.ts:441`; its `onSuccess` awaits board and sessions invalidation, so
  the session list is live again), then `launch(sessionId)` (existing; handles preparing wait and
  `ui.openSession`). Errors go to `ui.actionError[taskId]`; clear it first. `pending` covers the
  whole chain (`pending.add(sessionId)` before restore). No confirm: the session is stopped.
- `sessions/AdeStoppedRow.vue`: when `archived`, render `Resume` (`common.action.resume.label`; add
  key if missing) `variant="dialog" size="kira"`, `AdeTip` `space.ade.archived.resume.tooltip`
  ("Restores the task to Later and continues this session"), `data-testid="ade-stopped-resume"`,
  calls `takeOver.resumeArchived(view.session.taskId, view.session.id)`. Only for a session with a
  conversation to continue: `view.session.agentSessionId !== ''`. Same `ref="takeBtn"` focus wiring.
- `panel/AdeArchivedPanel.vue`: show `boardUi.actionError[taskId]` in the existing error `Alert`
  area (keep `ade-archived-restore-error` for the Restore button; resume error testid
  `ade-archived-resume-error`).
- Backend half: new flow test `TestResumeArchivedSession` in
  `internal/flows/adeflow/archived_test.go`, using `newRunFixtureWith` with a tracker (harness
  options as `TestInteractiveSessions`): run a step, archive, `RestoreTask`, `TakeOver` on the
  run's headless session. Assert launch command contains `--resume`, cwd is the restored branch
  worktree, session row taskId matches. Write contract keys to `tests/contract/ade-archived.json`:
  `args:AdeTaskService.TakeOver` and `AdeTaskService.TakeOver#archived-resume` (launch result);
  regenerate per `docs/DEV_ENVIRONMENT.md` "Contract fixtures".

### 5. Weekend pattern

- `AdeDayBand.vue`: on the content column (`ade-band-drop`), when `band.weekend` add
  `bg-[repeating-linear-gradient(135deg,var(--color-border)_0_1px,transparent_1px_6px)]`; on the
  outer band add `:data-weekend="band.weekend || undefined"`. Literal class string in the template so
  Tailwind emits it. Day-off bands keep their line-through, no pattern. No colour literal, so
  `check-ade-colours.sh` and `check-tokens.sh` stay green.

### 6. Branch status colours

- `AdeActionCell.vue`: delete the `tone` computed; pass `tag.tone` straight to both `AdeChip`s.
  Merged purple, clean green, rebasing/waiting blue, amber/red unchanged; task-level tags already
  passed their tone.
- `AdeChip.vue`: add `:data-tone="tone"` for specs.

### 7. Per-task session indicator

- New pure `board/taskSessions.ts`:
  `export type TaskSessionState = 'input' | 'running' | 'finished'`;
  `taskSessionsOf(sessions: readonly Session[]): { state; running: number } | null`. Ignore
  `purpose === 'review'`. No sessions: `null`. Any running with `activityKind === 'input'`:
  `input`. Any running headless, or running TUI `working`/`waiting`: `running`. Else (running TUI
  idle, or only stopped sessions): `finished`. `running` = count of `state === 'running'`.
- `usePlanModel.ts`: `CardModel.sessions: ReturnType<typeof taskSessionsOf>`; set in `buildCard`
  from the existing per-task `sessions`.
- New `plan/AdeTaskSessions.vue`: `TooltipIconButton`-style `Button variant="toolbar"
  size="kira-icon"` `size-4.5`, `@click.stop` → `ui.openSessions(taskId)`. Glyph: `input` →
  `AdeActivityIcon kind="input" bare`; `running` → `AdeActivityIcon kind="working" bare` plus
  `text-kira-sm` count when `running > 1`; `finished` → codicon `check` 12 `text-tone-green`.
  Tooltip keys `space.ade.plan.card.sessions.{input,running,finished}.tooltip` ("An agent needs your
  input" / "{count} agent session running | {count} agent sessions running" / "Agent finished, no
  session working"). `data-testid="ade-card-sessions"`, `:data-state`.
- `AdeTaskCard.vue`: render it in the head row before `AdeAttention`, `v-if="card.sessions"`.
- `state/adeBoardUi.ts`: `openSessions(taskId)`: `view = 'plan'`, `select(taskId)`,
  `taskTab = 'sessions'`.
