## User ask

- Kira Studio only. Dedicated MCP tool for validation proof, shaped like the query editor: query plus results.
- Generic: agent pushes arbitrary data from its own tools, picks which existing plain data view shows it. No
  visualisation view.
- Each step carries a short description.
- Grouped by session: agent starts, adds steps, closes. User notified only on close.
- New window. History of older sessions, last 30 kept, manual delete. Session names unique.
- Agent can modify an existing session. User sees old and new, accepts the new.
- Order matters everywhere: create, edit, display.
- Window design closely follows Kira Space review window.
- Screenshot button: one tab or all tabs in order. Default copy to clipboard; dropdown to save to disk.
- Scroll position and click-highlighted data persist per tab and match the screenshot exactly.

## Design

### D1. Tool surface (on the existing kira-db server)

Proof tools register on `buildMCPServer` next to the DB tools: no new port, token, install step or agent config.
Agent already has kira-db installed for Studio work. Proof tools touch no connection, so DB MCP mode
(read-only/prompt) and the approval broker do not apply. Available whenever DB MCP is enabled; documented.

Five tools, all through `withPanicRecovery`, descriptions/args in llmprompts (`Apps: studioApp`, `Kind: KindTool`):

- `proof_start_session{name, summary?}` → `{draftId, name}`. Opens a new session draft.
- `proof_edit_session{name, reason}` → `{draftId, name, steps:[{ordinal, description, view}]}`. Opens an edit draft
  on a closed session; returns its current steps so the agent can reference them.
- `proof_add_step{draftId, description, query?, language?, source?, view?, data?, keepOrdinal?, replacesOrdinal?}`
  → `{ordinal}`.
  - `view`: `"table" | "document" | "keyvalue"`. Required unless `keepOrdinal` set.
  - `data` per view:
    - table: `{columns:[{name, type?}], rows:[[scalar|object|null, ...]]}`. `type` one of `number|text|boolean|
      temporal|json|other` (maps to `ColumnDescriptor.typeClass`; default inferred from first non-null value).
    - document: `{documents:[{id?, body: object}]}`. Missing `id` becomes the 1-based position.
    - keyvalue: `{entries:[{field, value}]}`.
  - `query`: text the agent ran (SQL, ES query DSL, CLI line). `language`: `sql|json|shell|text` (default `text`),
    picks Monaco highlighting. `source`: short label of the producing tool (e.g. `elasticsearch`).
  - Only in an edit draft: `keepOrdinal` copies an old step unchanged (no other payload fields allowed);
    `replacesOrdinal` marks the step as a changed version of that old step. Neither means added.
- `proof_close_session{draftId}` → `{name, steps, status: "closed" | "pending_review"}`. Rejects an empty draft.
- `proof_list_sessions{}` → `[{name, closedAt, steps, pendingEdit}]`, newest first. Lets the agent find a name to edit.

Why generic `view` + `data` instead of reusing the DB tools: the agent's data comes from any tool (Elastic, HTTP, logs);
it picks the view (SQL-like table for log hits that map to columns). Stream view excluded: `ConsoleResultGrid` has no
stream renderer, and log-like data fits table or document. "Plain data views only" holds: table, document, keyvalue.

Op log: proof calls write no op_log rows. Studio op_log is the adapter-op audit (what touched a database); a proof call
touches none. The proof session itself is the durable record of what the agent did.

### D2. Names, drafts, collisions

- Name: trimmed, 1–80 chars, no control characters. Uniqueness key `lower(trim(name))`, unique across every session row
  (open drafts included), enforced by a unique index.
- Collision on `proof_start_session` → `errResult`: `a proof session named "<name>" already exists (closed <time>);
  pick another name, or call proof_edit_session to change it`. Collision with an open draft: `... is still open`.
  Never auto-suffix: the agent must decide, so the user's history stays meaningful.
- `proof_edit_session` on an unknown name, an open (never closed) session, or one with a pending edit → error naming
  the reason. One pending edit per session.
- `draftId`: random UUID, opaque. Unknown or already-closed `draftId` → error.
- Abandoned drafts (never closed): purged when older than 24 h, at startup and on each `proof_start_session`. Drafts
  are invisible in the window and never notify.
- Concurrent open drafts capped at 5 (error beyond) so a looping agent cannot grow storage unbounded.

### D3. Order and ordinals

- Server assigns ordinals 1..n in commit order of `proof_add_step` per draft, inside one SQLite transaction
  (`MAX(ordinal)+1`). Parallel calls on one draft serialize; returned ordinal tells the agent the position.
- Display order = ordinal, everywhere: tab strip, compare list, "all tabs" screenshot.
- An edit draft is a full new ordered list. Old ordinals never shift inside the old revision.
- History list: newest `closed_at` first (the agent-facing `proof_list_sessions` uses the same order).

### D4. Edit, compare, accept

- Revision model: a session has `current_rev` and at most one `pending_rev`. Closing a new-session draft makes rev 1
  current. Closing an edit draft makes it pending (`status: "pending_review"`).
- Diff is provenance-based, not positional (an inserted step must not mark every later step changed):
  - new step with `keepOrdinal` → `unchanged`, paired with that old step;
  - with `replacesOrdinal` → `changed`, paired;
  - neither → `added`;
  - old step referenced by neither → `removed`.
  - A referenced old ordinal may be referenced once; a second reference → error.
- Window shows a pending session with a banner and the right-hand "Proposed change" pane (D9). Compare mode splits the
  centre into Old | New for the paired steps of the active tab; `added`/`removed` show one side with an empty-state
  on the other.
- Accept (`ProofService.AcceptEdit`): pending becomes current, old revision deleted (cascade), view state of
  `unchanged` steps copied to the new ordinals. Reject (`RejectEdit`): pending revision deleted. Both bump
  `updated_at` and emit `kira:proof:changed`.

### D5. Retention and delete

- Keep the 30 newest closed sessions by `closed_at`. Prune runs in the same transaction as each close of a
  new-session draft (an edit does not create a session). Open drafts never count and are never pruned by this rule.
- Pruning a session deletes its revisions, steps, view state (FK cascade) and dismisses its prompt if raised.
- Manual delete: `ProofService.Delete({sessionId})`, from the history list (hover trash button + context menu),
  behind the existing confirm dialog. Deletes a pending edit along with it. A deleted name becomes reusable.

### D6. Storage

Migration `apps/kira-studio/internal/storage/migrations/0046_p420_validation_proof.sql`, repo
`internal/storage/repos/proof.go`:

```sql
CREATE TABLE proof_sessions (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, name_key TEXT NOT NULL UNIQUE,
  state TEXT NOT NULL CHECK (state IN ('open','closed')),
  current_rev INTEGER, pending_rev INTEGER, summary TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL, closed_at TEXT, seen_at TEXT, updated_at TEXT NOT NULL
);
CREATE INDEX proof_sessions_closed ON proof_sessions(closed_at);
CREATE TABLE proof_revisions (
  session_id TEXT NOT NULL REFERENCES proof_sessions(id) ON DELETE CASCADE,
  rev INTEGER NOT NULL, draft_id TEXT UNIQUE, reason TEXT NOT NULL DEFAULT '',
  state TEXT NOT NULL CHECK (state IN ('draft','current','pending')),
  created_at TEXT NOT NULL, closed_at TEXT, PRIMARY KEY (session_id, rev)
);
CREATE TABLE proof_steps (
  session_id TEXT NOT NULL, rev INTEGER NOT NULL, ordinal INTEGER NOT NULL,
  description TEXT NOT NULL, query TEXT NOT NULL DEFAULT '', language TEXT NOT NULL DEFAULT 'text',
  source TEXT NOT NULL DEFAULT '', view TEXT NOT NULL CHECK (view IN ('table','document','keyvalue')),
  payload BLOB NOT NULL, payload_bytes INTEGER NOT NULL, diff TEXT NOT NULL DEFAULT 'added',
  origin_ordinal INTEGER,
  PRIMARY KEY (session_id, rev, ordinal),
  FOREIGN KEY (session_id, rev) REFERENCES proof_revisions(session_id, rev) ON DELETE CASCADE
);
CREATE TABLE proof_view_state (
  session_id TEXT NOT NULL, rev INTEGER NOT NULL, ordinal INTEGER NOT NULL, state TEXT NOT NULL,
  updated_at TEXT NOT NULL, PRIMARY KEY (session_id, rev, ordinal),
  FOREIGN KEY (session_id, rev, ordinal) REFERENCES proof_steps(session_id, rev, ordinal) ON DELETE CASCADE
);
```

`payload` holds the validated, normalized `data` JSON. Implementer confirms `PRAGMA foreign_keys=ON` on the Studio DB
(existing migrations rely on cascades; verify), else deletes children explicitly in the repo.

### D7. Limits and validation (Go, `internal/proof/validate.go`)

All enforced before any write; each violation → `errResult` naming field and limit. Decided once:

- description 1–200 chars, single line. summary/reason ≤ 500. source ≤ 64. query ≤ 64 KiB.
- table: 1–500 columns, column names non-empty ≤ 256, unique; rows ≤ 10 000 (`MAX_PAGE_SIZE`); each row length =
  column count; cell = JSON scalar/object/array/null, serialized ≤ 64 KiB (`MAX_CELL_BYTES`).
- document: ≤ 10 000 documents, body a JSON object, serialized ≤ 1 MiB each; ids unique strings ≤ 256.
- keyvalue: ≤ 10 000 entries, field ≤ 1 KiB, value serialized ≤ 64 KiB.
- step payload ≤ 4 MiB serialized; steps per revision ≤ 100; session total (current + pending) ≤ 32 MiB.
- MCP HTTP handler gets `http.MaxBytesReader` at 8 MiB (none today). Covers the 4 MiB payload plus JSON-RPC envelope
  with margin; existing tools send kilobytes.

Unicode is preserved; no HTML stripping is needed because nothing is ever rendered as HTML (D11).

### D8. Window lifecycle (Go)

- One proof window at a time, key `proof-<uuid>`. `ProofService.OpenWindow({sessionId?})`: if a proof window is live,
  focus it and `EmitTo` it `kira:proof:select {sessionId}`; else create a `windows` row (order max+1, like
  `OpenNewWindowKeyed`), stash the requested sessionId for the key, open via `shell.OpenWindow` cascaded from the
  current window, title `Validation proof` (i18n backend key) through the same title path Space's `OpenReviewWindow`
  uses; add a Studio equivalent if missing.
- `main.go` `wireWindowsAndMenu`: set `Ephemeral: proof.IsWindowKey` (prefix test) on `deps`; filter proof rows out of
  the startup list and delete them (purge, like Space `purgeReviewWindows`); assign the bridge's window opener hook
  the way `WindowsSvc.OpenNewWindow` is assigned. Ephemeral means never restored and never the last window, so
  closing the main window still quits per existing rules.
- `ProofService.WindowTarget({key})` → `{sessionId | null}` read once at boot by the proof window (initial selection).

### D9. Notification on close

- New router kind `KindProof = "proof"` in `internal/prompts` (additive), `Ref` = sessionId, `Title` =
  `i18n.T("backend.prompt.proof.title", {name})` (new or edited: separate key `backend.prompt.proofEdit.title`).
- Raised only by `proof_close_session` (D2 drafts never notify). Target: the focused workbench window, else any
  non-proof window, through Studio's `newPromptRouter` (OS notification when unfocused + `advanced.notifyPrompts`).
- Studio `App.vue` adds `proof` to `promptKinds`; `ProofReadyPrompt.vue` (shadcn `Dialog`, mirrors
  `DbMcpApprovalDialog.vue`) shows name, step count, "Open" (calls `OpenWindow`) and "Later" (dismiss).
- `seen_at` set when the session is opened in the proof window or the prompt is acted on. At startup, re-raise
  prompts for closed sessions with `seen_at IS NULL` or a pending edit (router persists nothing; same shape as Space
  `reopenHandoverPrompts`).

### D10. Bridge API (`apps/kira-studio/internal/bridge/proof.go`, `ProofService`)

`Sessions()` (history list: id, name, closedAt, steps, pending, seen), `Session({sessionId})` (header + step metas of
current and pending revisions with diff/origin), `Step({sessionId, rev, ordinal})` (full payload JSON),
`ViewState({sessionId, rev})` / `SetViewState({sessionId, rev, ordinal, state})`, `AcceptEdit`, `RejectEdit`,
`Delete`, `MarkSeen`, `OpenWindow`, `WindowTarget`, `SavePng({filename, pngBase64})`.

- `SavePng`: decodes base64 (≤ 64 MiB decoded), checks PNG magic, opens `Dialogs.SaveFile` (default dir
  `~/Downloads`, filename `<session>-<ordinal|all>.png` sanitized), writes only to the returned path; cancel → `{saved:
  false}`. Follows `FilesService.ChooseSave`.
- `SetViewState`: state JSON ≤ 64 KiB, schema-checked in Go (fields in D12).
- Events: `kira:proof:changed` (all windows, on close/accept/reject/delete/prune), `kira:proof:select` (proof window).
- Shared domain types: `packages/shared/domain/proof.ts` (zod schemas for `ViewState` and payloads, reused by the
  frontend parser).

### D11. Rendering and security

- Frontend builds a `Page` from the step payload with the shared builders (`createTabularPageBuilder` etc.) and stores
  it via `resultPages.setPage(proofPageKey)`; renders through `ConsoleResultGrid` with `connectionId = null` (no
  edit, no navigation into a connection; menus needing a connection already hide on null — implementer verifies).
- No `v-html` anywhere in the proof window. Values reach the DOM through Vue text interpolation, SlickGrid's existing
  escaping formatters (same path as DB data), and Monaco read-only models (text). Descriptions/names render as text.
- Payload is parsed with zod on the frontend before building pages (defense in depth; Go already validated).
- Screenshot capture runs on same-origin DOM only; no remote fetch.

### D12. View state and exact screenshot match

Persisted per step (`proof_view_state`), restored on every mount, debounced write (`useDebounceFn`, 250 ms):

```ts
{ queryScrollTop, resultScrollTop, resultScrollLeft,
  selection: Selection | null,            // table: SlickHybridSelectionModel ranges, active cell included
  selectedRow: number | null,             // document/keyvalue highlighted row
  expanded: string[],                     // document ids expanded
  columnWidths: Record<string, number> }  // table
```

- `ConsoleResultGrid`/`ConsoleSlickGrid` gain optional `viewState` prop + `update:viewState` emit + `ready` emit
  (after first render with state applied). Console callers pass nothing; behaviour unchanged. Table restore: column
  widths, then `viewport.scrollTop/Left`, then selection via `selectionFromRanges`; document: seed console view store
  expansion for the proof tabId, then scroller scrollTop, selected row; keyvalue: scrollTop + selected row.
- Match guarantee: the screenshot captures the live DOM of the step pane after `ready`. One-tab capture = exactly what
  is on screen. All-tabs capture activates each tab in order, the step view restores from the same persisted state the
  user sees, waits for `ready` + two animation frames, captures. A capture overlay sits outside the capture root.
- DOM clones lose scroll offsets. Capture hook (`onCloneEachNode` or equivalent in the chosen library) copies each
  scrolled source element's offsets onto its clone: clone gets `overflow:hidden` and its children
  `translate(-scrollLeft, -scrollTop)`. SlickGrid/virtual lists only mount visible rows, so the clone has the same rows
  the user sees.
