# P410 Task plus button: terminal or ad hoc Claude session in worktree

Plan for `docs/v0.2.23/SPEC.md` row P410. Base: `8ecbb2a`. Discovery ran through `codegraph_explore`.

One sequential Sonnet implementer. No stream split: engine method, bridge, bindings, frontend menu and
tests form one chain (the menu calls the new binding; the UI spec reads the flow test's contract).

## Terms

- **Target** = one branch of the task that has a worktree: `Branch.name !== ''` and
  `Branch.worktree !== ''` (board wire). Kind `mine` or `review` alike; `parked` never has one.
- **Ad hoc session** = interactive agent TUI in one target's worktree, opened with no first message.
  The user types the first prompt. Everything else matches a branch Start session.
- **Plus menu** = shadcn-vue `DropdownMenu` behind a `+` icon button; lists Terminal and agent-session
  items per target.

## Findings (current tree)

- **Branch Start session** (`internal/ade/launches.go:581` `StartBranch`): task lock; branch must be on a
  live task and named; refuses a second running TUI on the branch ("a session is already open on …") and a
  pending launch; `checkNoBackgroundRun` before and after `launchGate` (creates a missing worktree, refuses
  while setup is not ready, refuses while archiving); message = `args.Message` or `composeStartMessage`;
  then `prepareWithGrant(tr, tc, PrepareArgs{TaskID, BranchID, Cwd: path, Message}, "", "")`.
- **Grant** (`prepareWithGrant`, `launches.go:341`): no run → `RunOutcome`, `Handover`, all
  `agentmcp.SpaceToolIDs` (`task_info`, `declare_repos`, `request_branches`, `branch_status`,
  `report_artifacts`). Grant lives until the record stops.
- **No first message** already works end to end: `Tracker.Compose` (`tracker.go:409`) calls
  `WithPrompt` only when `intent.Message != ""`. No harness change needed.
- **Recording**: `Compose` inserts the `ade_sessions` row (mode `tui`, task, branch, step `""`, purpose `""`),
  fires `OnChange` (sessions push) and `OnStarted`. The row then shows in: Sessions tab strip
  (`AdeSessionsTab.vue`), card indicator (`board/taskSessions.ts` counts every non-review session), All
  sessions, dialog Send targets (`dialog/compose.ts` `runningTui`). Take over / Restart / resume work on it
  (`takeOverLocked` keeps `BranchID`). Archive closes it (`archive.go:248` `closeTaskTerminals`).
- **Frontend launch path**: `queries.ts` `useStartBranch` → `control.adeTaskStartBranch` →
  `useLaunchOpener().open(launch)` (tracks the tab in `adeTerminals`, opens the PTY with
  `launchKind 'agent'`) → `ui.openSession({taskId, branchId, sessionId})` selects it.
  Today the only Start UI is the branch `start` action → `dialogs.start` → session dialog with an edited
  or composed message; no way to open a blank session.
- **Terminals**: ADE has no shell tab surface; its panes show only ADE session TUIs. Plain terminals live
  in workbench tab strips. Git module already opens a terminal at a worktree:
  `RepoList.vue` worktree row menu → `openRepoTerminalTab(repo.id, wt.path)` (`state/repoTabs.ts:306`),
  which opens the repo workspace, switches mode to `git`, and opens a `terminal` tab (`launchKind 'shell'`).
  `RepoWorktreeRow.vue` then shows its terminal indicator (`terminalCountAtPath`).
- **Custom scripts** for a task already exist: task menu Run automation → `useRunAutomation().start` →
  shared run dialog → Automations tab. Not touched; the plus menu does not duplicate them.
- **Card head** (`plan/AdeTaskCard.vue`) already ends in toolbar icon buttons (`size-4.5`): Change base
  (a `DropdownMenu` when several choices) and Review code. Head is `v-if="!card.review"`.
- **Sessions tab** (`sessions/AdeSessionsTab.vue`): bar row (strip, stopped menu, actions) renders only
  when sessions exist; branch panel reuses it with `branchId`.
- **Shared pickers (P398)**: `ProjectPicker`/`BranchPicker` choose or create refs from candidate lists with
  search, create and custom entry.

## Design

### Decisions

1. **Where the button goes.** Two places, one component (`sessions/AdeTaskLaunchMenu.vue`):
   - **Task card head**, last icon after Review code. The row asks for a task button; the card is where
     the user is. Same pattern as Change base (icon trigger, `@click.stop`, dropdown `align="end"`).
     Rendered only when the task has at least one named branch; review cards have no head, so none there.
   - **Sessions tab bar row**, right end. This is the tab-strip "+" convention: new sessions appear in
     this strip. Task panel scope lists every target; branch panel scope lists only that branch.
     The bar row now renders whenever `!archived`, so the plus is reachable with zero sessions.
   - Not added: task panel action row (already 4 to 5 buttons; Sessions tab covers it), Later/Backlog
     shelf rows (compact queue entries; panel opens from them), task context menu (the plus is a focusable
     button, so keyboard reach exists). Mobile: out of scope.
2. **Worktree choice: grouped flat menu, not the P398 picker.** A task has one row per repo, so targets
   are few and known. P398 pickers solve search over large candidate lists plus create/custom entry;
   none applies here. Menu shape:
   - One target: two items, `Terminal` and `<Agent> session`.
   - Several: `DropdownMenuLabel` "Terminal", one item per target (`<repo> · <branch>`), separator,
     label "<Agent> session", one item per target. One click, no submenu.
   - A named branch without a worktree still lists, disabled, reason inline ("No worktree yet"), per the
     P398 rule that a disabled option shows its reason inline.
   - `<Agent>` is `useAgentInfo().info.productLabel` (provider-neutral; Claude Code today).
   - No task-wide "all worktrees" agent session: the manual step session (`LaunchStep`) already spans
     every repo via `--add-dir`. Kept out entirely.
3. **Terminal goes to the Git module**, via `openRepoTerminalTab(codeRepoId, worktree, launch)` with
   `launch = { command: '', kind: 'shell', label, color: 'none' }`, label from catalog
   `{task} · {branch}`. Reason: it is exactly the existing worktree-row "Open terminal" action, so the tab,
   repo workspace and terminal indicator already exist and stay consistent. No new IPC, no new Go code.
   ADE has no shell surface, and adding one (a non-agent session kind) is far beyond this row.
   Archive does not close such a shell; same as a Git-module worktree terminal today. Kept out.
4. **Ad hoc session = new engine method `StartAdHoc`, not a flag on `StartBranch`.** Shared helper keeps
   every Start rule. Refactor `StartBranch` body into
   `startBranchLocked(ctx, branchID string, message func(tc *taskCtx, sb model.AdeTaskBranch, path string) string) (adewire.Launch, error)`
   (lock taken inside, as today). `StartBranch` passes `args.Message` or `composeStartMessage`;
   `StartAdHoc` passes `func(...) string { return "" }`.
   - Same refusals as Start: one running TUI per branch, pending launch, background run, setup not ready,
     archiving, unnamed branch, branch not on a live task. Reason: two agents in one worktree conflict;
     the user can open the running one instead.
   - Wire: reuse `adewire.BranchArgs{BranchID}`; returns `adewire.Launch`. Bridge
     `AdeTaskService.StartAdHoc` validates with `validateAdeItemID(args.BranchID, "branchId")`, maps
     errors through `adeTaskError`.
5. **Recording: no new state.** Row is identical to a Start session (purpose `""`, step `""`, branch set).
   It shows in the Sessions tab, card indicator, All sessions and as a dialog Send target; Take over,
   Restart, resume-archived and archive close work unchanged. Tab name follows `sessionView`
   (`<agent session name> · <repo>`). No `purpose` value (`adhoc`) and no migration: the only difference
   from Start is the first message, which is not state. Later ops (P415) read the same row like any session.
6. **MCP and Space tools: yes, same grant as Start.** `prepareWithGrant` with no run: `run_outcome`,
   `handover`, Space tools (incl. `request_branches`, `report_artifacts`). Reasons: P408 made Space tools
   always on for every task session; an ad hoc session works in the task's worktree, so its handover notes
   and reported artifacts belong to the task (P407 grants `handover` to every task session without a run;
   P409 `report_artifacts` is in `SpaceToolIDs`). `Grant.StepID` stays `""` as for Start, so a handover
   records on the current stage without the moved-on check.
7. **No first message means no composed task context.** The agent learns the task through `task_info`
   and tool descriptions. That is the point of "ad hoc": the user drives.
8. **Disabled states.**
   - Archived task: no plus (archived panel's Sessions tab passes `archived`; board history rows are not
     `AdeTaskCard`). Server also refuses (`branch … is not on a live task`).
   - Card: hidden when no branch is named. Shown, disabled with tooltip "No worktree yet" when names exist
     but no worktree.
   - Sessions bar: always shown on a live task; disabled with the same tooltip when no target.
   - Per item: no worktree → both items disabled, reason "No worktree yet". Agent item only: setup
     `running` → "Preparing worktree"; setup `failed` → "Setup failed"; a running TUI on the branch
     (from the sessions query, `mode === 'tui' && state === 'running' && branchId === b.id`) →
     "Session open". Terminal stays enabled while setup runs (useful to watch).
   - Server refusals that the client cannot see (background run, pending launch, archiving race) land in
     `ui.actionError[taskId]` with `ui.select(taskId)`, as `useTaskMenu.fail` does.
9. **After an agent launch**: `useLaunchOpener().open(launch)`, then
   `ui.openSession({ taskId, branchId, sessionId: launch.sessionId })` (branch panel Sessions tab, session
   selected). Mutation `isPending` disables the trigger while starting.

  `DropdownMenuLabel`, `DropdownMenuItem` (`@select`), `DropdownMenuSeparator`. Disabled item shows reason

- `plan/AdeTaskCard.vue`: menu after Review code, `v-if` any named branch.
- `sessions/AdeSessionsTab.vue`: bar row `v-if="!archived"`; strip and stopped menu keep their own
  `v-if`s; menu at the right end with `ml-auto` (`size="bar"`, `branchId` passed through).
- i18n (`packages/theme/src/i18n/en.json`, under `space.ade.taskLaunch`; follow catalog rules C1-C11 for
  suffixes; reuse an existing key when wording matches, e.g. `common.newTerminal.label`):
  trigger tooltip/aria "New terminal or agent session", terminal item "Terminal", agent item
  "{agent} session", group labels, target "{repo} · {branch}", terminal tab label "{task} · {branch}",
  reasons "No worktree yet", "Preparing worktree", "Setup failed", "Session open". No concatenated
  translations (U64-U71).
