# P416 Move automation runs into Operations panel

Plan for `docs/v0.2.23/SPEC.md` row P416. Base: `1cec029` (P415 Part 1 done). Discovery ran through
`codegraph_explore` (run queries, `RunsSection`, `RunOutcomeBlock`, `TerminalTabView` tail, `scriptruns` service,

## User ask

"Historical runs, success or failed, live in the Operations panel. Automation panel keeps only running ones.
Persist errors; keep copy."

Do not rename Automations to Runs here (v0.2.25 P438 does that).

## Findings (current tree)

  `App.vue` root, above `WorkbenchShell`, so the Operations dock can inject it).
- History UI today: `runs/RunsSection.vue`, mounted at the bottom of `AutomationsPanel.vue:552`. Collapsible
  section, filter tabs All/Running/Failed (`runs-filter-*`), every run row, inline `RunOutcomeBlock` for terminal
  runs, tab open for smart and headless runs, Stop on running rows.
- `RunOutcomeBlock.vue`: reason, summary, cost, denials, exit code, `lastError`, Copy for agent
  (`runReportText(run, tail)`), Resume, Run again. Also used by `TerminalTabView.vue` (compact, live xterm tail),
  `ScriptRunView.vue` (smart run tab) and Space `ade/v2/automation/AdeAutomationsBlock.vue`.
- Data: `script_runs` per app DB, owned by root `internal/scriptruns`. Newest 500 finished kept (`keepFinished`),
  logs in `script_run_logs`. Frontend `useScriptRuns` (`['scriptRuns','list']`, `LIST_LIMIT` 200), patched by
  `kira:scriptRuns:changed`. `RunsStatusItem.vue` counts running runs; click opens the Runs section.
- Error persistence gap: a terminal script run stores only `outcome` from `runoutcome.ForProcess` ("exited with
  status 3"). Its output lives only in the xterm buffer; Copy for agent reads `tailTerminal(tabId, 40)`. Once the tab
  closes or the app restarts, the error text is gone. Headless runs keep `script_run_logs` plus `lastError` (last

- `terminal.BoundService.Open` taps output only for agent sessions (`Arbiter.Output`); script sessions get `OnEnd`

- `apps/kira-space/internal/gitprepare/output.go` has the repo's only ANSI stripper and line sanitizer
  (`stripANSI`, `sanitizeLine`).
- Operations panel: shared `OpLogPanel.vue` (generic `R extends OpLogRecord`) plus `createOpLogStore`; Studio
  `workbench/panels/OperationsPanel.vue` over `OpRecord` (DB ops, Re-run), Space `workbench/OperationsPanel.vue`
  over `SpaceOpRecord` (P415). Studio `op_log` and Space `op_log` are different tables and shapes.
- Mobile (Space phone web) has no runs list and no Operations panel.

## Design

### 1. Storage: `script_runs` stays the one store (no op_log rows)

Automation rows in the Operations panel are a projection of `script_runs`, not copies in `op_log`.

Reasons (P415's plan floated `category automation` in Space `op_log`; declined):

- Both apps show Automations. Studio `op_log` is DB-op shaped (`opKindSchema`, connection, rows, Re-run replays
  SQL). Writing runs into two different op logs means two writers and two retention rules for one fact.
- `script_runs` already holds everything the panel needs (state, outcome, trigger, task, resume, log) and is the
  key for Resume, Run again, Open run and the run log. A copy would need sync on every state change.
- Space `internal/oplog` and its migrations are P415 Part 2's files in the parallel run.

Retention: the panel shows what `script_runs` keeps (500 finished, plus live), loaded newest 200 (`LIST_LIMIT`,
same as the op log's `HYDRATE_LIMIT`). Op rows keep their own retention. Clear hint text states both.

### 2. Persist errors: output tail on the outcome

- `internal/runoutcome/outcome.go`: `Outcome.OutputTail string \`json:"outputTail,omitempty"\`` and
  `WithOutputTail(s string) Outcome` (cap 8 KiB, rune-safe, keeps the end). Lives in `outcome_json`, so no
  migration in either app; ADE `ade_runs.outcome_json` is unaffected (omitempty, never set there).
- New root package `internal/termtext` (move, not new code): `stripANSI` and `sanitizeLine` from
  `gitprepare/output.go`, exported as `SanitizeLine`. `gitprepare` imports it; its local copies go. Add
  `Tail{maxBytes}` ring (raw bytes, 64 KiB) with `Write(b)` and `Lines(n int) string`: split on `\n`, a `\r` inside a
  line keeps only the text after the last `\r` (progress redraws), `SanitizeLine` per line, drop a partial
  leading line, last `n` non-empty lines. Library check: `charmbracelet/x/ansi` (MIT) strips escapes but does no
  line or `\r` handling; the repo's own tested stripper already exists, so moving it removes a duplicate instead of
  adding a dependency.
- `internal/terminal/bound.go`: `ScriptLauncher` gains `Output(terminalID string, b []byte)` (must not block).
  `Open` taps script sessions: when `scriptRun != ""`, tap calls `b.Scripts.Output`; when both agent and script
  taps exist, call both.
- `internal/scriptruns/service.go`: `tails map[string]*termtext.Tail` under its own mutex. `Begin` registers one
  for the terminal id (not for the blocked-folder failure). `Output` appends. `Exited` takes and deletes it; when
  the outcome status is `failed`, `WithOutputTail(tail.Lines(40))`. `Failed` deletes it. Done, cancelled and
  skipped runs store no tail. `Recover` stores none (process gone).
- `internal/scriptruns/logs.go` + `headless.go`: `logSink` keeps the last 40 added lines (ring of strings);
  headless finish applies `WithOutputTail` on a failed outcome beside `WithLastError` (`headless.go:117`).
  Smart runs unchanged (log plus `lastError`).
- Frontend `packages/shared/domain/runOutcome.ts`: `outputTail: z.string().optional()`.
- Copy keeps working after the tab is gone: `runReportText(run, tail)` uses the live tail when non-empty, else
  `run.outcome?.outputTail`. `RunOutcomeBlock` shows `outputTail` under `lastError` (not compact).

### 3. Automation rows in the Operations panel (both apps)

New `packages/workbench/src/automations/runs/runOps.ts`:

```ts
export interface AutomationOp extends OpLogRecord {
  kind: 'automation';
  run: ScriptRun;
}
export function isAutomationOp(r: OpLogRecord): r is AutomationOp;
export function automationOp(run: ScriptRun): AutomationOp;
```

Mapping (`automationOp`):

- `id`: `run:<run.id>` (no clash with op ids in `expandedId` or `data-op-id`).
- `startedAt`: ISO of `run.startedAt ?? run.createdAt`. `durationMs`: `runElapsedMs` for ended runs, null while
  live.
- `status`: running, waiting → `running`; done → `ok`; failed, blocked → `error`; cancelled, skipped → `cancelled`.
- `command`: `run.command` for a script, `run.prompt` for a smart run.
- `error`: `outcome.reason`, then `lastError` on a new line when set; null for done.

New composable `packages/workbench/src/automations/runs/useAutomationOps.ts`, used by both panels:

- Input: the app's op store (`filterText`, `statusFilter`, `clearedAt`). Rows from `useScriptRuns()`.
- `merge(ops)`: automation rows filtered with the store's own predicate (below) and `clearedAt`, merged into the
  newest-first op list by `Date.parse(startedAt)` (two sorted lists, linear merge).
- `runningCount`: live runs count, added to the store's `runningCount` for the panel.
- `statusNote(op)`: run state label (`stateLabel`) when it differs from the op status word (waiting, needs you,
  skipped), plus "scheduled" or "task <title>" trigger text.
- `detailLines(op)`: summary, cost, denials, exit code, then each `outputTail` line (tone error). One line each.
- `canCancel(op)`: running or waiting. `cancel(op)`: running → `runs.stop`, waiting → `runs.confirmDecline`.
- `menuFor(op)`: `opLogMenuItems` (Copy command, Copy error, Cancel) plus: Copy for agent (`runReportText`, uses
  `outputTail`, `copyAndAnnounce`), Open run (smart, headless or a run whose terminal tab is still open:
  `ctx.showAutomations()` then the `scriptTabs` placement used by `RunsSection.toggle` today), Resume when
  `run.resumable` (`useResumeScriptRun`), Run again when `run.scriptId` (`useRerun`).

`createOpLogStore.ts`:

- Export the filter predicate as a pure function `opLogMatches(record, filterText, statusFilter, extraText)`;
  `visibleOps` uses it. `useAutomationOps` reuses it, extra text = script name, task title, trigger.
- `clearedAt` state (ms, 0 at start); `clearOps` sets it to `Date.now()` and empties records as today.
  Automation rows started before it stay hidden in this window (renderer-only, same as op Clear).

Studio `workbench/panels/OperationsPanel.vue`:

- `records` = `auto.merge(opsStore.visibleOps)`; `running-count` adds `auto.runningCount`.
- `menuFor`, `canCancel`, `statusNote`, `detailLines`, `@cancel` branch on `isAutomationOp`; DB-only actions (reveal
  tab, Re-run, preconnect note) never see an automation row.
- Cells for an automation row: connection column shows the script name, source shows the trigger label, tab and
  rows empty, kind `automation`.

Space `workbench/OperationsPanel.vue`:

- Same merge and branches. Cells: module `automations`, source the trigger label, subject task title or script name
  (tooltip: `cwd`), kind `automation`. Steps and Copy details stay for op rows only (automation rows have Copy for
  agent instead).
- `background` lane rules never apply to automation rows (always foreground).

Clear hints: `space.operations.clearHint.hint` and `studio.operations.clear.hint` gain one sentence: automation runs
come from the run history (newest 500 kept); Clear hides them in this window only.

### 4. Automations panel keeps only live runs

`RunsSection.vue` becomes the live list:

- Rows: runs with state `running` or `waiting`, newest first. Heading "Running" with count; collapsible state key
  `kira.automations.runsOpen` stays (status bar item still opens it).
- Remove: filter tabs and `FILTER_ITEMS`, the inline `RunOutcomeBlock` expansion, `expanded`, `rerun` emit (and
  `AutomationsPanel.vue`'s `@rerun` handler if nothing else uses it).
- Row click: smart, headless or waiting run → open its run tab (today's `toggle` branch); terminal run → focus its
  terminal tab through the same `scriptTabs` placement. Stop stays.
- Empty state: one line "No automation is running. Finished runs are in Operations." plus a "Show history" button
  calling new `AutomationsModuleContext.showOperations()` (each app's `workbench/automationsModule.ts` sets
  `panel.operations.visible` true through its layout store; add a `showOperationsPanel()` beside
  `toggleOperationsPanel` in `createLayoutStore.ts` if no setter exists).
- `RunsStatusItem.vue` unchanged in behaviour.

Kept, not moved (task context, not the Automations panel): Space ADE `AdeAutomationsBlock.vue` and
`AdeAutomationChip.vue` (task runs), `ScriptRunView.vue` (run tab), `TerminalTabView.vue` outcome strip.

## Tests
