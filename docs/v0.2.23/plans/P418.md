## User ask

- Review window also shows uncommitted changes, reviewable like committed ones (comments, hunk checks).
- Clear separation between committed and uncommitted work.
- Agent panel in the review window is off by default.

## Design

### D1. Agent panel default off

`adeReviewWindow.ts`: default `false`, same key. Users who never toggled get the new default; an explicit stored
choice still wins. No key rename: renaming would also discard a deliberate "on". Update the store comment.

### D2. Hunk identity for uncommitted work

Same model as committed review, separate records. A check is a set of line ranges in the coordinates of a content
snapshot taken at mark time; a hunk is checked when its change block is fully covered after projection. No hunk id is
stored, so edits need no id matching:

- Worktree file unchanged since the mark (content hash equal): ranges apply as stored.
- Changed: `git diff --no-index snapshot current` (the same spawn `FileDelta` tier 2 already uses), then
  `gitreview.ProjectRanges`. Edited lines drop out, so a touched hunk re-opens; untouched hunks keep their check even
  when lines shift.

Why separate records, not the committed `review_file` row: one row per `(session, path)` holds one snapshot. Marking
working content would replace the committed snapshot, and lines reviewed at the tip but edited in the worktree would
regress to unreviewed in the committed view. Two records keep the two reviews independent ("clear separation").

Content hash, not git blob OID: working content is never a git object; `sha256` of the bytes needs no spawn and no
object-format awareness. Column named `content_hash` so nobody mistakes it for an OID.

Content kinds mirror committed: text up to `gitreview.MaxSnapshotBytes` (1 MiB) stores content; `binary`,
`tooLarge`, `absent` (deleted in worktree) take whole-file marks only (`ErrRangedMarkOnNonText` equivalent).

### D3. Uncommitted comments and stale handling

`review_comment` gains `origin` (`commit` | `working`) and `anchor_content` (flate, text only, NULL for commit
origin). A working comment stores the worktree content it was written against, `anchor_sha` = worktree HEAD at write
time (informational), `anchor_blob_oid` = the content hash.

Anchoring against the worktree (`ReviewWorkingComments`): hash equal, `exact`; else diff `anchor_content` vs current
content and `ProjectRanges`, `projected` or `removed`. Working tabs paint only `exact`/`projected` working-origin
comments. `removed` ones stay listed (Comments pane, forward, copy) until the user deletes or addresses them: an open
comment never vanishes silently.

Anchoring against a commit (`review.comment.list`, the existing path): `anchorOne` must branch on origin. A
working-origin comment never runs the commit tiers (its range is in worktree coordinates; `diff anchor_sha..at` would
mis-project it). It returns new anchor value `uncommitted` with its stored range. Committed tabs skip it; the Comments
pane shows it with an "Uncommitted" badge.

One comment list per branch session stays: forward, copy text, workflow review rounds, MCP review tools and
archive/restore keep reading `Comments`/`OpenComments`. They gain the origin; nothing else forks.

### D4. Promotion when uncommitted work gets committed

Without it, a hunk checked while uncommitted shows unchecked once the agent commits it, and comments stay labelled
uncommitted forever. `RepoEntry.PromoteWorkingReview(ctx, branch) (paths []string, err)`, per path holding
`Store.Lock(repoID, branch, path)` (the committed lock key, so working marks, committed marks and promotion on one
path serialize):

1. Marks: T = tip content of path, W = working snapshot. `landed = ProjectRanges(W ranges, diff(W, T))`. Non-empty:
   `markFileAt(tip, ..., reviewed=true, landed)` (unions into the committed record at the tip). Then remove what
   landed from the working record: `back = ProjectRanges(landed, diff(T, W))`, `W ranges = Subtract(W ranges, back)`;
   delete the record when empty. A second run finds nothing left, so an unmark made in the committed view after
   promotion sticks.
2. Comments: a working comment whose range projects non-empty into T becomes `origin = commit`, `anchor_sha = tip`,
   `anchor_blob_oid = tip blob OID`, range = projected range, `anchor_content = NULL`, one transaction per comment.
   Other working comments stay.

Equal content (exact commit) skips the diff (byte compare). Non-text W or T: whole-file records promote only when
W's hash equals T's content hash; comments need text.

Trigger, explicit and idempotent, not in the git watcher (agent commits happen outside the app and the review window
already re-reads on every commit):

- `TaskBoard.ReviewWorking` runs promotion first; its result gains `promoted: string[]`. The window already calls it
  on board push (commit, stage), focus and agent `Stop`/`PostToolUse`.
- `OpenReviewWindow` and `forwardMessage` (forward, copy text) run it too, so a forward after a commit sent with the
  window closed labels nothing wrongly.

Frontend: `AdeReviewFiles.vue` watches `promoted`; non-empty calls `api.refresh()` and fires repaint `mark` (commit
scope, those paths) and `comments`.

### D5. Persistence (review.db, not the app DB)

New `apps/kira-space/internal/gitreview/migrations/0005_p418_working.sql`. App DB migrations (latest `0060`) untouched.

```sql
CREATE TABLE review_working_file (
  session_id   INTEGER NOT NULL REFERENCES review_session(id) ON DELETE CASCADE,
  path         TEXT    NOT NULL,
  state        TEXT    NOT NULL,          -- 'full' | 'partial'
  head_sha     TEXT    NOT NULL,          -- worktree HEAD at mark time; '' for an unborn HEAD
  reviewed_at  INTEGER NOT NULL,          -- unix millis
  content_hash TEXT    NOT NULL,          -- sha256 hex of the worktree bytes; '' when absent
  content_kind TEXT    NOT NULL,          -- 'text' | 'binary' | 'tooLarge' | 'absent'
  content_bytes INTEGER NOT NULL,
  line_count   INTEGER NOT NULL,
  content      BLOB,                      -- flate(raw); NULL unless text
  PRIMARY KEY (session_id, path)
);
CREATE TABLE review_working_range (
  session_id INTEGER NOT NULL,
  path       TEXT    NOT NULL,
  start_line INTEGER NOT NULL,
  end_line   INTEGER NOT NULL,
  PRIMARY KEY (session_id, path, start_line),
  FOREIGN KEY (session_id, path) REFERENCES review_working_file(session_id, path) ON DELETE CASCADE
);
ALTER TABLE review_comment ADD COLUMN origin TEXT NOT NULL DEFAULT 'commit' CHECK (origin IN ('commit', 'working'));
ALTER TABLE review_comment ADD COLUMN anchor_content BLOB;
```

Existing rows default to `commit`: correct, every stored comment today was written against a commit. Reaper, `Purge`
and session delete cascade to the new tables. Pinning unchanged. `normalizeStoredPaths` (`normalize.go`) must also
rekey `review_working_file`/`review_working_range` paths; read it and extend in the same pattern.

Store API (`gitreview`): `WorkingRecord(ctx, repoID, branch, path) (FileRecord-like, content, found, err)`,
`WorkingRecords(ctx, repoID, branch)`, `PutWorking`, `DeleteWorking`; `Comment` gains `Origin`, `AnchorContent`;
`AddComment` writes both (compressing content); `PromoteComment(ctx, repoID, branch, id, anchorSHA, blobOID, rng)`.
Reuse `FileRecord` with a `HeadSHA`/`ContentHash` pair only if it stays readable; otherwise a `WorkingRecord` struct.

Archive snapshot (`ade/reviewcomments.go` `storedComment`): add `origin` and `anchorContent` (`[]byte`, base64 in
JSON) so archive, detach and restore keep working comments intact; `restoreRowComments` passes both to `AddComment`.
Older snapshots decode with empty origin, treated as `commit`.

### D6. Diff source and IPC (Go)

Path safety stays in ade: the worktree comes from the branch row, never the caller (as `ReviewWorkingDiff`). ade
reads both sides with `codeworkspace.ReadDiffAt` and hands bytes plus kind to gitsession; gitsession owns review
logic and git spawns. Mapping: `found` within 1 MiB is text, `found` above is `tooLarge`, `binary`, `missing` is
`absent`.

gitsession (new `internal/gitsession/working_review.go`):

- Extract `contentDelta(ctx, old, new []byte) (hunks, body, rawBytes, err)` from `FileDelta` tier 2 (temp files,
  `NoIndexDiffArgs`, `parseAndResolve`). Callers: `FileDelta` tier 2, working diff, working projection, promotion.
  One helper, no second diff path.
- `WorkingFileReview(ctx, branch, path, head, cur WorkingContent) (WorkingFileReviewResult, error)`: body = hunks of
  head vs cur, `reviewedRanges` projected from the working record, `lineCount`, `contentKind`.
- `MarkWorkingFile(ctx, branch, path, cur WorkingContent, headSHA string, reviewed bool, ranges []LineRange)
  (ReviewFileStatus, error)`: `nil` ranges = whole file, same union/subtract/`normalizeState` rules as `markFileAt`.
- `WorkingReviewStates(ctx, branch, files map[path]WorkingContent) map[path]ReviewFileStatus`: same rule as
  `reviewFileStatus` (`incremental.go:71`), `changedSinceReview` = hash differs.
- `AddWorkingComment(ctx, branch, path, cur WorkingContent, headSHA, rng, body, kind) (CommentEntry, error)`: text
  only, range bounded by line count (`ErrCommentNotText`, `ErrCommentRangeOutOfFile`).
- `ListWorkingComments(ctx, branch, contents func(path) (WorkingContent, error)) ([]CommentEntry, error)`.
- `PromoteWorkingReview` (D4). `anchorOne` origin branch (D3). `CommentEntry` gains `Origin`.
- `gitreview.FormatComments`: `uncommitted` anchor appends `  [uncommitted; lines as of the worktree]`.

ade (`internal/ade/review.go`, new `review_working.go` if `review.go` grows past lint limits): `ReviewWorkingFile`,
`ReviewWorkingMark`, `ReviewWorkingComments`, `ReviewWorkingCommentAdd`; `ReviewWorking` adds per-file `review` and
`promoted`. Each loads via `reviewWorktree`, refuses a branch without worktree, validates the path with
`codeworkspace.ValidateRelPath`.

Bridge (`internal/bridge/adetask.go`, `adewire/wire.go`), all on `AdeTaskService`:

| Method | Args | Result |
| --- | --- | --- |
| `ReviewWorkingFile` | `ReviewWorkingDiffArgs` | `ReviewWorkingFileReview{path, body, reviewedRanges, lineCount, contentKind}` |
| `ReviewWorkingMark` | `ReviewWorkingMarkArgs{branchId, paths, reviewed, ranges?}` | `ReviewWorkingMarkResult{files[{path, review}]}` |
| `ReviewWorkingComments` | `BranchArgs` | `ReviewWorkingCommentsResult{comments}` |
| `ReviewWorkingCommentAdd` | `ReviewWorkingCommentAddArgs{branchId, path, range, body, kind}` | `ReviewComment` |

`ReviewWorking` gains `files[].review` (wire: `ReviewWorkingFile{change, review}` or a parallel `reviews` map; pick
the shape that keeps `porcelain.FileChange` reuse simple) and `promoted`. Validation: ids via `validateAdeItemID`,
path non-empty, `ranges` only with exactly one path, each range `start >= 1`, `end >= start`, at most 256 ranges,
body trimmed non-empty and `<= gitreview.MaxCommentBytes` after `\r\n` normalisation (reuse the git-rpc rule), kind
`change|question`, `paths` non-empty, at most 1000. Edit, setState and remove of a working comment use the existing
id-scoped `review.comment.*` git-rpc calls: no new methods.

Agent prompts (`internal/llmprompts/registry.go`): `ReviewCommentVar` gains `Uncommitted bool`; default templates at
the two `{{range .Comments}}` sites render ` (uncommitted)` after `{{.Lines}}`. Custom user prompts without the field
keep working. Add one uncommitted comment to the registry sample; regenerate goldens under
`internal/llmprompts/testdata/golden/`. `commentVars` sets it from `Origin`.
