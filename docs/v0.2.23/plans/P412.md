# P412 Review: stale-changes indicator, PR link in review agent prompt

Plan for `docs/v0.2.23/SPEC.md` row P412. Base: `f316cf2`. Discovery ran through `codegraph_explore`.

## User ask

"In the review window, i should see if the changes are stale. The check is done before approving a pr, so i d
want to have the indicator present there to know. And the prompt for the review agent should have the pr link
too."

## Findings (current tree)

### Where the stale check lives

- Backend: `gitsession.RepoEntry.ChangeRequestReviewState` (`internal/gitsession/crreview.go`) reads the host's
  current head (`ReviewTarget` → `HeadSha`) and the local branch tip (`branchTip` → `LocalHeadSha`, `""` when the
  branch is gone). Served as git-stream `changeRequest.reviewState` (`gitrpc/changerequests.go`
  `handleChangeRequestReviewState`, wire `gitrpc.ChangeRequestReview`, TS `ChangeRequestReviewState` in
  `packages/git-ipc/src/contract.ts`). Every field the indicator needs is already on the wire.
- Frontend: `review/useChangeRequestReview.ts` owns the TanStack query (key
  `['changeRequestReviewState', gitRepoId, branch, number]`, `staleTime: 60_000`, `refetchOnWindowFocus`).
  `AdeReviewActions.vue` (title bar) and `AdeReviewSubmitDialog.vue` share it.
- The "check before approve" is `AdeReviewSubmitDialog.vue` `headDiffers`: `mode !== 'conversation' &&
  localHeadSha !== '' && localHeadSha !== headSha`. The dialog refetches on mount and renders a warn `Alert`
  (`ade-review-submit-head`, text `space.ade.review.actions.headDiffers.hint`, local sha → host sha via
  `Identifier`). It shows only after the user opens Approve/Comment/Request changes. Nothing up front.
- Header: `AdeReviewHeader.vue` left group has title, repo tag, branch, base and the uncommitted `Badge`
  (`variant="warn"`, `Tooltip`). Right group renders `AdeReviewActions`.

### What "stale" means here

Local branch tip ≠ change request head on the host. The window reviews the local branch; a submitted review
applies to the host head (`commit_id`). So a mismatch means what the user reads is not what they approve:
either local has unpushed commits or the host moved on (someone pushed, local not fetched).

Direction (ahead/behind) is out of scope: the host head is often absent locally until a fetch, so a direction
would need a fetch or a third "unknown" state. The ask is to see the existing check up front; the sha pair
already says which commits differ.

### Refresh signals available

- Query: mount, window focus, 60 s staleness.
- `repo.changed` git-stream event (`kind: 'refsChanged'`) fires on local commit, pull, fetch (also auto-fetch).
  The files pane already reloads on it. Subscribable via `gitTransportFor(codeRepoId).on('repo.changed', …)`;
  the lease's `dispose()` releases it. A refsChanged reload is exactly "local tip or remote-tracking ref moved".
- No polling in the review window (ARCHITECTURE "Review code" bullet on uncommitted queries). Keep that rule.

## Design

### 1. Stale indicator (frontend only, no wire change)

Shared rule, `review/useChangeRequestReview.ts`:

```ts
/** The local branch tip differs from the head the host reviews. False when the branch is gone locally. */
export function headStale(s: OkState): boolean {
  return s.localHeadSha !== '' && s.localHeadSha !== s.headSha;
}
```

`AdeReviewSubmitDialog.vue` `headDiffers` becomes `props.mode !== 'conversation' && headStale(live.value)`.
One rule, two surfaces.

New composable `review/useReviewHead.ts` (`useReviewHead(target: () => ReviewWindowTarget)`):

- Reads `useChangeRequestReview(target).state` (same query key: no extra request).
- Returns `head: ComputedRef<{ state: 'current' | 'stale'; local: string; host: string; short: string } | null>`.
  `null` unless data is `kind: 'ok'`, `state === 'open'`, `localHeadSha !== ''`. `short` from `hostWords`.
- Refresh: `const lease = gitTransportFor(target().codeRepoId)`; `lease.on('repo.changed', p => …)` where
  `p.repoId === target().gitRepoId && p.kind === 'refsChanged'` calls a `useDebounceFn` (VueUse,
  `TIMING.fileSettle`) that runs `state.refetch()`. `tryOnScopeDispose(() => lease.dispose())`. Other
  refreshes stay as is (mount, focus, 60 s). No polling. While refetching, the last value stays (TanStack
  keeps data), so no flicker and no spinner.

States:

| reviewState | indicator |
|---|---|
| loading, error, `disabled`, `none`, `unavailable` | none (Review button already explains) |
| `ok`, state not `open` (merged/closed) | none |
| `ok`, open, `localHeadSha === ''` | none (nothing local to compare) |
| `ok`, open, equal | `current`: `Badge` default variant, `check` codicon, "At {short} head" |
| `ok`, open, differ | `stale`: `Badge variant="warn"`, "Stale" |

`AdeReviewHeader.vue`: after the uncommitted badge, a `Tooltip` + `TooltipTrigger as-child` + `Badge`
(`tabindex="0"`, `wails-no-drag shrink-0`, `:aria-label` = tooltip sentence, `data-testid="ade-review-head"`,
`:data-state="head.state"`). Same recipe as the uncommitted badge. Tooltip:

- stale: `space.ade.review.actions.headDiffers.hint` (reused, same sentence as the dialog), then a row
  `Identifier(local) → arrow-right codicon → Identifier(host)` with `shortSha` (dialog markup).
- current: `space.ade.review.header.headCurrent.hint` + `Identifier(host)`.

i18n (`packages/theme/src/i18n/en.json`, pseudo if generated by script):
`space.ade.review.header.stale.label` "Stale", `space.ade.review.header.headCurrent.label` "At {short} head",
`space.ade.review.header.headCurrent.hint` "Your local branch is at the {short} head.".

Libraries: TanStack Query (existing query), VueUse (`useDebounceFn`, `tryOnScopeDispose`), shadcn-vue
`Badge`/`Tooltip`, Tailwind classes only, `<script setup lang="ts">`. No Pinia store: no new client state; the
query cache is the shared state.

### 2. PR link in review agent prompts

llmprompts (`internal/llmprompts/registry.go`):

- `RepoLineVars` adds `ChangeRequestURL string \`json:"changeRequestURL"\`` with comment "review messages
  only" (precedent: `repoLine.Base`).
- `ReviewRoundVars` adds the same field.
- `ade.review.message` repo line becomes:
  `{{if .ReadOnlyRoot}}- {{.Repo}}: read only, in {{.ReadOnlyRoot}}{{else}}- {{.Repo}}: {{.Branch}} (base
  {{.Base}}) worktree {{.Worktree}}{{end}}{{if .ChangeRequestURL}}, PR {{.ChangeRequestURL}}{{end}}`.
- `ade.review.round.message`: after the `Repo …, worktree ….` line add
  `{{if .ChangeRequestURL}}\nPR {{.ChangeRequestURL}}{{end}}` (own line: no trailing period glued to the URL).
- Wording "PR": agent-facing; the URL itself names the host. No host-word var.
- Examples: `ReviewVars` example first repo and `reviewRoundExample` get
  `ChangeRequestURL: "https://github.com/acme/kira-space/pull/42"`.
- `golden_test.go`: `ade.review.message.full` repo 0 and `ade.review.round.message.full` carry a URL; `minimal`
  stays without (covers absent). Regenerate: `go test ./internal/llmprompts -run TestGolden -update`. The
  shared `repos` slice also feeds other cases; give the URL only to the review case (copy) so unrelated goldens
  do not churn.
- `budget.tsv`: raise `ade.review.message` and `ade.review.round.message` to the measured rendered size (the
  budget test prints it). Visible line change, per the ratchet.
- i18n: `llmPrompts.var.changeRequestURL.description` "The pull or merge request link of the branch. Empty when
  it has none."

Engine (`apps/kira-space/internal/ade`):

- `repoLine` adds `BranchID string` (set by `launchDirs` for every line it builds, mine and read-only) and
  `ChangeRequestURL string`; `repoLineVars` copies the URL.
- New helper in `ade/review.go`:
  `changeRequestURL(ctx, sb model.AdeTaskBranch, hostURL string) string`: `""` unless `sb.Name != ""` and kind
  mine or review; `openRepo` error → `""`; linked number via `linkedChangeRequest` → `entry.ChangeRequestURL`;
  else `ResolveBranchChangeRequest(ctx, sb.Name)` kind `ok` with a record → its `URL`; else `""`. Never an error:
  a missing link must not block a launch.
- `launchReviewAgent`: in the `message == ""` branch, before `composeReviewMessage`, fill
  `lines[i].ChangeRequestURL` from the branch with `lines[i].BranchID` (lookup in `tc.branches`). Resume path
  untouched (no new first message). Runs under the task mutex like the rest of the launch; warm path is local,
  cold path one bulk host call behind the breaker. Accepted.
- `roundVars` gains `ctx` and sets `ChangeRequestURL: b.changeRequestURL(ctx, rc.sb, rc.tc.task.HostURL)`.
  Update the three call sites in `reviewstep.go` (send path uses its `ctx`; `queueFallback` uses `b.ctx`;
  resume uses its `ctx`). `forwardMessage` builds its own vars; leave it.
