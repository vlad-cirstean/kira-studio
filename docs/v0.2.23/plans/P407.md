# P407 Stage handover: session context notes and stage-change dialogs

Plan for `docs/v0.2.23/SPEC.md` row P407. Base: `0253b0a`. Discovery ran through `codegraph_explore`.

One sequential Sonnet implementer. No stream split: the store, the MCP tool, the engine, the wire
(Go `adewire`, bindings, `wire.ts`) and the UI form one chain; every later commit reads the one before.

## Terms

- **Stage** = workflow step (`adewire.WorkflowStep`, ids from the workflow YAML). Status follows steps
  through `syncStatus` and stays untouched here; P411 reworks statuses. Nothing below names a step or
  status: every stage id and name comes from the task's workflow snapshot, so arbitrary stage sets work.
- **Handover** = text one stage leaves for the next. One row per stage transition, plus at most one
  open **draft** per (task, stage) that sessions write before the move.

## Design

### Data model: migration `0057_p407_ade_handovers.sql`

```sql
CREATE TABLE ade_task_handovers (
  id TEXT PRIMARY KEY,
  task_id TEXT NOT NULL REFERENCES ade_tasks (id) ON DELETE CASCADE,
  from_step_id TEXT NOT NULL,            -- '' for a task without a workflow
  from_step_name TEXT NOT NULL,
  to_step_id TEXT NOT NULL DEFAULT '',   -- '' while a draft; 'done' past the last step
  to_step_name TEXT NOT NULL DEFAULT '',
  body TEXT NOT NULL,
  source TEXT NOT NULL CHECK (source IN ('agent', 'run', 'user')),
  state TEXT NOT NULL CHECK (state IN ('draft', 'handed')),
  finished INTEGER NOT NULL DEFAULT 0 CHECK (finished IN (0, 1)),
  dismissed INTEGER NOT NULL DEFAULT 0 CHECK (dismissed IN (0, 1)),
  edited INTEGER NOT NULL DEFAULT 0 CHECK (edited IN (0, 1)),
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE UNIQUE INDEX ade_task_handovers_draft ON ade_task_handovers (task_id, from_step_id) WHERE state = 'draft';
CREATE INDEX ade_task_handovers_task ON ade_task_handovers (task_id, created_at);
```

- Names are snapshots: a workflow edit or P411 status rework never rewrites history.
- `model.AdeHandover`; repo `AdeHandoverRepo` (or methods on the task repo, implementer's pick by file
  size): `UpsertDraft`, `Drafts(taskID)`, `List(taskID)` newest first, `LatestHanded(taskID)`,
  `Update(id, body)` (sets `edited`), `Delete(id)`, `Dismiss(taskID, stepID)`, `Insert`, and a
  board read `BoardHandovers(taskIDs)` (latest handed + drafts per task, two queries, no N+1).
- `SetEntryStep` gains an optional `*model.AdeHandoff` applied in the same transaction (draft to
  handed, or a fresh handed row), so a move and its handover never land apart.
- Body limit `adeMaxHandoverBytes = 16 KiB` for agent and user writes. Prompt cap: `capNotes`
  (2000 runes) reused for the handover text.
- Plain create: no migration test (nothing to fold).

### MCP tool `handover` (`internal/agentmcp/handover.go`)

- Args `notes` (string, required, <= 16 KiB), `finished` (bool). Granted to every **task session
  without a run**: `g.TaskID != "" && g.RunID == "" && s.handover != nil`. A run grant (headless,
  or a taken-over finishable run) reports through `finish_step`; its `summary` is that run's handover
  (below). One path per session kind, no overlap.
- `Options.Handover HandoverRecorder` (`RecordHandover(ctx, taskID, stepID, notes string,
  finished bool) error`), implemented by `*ade.TaskBoard`. `Grant.StepID`: the stage the session
  was opened for (`LaunchStep`: step id; take over: `rec.StepID`; review agent: review step id when
  launched from the step, else ''; `StartBranch`: ''). `Register` accepts a grant that allows only
  `handover`. `sharedServer` key grows to `[6]bool`. New id `agentmcp.Handover` in `tools.go`.
- Engine `RecordHandover`: lock task; current stage = `currentStep` id (`''` without a workflow,
  `done` when complete). A grant `StepID` that differs from it returns `ToolError` ("The task moved on
  to <name>; nothing was recorded. Tell the user."). Upsert the draft for (task, current stage):
  body replaced, `source agent`, `finished`, `dismissed=0`. `finished` on a live workflow stage
  (not '' and not `done`) opens the routed prompt. `notifyBoard`.
- Ack: new `KindToolResult` entry `headless.handover.ack` "Recorded. The user moves the task on."
- `prepareWithGrant` always registers for a task TUI (handover needs no switch) and appends
  `agentmcp.Handover` to the allowed tools; `launchReviewAgent` registers the same grant (both new
  and resumed paths) and binds its release with `bindTUI`. Factor one helper; no copy.

### Engine (`internal/ade/handover.go`)

- `handOffLocked(tc, from, to stepView ids, notes *string)` builds the `AdeHandoff` for
  `SetEntryStep`: draft for `from` exists: `notes == nil` keeps its body, else body = notes
  (`edited` when it differs), empty notes deletes it. No draft: non-empty notes insert a handed `user`
  row. Then close the routed prompt.
- `StepDone(ctx, taskID, notes *string)` and `SetTaskStep(..., notes *string)` call it; from =
  current stage, to = new entry (`done` included). Backward moves record too (notes say why).
- **Run handover.** In `recordOutcomeLocked`, after `UpdateRun`, before `advanceLocked`: when a done
  step run leaves its step done (every target done) and the walked path now ends past it, insert a
  handed `run` row from that step to where the path ends (`done` past the last). Body: the summary;
  several targets give one `- <repo> · <branch>: <summary>` line each. A draft for that step (an
  interactive branch session during an automatic stage) is folded in first, blank line, then the
  summaries. Close the prompt.
- **Prompt routing.** New `prompts.KindHandover = "handover"`, `Ref` = task id, title
  `backend.prompt.handover.title` (`{task}`), count title `backend.prompt.count.handover.title` in
  `Router.countTitle`. `TaskBoardDeps.PromptSink prompts.Sink` (nil-safe), wired to the Space router
  in `appwire`. Opens: finished draft on a live stage. Closes: any stage move, dismiss, draft delete,
  archive. On board start reopen prompts for finished, undismissed drafts of the current stage.
- `DismissHandover(taskID)`: set `dismissed` on the current stage's draft, close the prompt.
- `UpdateHandover(id, body)`: body `''` deletes; draft delete closes its prompt. `notifyBoard`.
- `Handovers(taskID)`: full list, archived tasks included.
- **Next stage input.** `handoverInto(tc, stepID)`: the task's latest handed row when its
  `to_step_id == stepID`, else none. One rule shared by server prompts and the frontend mirror
  (below), so preview and send never disagree.

## Tests

- **Go flow** `internal/flows/adeflow/handover_test.go` `TestStageHandover` (backend half), workflow
  agent `one` → manual `work` (`session: true`) → agent `two`:
  1. Run `one` finishes with summary "did A": `Handovers` has a handed `run` row one→work;
     board `handoverIn` set; no prompt.
  2. `LaunchStep`: fake prompt file holds "did A" and the tool line. The TUI fake calls `handover`
     `{notes: "wired B", finished: true}` then waits: draft (work, finished); router lists kind
     `handover` with ref = task; board `handoverDrafts` has it.
  3. `DismissHandover`: prompt gone, draft `dismissed`. A second `finished` call reopens it.
  4. `StepDone` with notes "wired B, check C": handed work→two, `edited`, prompt closed. `StartRun`:
     run `two` prompt holds "wired B, check C" and the task notes.
  5. `UpdateHandover` edits a row; empty body deletes it.
  6. `SetTaskStep` back to `one` with notes "redo": handed `user` row two→one.
  7. A TUI whose grant `StepID` is stale gets the tool error; nothing stored.
  Records `ade-handover.json`.
