## Design

### Scope

- Editable: `repo-file` tabs on the worktree (`rev === null`), text files that read as `found` and valid UTF-8.
- Not editable: revision-pinned tabs, diff tabs, `local-file` tabs (outside every repository, not git module),
  binary, too large, missing. No Edit button there.
- Edit existing files only, plus recreate a file deleted on disk while being edited (Overwrite after a conflict,
  below). No new-file, rename or delete actions.

### D1 Bridge API: two methods on `CodeWorkspaceService`

Same service as `ReadFile`: same session resolution, same path check, same `filesCtx`. A separate service would
duplicate `session()`.

- `ReadFileForEdit(ctx, CodeWorkspaceReadFileArgs) (codeworkspace.EditContent, error)`
  - `EditContent{Kind, Text, Hash, Language}` (`json:"kind"`, `"text"`, `"hash"`, `"language"`).
  - Kind: `found`, `missing`, `binary`, `tooLarge`, `notUtf8`. Reuses `codeworkspace.ReadFile` for the first four.
  - `notUtf8`: `found` but `!utf8.ValidString`. JSON would replace invalid bytes with U+FFFD, and saving would
    corrupt the file. Refused up front.
  - `Hash`: SHA-256 hex of the on-disk bytes. `""` when `missing`.
  - Why a new method, not a `hash` field on `FileContent`: `FileContent` is shared by `OpenedFilesService.Read`,
    `ReadDiff` sides and two contract fixtures (`opened-files.json`, `ade-review-working.json`, the latter in
    P418's area). A new method keeps every existing read and fixture byte-identical.
  - Edit mode always starts from this fresh read, so its base is current, not the possibly older text the
    viewer mounted with.
- `WriteFile(ctx, CodeWorkspaceWriteFileArgs{ID, Path, Text, BaseHash}) (CodeWorkspaceWriteResult{Hash}, error)`
  - `ID`, `Path` required. `BaseHash` may be `""`: means "expect the file absent".
  - Path: `codeworkspace.ValidateRelPath(sess.Root, path)`, unchanged rules. Escape -> `ipcerr.Contract`.
  - Body in `codeworkspace.WriteFile(absPath, text, baseHash) (string, error)`, new file
    `apps/kira-space/internal/codeworkspace/edit.go`:
    1. `len(text) > MaxReadBytes` -> `ErrTooLarge`. A file the viewer could not reopen must not be written.
    2. `!utf8.ValidString(text)` -> contract error (defensive; the renderer always sends valid text).
    3. Lstat target: exists but not a regular file (dir, FIFO) -> `ErrNotRegular`.
    4. Current hash: SHA-256 of current bytes (bounded read, `MaxReadBytes+1`), `""` when absent.
    5. Current hash != `baseHash` -> `ErrConflict`.
    6. Write: `renameio.NewPendingFile(absPath, renameio.WithExistingPermissions(), renameio.WithPermissions(0o644))`,
       write, `CloseAtomicallyReplace`. Atomic: a crash never leaves a half-written file. Existing mode kept; a
       recreated file gets `0644 &^ umask`. `absPath` is the symlink-resolved target, so a symlinked leaf keeps its
       link and the target is replaced.
    7. Return the new hash.
  - Steps 4 to 6 run under `writeMu sync.Mutex` on `CodeWorkspaceService` (zero value, no wiring change). Both
    windows share one Go process, so two in-app saves of one file serialize and the second sees a conflict. An
    external writer racing the microseconds between 4 and 6 is not guarded; stated in ARCHITECTURE.
  - Error mapping in the bridge:
    - `ErrConflict` -> `ipcerr.T(CodeConflict, "backend.space.codeWorkspace.fileChanged.body")`.
    - `ErrTooLarge` -> `ipcerr.T(CodeBadRequest, "backend.space.codeWorkspace.saveTooLarge.body")`.
    - `ErrNotRegular` -> `ipcerr.T(CodeBadRequest, "backend.space.codeWorkspace.notRegularFile.body")`.
    - session errors as `ReadFile` already does.
  - Hash helper: one `hashBytes([]byte) string` in `edit.go`, used by both methods.
- Rejected alternatives:
  - In-place truncate-and-write (keeps inode and hard links): not atomic; a crash mid-write loses the file.
    Hard-linked worktree files are rare; atomic replace wins. Caveat recorded in ARCHITECTURE.
  - mtime+size as the version token: coarse mtime granularity and same-size edits miss changes. Content hash is
    exact and cheap at an 8 MiB cap.
  - Going through `gitclient.Repo.Write`: that gate serializes git processes; a file write is not one.

### D2 Op log

No op-log row for a save. The op log records spawned processes (git), sessions, MCP/tool calls and tracker
calls; a save spawns nothing and is the user typing into a file. `filesCtx` still stamps the call, so any git
spawn inside `session()` stays attributed to `files` as today.

### D3 Edit session state: one Pinia store

`apps/kira-space/frontend/src/state/fileEdit.ts`, `useFileEditStore`. One concern: per-tab worktree edit
sessions.

- `sessions: Record<tabId, { baseHash: string; savedVersionId: number; dirty: boolean; conflict: 'changed' |
  'gone' | null; diskChanged: boolean }>`. Present only while the tab is in edit mode.
- Actions: `begin(tabId, baseHash, versionId)`, `markSaved(tabId, hash, versionId)`, `setDirty`, `setConflict`,
  `setDiskChanged`, `end(tabId)`, getters `isEditing(tabId)`, `isDirty(tabId)`.
- `registerTabRuntimeCleanup((tabId) => end(tabId))`: a closed tab drops its session (precedent:
  `definition/state.ts`).
- Not persisted. A restored window opens read only (the ask's default).

### D4 Draft survives a tab switch

The view unmounts on switch, the Monaco model stays in `modelCache`. On remount, `mount()` would read the file
and `getOrCreateModel` would `setValue` the disk text over the draft.

- Add `peekModel(uri)` to `views/repo/monaco.ts`: the cached, not-disposed model or `undefined`.
- `RepoFileView.mount()`: when `fileEdit.isEditing(tab.id)` and `peekModel(uri)` exists, skip the read and mount
  over that model (pass its current value as `text`, so `getOrCreateModel` finds no difference and never calls
  `setValue`). Then re-apply edit options (D6).
- Dirty is `model.getAlternativeVersionId() !== session.savedVersionId`: undoing back to the saved text reads
  clean again. Tracked through `editor.onDidChangeModelContent`.

  Source/Reading `SecondaryTabs` (markdown only, hidden while editing). Right: `RepoFileEditBar.vue`.
- `RepoFileEditBar.vue` (`<script setup lang="ts">`, Tailwind classes, shadcn-vue `Button`, `Tooltip`,
  `Kbd`, `Badge`):
  - Read mode: `Edit` button (`common.action.edit.label`), `data-testid="repo-file-edit"`.
  - Edit mode: `Modified` badge while dirty (`variant="warn"`), `Save` (`common.action.save.label`, disabled
    when clean, `:pending` while the mutation runs, tooltip shows the `form.save` chord in `Kbd` via the
    existing shortcut formatter), `Done` (`space.repo.file.doneEditing.label`). Test ids `repo-file-save`,
    `repo-file-done`, `repo-file-modified`.
- Below the toolbar, an `Alert`:
  - Conflict `changed` (`variant="warn"`, `space.repo.file.changedOnDisk.body`): `Reload`
    (`common.action.refresh.label`: discards the draft, re-enters edit from a fresh read) and `Overwrite`
    (new `space.repo.file.overwrite.label`; the workflow editor's key sits in the ADE namespace). Overwrite
    re-reads only the hash via `ReadFileForEdit`, then saves with it.
  - Conflict `gone` (`space.repo.file.deletedOnDisk.body`): `Overwrite` recreates (hash `""`), `Reload` leaves
    edit mode and shows the missing state.
  - Save error other than conflict (`variant="error"`): `errorText(err)`.
  - Disk changed while clean editing: silently reloaded, no alert (D7).
- Enter edit (`Edit` click):
  1. `ReadFileForEdit`. Non-`found` kinds: error alert with the reason (`notUtf8` ->
     `space.repo.file.notUtf8.error`; others reuse the existing `space.repo.view.*` texts), stay read only.
  2. If text differs from the model, `model.setValue(text)`.
  3. `tabsStore.promoteTab(tab.id)`: a preview tab would otherwise be evicted (and the draft lost) by the next
     single-click open.
  4. Markdown: switch to Source.
  5. `inlineBlame.dispose()`: blame line numbers stop matching once text changes.
  6. `editor.updateOptions(EDIT_OPTIONS)` (D6), `fileEdit.begin(...)`, focus the editor.
- Save (button or shortcut): no-op when clean or pending. `WriteFile({ text: model.getValue(undefined, true),
  baseHash })`. `getValue(eol, preserveBOM=true)`: Monaco strips a leading BOM from the model; without this a
  BOM file loses its BOM on save. Model EOL is the file's detected EOL, so CRLF survives. On success:
  `markSaved(newHash, model.getAlternativeVersionId())`, refresh the file tree if loaded
  (`useFileTreeStore().refreshRepoTree(repoId)` when `isRepoTreeLoaded`) so the status glyph updates. On
  `E_CONFLICT`, set conflict (`changed`, or `gone` when a follow-up `ReadFileForEdit` says `missing`).
- Done: clean -> leave edit mode. Dirty -> `useConfirmDialogStore().confirm` with the tab strip's own discard
  texts (`workbench.tabStrip.discard.*`, count 1); confirmed -> restore the disk text (`ReadFileForEdit`, then
  `setValue`), leave edit mode. Leaving edit mode: `updateOptions(READ_OPTIONS)`, `fileEdit.end`, re-attach
  inline blame (same guard `mount()` uses).
- Server state through TanStack Query: `useMutation` for `ReadFileForEdit` and `WriteFile` (user-triggered,
  imperative; same shape as `useSaveWorkflowYaml`). No cached query: the edit base must never come from cache.
- `RepoFileView.vue` keeps reading through `loadFileContent` in read mode; unchanged for non-editable tabs except
  the toolbar now showing on editable ones.

### D7 External change detection

No worktree watcher exists for plain files (`RepoWatcher` sees `.git` only). Adding an fsnotify watch over a
whole worktree is a large change for one view. Instead, three checks:

1. Save is hash-guarded (D1): an external change is never silently overwritten.
2. Edit start reads fresh (D5 step 1).
3. While in edit mode, on window focus (VueUse `useWindowFocus`, watch to `true`) and on remount: call
   `ReadFileForEdit`, compare hash with `baseHash`.
   - Different and clean: `model.setValue(text)`, new `baseHash`, new `savedVersionId`. `setValue` resets undo;
     acceptable, nothing is unsaved.
   - Different and dirty: show the `changed` alert now (same Reload/Overwrite), before the user hits Save.
   - `missing`: `gone` alert.
   Focus covers the main case: the user edits in another app or an agent changes the file, then comes back.

No cross-window event on save: the other window's check runs when it gets focus.

### D8 Unsaved-changes guards

- Tab close: `TAB_KINDS['repo-file'].isDirty = (tabId) => useFileEditStore().isDirty(tabId)`. The shared
  `createTabsStore` then asks to discard on close, close others, close right, close all.
- Tab badge: `TAB_KINDS['repo-file'].badge` returns `{ icon: 'circle-filled', tooltip:
  t('space.repo.file.unsaved.tooltip') }` while dirty (Space host already renders `kind.badge`).
- Preview eviction: prevented by promoting on edit start (D5).
- Done with dirty: confirm (D5).
- Quit or window close with a dirty buffer: not guarded. The quit confirm (`LifecycleService.QuitStatus`) is
  computed in Go from agents, runs and scripts; it has no renderer state. Wiring renderer dirty state into the
  quit handshake is a separate design. Recorded under ARCHITECTURE "Known open items". The last window's close
  hides it (page kept), so the draft survives that path.
- Studio's `editDirty.ts` not hoisted: Kira Space needs its own store anyway for `baseHash`/conflict, and
  hoisting would touch three Studio files while P420 works in Studio. The store covers `isDirty` directly.

## Tests

Per CLAUDE.md: same scenario split at the IPC boundary, contract JSON between halves. No dedicated unit test:

### Go flow test `repoflow/edit_test.go` `TestEditFile`

Real repo via `flowharness` (pattern of `TestBrowseReadDiff`). Subtests:

- read for edit: `found` with hash = SHA-256 of disk bytes, language; contract key
  `CodeWorkspaceService.ReadFileForEdit`.
- save: `WriteFile` with that hash; disk bytes equal the text; file mode unchanged (chmod 0755 first, assert
  kept); returned hash = SHA-256 of new bytes; contract key `CodeWorkspaceService.WriteFile`.
- CRLF and BOM bytes round-trip byte-exact through read-for-edit then write.
- conflict: change disk after read, save with old hash -> `E_CONFLICT`, disk unchanged; contract key
  `CodeWorkspaceService.WriteFile#conflict` (via a `failure(t, err)` helper like `llmpromptsflow`).
- gone then recreate: delete, save with old hash -> `E_CONFLICT`; save with `""` -> file recreated.
- refusals: symlink escaping root -> contract error, target untouched; `..` path -> contract error; `notUtf8`
  kind for a Latin-1 file; `binary`, `tooLarge` kinds; text over `MaxReadBytes` -> `E_BAD_REQUEST`; directory
  path -> `E_BAD_REQUEST`.
- symlink inside root: save writes the target, link stays a link.
- two saves with the same base hash: second -> `E_CONFLICT`.
