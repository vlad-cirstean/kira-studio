## Interpretation (ambiguity, stated plainly)

The row says the Backlog tab becomes "Later" with two sections, Plan to Later is a direct move, and a
task moves Plan <-> Backlog alongside Archive. Today "Later" names the Plan's undated band and
"Backlog" names a list of non-task items. Read literally, both sections must hold **tasks** that keep
their branches, worktrees and sessions while off the Plan. Chosen model:

- **Later** = live tasks of kind `task` or `parked` with no plan day and not on Backlog. That is
  exactly today's undated tasks. "Plan to Later" stays the existing `Plan > Later` move (`SetPlan`
  day null), now taking the task off the Plan timeline and into the Later tab. Non-destructive.
- **Backlog** = live tasks whose plan row carries a new `backlog` flag (day always null).
- **Backlog items fold into tasks.** Each `ade_backlog` row becomes a repo-less, workflow-less task on
  Backlog, in its current order (same shape `PromoteBacklogItem` creates today). `ade_backlog` and the
  whole item API go. One model, no promote step. Old items land in **Backlog**, not Later: they were
  captured "maybe" work, and Backlog keeps their name.
- **Review items never shelve.** An undated review item keeps its P368 auto placement on the Plan.
  Moving one to Backlog is refused.
- **Plan tail band.** It still holds dated tasks beyond the 7-day window and unplaced review items.
  Relabel it "Further out" so it no longer collides with the Later tab. Render it only when it has
  entries. Drops onto it are refused (it no longer means "no day").
- **Tab order** (confirmed against `AdeShell.vue`): today Backlog · Needs you · Plan | Workflows. New:
  Needs you · Plan · Later | Workflows. Workflows stays on the right; the spec does not mention it.
  Default view stays `plan`.
- **Mobile is in scope** only because its backlog routes go with the item API. It gets the same model:
  Later screen with both sections, tab renamed and reordered the same way. No other mobile change.
- **Quick add** = the top-bar capture box (`AdeCaptureBox`). It creates a task at the top of Later.
  The full Add popover (`AdeAddPopover`, lands today) is unchanged. The Later page drops its own add
  field: the top-bar box is always visible on that tab.

## Design

### 1. Storage (Go)

- Migration `0055_p405_ade_plan_backlog.sql`:
  `ALTER TABLE ade_task_plan ADD COLUMN backlog INTEGER NOT NULL DEFAULT 0 CHECK (backlog IN (0, 1));`
- Migration `0056_p405_fold_ade_backlog.sql` (lands in commit 4):
  - `INSERT INTO ade_tasks (...) SELECT ... FROM ade_backlog`: `id` = item id, `kind 'task'`,
    `title = text`, `owner ''`, `jira_key`, `jira_url`, `host_url`, `notes`, empty workflow fields
    and `est`, `created_at = added_at`, `status_by 'auto'`, `status_step ''`,
    `status_id` = first `todo` status by position, falling back to the first status by position.
    `color = (ROW_NUMBER() OVER (ORDER BY position, id) - 1) % 20` (approximates `pickColorSlot`; good
    enough for one-off data). Read 0008 and every later `ALTER TABLE ade_tasks` for the full NOT
    NULL column list before writing it.
  - `INSERT INTO ade_task_plan (task_id, day, position, backlog)`: `day NULL`, `backlog 1`,
    `position` = current `MAX(position)` (or -1) + `ROW_NUMBER()` in item order.
  - `DROP TABLE ade_backlog;`
  - Test `migrate_ade_fold_backlog_test.go` (one-way conversion of user data with ordering, status
    and color rules; same precedent as `migrate_ade_task_statuses_test.go`): items with mixed and
    negative positions become backlog tasks in order, with a todo status id, distinct colors, and
    the table gone.
- `model.AdeTaskPlanRow` gains `Backlog bool`; plan reads select it.
- `repos.AdeTaskRepo`:
  - `SetPlan`: every `days` write also sets `backlog = 0` (a day or null both mean "not Backlog").
  - New `Shelve(taskID string, backlog bool, beforeID string) error`, one transaction: upsert the
    task's plan row (a live task with no plan row is legal per `ListLive`), set `day = NULL` and
    `backlog`, then rewrite positions densely with the task placed right before `beforeID`, or,
    when `beforeID == ""`, right after the last task already on that shelf (end of the global
    order when the shelf is empty). `beforeID` must be on the same shelf; otherwise
    `ErrShelfTarget` (new sentinel, mapped in `adeTaskError` as bad request).
  - `insertTask` gains a placement: `end` (today's `MAX+1`) or `top` (`MIN-1`). `CreateTask` keeps
    `end`; new `CaptureTask(t model.AdeTask) (model.AdeTask, error)` uses `top` with day NULL.
    Top of the global order is top of Later, since a section's order is its filter of the global
    order and undated tasks never sort into day bands.
- Commit 4 deletes `AdeBacklogRepo`, `model.AdeBacklogItem`/`AdeBacklogPatch`, `ErrBacklogGone`,
  `Repos.AdeBacklog`.
