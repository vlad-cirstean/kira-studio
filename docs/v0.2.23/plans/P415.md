## Split decision: memory MCP

Kira Space has two MCP servers. `internal/agentmcp` runs in the app process (ADE tools, `git`, sandbox git,
handover). The memory server (`internal/memory/memorycli`, `kira-space memory-mcp`) is a separate stdio process
Claude Code spawns per session; it has no channel to the app's op log. Recording it needs a cross-process design
(child writes `op_log` rows into `kira-space.db`, app learns of them by some notify path). That is a real design
decision outside this phase's seam.

Planner decision per CLAUDE.md split rule: rename the row `P415 Part 1: Operations panel: shared git primitives,
all git ops, session and in-app MCP ops` and add `P415 Part 2: Operations panel: memory MCP tool ops
(out-of-process)` right after it. This plan is Part 1. Orchestrator: apply the SPEC.md rename in its own commit
(this plan commit touches only the plan file); Part 2 gets its own Opus plan after Part 1 lands. Part 1 builds the
persisted `op_log` table Part 2 writes into.

## Design

### 1. Op model (Go `oplog.Record`, wire)

Fields added to `oplog.Record` (always present on the wire):

- `category`: `git` | `session` | `mcp`. Open set; P416 adds `automation`.
- `module`: `git` (Git module windows), `ade`, `files` (codeworkspace), `vscode` (external git-stream client),
  `app` (no origin: discovery, anything unstamped).
- `trigger`: `user` | `mcp` | `auto` (Kira on its own: polling, watcher, auto-fetch, board refresh, engine
  follow-through on `b.ctx`).
- `subject`: task title for session/MCP ops, else `""` (repo columns stay `repoRoot`/`repoName`).
- `taskId`, `parentId`: `""` when none. `parentId` links an op started inside another (a `worktreeAdd` under a
  `request_branches` call).
- `background`: bool. See section 4.
- `repeat`: int, 1 by default; >1 on a deduped background failure.
- `steps`: `[]Step{argv string, readOnly bool, exitCode *int, durationMs *int, status string, stderr *string}`:
  every git spawn the op ran, in order. Cap 64 per op; then `stepsDropped int` counts the rest.
- Keep `source` as the human label (conn label, `MCP <tool>`, agent provider name), `kind`, `command`, `error`,
  `repoRoot`, `repoName`, `cancellable`.

`kind` per category: `git` keeps the existing op kinds (`branchCreate`, `fetch`, `undo`, `restack`,
`worktreeAdd`, `autoFetch`, ...) and uses the git subcommand (`status`, `for-each-ref`, `log`) for a spawn row with
no enclosing op. `session`: `start`, `adHoc`, `takeOver`, `restart`, `manual`, `reviewAgent`, `run`, `resume`,
`rebase`, `review`, `setup`, `stop`. `mcp`: the tool name.

`command`: for a git op, the non-read steps' argv joined with ` && ` (today's `noteWrite` output, now derived);
for a spawn row its own argv; for an MCP op `<tool> <args JSON>`; for a session op the agent command line as
`Tracker` composes it, minus env.

`error`: classified message, then a blank line, then the failing step's stderr tail (8 KiB cap). One copyable
string.

### 2. Origin in ctx (attribution)

`internal/oplog/origin.go`:

```go
type Origin struct {
	Module, Trigger, Label, TaskID string
	Background bool // forces background for every spawn under it (auto-fetch)
}
func WithOrigin(ctx context.Context, o Origin) context.Context
func OriginFrom(ctx context.Context) (Origin, bool)
func WithOp(ctx context.Context, op *Op) context.Context // moved from gitsession/oplog.go
func OpFrom(ctx context.Context) *Op
```

`Log.Start(ctx, Meta)` reads origin and the enclosing op from ctx: fills `module`, `trigger`, `taskId`,
`parentId`; `Meta` keeps `Kind`, `Category`, repo fields, `Source`, `Subject`. Missing origin: `module: app`,
`trigger: auto`.

Stamp sites (the only places origin is set):

1. `gitrpc.Router.ForConn` wraps `Request` and `Stream` ctx with `{Module: c.Module, Trigger: user, Label:
   c.ClientLabel}`. New field `gitsession.Conn.Module`, set after `NewConn` at `bridge/gitstream.go:83` (`git` for
   `nativeClientID`, else `vscode`) and `ade/board.go:190` (`ade`).
2. `RepoEntry.life` (`entry.go:178`): `{Module: git, Trigger: auto}`. Auto-fetch tick ctx adds `Background: true`.
3. `bridge/codeworkspace.go` methods: `{Module: files, Trigger: user}`.
4. `bridge/adetask.go`: each of the 78 `AdeTaskService` methods taking a ctx starts with `ctx = adeUserCtx(ctx)`
   (`{Module: ade, Trigger: user}`). `MobileWriter` calls through this service, so it is covered.
5. `ade.NewTaskBoard`: `b.ctx` gets `{Module: ade, Trigger: auto}` (scheduler, folder watcher, rebase checker,
   board refresh, runs started on `b.ctx`).
6. agentmcp middleware (section 6): `{Module: <Options.Module>, Trigger: mcp, Label: "MCP " + tool, TaskID}` plus
   the MCP op as enclosing op.

Wails v3 has no per-call ctx hook for bound methods that this plan can rely on; the 78 one-liners are the
explicit seam. Orchestrator check: `grep -c 'ctx = adeUserCtx(ctx)' bridge/adetask.go` equals the count of
`^func (s \*AdeTaskService) [A-Z].*ctx context.Context` (78 at base).

`gitsession` `startOp(ctx, kind, label)` and `recordFailure(ctx, ...)` pass ctx through; their callers already hold
one.

### 3. One recording seam at the shared runner

`internal/oplog/runner.go`: `RecordingRunner{Inner gitclient.Runner; Log *Log}` implements `gitclient.Runner`.
`wireGit` builds `oplog.NewRecordingRunner(gitclient.NewExecRunner(), opLog)` and hands that one value to the
registry, discovery, gitrpc, ADE and codeworkspace (all already take `git.runner`). Nothing else wraps or spawns.

`Start(ctx, gitPath, spec)`:

- `spec.Stdin` (persistent `cat-file --batch` pair): pass through, no record (one process serving many requests
  would show as a row "running" for hours).
- Enclosing op in ctx (`OpFrom`): add a step to it (redacted argv, `readOnly`) before the spawn, finish the step
  from the wrapped `Process.Wait`/`Close` result. No own row.
- No enclosing op: own row, `category: git`, `kind` = first non-flag argv after `configOverrides`, `command` = argv,
  `background = origin.Background || spec.ReadOnly`.
- Outcome: ctx cancelled → `cancelled`; spawn error → `error`; `exitCode` in `{0} ∪ spec.OKExits` → `ok`; else
  `error` with `exit <n>` plus stderr tail.

`gitclient.Spec` gains `OKExits []int` (exit codes the caller treats as an answer, not a failure).
`RepoEntry.runAllowingExit` sets it from its allowed list. Implementer audits every `gitclient.Run`/`Start` caller
that branches on a non-zero `ExitCode` as a normal answer (`merge-base --is-ancestor`, `check-ref-format`,
`diff --quiet`, `show-ref --verify --quiet`, `rev-parse --verify`, `ls-remote --exit-code`) and sets `OKExits`
there too. Without this, polling reads flood the Error filter.

`gitsession` cleanup: delete `noteWrite` and its four call sites (`ops.go:1129` and siblings, `remote.go:156`,
`stack.go` spawn); the step mechanism records the same argv at the same moment. `withOp`/`opFrom` move to
`oplog`. `AddCommand` becomes internal to step recording. Audit every non-`ReadOnly` spawn in `gitsession` and
`ade`: each must run under a logical op (all do today via `RunOp`/`UndoRun`/`RunRemote`/`RunRestack`, or
auto-fetch with `Background`); list any exception in the result.

### 4. Volume and retention

- Two lanes in `Log`. Foreground ring 500, background ring 300. A background record never evicts a foreground one.
- Foreground: every logical op, every non-read spawn row, every session and MCP op. Persisted.
- Background: read spawn rows with no enclosing op, and everything under `Origin.Background`. Never persisted,
  except failures. Not broadcast one by one: a coalescing emitter flushes changed background records at most once
  per second on new channel `kira:op:batch` (`appevent.ChannelOpBatch`, payload `[]Record`, last state per id
  wins). Foreground keeps `kira:op:update`, immediate.
- Background failure dedupe: key `(module, repoRoot, kind, first line of error)`; a repeat within 10 minutes bumps
  `repeat` on the existing row (ring and DB) and re-emits it instead of adding a row.
- Persistence: migration `apps/kira-space/internal/storage/migrations/0060_p415_op_log.sql`, table `op_log` (id TEXT
  PK, started_at, duration_ms, category, kind, status, module, trigger_, source, subject, repo_root, repo_name,
  task_id, parent_id, command, error, steps_json, background INTEGER, repeat_count INTEGER), index on
  `started_at`. Column names avoid SQL keywords. New `repos.OpLogRepo` (`Upsert`, `Recent`, `Prune(cutoff,
  maxRows)`, `ReconcileInterrupted(msg)`); `repos.Repos` gains `OpLog`.
- Writes never block git: `Log` owns one writer goroutine fed by a buffered channel (1024). Start and finish of an
  op are both upserts by id, so order within one id is the only ordering rule; one goroutine gives it. Full
  channel: drop the write, count it, `slog.Warn` at most once per minute. `Log.Close` drains with a 2 s bound
  (Kira Studio's `oplog.Wiring` `stopWait` precedent), called in appwire teardown beside `detachOpLog`.
- Startup (appwire, before the first window): `ReconcileInterrupted` turns `running` rows into `error` with
  catalog text "Kira Space quit while this ran."; `Prune(now - 30 days, 5000 rows)`; seed the foreground ring from
  `Recent(500)`. Prune again every 500 finished foreground ops.
- Retention is constants in `oplog` (30 days, 5000 rows, 500/300 rings, 10 min dedupe). No setting.
- `OpsService.Recent(limit)`: up to `limit` foreground plus up to `limit` background, newest first. No new bridge
  type.

### 5. Redaction

`oplog.RedactArgv([]string) []string`, applied to every step and spawn row before it reaches a record:

- URL userinfo in any arg: `scheme://user:secret@host` → `scheme://***@host` (keep scheme and host; also
  `user@` with a token-shaped user, i.e. any userinfo with `:`, is masked whole).
- `-c key=value` and `--config-env`: value → `***` when key matches `(?i)extraheader|password|token|secret|
  authorization|credential`.
- `--password=`, `--token=` style flags: value → `***`.

Env is never recorded (askpass tokens stay out, as today). stderr tails pass through the URL rule.
`oplog.RedactJSON(raw, maxBytes)` for MCP args: values of keys matching the same key pattern → `"***"`, git-tool
`args` arrays through `RedactArgv`, then truncate at 2 KiB with `…`.

### 7. Session ops (Go only)

- `TaskBoardDeps.Ops *oplog.Log`, `TrackerDeps.Ops *oplog.Log`, set in appwire.
- TUI: `PrepareArgs.OpKind` (`start`, `adHoc`, `takeOver`, `restart`, `manual`, `reviewAgent`) set by each caller.
  `Tracker.Prepare` starts the op (`category: session`, subject task title, `source` agent provider name) and keeps
  the `*oplog.Op` on the pending intent. `Compose` finishes `ok`; `expirePending` and `Abort` finish `error`
  ("The terminal never started the session."); a Prepare failure finishes `error` with it. `Tracker.Stop` records
  one finished `stop` op.
- Headless: the three `InsertHeadless` sites start ops `run`, `rebase`, `review`; the handle lives on `liveRun`;
  `recordOutcomeLocked`, `completeRebase`, `completeReviewRound` finish with the outcome (`ok`, `error` with the

  func that only signals `StopRun` (kill/cancel); it must never call `Finish` inline: `Log.Cancel` holds the log
  lock.
- Setup scripts: `prepareWorktrees` / `RetrySetup` start `setup` per branch, finish with the script result;
  `command` = script path, never its env.
- Session and MCP ops started inside an origin carry its trigger (`user` from the bridge, `auto` on `b.ctx`).
