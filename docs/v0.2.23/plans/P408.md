## Design decisions

1. **One tool, many repos: `request_branches`** replaces `request_branch`. Arg `repos` (string array,
   1 to 20, same cap as `declare_repos`, duplicates collapse). A task has at most one mine branch per
   repo, so "many branches" = many repos. The plural name states the contract; an old prompt override
   keyed `headless.tool.request_branch` no longer matches any entry and is dropped by the store like
   any unknown id (accepted: the arg shape changed, so the old override is wrong anyway).
2. **Blocking approval.** The call waits for the user. Items that need nothing (branch named and its
   worktree exists) return at once and never raise a prompt; a call where every item is ready raises
   none. Items whose base refuses (`baseParentDraft`, `baseMissing`) or that are not mine return
   `failed` with that text and are not shown. The rest go to one dialog.
3. **Per-item deselect: yes.** Checkboxes, all checked by default; Approve sends the checked repos,
   unchecked ones return `denied`. Reason: agents often ask for every repo they read; whole-batch
   approve or deny would force a deny-and-reask round trip, the exact repeat prompt the row wants to
   avoid. Approve with none checked is disabled; Deny returns every item `denied`.
4. **No lock while waiting.** Phase 1 under `taskMu` validates and builds items; the lock is
   released for the wait; phase 3 re-takes it, reloads the task and re-validates each approved item
   (task archived, branch named or removed meanwhile) before `ensureWorktree`. Per-item failure never
   aborts the others.
5. **End conditions** (each resolves exactly once, through one `resolve` like dbmcp):
   - User approves or denies: result per item.
   - Timeout `branchRequestWait` = 30 min (`TaskBoardDeps.BranchRequestWait`, 0 = default; the flow
     test sets it short): every item `timeout`, prompt closed. A headless run's step timeout (default
     30 min) may end the process first; both paths land on abandon or timeout, never a half state.
   - Caller gone: the MCP request ctx ends (agent process exits, client drops) or the grant is
     released. New in agentmcp: each registration owns a ctx that `release()` cancels; tool handlers
     run under a ctx done when either ends (`context.AfterFunc`). So a TUI session stop, a run stop or
     exit abandons the request and closes its prompt even if the HTTP connection lingers.
   - Task archived or deleted: abandon its request (archive and delete paths).
   - App quit: `TaskBoard.Close` abandons all.
   - A second call for a task that already has a request waiting returns `ToolError` "A branch request
     for this task already waits for the user. Wait for its answer, then call again." One pending
     request per task bounds the queue; no cap constant needed.
   Abandoned calls return nothing to anyone (the caller is gone); timeout and decisions return a
   normal (non-error) result: a decision is a value, not a failure.
6. **Result shape.** `RequestBranchesResult{Branches []RequestedBranch}`; `RequestedBranch` embeds
   `BranchInfo` plus `Outcome` = `created` | `existing` | `denied` | `failed` | `timeout`. `Next` text
   per outcome: denied "The user declined this branch. Do not create it with git; continue without it
   or ask the user."; timeout "No answer from the user in 30 minutes; nothing was created. Call
   request_branches again later or ask the user."; created/existing keep today's `branchInfo` text.
7. **Headless vs interactive.** Same tool, same wait, same dialog. Source shown in the dialog:
   `run` (RunID found in `ade_runs`: step name), `session` (no RunID: grant `StepID` step name, else
   none), `automation` (RunID not an ADE run: a scriptruns automation). A headless run's row note reads
   `waiting for branch approval` while waiting (`setPendingNote` style, `emitRuns`), cleared after.
   Mobile has no approval UI: a phone-started run waits for the desktop (OS notification fires there).
8. **"Kira Space tools" always on.** Every task grant carries the Space tools, except rebase runs and
   review rounds (they keep their git-only tool sets, as today). `Grant.Space` stays: it is the grant's
   capability, not the workflow switch. `spaceEnabled`, `Workflow.KiraSpaceMcp`, the editor checkbox,
   the chip, `useSpaceTools` and their i18n go. The YAML key: the parser keeps accepting
   `kira_space_mcp` (any bool) and ignores it, so existing workflow files still load; the writer drops
   it on the next save (`topOrder` loses it). Not a breaking change.
9. **Branch creation at Run.** Today's Space-on rule becomes the only rule, with one fix: when the
   step Run starts is an **agent** step, an unnamed mine branch gets no worktree (the run starts at the
   repo root and the agent calls `request_branches`). For a **script or review** step nothing can ask,
   so an unnamed branch keeps today's Space-off path (title-derived `feat/<slug>` at Run, a user
   action). `BranchNames` (user-typed names at Run) stays on the wire and is honoured for every step
   kind: a user-named branch is the user's own act, not an agent's. The Run dialog shows the optional
   name inputs again for unnamed branches; placeholder for an agent step: "Empty: the agent asks you
   for one", else the `feat/<slug>` it shows today.
10. **Prompts.** `headless.space.suffix` becomes the one "branches only through request_branches"
   line and is included unconditionally in the step prompt and smart steps, and newly in the manual,
   review and start messages (TUI sessions now carry the tools). No new fragment.
11. **Discoverability.** Board `Task.branchRequestId` ('' when none, from the in-memory broker) so the
   Task tab shows a "waiting for branch approval" row that reopens the dialog after Escape.

### Engine (`apps/kira-space/internal/ade/branchrequest.go`, new)

- `branchRequest{ID, TaskID, Source, StepName string; Items []branchRequestItem; CreatedAt,
  ExpiresAt int64; result chan branchDecision}` (1-buffered). `branchRequestItem{CodeRepoID, Repo,
  Kind ("branch" | "worktree"), Branch (existing name for worktree kind), Base string}`.
  `branchDecision{Approved []string (code repo ids); Outcome (approved | denied | timeout | abandoned)}`.
- `branchRequests` on `TaskBoard`: `mu`, `byID map[string]*branchRequest`, `byTask map[string]string`.
  Methods `add` (refuses a task that has one), `resolve(id, decision) bool` (remove, close prompt,
  send; false when already gone), `abandonTask(taskID)`, `abandonAll()`, `get(id)`, `forTask(taskID)`.
- Prompt: `prompts.KindBranchRequest = "branch-request"`, `Ref` = request id, title
  `backend.prompt.branchRequest.title` (`{task}`), count title `backend.prompt.count.branchRequest.title`
  in `Router.countTitle`. Opened under `branchRequests.mu` (fast answer cannot close before open).
- `TaskBoard.RequestBranches(ctx, call, refs)`:
  1. Lock task. `spaceCtx`, `spaceWritable`, resolve every ref (an unknown or undeclared ref fails the
     whole call with today's `ToolError`, before any prompt: the agent fixes its list in one retry).
     Per repo: not mine → `failed` ("not yours to create"); named with a worktree (`worktreeOf`) →
     `existing` via `branchInfo`; else build an item: kind `branch` (unnamed) or `worktree` (named, no
     worktree); base via a new `newBranchBase(ctx, sb) (display, refusal string, err)` factored out of
     `startPoint` (one resolution, two callers); a refusal → `failed` with its text.
     Source/step label from `call`. Unlock.
  2. No items → return. Else `add` (one per task), set run note when `call.RunID` is an ADE run,
     `notifyBoard`, wait: `select` on result, timer (`BranchRequestWait`), `ctx.Done()`; timer and ctx
     branches go through `resolve` and take the decision if a user answer won the race (dbmcp shape).
  3. Clear run note. Abandoned → return `ctx.Err()` (nobody reads it). Timeout / denied → outcomes.
     Approved → lock task, `loadTaskCtx`, per approved item re-find the branch row by code repo id,
     re-check mine and unnamed/missing worktree, `ensureWorktree(generated)`, `SetBranchOrigin(agent)`
     on a fresh name, `startSetup` on a fresh worktree → `created`; errors → `failed` with
     `toolErr` text; unchecked → `denied`. `notifyBoard`.
- `ApproveBranchRequest(id, codeRepoIDs)`: ids must be a non-empty subset of the request's items
  (else `invalid`); `DenyBranchRequest(id)`; both return `resolved bool`. `BranchRequest(id)` returns
  the wire view or `ErrNotFound`-style sentinel the bridge maps to E_NOT_FOUND.
- `TaskBoard.Close`: `abandonAll` before waiting on goroutines. Archive and delete task:
  `abandonTask`. Board snapshot: `Task.BranchRequestID` from `forTask`.
- Remove `RequestBranch` (old), `spaceEnabled`. `prepareWithGrant`: `Space: true` always, append
  `SpaceToolIDs` always; doc comment updated. `superviseAgent`: `space := !rebase && !round` (drop the
  task read). `allowedTools`/`smartStep.spec` keep their `space` param (false for rebase/round only).
  `planSmartStep`: `SpaceNote` always. `startRun`: drop `Space` from `promptInput`.
- `prepareWorktrees(ctx, tc, names, agentStep bool)`: skip an unnamed, unnamed-by-user branch only when
  `agentStep`; `StartRun` passes `plan[cur].Def.Kind == adewire.KindAgent`. Comment rewritten.
- `ade/agenttools_test.go`: drop `kira_space_mcp: true` from the fixture workflow; delete the
  `RequestBranch` cases the new flow test covers (`TestSpaceTools_requestBranch`,
  `TestSpaceTools_startRunCreatesNoBranch`); keep the declare and branch_status cases, adapted (they
