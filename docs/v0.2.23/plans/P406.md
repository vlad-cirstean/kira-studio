## Design

### Name format

- `kira/<id>`, `<id>` = 10 chars of the Crockford lowercase alphabet (50 bits).
- `kira/` prefix marks app-generated agent branches in any git client and keeps them grouped. Board
  short name (`shortBranchName`) and worktree directory (`freePath` last segment) both show `<id>`.
- Length 10: collision odds negligible at repo scale, still short in a terminal prompt.
- `git check-ref-format --branch` always accepts it; it can never equal main or an integration
  branch in practice, so `validateAgentBranch` goes.
- Known edge, accepted: a repo with a local branch named exactly `kira` makes `git worktree add -b
  kira/<id>` fail (ref D/F conflict). The git refusal reaches the agent verbatim through
  `addWorktree`'s `invalid(...)` and `toolErr`; the row is released. No special case.

### Nanoid source

- Reuse `go-nanoid/v2`. No hand-rolled generator.
- Extract the shared bit into new package `internal/shortid`:
  - `const Alphabet = "0123456789abcdefghjkmnpqrstvwxyz"` (doc: Crockford base32 lowercase, no i, l,
    o, u).
  - `func New(n int) (string, error)` = `gonanoid.Generate(Alphabet, n)`.
- `internal/memory/ids.go` `newID` calls `shortid.New(idLen)`; drop its local `idAlphabet`. Same
  alphabet and length, so `memfmt.FactID` patterns and stored ids are unaffected.
- No unit test for `shortid` (thin wrapper).

### Engine: generated naming in `ensureWorktree`

- Replace `ensureWorktree`'s `title, wanted string` params with one value (in `setup.go`):

  ```go
  // newBranchName is how a not-created branch gets its name: wanted as given, generated, else derived from title.
  type newBranchName struct {
  	title, wanted string
  	generated     bool
  }
  ```

  Update the 6 callers mechanically: existing ones pass `newBranchName{title: ..., wanted: ...}`
  with today's values; `RequestBranch` passes `newBranchName{generated: true}`.
- `claimBranchName(sb, n newBranchName, inv)`:
  - `wanted != ""`: today's path, unchanged.
  - `generated`: loop `maxGeneratedNameTries = 5`. Each try `shortid.New(agentBranchIDLen)` (const
    10), name `agentBranchPrefix + id` (const `"kira/"`). `branchExists(inv, name)` -> next try.
    `SetBranchName` returning `repos.ErrBranchNameTaken` -> next try; other error returned. After
    the loop: `fmt.Errorf("ade: no free generated branch name after %d tries", ...)` (a real error,
    not a ToolError; `fail` reports it generically).
  - else: today's derived `feat/<slug>` loop, unchanged.
- Release on git failure stays as is (it already covers any claimed name).

### Engine: `RequestBranch`

- Signature `RequestBranch(ctx, taskID, ref string) (agentmcp.BranchInfo, error)`.
- Keep: task mutex, `spaceCtx`, `spaceWritable`, repo resolution, non-`mine` refusal, registered
  check.
- Named row (`sb.Name != ""`): idempotent. `ensureWorktree` with the row's name (it takes the
  `sb.Name != ""` branch and returns the existing or recreated worktree). Rename refusal goes (no
  name to compare).
- Unnamed row: `ensureWorktree(..., newBranchName{generated: true})`, then
  `SetBranchOrigin(agent)`, `sb.Name = res.Name`.
- `startSetup` on `res.Fresh`, `notifyBoard`, `branchInfo` as today. `BranchInfo.Branch` returns the
  generated name, so the agent learns it.
- Delete `validateAgentBranch`. Update `RequestBranch` doc comment.
