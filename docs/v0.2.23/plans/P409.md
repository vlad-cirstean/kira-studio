# P409 Finishing a task returns every artifact via MCP

Plan for `docs/v0.2.23/SPEC.md` row P409. Base: `2619918`. Discovery ran through `codegraph_explore`.

One sequential Sonnet implementer. No stream split: store, engine aggregator, MCP tools, wire, bridge
and UI form one chain; each commit reads the one before.

## Terms

- **Artifact** = something a task produced or points at, outside its own records: change request (PR/MR),
  issue (Jira, host issue), branch, deployment, doc, link.
- **Detected** artifact = derived on read from data the app already has (task fields, git, code host).
  **Stored** artifact = a row an agent or the user reported (things the app cannot detect: docs,
  preview deployments, external links).
- **Finish** = the MCP calls that end an agent's work on a task: `finish_step` (run grants) and
  `handover` with `finished: true` (task sessions without a run). Moving a task to Done stays a user act.

- **Excluded from artifacts** (justified): notes and handovers are the task's own records, already fed
  to the next stage; runs, sessions, logs and automation runs are process history, already on the board
  and reachable through `run_outcome`; commits are reachable from the branch artifact and would bloat a
  reply. Worktree path rides on the branch artifact (`ref`), not as its own kind.
- **Migrations**: latest `0057_p407_ade_handovers.sql`; `migrations/embed.go` lists names.
- **Fake agent** records each scripted MCP reply as `<dir>/mcp-<tool>-<n>.json` (`recordMCPResult`,

- **P417** later adds Jira through `acli` behind an issue-tracker abstraction: title, status, associated
  PRs from a Jira key/link. The aggregator below takes that as one more source.

## Design

### Artifact model

```go
// adewire (wire contract, TS mirror in wire.ts)
type Artifact struct {
	ID        string `json:"id"`        // stored row id; '' for detected
	Kind      string `json:"kind"`      // changeRequest | issue | branch | deployment | doc | link
	Title     string `json:"title"`
	URL       string `json:"url"`       // '' none
	Ref       string `json:"ref"`       // display ref: #12, PROJ-7, worktree path, short sha, file path
	Status    string `json:"status"`    // open, merged, closed, deployed, stale, pushed, local; '' none
	Repo      string `json:"repo"`      // repo nickname; '' none
	Source    string `json:"source"`    // task | host | git | agent | user (P417 adds its tracker id)
	CreatedAt int64  `json:"createdAt"` // 0 unknown
}
type ArtifactGap struct {
	Source string `json:"source"` // host | git | <extra source name>
	Repo   string `json:"repo"`   // '' when not repo-bound
}
type ArtifactsResult struct {
	Artifacts []Artifact    `json:"artifacts"`
	Gaps      []ArtifactGap `json:"gaps"` // sources that failed or timed out; the list is partial
}
```

- `agentmcp` (shared `internal/`, cannot import `adewire`) gets the agent-facing twins:
  `ArtifactInput{Kind, Title, URL, Ref}`, `Artifact{Kind, Title, URL, Ref, Status, Repo, Source}` (no id,
  no time: tokens), `ArtifactGap`, `TaskArtifacts{Artifacts, Gaps}`. The engine converts; one small
  func, no logic.
- Reportable kinds (agent and user): `changeRequest`, `issue`, `deployment`, `doc`, `link`. `branch` is
  never reported: branches come only from `request_branches` and the user.
- Kind normalisation: a reported URL that `TaskBoard.hostLink` recognises takes the provider's kind
  (`changeRequest`/`issue`) and ref; else the given kind stays.

### Store: migration `0058_p409_ade_task_artifacts.sql`

```sql
-- P409: artifacts agents and the user report for a task. Detected artifacts (PRs, branches,
-- deployments, task links) are derived on read and never stored here.
CREATE TABLE ade_task_artifacts (
  id TEXT PRIMARY KEY,
  task_id TEXT NOT NULL REFERENCES ade_tasks (id) ON DELETE CASCADE,
  kind TEXT NOT NULL CHECK (kind IN ('changeRequest', 'issue', 'deployment', 'doc', 'link')),
  title TEXT NOT NULL,
  url TEXT NOT NULL DEFAULT '',
  ref TEXT NOT NULL DEFAULT '',
  source TEXT NOT NULL CHECK (source IN ('agent', 'user')),
  step_id TEXT NOT NULL DEFAULT '',
  run_id TEXT NOT NULL DEFAULT '',
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  CHECK (url <> '' OR ref <> '')
);
CREATE UNIQUE INDEX ade_task_artifacts_url ON ade_task_artifacts (task_id, url) WHERE url <> '';
CREATE INDEX ade_task_artifacts_task ON ade_task_artifacts (task_id, created_at);
```

- `model.AdeTaskArtifact`; methods on `AdeTaskRepo` in new `repos/adeartifact.go`: `Artifacts(taskID)`
  (oldest first), `UpsertArtifact(a) (model.AdeTaskArtifact, error)` (same `(task, url)` updates kind,
  title, ref, `updated_at`; empty url always inserts), `GetArtifact(id)`, `DeleteArtifact(id)`,
  `CountArtifacts(taskID)`.
- Rows survive archive and restore (child of the task; cascade only on task delete). Plain create: no
  migration test.
- Limits (constants in `agentmcp/artifacts.go`, engine and bridge reuse them): title 1..200 bytes,
  url <= 2048 bytes and absolute `http`/`https` (`net/url`), ref <= 512 bytes, url or ref required,
  20 per call, 200 stored per task (refusal names the cap).

### Engine aggregator (`apps/kira-space/internal/ade/artifacts.go`)

```go
// ArtifactSource is one supplier of a task's artifacts. Built-ins cover task links, repos and stored
// rows; TaskBoardDeps.ArtifactSources appends more (P417's issue tracker).
type ArtifactSource interface {
	Name() string // gap source label, stable id
	Artifacts(ctx context.Context, s ArtifactScope) ([]adewire.Artifact, []adewire.ArtifactGap, error)
}
type ArtifactScope struct {
	Task     model.AdeTask
	Rows     []model.AdeTaskBranch // every branch row of the task, detached included
	Archived bool
}
```

- `TaskBoard.TaskArtifacts(ctx, taskID) (adewire.ArtifactsResult, error)`: `GetTask` (archived allowed),
  `BranchesOfTask`, then every source concurrently (`errgroup`, limit `boardFanOut`), each under
  `artifactSourceTimeout = 5 * time.Second` (precedent `archivedHostTimeout`). A source error or timeout
  becomes a gap `{Source: Name()}`, never a call error. Merge, dedup, sort, return. `Gaps` never nil.
- **Dedup**: same non-empty URL, or same `(kind, repo, ref)` when URL is empty. Detected wins over
  stored (fresher status); the hidden stored row stays in the table. Among detected, first source in
  registration order wins (so P417's tracker PR entry folds into the host's).
- **Sort**: kind order changeRequest, issue, branch, deployment, doc, link; then `CreatedAt`, then title.
- **Built-in sources**, registered in this order:
  1. `taskLinkSource` (`task`): `HostURL` via `hostLink` (kind `changeRequest`/`issue`, ref = link ref;
     unrecognised URL = `link`); Jira fields as kind `issue`, title = key, ref = key, url = `JiraURL`.
     P417 replaces the Jira half by its tracker source (title and status filled); the static entry
     then dedups by URL.
  2. `repoSource` (`host`, `git` gaps per repo): rows grouped by repo (`branchesByRepo`). Per repo:
     - change requests: `resolveRepoHost(ctx, entry, namedRows)` live; per row fall back to the
       archive snapshot `row.ChangeRequest` (same rule as `archived.go`). Kind `changeRequest`, title,
       ref `#<n>`, status = state, url. Detached rows included: a PR stays a real artifact. Host kind
       not `ok` adds gap `{host, repo}`.
     - branches: named rows that are not detached (`ArchivedAt == nil`, or equal to the task's
       `ArchivedAt` for an archived task). Kind `branch`, title = name, url = branch URL from
       `resolveRepoHost`, ref = worktree path (live only), status `merged` (`MergedAt` set, or
       `MergedIntoMain` from git facts), `pushed` (git facts `Upstream` set), else `local`,
       `CreatedAt = AddedAt`. Archived tasks: `merged` or `local` from the row alone.
     - git facts (live task only): `repoFacts(ctx, repoID, liveRowsOfThatRepo, setups)` over every
       live row of the repo, the same input `Board` uses, so stacked bases resolve. From the task's
       rows take branch status (above) and `Deployments` with status `deployed` or `stale`: kind
       `deployment`, title = env, ref = short deployed SHA, status, repo. Archived tasks skip git
       facts. A repo that fails to open adds gap `{git, repo}`.
     Factor: one `repoArtifacts(ctx, scope, repoID, rows)`; reuse `resolveRepoHost`, `repoFacts`,
     `openRepo`; no copy of `archivedRepo`.
  3. `storedSource` (`stored`): `Artifacts(taskID)` rows, `ID` set, source `agent`/`user`.
- `TaskBoardDeps.ArtifactSources []ArtifactSource` (nil today), appended after the built-ins. `appwire`
  passes nothing yet. P417 adds its tracker here; no aggregator change.
- **Writes** (all under `taskMu`, refuse an archived task via `loadTaskCtx`):
  - `ReportArtifacts(ctx, call agentmcp.SpaceCall, in []agentmcp.ArtifactInput) (agentmcp.ReportArtifactsResult, error)`:
    validate each (`agentmcp.CheckArtifact` returns refusal text, wrapped as `agentmcp.ToolError`),
    normalise kind, cap check, upsert source `agent`, `step_id` = `call.StepID` or the run's step,
    `run_id` = `call.RunID`. Result `{recorded: n}`.
  - `AddArtifact(ctx, args adewire.AddArtifactArgs) (adewire.Artifact, error)`: same rules, source
    `user`, refusals as `invalid(...)`.
  - `RemoveArtifact(ctx, id)`: stored rows only (detected rows have no id).
  - Each write calls `notifyBoard` so open lists refetch.

### MCP (`internal/agentmcp/artifacts.go`, `space.go`, `mcp.go`, `handover.go`)

- **Reporting**: separate tool `report_artifacts`, not an argument on `finish_step`. Reasons: artifacts
  are made mid-session and a crash before finish must not lose them; interactive sessions call
  `handover` several times or never; `finish_step` is "exactly once, last action", so a reply that
  shows something missing must still leave a way to add it; one path for runs and sessions alike.
  - Args `artifacts` (1..20 of `{kind, title, url, ref}`). Part of the Space tool set: `addSpaceTools`
    adds it, `SpaceToolIDs` gains `{ServerName, "report_artifacts"}`, so every grant that lists Space
    tools (step runs, TUI sessions, review agent, Space smart scripts) gets it with no new flag. Studio
    has no Space grant: no tool.
  - `SpaceTools` gains `ReportArtifacts(ctx, SpaceCall, []ArtifactInput) (ReportArtifactsResult, error)`
    and `TaskArtifacts(ctx, taskID string) (TaskArtifacts, error)`; `*ade.TaskBoard` implements both
    (`TaskArtifacts` converts the adewire result).
  - Ack: typed result `ReportArtifactsResult{Recorded int}` (same style as the other Space tools).
- **Finish returns artifacts**: helper `s.artifactsReply(ctx, req, taskID) ([]mcp.Content, any)`:
  bounded by `callCtx` plus a 10 s cap; on error logs and returns one text line
  `headless.artifacts.unavailable`, never fails the call. Output: one `TextContent` = header
  `headless.artifacts.header` + newline + compact JSON `{"artifacts":[...],"gaps":[...]}`, and
  `StructuredContent` = the same value (if the go-sdk refuses structured content on a tool without an
  output schema, keep only the text block and read it in the flow test). At most 100 artifacts; past
  that the header line names the remainder count.
  - `finishStep`: when `g.Space && g.TaskID != "" && s.space != nil`, append after the ack text. Takes
    ctx now. Studio and rebase runs keep the single ack block.
  - `handover` with `finished: true`: append after `headless.handover.ack`. `finished: false` unchanged.
- No change to `task_info`: the reply cost lands only at finish.
