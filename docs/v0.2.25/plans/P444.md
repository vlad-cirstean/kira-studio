## CLI facts (claude 2.1.316)

- `claude mcp list`: no flags, no JSON. Health-checks every server (spawns stdio servers, connects http)
  and prints one line per server. Output seen:

  ```
  Checking MCP server health…

  remote: http://127.0.0.1:9/mcp (HTTP) - × Failed to connect — ECONNREFUSED: Unable to connect. Is the computer able to access the url?
  local: python3 /tmp/.../srv/mcp.py - √ Connected
  ```

  Prints stdio args and full URL, never headers or env. Glyphs vary by platform (`√`/`✓`, `×`/`✗`).
- `claude mcp get <name>` prints `Headers:` and `Environment:` in plain text. Kira must never run it.
- User-scope `mcpServers` load only when `--setting-sources` contains `user`. `""`, `local`, `project`
  each load none. `--strict-mcp-config` drops them too.
- `--settings '{"allowedMcpServers":[{"serverName":"local"}]}'` limits loaded servers to the named ones,
  `--mcp-config` servers included: the Kira grant must be in the list or claude prints
  `Warning: MCP server blocked by enterprise policy: kira` and drops it. Verified via the init event.
- `--settings '{"disableAllHooks":true}'` stops user `SessionStart` hooks (marker file absent).
- With `--setting-sources user`, user `permissions.allow` rules apply: `Bash(touch:*)` in user settings
  ran `touch` under `--permission-prompts none` without `--allowedTools`. `allowManagedPermissionRulesOnly`
  in `--settings` does not stop that. No flag found that loads user MCP servers without the user
  settings file.
- `--allowedTools mcp__<server>` allows every tool of that server (control run denied both tools; this
  run called both, no denials).
- stream-json `system/init` lists `mcp_servers` (name, status, source) and tool names, but only after the
  first user message, so reading it costs a model call. Rejected for listing.

## Design

### Listing: ask claude

- `UserMCPServers` runs `claude mcp list` and parses its stdout. Kira never opens `~/.claude.json`.
- Run it the way `RunHeadless` runs claude: user's login shell (`loginshell.ResolveShell`), so stdio
  servers see the same `PATH` a run sees and the health status matches. Env: `ScrubEnv(os.Environ())`.
  cwd: the caller's app home (no `.mcp.json` there). Timeout 30 s.
- Parser, one line at a time: `<name>: <target> - <status>`. Split name at the first `": "`, status at
  the last `" - "`. Keep a line only when name matches `^[A-Za-z0-9_-]+$` (claude's server-name charset;
  drops headers, blank lines, the "No MCP servers configured" line and claude.ai connectors whose names
  have spaces).
  - Transport: target ending ` (HTTP)` is `http`, ` (SSE)` is `sse`, else `stdio`.
  - Target: http/sse the URL host only; stdio the base name of the first word. Never args, path, query
    or the rest of the line (unchanged `UserServer.Target` contract).
  - Status: text after the glyph. `Connected` is `connected`, `Failed…` is `failed`, text naming
    authentication is `needsAuth`, `Pending…` is `pending`, else `unknown`. Implementer confirms the
    exact strings on the installed CLI (seed a server that needs OAuth if feasible; else keep `unknown`).
- Output never leaves the parser: not logged, not in an error. A non-zero exit or timeout returns a fixed
  error ("could not list your Claude MCP servers", plus exit code or "timed out"), never stdout/stderr.
- Cache 30 s per cwd with `golang.org/x/sync/singleflight` coalescing (already a dependency: issuetracker
  uses it). Opening the picker and a preview right after it share one spawn.
- `UserServer` gains `Status string` (`json:"status"`).

### Tools: no listing

- Kira can no longer connect to a user server, so `UserMCPTools`, `harness.UserTool`, `listTools`,
  `headerTransport`, `firstLine`, the `McpTools` binding and `runs.mcpTools` go.
- A ticked server grants either all its tools or named tools. New field `MCPChoice.AllTools bool`
  (`json:"allTools"`), mirrored in `harness.MCPTools.AllTools` and `mcpChoiceSchema.allTools`.
- `ToolArgs` renders `AllTools` as `mcp__<server>` (verified above), else one `mcp__<server>__<tool>` per
  name, as today. TS `allowedToolsOf` mirrors it.
- `validMCP`: `AllTools` true needs `Tools` empty (normalize to `[]`); false needs at least one tool
  (existing message). Stored scripts decode `allTools` as false and keep their tools: no migration.

### Runs: claude loads its own config

- `harness.HeadlessSpec` gains two neutral fields:
  - `UserMCP []string`: servers from the user's own agent config that the agent loads itself, by name.
    Kira never reads their definitions.
  - `GrantMCP []string`: names of the servers in `MCPConfigs` (Kira's grants).
  - `Isolated` doc: loads no settings file and only `MCPConfigs` servers; with `UserMCP`, the user's own
    settings source loads too, bounded to `GrantMCP` plus `UserMCP` servers, hooks off.
- Claude `Script`, `Isolated` with `UserMCP` non-empty:
  - `--setting-sources user` (via `settingSources`), not `''`.
  - No `--strict-mcp-config`. `--permission-prompts none` stays.
  - `--settings '<json>'`, single-quoted, `{"disableAllHooks":true,"allowedMcpServers":[{"serverName":g},…,{"serverName":u},…]}`,
    grant names first, then user names, in order.
  - Everything else unchanged. `Isolated` without `UserMCP`: argv byte-identical to today.
- `harness/claude` cannot import `agentmcp` (cycle: `agentmcp` imports `harness/claude`), so callers
  pass `GrantMCP: []string{agentmcp.ServerName}`.
- `scriptruns.launchSmart`: drop the `WriteUserMCPConfig` block and `releaseUser`; set
  `UserMCP: p.mcp`, `GrantMCP: []string{agentmcp.ServerName}`, `MCPConfigs: []string{cfg}`.
- `ade.superviseAgent`: drop the `WriteUserMCPConfig` block; when `l.smart.mcpNames()` is non-empty set
  `spec.UserMCP` and `spec.GrantMCP` the same way.
- Preview blocker (`smartBlocker`): `agent.UserMCPServers(ctx, s.Home)`; a ticked name missing from the
  list keeps `ErrServerGone` and its text. A list failure blocks with the fixed error above.
- `MCPHost` after P444: `MCPConfig`, `MCPToolName`, `ToolArgs`, `UserMCPServers(ctx context.Context, dir
  string) ([]UserServer, error)`, `MCPInstaller`. `WriteUserMCPConfig` and `UserMCPTools` removed.
  `getenv` leaves the signature: the CLI resolves its own config dir.

### User-visible change (state plainly in docs and copy)

- Picker lists the servers `claude mcp list` reports from the app home: user scope (plus local scope of
  that folder, normally none). Each row shows name, transport, host or command name, and claude's own
  health status (new).
- Opening the picker runs claude's health check once (starts every stdio server briefly); before, Kira
  started only the enabled server. Cached 30 s.
- No per-server tool list and no tool descriptions. Enabling a server ticks "All tools" by default;
  untick it to type tool names.
- A run that ticks a user server loads the user's Claude settings file: their permission allow rules,
  env and plugins apply; hooks are off; only the ticked servers and Kira's report server load. A run with
  no user server stays fully isolated, argv unchanged. New Known open item (below).
- No per-run copy of user server entries on disk any more.
- Removed-server blocker text unchanged.

## G5 extension

In `scan`, `inClaudeHarness := strings.HasPrefix(dir, "internal/harness/claude")` (non-test files, all
subpackages). Findings, each `add("G5", …, why+g5Rule)`:

- String literal (including struct tags; `strconv.Unquote` handles backquotes) containing `.claude.json`:
  `literal ".claude.json" (holds MCP headers and env)`.
- String literal containing `json:"headers"`: `struct tag json:"headers" (decodes stored MCP headers)`.
  Kira's own grant renders `"headers"` as a map key in `mcp.go`: plain `"headers"`, not flagged.
- Composite literal with adjacent `"mcp"`, `"get"` elements (pattern of `hasAuthToken`):
  `claude mcp get argv (prints stored headers and env)`.
- Call `<x>.Header.Set(...)` or `<x>.Header.Add(...)`: `request header injection`.
- `*ast.FuncDecl` named `RoundTrip` with a receiver: `http.RoundTripper (header-injecting transport)`.
- `permanentExemptions` gains `"G5 internal/harness/claude/sandbox.go": "names ~/.claude.json as a
  sandbox write path; Kira never opens it"`.
- `hooks/http.go` reads `r.Header.Get("Authorization")` (Kira's own hook token): `Get` is not flagged.
- Header check matches both `x.Header.Set` and `x.Header().Set`. Checked at base: outside `usermcp.go`,
  the five patterns hit only `sandbox.go:33`, so no other exemption is needed.
- Proof the guard bites: implementer copies base `usermcp.go` in under a spare name once
  (`git show d5f457e07:internal/harness/claude/usermcp.go > internal/harness/claude/usermcp_base.go`; the
  guard parses, never compiles, so duplicate symbols do not matter), runs
  `go test ./internal/conventiontest/`, sees G5 findings for the literal, the tag and `RoundTrip`, then
  deletes the file. Quote the finding lines in Result. Nothing of this is committed.
