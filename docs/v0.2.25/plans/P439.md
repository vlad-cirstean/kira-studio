### D2 Cluster client: `k8s.io/client-go` v0.37.2 (+ `k8s.io/api`, `k8s.io/apimachinery` v0.37.2)

- License: Apache-2.0 for all three. Transitive set (gnostic-models, json-iterator, cbor, go-openapi,
  structured-merge-diff, sigs.k8s.io/yaml, klog, kube-openapi): Apache-2.0, MIT or BSD. Implementer
  re-checks every new `go.sum` module's LICENSE file (package level) and lists them in the Result.
  No module may be non-OSS.
- Real requirements a `kubectl` runner (`internal/toolexec`) misses: kubectl is not guaranteed
  installed; per-call process spawn plus output parsing for lists; no typed errors (401/403/404 need
  distinct UI states, and P440 needs them for MCP errors); log follow needs cancellable streaming.
- Measured (scratch module, `go build -ldflags="-s -w"`, linux/amd64): base hello 1.5 MB; clientcmd +
  discovery + dynamic + typed core/v1 25.5 MB; same plus `k8s.io/kubectl/pkg/describe` 62 MB
  (pulls cli-runtime, kustomize). The Studio binary already links much of the shared set
  (protobuf, x/net, oauth2), so the real delta is lower. Implementer records the Studio binary
  size before and after in the Result.
- Declined `k8s.io/kubectl/pkg/describe`: +37 MB stripped for text formatting alone. Describe is
  built from the object itself (D7). This is not a hand-rolled parser; it is field selection from
  `unstructured` plus an events list.
- Use only: `tools/clientcmd` (kubeconfig), `discovery` + `discovery/cached/memory`, `rest`,
  `kubernetes/typed/core/v1` (namespaces, events, pod logs). No `dynamic`: lists use the server-side
  Table format through the discovery REST client (D6), single gets use raw JSON.
- `go.mod`/`go.sum` are Stream C's (streams.md). No other stream touches them.

### D3 Kubeconfig, environment, auth plugins

- Source: `KUBECONFIG` (path list), else `~/.kube/config`, via `clientcmd.NewDefaultClientConfigLoadingRules`
  with `ExplicitPath` unset and `Precedence` set from the resolved `KUBECONFIG`.
- A Finder-launched app has launchd's minimal env: no `KUBECONFIG`, and a PATH without Homebrew, so
  exec credential plugins (`aws`, `gke-gcloud-auth-plugin`, `kubelogin`) fail. Resolve once, lazily,
  cached for the process: run `$SHELL -l -i -c` (only when `$SHELL` is absolute and executable,
  `toolexec.IsExecutable`; same rule as `claude/locate.go`) through `toolexec.RunIO` with a 5 s
  timeout, script `printf '\n__KIRA_KUBE_ENV__%s\0%s\0' "$PATH" "$KUBECONFIG"`. Parse after the last
  marker (interactive shells print noise). Process env wins for `KUBECONFIG` when set; PATH is the
  shell's when found, else the process PATH. Failure or timeout falls back to process env, logged
  with `slog.Warn` scope `kubernetes`.
- Exec plugins: before building a context's client, for each `AuthInfo.Exec` whose `Command` is not
  absolute, resolve it against the resolved PATH (`filepath.SplitList` + `toolexec.IsExecutable`),
  set the absolute path, and append `PATH=<resolved>` to `Exec.Env`. Go's `exec.Command` looks up the
  name with the process PATH, so the rewrite is required, not cosmetic. Unresolved: leave as is
  (client-go reports the missing binary; mapped to reason `plugin`).
- No stdin is attached: an exec plugin with `interactiveMode: Always` fails; mapped to reason
  `plugin` with a message telling the user to run `kubectl` once in a terminal. Recorded in
  ARCHITECTURE Known open items.
- Legacy `auth-provider` (removed from client-go): surfaces as reason `config`.
- Seam `WithEnv(func() Env)` (`Env{Path, Kubeconfig string}`) replaces the shell probe; the flow
  harness always sets it from the test process env, so no flow test runs the user's shell.
- Rate limits: `rest.Config.QPS=50`, `Burst=100` (discovery fan-out). Per-call timeout 15 s for
  discovery, get, events; 30 s per list page. Status probe 5 s.

### D4 Cluster entity ("connection-like"), shaped for P440

- One stored row per (context name, server URL): a stable `id` that P440 hangs per-cluster MCP
  settings on. Context names are unique in the merged kubeconfig; the server is in the key so a
  reused name pointing at a new cluster starts fresh (fail closed for P440's default `ask`).
- Migration `0049_p439_kube_clusters.sql` (Stream C reserves 0049 upward):

  ```sql
  CREATE TABLE kube_clusters (
    id TEXT PRIMARY KEY,
    context TEXT NOT NULL,
    server TEXT NOT NULL,
    created_at TEXT NOT NULL,
    last_seen_at TEXT NOT NULL,
    UNIQUE (context, server)
  );
  ```

  P440 adds columns with `ALTER TABLE ... ADD COLUMN` (`mcp_enabled`, `mcp_description`, per-operation
  modes); nothing here gets reworked. No `description`/MCP column in P439: scope left out stays out.
- Rows are never deleted when a context disappears: they are just not listed, so P440 settings
  survive a temporary kubeconfig change. No sort or color column: order comes from the kubeconfig
  (D9).
- `internal/kubernetes` declares `ClusterStore` (`Ensure(context, server string, now time.Time)
  (ClusterRecord, error)`, `Get(id string) (ClusterRecord, bool, error)`). Studio
  `repos.KubeClustersRepo` implements it (same direction as `DockerRestoreRepo` /
  `docker.RestoreStore`), so the domain package never imports `repos`. `Ensure` is one
  `INSERT ... ON CONFLICT(context, server) DO UPDATE SET last_seen_at=excluded.last_seen_at RETURNING id, ...`.
- Wire type `Cluster`: `id`, `context`, `cluster` (kubeconfig cluster name), `server`, `user`,
  `namespace` (context default, `""` if unset), `current` (is `current-context`), `source` (file the
  context came from, `LocationOfOrigin`). P440 extends the same struct.

### D5 Backend package and surface

Package `apps/kira-studio/internal/kubernetes` (Studio-only, like `dbmcp`; P440 consumes it in-app).
Split: domain `Service` (ctx-taking methods returning wire types, what P440 calls) and
`BoundService` (Wails surface, `context.Background()` + window streams), mirroring
`docker.BoundService`. Bridge shim `apps/kira-studio/internal/bridge/kubernetes.go`:
`type KubernetesService struct{ *kubernetes.BoundService }`.

Bound methods (all args structs, JSON camelCase):

| Method | Args | Result |
|---|---|---|
| `Clusters()` | none | `ClustersResult{config: {state: ok\|missing\|invalid, paths []string, message}, clusters []Cluster}` |
| `Status` | `{clusterId, refresh}` | `Status{state: ok\|unavailable, reason: unreachable\|unauthorized\|forbidden\|plugin\|config\|timeout, message, serverVersion}` |
| `Namespaces` | `{clusterId}` | `{namespaces []string, restricted bool, fallback string}` |
| `Kinds` | `{clusterId}` | `{kinds []Kind, partial bool}` |
| `List` | `{clusterId, kind, namespace, labelSelector}` | `ListResult{columns []Column, rows []Row, truncated bool}` |
| `Describe` | `{clusterId, kind, namespace, name}` | `Description` (D7) |
| `LogsOpen` | `{windowKey, streamId, clusterId, namespace, pod, container, previous, tail, timestamps, follow}` | none |
| `LogsClose` | `{streamId}` | none |

- Package functions, not methods (Wails binds every exported method): `CloseWindowBound(b, windowKey)`.
  `ServiceShutdown()` method ends every stream (Wails skips it in bindings).
- `Status` returns cluster trouble as `state: unavailable` (no error), like `docker.Status`; it errors
  only on an unknown `clusterId` (`E_NOT_FOUND`). Other methods map errors (`errors.go`):
  401 to `E_UNAUTHORIZED`, 403 to `E_FORBIDDEN`, 404 to `E_NOT_FOUND`, timeout to `E_TIMEOUT`, dial
  failure to `E_UNAVAILABLE`, plugin/config to `E_UNAVAILABLE` with the reason in `details`. Messages
  through `ipcerr.T` with new `backend.studio.kubernetes.*` keys (`.error` role).
- `Kind`: `key` (`v1/pods`, `apps/v1/deployments`, `<group>/<version>/<resource>`), `group`,
  `version`, `resource`, `kind`, `namespaced`, `category`, `logs` (true only for core `pods`).
  Source: `ServerPreferredResources`; keep resources whose verbs include `list` and `get`; drop
  subresources (name contains `/`). `discovery.IsGroupDiscoveryFailedError` keeps the partial result
  and sets `partial`. Category table for built-in groups: `workloads` (pods, deployments,
  replicasets, statefulsets, daemonsets, jobs, cronjobs), `network` (services, endpointslices,
  ingresses, ingressclasses, networkpolicies), `config` (configmaps, secrets, resourcequotas,
  limitranges, horizontalpodautoscalers, poddisruptionbudgets), `storage` (persistentvolumeclaims,
  persistentvolumes, storageclasses), `access` (serviceaccounts, roles, rolebindings, clusterroles,
  clusterrolebindings), `cluster` (namespaces, nodes, events, priorityclasses, runtimeclasses,
  customresourcedefinitions), else `custom`. Sorted by category order, then kind.
- Client cache: per cluster id, `{restConfig, discovery (memory-cached), core}` under a mutex, built
  through `singleflight` (an exec plugin can take seconds). `Status{refresh:true}` reloads kubeconfig,
  drops that cluster's client and its discovery cache. `Clusters()` reloads kubeconfig every call
  (cheap) and drops cached clients whose context's cluster, user or server changed.
- Unknown id in any call: reload kubeconfig once, then `E_NOT_FOUND`.
- Op log: none (the Docker module records none either). P440 decides MCP stamping.
- Read only: no method issues anything but GET. Write this as a package doc line and keep it true.

### D6 Lists: server-side Table, paging, cap

- One GET per page via the discovery REST client:
  `AbsPath(/api/v1/... or /apis/<g>/<v>/...[/namespaces/<ns>]/<resource>)`, params `limit=500`,
  `continue`, `labelSelector`, `includeObject=Metadata`, header
  `Accept: application/json;as=Table;v=v1;g=meta.k8s.io`. Decode into `metav1.Table`; each row's
  `Object` into `metav1.PartialObjectMetadata`. Gives kubectl's `get` columns for every kind,
  CRDs included, with no per-kind code.
- Columns: `ColumnDefinitions` with `priority == 0` (kubectl default, not `-o wide`). When the kind
  is namespaced and `namespace == ""` (all namespaces), prepend a `Namespace` column. Cells become
  strings (`fmt.Sprint`; nil to `""`).
- `Row{key: uid, name, namespace, cells []string}`.
- Cap: stop after 5 000 rows (`maxListRows`) and set `truncated`. Seam `WithListLimits(page, max int)`
  for the flow test. Cluster-scoped kinds ignore `namespace`.
- Invalid label selector: validate with `labels.Parse` first, `E_BAD_REQUEST` with the parse message.

### D7 Describe

`Description`:
`kind`, `apiVersion`, `name`, `namespace`, `uid`, `created` (RFC3339), `labels map`, `annotations map`,
`owners []{kind, name}`, `conditions []{type, status, reason, message, lastTransition}` (from
`status.conditions` when present), `containers []{name, init bool}` (pods only: `initContainers`,
`containers`, `ephemeralContainers`), `events []{type, reason, message, count, first, last, source}`,
`manifest string` (YAML).

- Object: raw GET JSON, decode to `unstructured.Unstructured`, delete `metadata.managedFields`, then
  `sigs.k8s.io/yaml.JSONToYAML` for `manifest`.
- Secrets (core `secrets`): replace every `data` and `stringData` value with `<N bytes>` before any
  rendering, and drop the `kubectl.kubernetes.io/last-applied-configuration` annotation (it can
  carry values). Secret values never cross the bridge. P440 inherits this.
- Events: core/v1 `Events(ns).List` with `fieldSelector=involvedObject.uid=<uid>`; namespace is the
  object's, or `""` (all) for cluster-scoped. Sort by last timestamp descending, cap 200. An events
  list failure (403) leaves `events` empty, never fails the describe.

### D8 Logs: streaming, limits

- Pods only (`Kind.logs`). `LogsOpen` validates args (`ipcerr.Contract`), registers the stream under
  `streamId` (duplicate is `E_CONTRACT`), opens `CoreV1().Pods(ns).GetLogs(pod, &PodLogOptions{Container,
  Previous, Timestamps, Follow, TailLines, LimitBytes}).Stream(ctx)`; open errors return directly
  (unknown container, previous not found). Later failures arrive as the final event.
- Limits: `tail` is 100, 1 000, 5 000 or -1 (all). `LimitBytes` 8 MiB always for a non-follow open
  and for the initial backlog of `tail: -1`; a follow stream after the backlog is unlimited and lives
  only while the view is open. Line cap 64 KiB, truncated with `…`. Frontend keeps the newest
  20 000 lines (same as Docker).
- Own small line framer in `logs.go` (Docker's is unexported in root `internal/docker`, which Stream
  C does not own): split on `\n`, strip one trailing `\r`, cap length, keep the partial tail across
  reads, flush at EOF, split the RFC3339Nano timestamp prefix when `timestamps`.
- Emit: `appevent.NewCoalescer(16ms, 500 lines)` to `EmitTo(windowKey, "kira:kubernetes:logs",
  LogsEvent{streamId, lines []{ts, text}, ended, error})`. No stdout/stderr split: the API merges them.
- Registry per window: `LogsClose`, `CloseWindowBound` (wired in `appwire` `OnWindowClosing`),
  `ServiceShutdown`, and the `Status{refresh}` client reset (that cluster's streams) cancel streams.
  Streams run only while the Logs view is mounted.
