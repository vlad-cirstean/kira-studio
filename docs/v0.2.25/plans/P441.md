## Decisions

### D1 Flow: banner per module, dialog on click, nothing at start

- Docker: unchanged flow. `RestoreBanner` and its "Review containers" button stay; the dialog it opens renders the
  shared component. Backend, queries, live-sync push and trigger unchanged.
- Runs (Space and Studio, same code): when the offer has items, an info `Alert` strip sits at the top of
  `AutomationsPanel` under `PanelHeader`, mirroring Docker's banner. Its button opens the Runs restore dialog. No
  auto-open, no claim, no host, no Pinia store: the banner owns `open = ref(false)` like Docker's.
- Both dialogs behave like Docker today: confirm restarts the checked items; an item that started leaves the offer;
  deselected and failed items stay, so the banner lingers until the user dismisses. "Don't restore" forgets the whole
  offer. Escape/X closes without change. The dialog closes when every chosen item started; any failure keeps it open
  with row errors.

### D2 "Was running" for scripts: `restore_pending`, taken at boot

- Migration per app adds `restore_pending`. `Repo.finish` and `Repo.FailRunning` set it in the UPDATE that ends the
  run, keyed on outcome source `restart` like `resumeExpr`. Quit (terminal, smart, headless) and crash both mark. A
  user stop, window close, exit or timeout never marks.
- Boot `Recover` takes the marks (`TakeRestore`: clear and return ids in one statement) into `Service.restore`. The
  offer lives for that app session: answered, or replaced by the next quit's set. Nothing accumulates across
  sessions. An offer the user ignores is gone after the next restart; acceptable, since the banner sat in Runs the
  whole session.
- Declined: deriving the set from source and timestamps (cannot separate sessions); a `settings` key (user preferences
  only); a JSON file (state outside the DB).
- Purge (`keepFinished = 500`) drops a marked row only after 500 newer runs; the offer then omits it.

### D3 Backend per run (`internal/scriptruns/restore.go`, `bound.go`)

- `RestoreState() (RestoreState, error)`: offered runs newest first, deduped by run key (`scriptId`, `taskId`,
  `branchId`). Each item is planned against the current script (`resumeArgs` + `s.plan`; provider pinned for a
  resumable smart run) and gets a status:
  - `ready`: no blocker, no missing param, no live run of the key.
  - `running`: a live run of that key exists now. Reason `alreadyRunning`.
  - `needsInput`: a secret or required param is missing. Reason `restoreNeedsInput` ("Kira never stores secrets, so
    start it yourself").
  - `gone`: script deleted, or plan error `CodeNotFound`.
  - `blocked`: plan blocker or other plan error; reason carries the text.
  - Fields: `runId`, `scriptId`, `scriptName`, `color`, `kind`, `trigger`, `taskTitle`, `branchLabel`, `cwd` and
    `command` from the new plan (smart: prompt excerpt, 160 runes), `model`, `resume`, `params` (masked as stored),
    `endedAt`, `hash`, `status`, `reason`.
- `Restore(RestoreArgs{Items []{RunID, Hash}}) (RestoreResult, error)`: an id outside the offer refuses the call
  (`restoreNotOffered`). Per item, in order:
  - smart and resumable: under `startMu`, check `Runs.Running(key)` first (answer `alreadyRunning`), then
    `resume(id, hash, true)`. New: today's partial code skips the live-run check.
  - otherwise: `Start(StartArgs{RunArgs: resumeArgs(...), Hash})`; a changed script answers `E_CONFLICT`.
  - Outcome per item `{runId, started, code, error}`. A started item and every other offered id of the same key
    leave the offer. Fix: collect those ids with `Runs.Get` before calling `offer.drop`, which then filters by an id
    set with no DB call under the mutex.
  - New run's trigger: `manual`. No new trigger value.
- `RestoreDismiss()`: clears the offer.
- No push channel: the Service has no emitter for it, and one means both appwires. The Runs query refetches on mount,
  window focus, banner click and after each mutation; a stale banner in another window resolves on its next focus.

### D4 Shared dialog: `packages/workbench/src/restore/`

Presentational only. No data fetching, no Pinia store, no injection, no sources registry.

- `types.ts`:
  - `RestoreRow { id; label; detail?: string; folder?: string; badges?: string[]; state: 'ready' | 'waiting' |
    'unavailable'; status: string; reason?: string; error?: string; members?: RestoreMember[] }`. `status` is the
    source's own value, rendered as `data-status` only.
  - `RestoreMember { id; label; error?: string }` (Compose services).
- `RestoreDialog.vue` (`<script setup lang="ts">`):
  - Props: `title`, `description`, `icon` (codicon name), `rows: RestoreRow[]`, `pending: boolean`,
    `dismissing: boolean`, `callError?: string`.
  - `v-model:excluded` (`string[]`): ids the user unchecked. Every `ready` row counts as selected unless excluded, so
    rows arriving on a refetch start checked; the adapter keeps the model across refetches.
  - Emits `confirm(ids: string[])` (checked `ready` row ids, in row order), `dismiss`, `close`.
  - `waiting` rows: shown in the main list, disabled, never selected. `unavailable` rows: in the "Not restored"
    section with their `reason`.

Look (Tailwind utilities only, no scoped `<style>`; existing primitives only: `Dialog*`, `Checkbox`, `Badge`, `Button`,
`Collapsible`, `Alert`, `Spinner`, `FieldError`, `CodiconIcon`; no new shadcn-vue primitive):

- `DialogContent size="lg"`. Header: `icon` in a muted rounded square, `title`, `description`.
- Selection bar: "{selected} of {total} selected" left; "Select all" / "Select none" (`variant="toolbar"`) right.
- Main list: one rounded-md bordered block, rows divided by `divide-y`, row padding `px-3 py-2`, hover
  `bg-muted/40`, whole row is the checkbox's `Label`.
- Row: checkbox, then two lines. Line 1: label (`font-medium truncate`) and badges (`Badge`). Line 2 (`font-data
  text-kira-sm text-muted-foreground truncate`, full text in `title`): `detail` (command or image), then codicon
  `folder` and `folder` when set. Waiting row: spinner and its `reason` instead of the checkbox. Members (Compose):
  indented muted list under line 2, each with its own `FieldError`. Row `error`: `FieldError` under the row.
- "Not restored ({n})": `Collapsible`, collapsed by default, listing label and reason per row.
- Body scrolls inside `DialogBody` (implementer confirms it caps height; else `max-h-[60vh] overflow-y-auto`).
- `callError`: `Alert variant="error"` at the body's end.
- Footer: `Button variant="dialog"` "Don't restore" (`:pending="dismissing"`), `variant="dialog-primary"`
  "Restore {count}" (`:pending="pending"`), disabled at 0.
- Keyboard: Tab order header, selection bar, rows, collapsible, footer; Space toggles; focus trap from the primitive.

### D7 Safety

- Nothing starts without the confirm. Each row shows what will run now: command or prompt excerpt, folder, task,
  params count (secrets masked). The plan hash guards edits between view and confirm (`E_CONFLICT` -> row error,
  state refetches).
- Secrets are never replayed (`needsInput`, unselectable). A live run of the same key is never doubled (`running`,
  unselectable; `Start` and the new resume-path check refuse anyway). Worktree claims go through `Start`/`resume`.
