## Decisions

### D1 Operation groups: four, one mode each

| Group (stored word) | Tools | Why grouped |
|---|---|---|
| `discover` | `kube_list_namespaces`, `kube_list_kinds` | Cluster shape only, no object data. An AI calls both before any list; two prompts per first question is noise. |
| `list` | `kube_list_resources` | Object names, labels, status columns. |
| `describe` | `kube_describe` | Full object: spec, annotations, ConfigMap data, events. Secrets redacted by P439 D7. |
| `logs` | `kube_pod_logs` | Application output; can carry anything. |

Plus `kube_list_clusters`, ungated (mirrors `list_connections`: its job is to show each cluster's
modes and description up front).

### D2 Modes and storage: reuse the DB vocabulary

- Stored words `deny | prompt | allow` (same as `connections.mcp_*_mode`, same `McpPermissionMode` TS
  type, same `strictnessRank` semantics). SPEC's off/ask/allow are the UI meaning; the UI reuses the DB
  control's labels "Deny / Allow / Ask me" (`common.action.deny.label`,
  `studio.project.connectionDialog.mcp.{allow,prompt}.label`; C3 forbids duplicate strings).
- Default `prompt` for all four (SPEC: default ask). Existing P439 rows get it from the column default:
  fail closed.
- No separate `mcp_enabled` switch. DB connections have one (deny by default), but the SPEC sets the
  default to ask, and an extra switch would make the default effectively off. Instead a cluster whose
  four modes are all `deny` is hidden from `kube_list_clusters` and answers "no cluster exposed" to
  every tool (same text as an unknown id, `resolveEnabled` posture). State this in ARCHITECTURE.
- Migration `0051_p440_kube_cluster_mcp.sql` (0050 is Stream B's):

  ```sql
  -- P440: per-cluster MCP description and per-operation modes (deny | prompt | allow), 0021's shape.
  ALTER TABLE kube_clusters ADD COLUMN mcp_description TEXT NOT NULL DEFAULT '';
  ALTER TABLE kube_clusters ADD COLUMN mcp_discover_mode TEXT NOT NULL DEFAULT 'prompt';
  ALTER TABLE kube_clusters ADD COLUMN mcp_list_mode TEXT NOT NULL DEFAULT 'prompt';
  ALTER TABLE kube_clusters ADD COLUMN mcp_describe_mode TEXT NOT NULL DEFAULT 'prompt';
  ALTER TABLE kube_clusters ADD COLUMN mcp_logs_mode TEXT NOT NULL DEFAULT 'prompt';
  ```

  `embed.go`: `{Version: 51, Name: "p440_kube_cluster_mcp", File: "0051_p440_kube_cluster_mcp.sql"}`.
  `sqlitex.Migrate` tolerates the gap (it applies versions above `current` in list order; no
  contiguity check). Risk: a local dev DB migrated to 51 on this branch would skip B's 50 after
  landing. Tests always start from fresh DBs; the Result tells the orchestrator to note it. Released
  installs get 49, 50, 51 in order.
- Validation in Go (`Service.SetMcp`), not SQL CHECK (0021 precedent): each mode in the three words,
  else `E_BAD_REQUEST`; description at most 1000 runes (connection schema's `max(1000)`), else
  `E_BAD_REQUEST`. Unknown id: `E_NOT_FOUND`.

### D3 Backend shape (package `kubernetes`, P439's)

  gains `SetMcp(id string, m McpSettings) (bool, error)` (false when no row). `KubeClustersRepo`:
  extend `kubeClusterCols` and `scanKubeCluster`; `SetMcp` is one `UPDATE ... WHERE id = ?` with
  `RowsAffected`.
- `types.go`: `Cluster.Mcp McpSettings \`json:"mcp"\`` filled in `Clusters()` from the record
  `Ensure` returns. `SetMcpArgs{ClusterID string; Mcp McpSettings}`.
- `service.go`: `SetMcp(ctx, SetMcpArgs) (McpSettings, error)` (validate, store, return stored).
  `bound.go`: `SetMcp(args SetMcpArgs) (McpSettings, error)`.
- Bounded reads for MCP (new file `mcpreads.go`; no window, no stream):
  - `ListCapped(ctx, ListArgs, max int) (ListResult, error)`: `List`'s body moves to an unexported
    `list(ctx, args, max)`; `List` passes `s.listMax`. MCP passes its `maxRows`.
  - `ReadLogs(ctx, LogsReadArgs) (LogsReadResult, error)`. `LogsReadArgs{ClusterID, Namespace, Pod,
    Container string; Previous, Timestamps bool; Tail int}`. One non-follow `GetLogs(...).Stream`

    `Truncated` when bytes read reach the limit. Errors through `mapErr`. No new unit test: the framer
    already has one; the rest is plumbing.
- Op log: the `kubernetes` package still records nothing for UI reads (P439 decision stands). MCP
  calls are recorded by dbmcp (D5).

### D4 MCP tools (new `apps/kira-studio/internal/dbmcp/kube_tools.go`)

Registered by `addKubeTools(srv, src)` when `s.cfg.Kube != nil` (proof-tools pattern), each through
`withPanicRecovery` (so ctx carries `OpSourceMCP`). `dbmcp.Config` gains:

```go
// KubeReader is dbmcp's consumer-declared view of *kubernetes.Service.
type KubeReader interface {
	Clusters(context.Context) (kubernetes.ClustersResult, error)
	Namespaces(context.Context, kubernetes.ClusterArgs) (kubernetes.NamespacesResult, error)
	Kinds(context.Context, kubernetes.ClusterArgs) (kubernetes.KindsResult, error)
	ListCapped(context.Context, kubernetes.ListArgs, int) (kubernetes.ListResult, error)
	Describe(context.Context, kubernetes.DescribeArgs) (kubernetes.Description, error)
	ReadLogs(context.Context, kubernetes.LogsReadArgs) (kubernetes.LogsReadResult, error)
}
// OpRunner is adapterhost.Host's RunOp, for the op-log row of each Kubernetes read.
type OpRunner interface {
	RunOp(context.Context, adapterhost.OpSpec, func(context.Context, *adapters.OpCtx) (any, error)) (string, any, error)
}
```

Fields `Kube KubeReader`, `Ops OpRunner`. No import cycle: `kubernetes` imports neither.

| Tool | Args (required bold) | Result |
|---|---|---|
| `kube_list_clusters` | none | `[{id, context, cluster, server, namespace, current, description, permissions{discover,list,describe,logs}}]`, clusters with four `deny` omitted. No `user`, no `source` (auth user names and file paths are not the AI's business). No status probe (P439 lazy connect: probing fires SSO plugins). |
| `kube_list_namespaces` | **clusterId** | `{namespaces, restricted, fallback}` |
| `kube_list_kinds` | **clusterId** | `{kinds:[{key, kind, namespaced, category}], partial}` |
| `kube_list_resources` | **clusterId**, **kind** (key from `kube_list_kinds`), namespace (empty: all), labelSelector, maxRows (default 200, max 2000) | `{columns, rows:[{name, namespace, cells}], rowCount, truncated}` |
| `kube_describe` | **clusterId**, **kind**, **name**, namespace | P439 `Description` with `manifest` cut at 256 KiB on a line boundary plus `manifestTruncated` |
| `kube_pod_logs` | **clusterId**, **namespace**, **pod**, container, previous, timestamps, tail (default 200, max 5000) | `{lines:[{ts,text}], truncated}` |

Shared gate `s.kubeRun(ctx, clusterID, op string, statement func(kubernetes.Cluster) string, read
func(context.Context, *adapters.OpCtx) (any, int, error))`:

1. `resolveCluster(ctx, id)`: `Kube.Clusters(ctx)` (reloads kubeconfig; cheap), find id, refuse with
   `no cluster %q exposed to MCP` when absent or all four modes `deny`.
2. Mode `deny`: `errResult("cluster %q's MCP permissions deny %s; change them in the cluster's MCP
   settings")`. Nothing reaches the API server.
3. Mode `prompt`: `cfg.Approvals.Request(ctx, ApprovalRequest{ConnectionID: id, ConnectionName:
   context, Kind: "kubernetes", Class: adapters.ClassRead, Statement: stmt, Reason:
   ApprovalReasonPermission, Cluster: &ApprovalCluster{...}})`. Approved: re-resolve and re-check the
   mode (the `awaitApproval` posture: a tightened mode or a hidden cluster wins). Other outcomes:
   messages from one helper `approvalOutcomeError(outcome, subject)` that `awaitApproval` also moves
   to (subject `query against %q` there, `Kubernetes read on %q` here); wording of existing DB
   messages unchanged.
4. Run: `cfg.Ops.RunOp(ctx, adapterhost.OpSpec{Kind: "kubernetes"}, fn)`; `fn` calls
   `op.SetCommand(stmt)`, runs `read`, `op.SetRows(n)` (namespaces, kinds, rows, lines; describe 1).
   Result through `jsonResult`; errors through `toolError`.

Statement: a kubectl-equivalent line, shown in the dialog and stored as the op command. Never run.
Built by `kubeStatement` in `kube_tools.go`; every user or AI value quoted with `loginshell.Quote`
when it holds anything outside `[A-Za-z0-9._/:=,-]`:

- discover: `kubectl get namespaces --context <ctx>` / `kubectl api-resources --context <ctx>`
- list: `kubectl get <resource>[.<group>] (-n <ns> | -A) [-l <sel>] --context <ctx>`
- describe: `kubectl describe <resource>[.<group>] <name> [-n <ns>] --context <ctx>`
- logs: `kubectl logs <pod> -n <ns> [-c <c>] [--previous] --tail <n> [--timestamps] --context <ctx>`

Kind keys resolve to `<resource>[.<group>]` through the parsed key (`v1/pods` to `pods`,
`apps/v1/deployments` to `deployments.apps`); an unparsable key renders as given. No unit test:
a flat formatter, asserted through the flow test's contract.
