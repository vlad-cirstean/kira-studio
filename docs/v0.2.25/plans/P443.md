## Run budget (CLAUDE.md "one full run per phase")

This phase's ask is a before/after of the full suites, so it needs exactly two full runs per app: the
Before run (step 2) and the After run (step 10). The After run is the phase's one verification run. Between
them only targeted runs: single spec files, the worker sweep subset, `--repeat-each` checks. Say so in
Result. Never run the two apps' suites at the same time, and never beside a Go suite.

## Steps (commit per group, Conventional Commits)

### 1. `chore(test): UI timing report from Playwright JSON`

- `scripts/ui-timings.ts` (bun, no new dependency). Input: one or more Playwright JSON report files plus a
  label. Output: markdown on stdout.
- Walk `suites` recursively; per test result take `projectName`, file, title, `duration`, `startTime`,
  `status`, `retry`.
- Per project: tests, passed, failed, timed out, skipped; sum of durations; wall time (min `startTime` to
  max `startTime + duration`); effective parallelism (sum / wall).
- Per file (sum over its tests, per project): slowest 30 files. Also slowest 30 tests (file:line, title,
  duration, status).
- Test duration median and minimum per project (the minimum approximates one boot plus a trivial test; used
  by step 6).
- Totals line: report `stats.duration` (Playwright's own wall time).
- No unit test (CLAUDE.md bar: a report formatter). Typecheck and lint must pass; `scripts/` changes run the
  full pre-commit hook.

### 2. Before run (expensive, once per app) and `docs: P443 baseline UI timings`

Preconditions, each checked and quoted in the timings file:

- `uptime` load average 1-minute below 1. `pgrep -fa 'playwright|WebKit|chrome|go test|golangci'` empty.
  Otherwise wait; never measure under load.

- Clean tree at a recorded commit.

Write `docs/v0.2.25/plans/P443-timings.md`, section "Before": commit, preconditions, build time per app,

### 4. Fixed sleeps to condition waits

Scope: every `waitForTimeout` in `apps/kira-studio/tests/ui`, `apps/kira-space/tests/ui` and
`packages/workbench/src/testing/ui/scenarios`. Not `perfProbe.ts`, `heapProbe.ts`, `tests/perf`,
`tests/mobile`, `tests/ipc` (opt-in projects or outside the UI suites). Classify each, in this order:

1. Waits for something to happen (render, debounce end, menu settled, scroll applied): replace with the
   condition (`expect(locator)...`, `expect.poll`, `locator.waitFor`, `page.waitForFunction` on the DOM or
   app state the next step reads). These are load flakes whatever their cost.
2. Asserts an absence ("does not re-read", "no popup"): replace with a barrier. Trigger a second event whose
   effect is observable and is processed after the first (same channel or queue), wait for that effect, then
   assert the first had none. Example `ade-v2-review.spec.ts:507-509`: after the `/tmp/elsewhere` event emit
   a matching event, poll reads to `after + 1`, then the non-matching one provably caused no read. Where the
   code under test runs on timers the page clock controls, `page.clock.runFor` instead. Where no barrier
   exists, keep the sleep with a one-line why comment (CLAUDE.md comments rule).
3. Is the behavior under test (a real-time quiet window, the `slick-grid` chase "stay inside the 300ms quiet
   window", Sortable's 50 ms dragover tick in `dragTab`): keep, one-line why comment if missing. For
   `dragTab`, replace the 300 ms only if a DOM signal of the swap exists (placeholder moved); else keep.
- `support/copyScenarios.ts` `openContextMenu`: the 300 ms "menu stays open" check is a retry loop against a
  SlickGrid re-render. Replace with a condition: wait for the grid's render to settle (the same signal
  `support/grid.ts` already uses, if any) before the right click, then one click. Keep the loop only if the
  re-render has no observable end; say which.
- Group commits per app and helper: `test(ui): studio helpers wait on conditions`, `test(ui): studio specs
  wait on conditions`, `test(ui): space specs wait on conditions`, `test(ui): shared scenarios wait on
  conditions`.
- Per changed spec file: run it alone, `--repeat-each=5`, idle. Per changed shared helper (`tabs.ts`,
  `copyScenarios.ts`, `tree.ts`, `clipboard.ts`, `automationsOrder.ts`): one spec using it under the
  DEV_ENVIRONMENT load repro recipe, `--repeat-each=20 --workers=8`, compared with the same at base. A new
  flake is a stop and fix, never a longer wait (DEV_ENVIRONMENT rule).
- Count before and after per app in Result.

### 6. Shared setup and duplicate coverage (gated on the numbers)

Use the Before data only; no guessing from line counts.

- Boot cost: per app, take the minimum and median test duration from step 1. If the median test is under
  2x the minimum, boot dominates. Then, inside the slowest 30 files only, look for groups of tests that
  `relaunch` with identical options and only read state (no writes, no drag, no event that later tests
  depend on). Merge such a group into one test with one `test.step` per former test, every assertion kept.
  Each merge names the old test titles and the new step titles in Result. No merge across files, no shared
  page across tests (isolation and `fullyParallel` stay).
- If boot does not dominate: no merges; say so with the two numbers.
- Duplicates: inside the slowest 30 files, and for the shared `scenarios/*` registered in both apps. Use
  `codegraph_explore` (mandatory for this discovery, CLAUDE.md) on the spec, its helpers and the app code it
  drives. A test is removable only when another test in the same app drives the same app code path and makes
  the same assertion. A shared scenario stays in both apps unless the app-specific wiring it covers
  (`apps/*/frontend/src/workbench/*Module.ts`, the bridge) is driven by another spec of that app; name it.
- Each removal: one line in Result, `<removed test> covered by <file>:<line> <title>`. None found: say so.
- Builds: from step 2's build times. `test:ui:*` and `test:visual:*` each rebuild the same test bundle. If a
  build costs 60 s or more, add `scripts/build-test-if-stale.sh <app>`: hash `git ls-files -s` plus
  `git diff HEAD` of `apps/<app>/frontend`, `packages`, `package.json`, `bun.lock` into
  `apps/<app>/frontend/dist/.kira-test-build`; skip the build when equal. `build:test:<app>` scripts in the
  suite commands call it; `build:test:*` itself stays a plain build. Under 60 s: no change; say so.
- Commits: `test(ui): merge read-only <area> tests into steps`, `test(ui): drop <test> covered by <spec>`,
  `chore(test): skip an unchanged test bundle build` as each applies.

### 7. Local selection (gated) `feat(test): select UI suites by changed paths`
