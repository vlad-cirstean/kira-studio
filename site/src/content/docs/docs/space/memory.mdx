Memory is a store of short facts with an MCP server for Claude Code. It needs an authenticated `claude` CLI.

## What a memory holds

- **Kind**: a fact or a rule. A fact is a durable claim. A rule is a standing imperative with its reason, such as "Never write amounts as floats, because the ledger rejects fractions." A rule shows a **Rule** badge in the list. A question or a one-off task is never a memory.
- **Fact**: one claim or rule.
- **Reason**: why the fact is true.
- **Origin**: who stated it. User facts are challenged by a human and correct. External facts are correct, probably incomplete, and carry a source tag. Agent facts are reference only.
- **Scope**: Company, Project or Personal. A project is identified by the repository's `origin` remote.
- **Groups**: facts stored together share a session, request, document, task or thread.

A memory is never edited in place. A change adds a new version, and the detail view shows the version trail.

## Add a memory

Click **Add memory** and write facts in your own words. Claude splits them into single facts and checks them. If the check challenges a fact, answer and choose **Resubmit**.

Pick a scope. The default is Personal.

## Import files

Use **Import files…** or **Import folder…** in the panel header.

1. The app scans the selection and shows an estimate: files, chunks, Claude calls and time.
2. Set the origin and, for an external origin, a source tag.
3. Click **Start import**.

The import runs on your Claude subscription.

Tick **Write a kira-memory doc beside each file** to save the extracted facts as `<name>.memory.md` next to the source. Facts stated under a heading appear as plain list items under that heading, without a reason line. The app never overwrites the source. See [Memory formats](../../reference/memory-formats/).

Files an earlier import already finished are skipped when unchanged.

## Condense text with distill

An agent calls `ingest_files` with `distill` set to true and either `text` or one absolute file `path`. The call turns the input into short lines and stores nothing. It runs the same pipeline as an import. The input is split into parts and facts and rules are extracted from each part. Doubtful ones are checked against the source. One merge call then joins duplicates across the parts. Facts come back as short claims and rules as short imperatives. Negations, numbers, names, paths and template variables stay as written. A long example becomes a pointer to where it lives.

Nothing is stored, so the memory check does not run. Input is limited to 120,000 characters, split into at most 16 parts, and a call stops at 2 USD. It runs on your Claude subscription. See [MCP tools](../../reference/mcp-tools/).

For one short text such as a code comment, add `mode` set to `rewrite`. One call returns the same text in its own form. Trivia is dropped: phase tags, history, filler and sentences that restate the code. Every fact stays. Comment markers, indentation, backticked names, numbers and negations stay as written. A text that is already clean comes back unchanged.

The text must be at most 2,000 characters and `text` only. Optional `context` is the code around it, read only, up to 6,000 characters. Optional `check` runs a second call that checks the rewrite kept every fact. A rewrite is rejected when it breaks a rule. Rules: not longer than the input, same markers and indentation, no line over 100 columns, no lost name or number. The original then returns with `kept: <reason>`.

### Distill in the app

The Memory module runs the same pipeline. Click **Distill text** in the panel header. **Back to memories** returns to the memory view.

1. Choose **Text** and paste, or choose **File** and pick a document. In a file view, select text, open the context menu or command palette and run **Distill selection**. The selection arrives as text, with its path and line range shown.
2. Click **Run distill**.

For one short text, choose **Rewrite** beside **Text** and **File**. The result is the text in its own form. It shows what was left out, or says the text is already concise, or says why the original was kept. **Copy** puts the text on the clipboard. Rewrite results cannot be stored or imported. The limit is 2,000 characters.

The size line shows characters and about how many tokens the input holds (one token per three characters). While the run goes, the view shows the stage (reading parts, checking against the source, merging lines), the steps done and the cost so far. **Cancel** stops it. Work that already finished is charged.

The result shows characters and tokens before and after, the cost and the number of parts. Rules carry a **Rule** badge. Facts the input leaves open are listed under **Unclear, left out**, with the questions that would settle them. Pick the lines you want, then:

- **Copy** puts the picked lines on the clipboard, one per line.
- **Store…** stores the picked lines as memories, up to 20 at a time. The usual memory check applies and decides the kind, and a challenge asks you to answer and resubmit.
- **Import as document…** saves the lines as a document and opens the normal import confirmation. The document stays under `distilled/` in the memory folder as the import's source.

Distill alone writes nothing to the store. Only one distill runs at a time. The input limits above apply.

## Choose the Claude model

**Settings > Memory > Claude model** sets the model for memory checks, import and distill. The default is `sonnet`. The choice applies from the next Claude call, including a running import.

## Search

The search box finds facts by keyword. Semantic search adds matches by meaning.

- Open `Settings > Memory` and choose **Download model**. The model is about 35 MB and runs locally.
- A result shows whether it matched by keyword, by meaning or both.
- **Include history** adds older versions.
- **Boost project** ranks one project's facts higher. It does not hide the others.

Without the model, search stays keyword only. Nothing else changes.

## Connect Claude Code

Open `Settings > Memory` and choose **Connect Claude Code**. This registers the `kira-memory` MCP server in your user scope. Claude Code then stores and searches memories. See [MCP tools](../../reference/mcp-tools/).

The server works with the app open or closed.

## Check memory docs

`Settings > Memory` also shows a pre-commit hook that checks kira-memory doc files in a git repository and flags retired comment blocks.

## Where data lives

Memories live in `~/.kira-memory/memory.db`. The downloaded model lives in `~/.kira-memory/models`. Documents saved by **Import as document…** live in `~/.kira-memory/distilled`. Set `KIRA_MEMORY_HOME` to move the folder.
